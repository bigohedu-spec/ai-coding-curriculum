## 本版設計決策

1. **放棄 S3 HTML 小遊戲製作**：HTML 小遊戲週期過長，容易把 S3 變成低完成率的大型專案。
2. **移除 Minecraft 主線課程分類**：Minecraft 不再承載邏輯訓練、展示、驗收或任務發布；課後時間可自由遊玩。
3. **改用短任務閉環**：每週聚焦一張可完成、可提交、可評審的學習單任務。
4. **S3 核心不是大作品，而是短任務完成能力**：學生要練會「看任務 → 複製或撰寫提示詞 → 用合適工具生成 → 回填 → 送 AI 審核 → 必要時補件或修正」。
5. **VS Code 只做前置操作**：S3 不要求學生獨立開發，只要求能開檔、改內容、看結果、描述錯誤。
6. **W1 改為工具選擇與初次使用**：第一堂課做六個短任務，讓學生使用文字、圖片、音樂與影片入口；學生端回填生成結果，審核產出類型與任務相關性。
7. **AI 評審不獨立成模組**：AI 評審是從模組一開始就套用的任務評判方式，不是 W9-W12 的課程主題。
8. **模組三聚焦精確素材修正**：W9-W12 不只是產出素材，而是對同一素材反覆修改，練習滿足明確的尺寸、長度、風格、用途與限制。
9. **模組四聚焦複合型工具使用與設計思維**：W13-W17 以廣告、產品設計、有聲書等具體複雜任務，練習把需求拆開、選工具、組合成果並做基本設計取捨。
10. **W2、W3 採六題連續故事鏈**：每題保存資料供下一題使用，讓「找重點」從單題填空提升為跨題資料傳遞。
11. **W3 採一題一問一答**：每題只有一次 AI 提問與一個成果；不加入工具選擇題、前後測、第二輪追問或多成果欄位。
12. **W3 只讀上一題保存包**：B 只讀 A、C 只讀 B，依序到 F 只讀 E；保存包會累積必要資料，學生不需跨多張卡蒐集。
13. **Markdown 單一來源**：每週網站 JSON 嵌在對應課程規格 `.md`，不另維護同名 JSON；網站建置時抽取，生成檔不是正典。
14. **需求建立與受控修復分流**：W05 以天空要塞改修任務建立「做什麼／怎麼做／不能做什麼／目標」四種需求；四種需求合在同一份提示詞中才稱為規格。序章先做讀題測試；A～D 每次只修改並審查一種需求，通過後使用 Lab Image 生成並回填一張藍圖；E 對學生自己的累積 Prompt 做完整規格總驗收。從模組三 W09 起，教學重點再轉為多條件素材修正。

### JSON 政策

- JSON 可以存在，但必須放在相對應課程規格 Markdown 的 `LAB_TERMINAL_WORKSHEET_CONFIG` 區塊。
- Wiki 不建立新的手寫 `*-答題表設定.json`；舊檔視為待遷移資料，完成遷移前不得與課程規格同時宣稱正典。
- GPT Clone 只從課程規格 Markdown 抽取 JSON；抽出的 `.json` 是暫存建置產物，不進 Obsidian、不人工同步。
- 左側學生內容讀學習單，右側答題卡讀規格 JSON；兩側以 `contentRevision` 與 `contentRef` 做發布前檢查。

## S3 任務操作流程

W1 先用六個短任務建立成果類型與工具入口直覺；W2 進入六題連續故事，練習從陌生資料找重點並把前題成果帶到下一題；W3 把流程收斂成每題一次提問、一次回答，並讓上一題保存包直接成為下一題唯一舊資料。W4 再加入任務順序洗牌與錯誤修正。

W3 的新版答題流程固定為：

```
看任務
  → 讀上一題保存包
  → 把保存包與本題線索放進唯一 Prompt
  → AI 回傳一個成果
  → 回填或上傳一次
  → 通過後自動建立下一題保存包
```

W3 不設 `readChecks` 或額外小測。文字題只交一行；媒體題只交一個附件。成果由本地可重現條件判定，AI 不當關主。未通過只修改同一個 Prompt／成果，不新增第二個教學問題。

### W05 起的受控修復流程

W05 將「第一次生成」和「依規格修正」分開。W1 已讓學生操作文字、圖片、音樂與影片入口；後續修正週不必讓學生無限呼叫同一工具，而是讓學生在固定素材上練習真正重要的任務工作流：

```text
看 V0 缺陷作品 → 讀任務規格 → 找出不符合的條件
→ 寫修正 Prompt → 通過修復檢查 → 解鎖 V1 修復作品
→ 比對規格並留下修復紀錄
```

- **V0 / V1 是預生成版本**：學生不會靠重抽碰運氣；每一版差異都對應一個可學習的修正點。
- **Prompt 審核的定位**：學生端看見「修復 Prompt 檢查」；系統端以交付方式選擇、必要資料與同義詞規則作可重現判定，AI 僅將結果說成白話回饋，不能單獨決定通過。
- **API 邊界**：修復週不呼叫圖像、音樂或影片生成 API，也不提供無限重試。若日後需要真實生成，必須明列每題工具額度、修正理由與後端帳號配額。
- **修復紀錄**：保存原本哪裡不能用、學生要求改成什麼、V0/V1 版本與通過時間；它是 W23 通過紀錄作品集與 S3 里程碑的證據。

### W1–W4 支架遞減

- **W1**：完整任務與提示詞，重點是第一次走完工具與回填流程。
- **W2**：六題連續資料鏈，題面仍提供較完整問題句型；重點是從前題複製正確資料。
- **W3**：六題單回合資料鏈；每題固定工具、一次 Prompt、一個成果，只讀上一題保存包。
- **W4**：混合任務、順序洗牌與退件修正，學生自行判斷資料來源、成果類型與修改方向。

學生要記住的核心口訣：

> 上一題留下資料，下一題拿來解謎。

#### W2 學習單定位

W2 改為《馬雅星門的六道封印》六題連續故事。學生處理 ROT13、色票、Base64、聲音順序與動作規則，但不要求背誦編碼原理；重點是把陌生形式交給 AI 轉譯，並從前一張答題卡帶入下一題。

W2 保留較完整的問題句型與工具方向，主要門檻是「找出前題正確資料」：

```text
A 翻譯與分類 → B 生成石印 → C 還原場景與數字
→ D 生成聲音 → E 轉成動作 → F 整合影片
```

完整內容以 [[S3-W02-學習單]]、[[S3-W02-課程規格-G1-G2]] 為準；Semester 不再保存單週題目表。

#### W3 學習單定位

W3 是《不存在的午夜車站：零點列車》六站解謎。車站只在 23:40–00:00 出現；月光號在午夜離站時才被稱為零點列車。每站固定使用一個 Lab 工具、送出一次 Prompt、取得一個成果；學生只拿前一站留下的劇情物件開啟下一站。

```text
停止的時刻表 → 月光路條 → 星孔車票 → 藍燈印記
→ 發車回聲 → 第七節通行證 → 記憶鏡中的登車回憶
```

W3 的音訊只作學習成果；E 的正式技術輸入是 D 通過後由答題記錄區注入的 AI 可閱讀摩斯文字鑰匙，避免把生成模型或音訊辨識失敗算成學生錯誤。

W3 同時啟用新版職能切割：學生題面只在 [[S3-W03-學習單]]；答案、系統 packet、判定、解鎖與網站 JSON 只在 [[S3-W03-課程規格-G1-G2]]；教學時間、故事連續性與教師備援只在 [[S3-W03-教案]]。`PACKET_*` 僅供工程與教師除錯，不出現在學生介面。

W3 保留 W02「前題資料帶到後題」的設計核心，但拿掉交接小測與多階段提問。系統仍由 `PACKET_A` 傳到 `PACKET_E`；學生端依序只看月光路條、星孔車票、藍燈印記、發車回聲與第七節通行證。既有文字答案、車票圖、摩斯音訊與登車影片全部沿用，只改劇情銜接。

## 評量與考題方向

S3 的考題不再測 Minecraft 指令方塊，而改測任務工作流、精確素材修正與複合工具設計。

| 考題類型 | 範例 |
|----------|------|
| 工具判斷 | 「任務要求做 30 秒背景音樂，應該用哪個工具？」 |
| 任務重點抽取 | 「這張任務卡中，哪三個資訊必須放進提示詞？」 |
| 回填流程 | 「生成結果後，下一步應該回到哪裡提交？」 |
| 精確要求判斷 | 「任務要求藍白色、正方形、不能有文字，下面哪個成果比較符合？」 |
| 素材修正 | 「AI 評審說圖片缺少指定角色，下一次提示詞應該加上什麼？」 |
| 複合任務拆解 | 「如果要做有聲書片段，需要先準備哪些素材？」 |
| 設計思維 | 「這個廣告是給低年級學生看的，哪個標語比較清楚？」 |
| 條件判斷 | 「如果 AI 評審說缺少截圖證據，下一步應該做什麼？」 |
| 退件修正 | 「下面哪個修改最能解決『答案太籠統』的退件理由？」 |
| VS Code 前置 | 「修改 HTML 後，要看結果是否改變，應該做哪一步？」 |
