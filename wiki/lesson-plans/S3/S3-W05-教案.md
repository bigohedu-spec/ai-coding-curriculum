## 教學定位

- 本週唯一可觀察能力：學生能把一句提示詞要求分類為「做什麼、怎麼做、不能做什麼、目標」，並親手把四種需求組合成完整規格。
- 正式概念：每一種提示詞資訊稱為一種**需求**；四種需求合在同一份提示詞中，才稱為一份**規格**。
- 故事包裝：會把提示詞畫成建築圖的 AI 稱為「魔法藍圖」。年輕工程師洛可因為心急，每次只向它說一小部分；學生扮演見習魔法建築師，逐題把他的爛咒語修成完整規格。
- 序章沿用 W04 規則：先完成 3 題讀題測試，再開放 A 題。
- A～D 每題都修改目前累積 Prompt，只新增一種需求，通過限定範圍審查後由 Lab Tool 回傳教師預製的下一版魔法藍圖；E 再做完整四需求總驗收並取得成功圖。
- 本週不教程式控制、建築物理、自由設計或第五種需求。

### 固定教學語言

| 層級 | 名稱 | 教師固定說法 |
|---|---|---|
| 單項 | 需求 | 一句要求回答四個問題中的一個 |
| 四項組合 | 規格 | 做什麼＋怎麼做＋不能做什麼＋目標 |
| 給 AI 的文字 | 提示詞／Prompt | 故事中叫魔法咒語，正式名稱仍是提示詞 |

| 需求 | 固定問題 | 判斷線索 |
|---|---|---|
| 做什麼 | 要 AI 產生什麼？主體是什麼？ | 成果種類、作品主題、主要物件 |
| 怎麼做 | 畫面如何安排？部件怎麼組合？ | 數量、位置、順序、風格、視角 |
| 不能做什麼 | 哪些錯誤或危險不能出現？ | 不要、不能、禁止、避免 |
| 目標 | 給誰使用？希望帶來什麼效果？ | 對象、用途、理解、感受 |

> 不可把單張需求卡稱為「一份規格」。只有四種需求組合完成後，才能使用「完整規格」。

## 故事與題目的因果

故事只提供一條合理任務：魔力風暴逼近，浮空城艾爾利亞必須改修天空要塞。魔法藍圖會把收到的提示詞畫成建築圖；洛可把沒有說清楚的內容都交給它猜，學生每補一種需求，Lab Tool 才回傳下一版藍圖。

```text
模糊咒語
→ 不知道造什麼
→ 不知道如何組合
→ 不知道哪些錯誤要避免
→ 不知道給誰使用、希望產生什麼效果
→ 四種需求組合成完整規格
```

不另外要求學生記城市歷史、魔法規則或建築知識。

| 題 | 洛可的錯誤想法 | 學生修正 | 修正後仍留下的問題 |
|---|---|---|---|
| A | 說「改造」就夠了 | 補做什麼 | 塔橋排列混亂 |
| B | AI 會自己安排部件 | 補怎麼做 | 危險內容仍出現 |
| C | 不用明說禁止項目 | 補不能做什麼 | 外觀冰冷、居民不安 |
| D | 完整就等於適合居民 | 補目標 | 四段仍要合成同一份規格 |
| E | 四張需求卡分開交也可以 | 四種需求合在同一個 Prompt | 天空要塞完成 |

### 故事圖片與錯誤藍圖的分工

| 素材 | 出現位置 | 教學功能 | 不可出現 |
|---|---|---|---|
| GAMMA 任務開場圖 | 左側每題開頭 | 交代人物、事件、時間、地點與關鍵物件，延續冒險 | 本題錯誤藍圖、正確規格答案 |
| V0～V4 魔法藍圖 | Lab Tool 回傳區／右側答題卡 | 教師預製的連續缺陷鏈；讓學生觀察本題修好後，下一種需求仍造成什麼問題 | 同一張圖混入多題缺陷、正確答案文字 |
| V5 成功藍圖 | Lab Tool 回傳區 | 四種需求總驗收通過後的完成回饋 | 額外第五種需求或可閱讀文字 |

五題 GAMMA 開場固定使用同一位十歲見習魔法建築師、同一座艾爾利亞與同一組符文道具，時間由黃昏依序走到初夜、午夜、破曉與晨光。教師不以 GAMMA 開場圖要求學生診斷缺陷；診斷時必須指向 Lab Tool 回傳的魔法藍圖。

- 核對學習單內 A～E 五段 `GAMMA_ASSET_PROMPT` 均位於任務開頭，角色外觀一致，且沒有描繪本題錯誤或正確規格答案。

- `current-requirement-only`、`complete-spec`、pass token、reviewTicket、promptHash 與不重審範圍只供教師與工程端查看，不投影、不口述給學生。
- 準備四張大型名稱卡：`做什麼`、`怎麼做`、`不能做什麼`、`目標`；卡片只印名稱和問題，不印本週答案。

### 教師可接受的完整規格（僅教師版）

```text
做什麼：成果是一座空中要塞，名稱是天空守護要塞，主體是漂浮岩盤上的六角形城堡。
怎麼做：以中央水晶塔為中心，四座守望塔平均分布四角，用發光石橋連接，畫面由正面微俯視呈現。
不能做什麼：不要有斷裂石橋、城牆缺口、火焰或黑暗詛咒符號，也不要出現可閱讀文字。
目標：給浮空城的孩子與居民看，讓他們一眼辨認中央水晶塔和四座守望塔，並感到安全與希望。
```

這段不可投影或貼進學生輸入框。學生可使用同義說法，不以逐字相同作為通關條件。

## Lab Tool 魔法藍圖回傳流程

每題都使用同一個學生流程：

```text
看目前魔法藍圖 → 修改本題可編輯需求 → 點擊「送出需求」
→ 審查器只看本題需求 → 通過後回傳教師預製的下一版藍圖
→ 答題卡自動綁定 → 觀察圖片還有什麼問題 → 完成六題故事循環小測
```

教師須用以下矩陣判斷系統是否錯審：

| 題 | 只准審查 | 不准退件的原因 |
|---|---|---|
| A | 做什麼：成果、要塞主體、主要造型 | 沒寫排列、禁則或目標 |
| B | 怎麼做：位置、數量、連接、視角 | 不重新評價 A；沒寫禁則或目標 |
| C | 不能做什麼：具體危險與文字禁則 | 不重新評價 A、B；沒寫目標 |
| D | 目標：使用者、理解與感受 | 不重新評價前三種需求 |
| E | 完整四需求與跨段矛盾 | 可依固定順序一次退一種需求 |

### 教師看到的回圖狀態

1. `editing`：學生正在修改 activeRequirement。
2. `reviewing-current-scope`：送出按鈕已按下，但尚未回傳下一版資產。
3. `review-rejected`：只顯示一個本題缺漏，Prompt 與舊圖片保留。
4. `review-ticket-issued`：本題 Prompt 通過，ticket 綁定 promptHash。
5. `returning-teacher-blueprint`：Lab Tool 依 taskId 取得固定的 `resultBlueprintAssetId`。
6. `returned-auto-bound`：圖片已回傳並自動綁定答題卡。
7. `attachment-verified`：taskId、promptHash、ticket、assetId 與 MIME 一致。

若學生在 ticket 簽發後改動任何文字，ticket 與尚未綁定的回圖都必須失效並重新送出。圖片美術品質不判分；圖片的作用是讓學生指出「已修好什麼、還有什麼問題」。

### 可用與禁止的回饋

- A 可說：`這一題只檢查做什麼。你已寫出要塞名稱，再補上要產生哪種成果。`
- B 可說：`這一題只檢查怎麼做。你已寫出塔的位置，再補上部件如何連接。`
- C 可說：`這一題只檢查不能做什麼。再找一個仍未被禁止的危險。`
- D 可說：`這一題只檢查目標。你已寫出給誰看，再補上希望帶來的效果。`
- 禁止說：`你的 Prompt 還不完整，請把另外三種需求也補齊。`
- 禁止說：`這張圖片不夠漂亮，所以不能通過。`

### 每次回圖後的圖片追問

這些追問放在右側題中小測或教師口頭引導，不放進 GAMMA 學習單。先讓學生指著畫面說證據，再問它對應哪一種需求；不要先念出需求名稱。

| 回圖 | 先問學生看見什麼 | 再問缺少什麼資訊 |
|---|---|---|
| A／V1 | `這次已經像天空守護要塞了嗎？塔和橋哪裡還很亂？` | `魔法藍圖還不知道部件要如何安排嗎？` |
| B／V2 | `塔橋排列清楚了嗎？哪些地方仍然危險？` | `哪些內容只要出現就不應通過？` |
| C／V3 | `危險消失了嗎？居民看到會有什麼感受？` | `魔法藍圖知道作品給誰看、希望帶來什麼效果嗎？` |
| D／V4 | `四種需求都出現了嗎？為什麼藍圖仍未定稿？` | `四種需求要分開交，還是合在同一份提示詞裡？` |
| E／V5 | `哪些畫面證據顯示主體、排列、禁則和居民目標都生效？` | `這次為什麼可以稱為完整規格？` |

學生只要能指出可見問題與合理分類即可；不得用「圖不像老師心中的完美版本」退件。

## 序章讀題測試（約 4 分鐘）

- 第 1 題確認目前只有模糊咒語，不是完整需求。
- 第 2 題確認 A 題提示詞通過後，Lab Tool 先回傳 A 版魔法藍圖。
- 第 3 題確認開始方法是比較「目前咒語」與「失敗結果」。
- 三題只測任務理解，不詢問 A 的完整需求句，也不顯示正確卡片內容。
- 學生答錯時，只指向開場、保存規則或失敗畫面用途；不得口頭說出 A 的答案。

## 各題教師引導與評審

### A｜決定要改修什麼（約 10 分鐘）

- 先讀洛可的台詞「改造空中要塞就好了」，再指向提示詞框；提醒學生其他故事文字不是 Prompt。
- 看混合旅館、花園、飛船與城堡的失敗圖。
- 問：`魔法藍圖知道要畫圖片、影片還是建築設計嗎？`、`主要要造哪一種建築？`
- 學生從模糊 Prompt 開始，修改「做什麼」區塊；送出需求時只審成果種類、要塞主體與主要造型。
- Prompt 通過後由 Lab Tool 回傳並自動綁定 A／V1；請學生指出塔橋排列問題，不驗畫面是否已具備未來三種需求。
- 修正後預告：只要能辨認成果種類與要塞主體即可；塔橋排列留給 B。
- 6 題小測依序確認：A 在問哪種需求、A 的三項答案、剛修好的混合建築問題、B 要處理什麼、B 如何安排塔、B 要交魔法藍圖 B。
- 教師不可把顏色、排列或居民感受算進「做什麼」。

### B｜決定要如何改修（約 10 分鐘）

- 先讀洛可的台詞「AI 應該知道塔和橋放哪裡」，接續 A 已修好的要塞主體。
- 看水晶塔、守望塔與石橋齊全但散亂的失敗圖。
- 問：`中央要放什麼？`、`四座塔在哪裡？`、`部件如何連起來？`
- A 的認證段落鎖定帶入；學生修改「怎麼做」區塊，送出需求時只審位置、數量、連接與視角。
- Prompt 通過後由 Lab Tool 回傳並自動綁定 B／V2；請學生指出斷橋、缺口、火焰或黑暗符號，不得因缺少禁則或目標退件。
- 修正後預告：塔橋結構清楚即可；危險內容留給 C。
- 6 題小測依序確認：B 在問哪種需求、B 的完整排列方式、剛修好的塔橋排列、C 要處理什麼、C 要禁止哪些危險、C 要交魔法藍圖 C。
- 強調同一句若回答「如何呈現」，即使沒有使用「怎麼做」三字，也屬於怎麼做需求。

### C｜擋住錯誤改修（約 10 分鐘）

- 先讀洛可的台詞「不用說哪些東西不能出現」，承接 B 已排好的結構。
- 看斷橋、缺口、火焰與黑暗符號的失敗圖。
- 問：`哪些內容只要出現一個，就不能通過？`、`「不要畫壞」能不能明確檢查？`
- A、B 認證段落鎖定帶入；學生修改「不能做什麼」區塊，送出需求時只審具體禁則。
- Prompt 通過後由 Lab Tool 回傳並自動綁定 C／V3；請學生說明居民可能感到冰冷或害怕，不得重審做什麼／怎麼做或要求目標。
- 修正後預告：指定危險全部消失即可；居民感受留給 D。
- 6 題小測依序確認：C 在問哪種需求、C 的完整禁則、剛封印的危險、D 要處理什麼、D 的使用者、D 要交魔法藍圖 D。
- 不接受只說「不要失敗、不要畫錯、不要奇怪」等無法檢查的空話。

### D｜說清楚守護目標（約 10 分鐘）

- 先讀洛可的台詞「要塞沒壞，居民自然會喜歡」，承接 C 已安全的要塞。
- 看結構安全但像冰冷戰爭堡壘的失敗圖。
- 問：`誰會使用或觀看？`、`他們要看懂什麼？`、`希望產生什麼感受？`
- 前三種認證段落鎖定帶入；學生修改「目標」區塊，送出需求時只審使用者、理解與感受。
- Prompt 通過後由 Lab Tool 回傳並自動綁定 D／V4；請學生看出四種需求仍須合進同一份提示詞，前三種需求只驗 passToken，不再做語意評分。
- 修正後預告：居民能辨認部件並感到安全、希望；E 再把四段整理成一份規格。
- 6 題小測依序確認：D 在問哪種需求、D 的三項目標資料、剛修好的居民感受、E 要處理什麼、四種需求放在哪裡、E 要交完整提示詞與要塞圖片。
- 目標不能只重複「做一座要塞」，必須能指出使用者或用途、理解或感受。

### E｜寫出完整要塞規格（約 14 分鐘）

- 先讀洛可的反省「我一直叫 AI 猜」，再讓學生指出四種需求必須放在同一個 Prompt 框內。
- 系統載入學生自己的 D 版累積 Prompt，四個需求區塊全部開放檢查與修改，不載入教師答案。
- 這題審查範圍改為 `complete-spec`，才會同時檢查四種需求與跨段矛盾。
- E 版成果完成後的六題故事循環，再用兩種問法確認「四種需求寫在同一份提示詞中」才叫完整規格。
- 完成後 6 題依序確認：E 為何是完整規格、四種需求名稱、剛保存的成果、改修成功狀態、規格公式與最後舉手驗收。
- AI 可指出哪一種需求仍不清楚，但不得代寫缺漏句或輸出完整教師答案。
- 本地檢查通過並簽發 reviewTicket 後，Lab Tool 才回傳並自動綁定 E／V5 成功藍圖；請學生用畫面證據說明四種需求如何生效。
- 不因錯字、標點、句子順序或圖片美術品質退件；同義詞由系統或教師放行。

## 題中小測設計原則

- 每個主任務完成後固定 6 題 `readChecks`，主任務前不另設 `preReadChecks`；序章仍保留原本 3 題讀題測試。
- 每組固定使用同一條故事：艾爾利亞、洛可、魔法藍圖與天空要塞。不得插入海底地圖、漫畫、藥水、校園海報等無關情境。
- 核心概念可用不同問法反覆確認：`這是哪種需求？`、`它回答哪個問題？`、`洛可少說了什麼？`、`你剛修好了什麼？`

| 題序 | 教師心中要確認的事 | 題目功能 |
|---|---|---|
| 1～2 | 學生真的知道上一題在問什麼 | 同一個需求用「需求名稱」與「實際答案內容」兩種問法重複確認 |
| 3 | 學生沒有離開故事與操作情境 | 說出剛修正的洛可錯誤，以及剛放進答題欄的藍圖成果 |
| 4 | 學生有讀下一題 | 從下一題標題、洛可台詞或錯誤藍圖判斷下一種問題 |
| 5～6 | 學生知道下一題具體要做什麼 | 一題問要補的內容，一題問最後要放入答題欄的成果 |

E 題沒有任務 F，因此第 4～6 題改讀「天空要塞改修完成」：確認成功狀態、規格公式與舉手驗收，不虛構新的需求。
- 干擾項必須是其他三種真實需求，不能用明顯荒謬選項。
- 正解位置要分散；句子長度與語氣盡量接近，避免用外觀猜答案。
- 小測只存在右側答題卡；GAMMA 學習單不出現題幹、選項或答案。
- 答錯不清空需求卡或輸入文字，只請學生回看該需求回答的固定問題。

## 分題本地判定與 AI 回饋

A～D 的本地檢查各自只載入該題 evidence groups：

- A：成果種類、天空守護要塞、漂浮岩盤／六角形城堡。
- B：中央水晶塔、四座守望塔與四角、石橋連接、微俯視。
- C：斷橋、城牆缺口、火焰／黑暗符號、可閱讀文字等明確禁則。
- D：孩子／居民、辨認重要部件、安全／希望。

舊需求只驗證 passToken；未來需求完全不傳給審查器。只有 E 使用以下完整規格規則：

本地規則是正式通關依據：

1. 有 `做什麼`、`怎麼做`、`不能做什麼`、`目標` 四個名稱。
2. 有空中要塞、天空守護要塞、漂浮岩盤與六角形城堡等主體資訊。
3. 有中央水晶塔、四座守望塔、四角、石橋連接或同義安排。
4. 有斷橋／缺口／火焰／黑暗內容的明確禁止邊界。
5. 有孩子或居民，以及安全、希望或辨認重要部件的效果。
6. 文字約 130～280 字，6 題故事循環小測完成，並取得同題綁定的 V5 成功藍圖。

AI 在 A～D 只回覆 activeRequirement 是否清楚；在 E 才回覆四種需求與矛盾。若 AI 逾時、回覆到禁審範圍或格式錯誤，丟棄 AI 意見並沿用本地結果。

## 統一退件回饋原則

- 一次只指出一種最重要的缺漏，順序為：做什麼 → 怎麼做 → 不能做什麼 → 目標。
- 只說缺少哪類資料，不替學生補上完整句。
- 不因錯字、標點、口語或未使用專業名詞退件。
- 答錯、退件、換題、重新整理都保留序章、小測、五版 Prompt、認證 token、reviewTicket 與回圖紀錄。
- 教師圖片資產載入失敗不算學生失敗；Prompt scope 已通過且 ticket 有效時標記等待回圖，服務恢復後回傳原題固定資產。

| 4～8 分 | 完成序章 3 題讀題測試 | 只確認資料、成果與起手方法 |
| 8～18 分 | A：看 V0、修改做什麼、審查、取得並觀察 V1、完成六題循環 | 只處理 do scope |
| 18～28 分 | B：看 V1、修改怎麼做、審查、取得並觀察 V2、完成六題循環 | 只處理 how scope |
| 28～38 分 | C：看 V2、修改不能做什麼、審查、取得並觀察 V3、完成六題循環 | 只處理 avoid scope |
| 38～48 分 | D：看 V3、修改目標、審查、取得並觀察 V4、完成六題循環 | 只處理 goal scope |
| 48～62 分 | E：載入 D 版 Prompt、完整規格總驗收、取得並觀察 V5、完成六題循環 | 依固定順序一次回一種缺漏 |

## 技術備援

| 狀況 | 學生端處理 | 教師處理 |
|---|---|---|
| 序章狀態未保存 | 保留已選答案並顯示重新確認 | 恢復三題狀態，不直接解鎖 A |
| V0～V5 魔法藍圖載入失敗 | 顯示該版短文字，Prompt 與 ticket 仍保留 | 恢復素材後回傳原題固定資產，不要求重做 |
| AI 回饋逾時／失敗 | 顯示「改用本題需求檢查」 | 依 current scope 本地結果簽發 ticket，不要求重送 |
| AI 評到非本題需求 | 不顯示越界回饋 | 丟棄越界欄位，只保留本題 scope 結果 |
| 本地檢查漏判同義詞 | 顯示「需要老師確認」 | 確認語意後人工放行並記錄同義詞 |
| Lab Tool 回圖逾時／失敗 | 保留已通過 scope、Prompt 與 reviewTicket，顯示等待回圖 | 恢復後回傳原題 V1～V5，不要求改文字 |
| 圖片自動綁定失敗 | 保留縮圖、promptHash、ticket 與 assetId | 重新綁定同次結果，不要求重打文字 |
| Prompt 通過後又被修改 | 舊 ticket 與待綁定回圖顯示已失效 | 請學生用新 Prompt 重新送出需求 |
| 重新整理或短暫斷線 | 回到最後題目、測驗、Prompt、ticket 與附件 | 不要求重做已通過內容 |
| 舊版 W05 小測紀錄存在 | 保留舊 Prompt 與藍圖供查看，六題循環從未完成開始 | 舊 1＋4 題庫狀態唯讀封存，不映射為新版答案 |
| 學生打字困難 | 可先口述，再由本人逐段輸入 | 可指名稱卡提問，不代打完整句 |

## 差異化、翻轉教育與同儕協助

- 需要支援者：一次只顯示兩種需求名稱作比較；答對後再回到四選一，不改正式答案。
- 一般學生：序章後依序修改 A～D 的 activeRequirement、取得並觀察五張 Lab Tool 回圖，E 檢查自己的累積 Prompt。
- 進階學生：通關後口頭判斷「龍蛋孵化海報」的四句需求，不增加金幣或主線題目。
- 完成者只能問：`這句回答哪個問題？`、`AI 還在猜哪一件事？`、`這是一種需求還是完整規格？`
- 完成者不可代選、照念未解鎖卡、複製自己的完整規格、代打、代生成或代送審。

## 成功條件與 W06 銜接

學生完成時必須留下：

1. 序章 3 題讀題測試紀錄。
2. A～D 四張已通關的需求卡與認證 token。
3. A～E 五版學生累積 Prompt、逐題圖片觀察與每題 6 題故事循環小測紀錄。
4. A～E 各一次同題 promptHash／reviewTicket／assetId 的 Lab Tool 回圖紀錄。
5. 一份由學生逐步修改、包含四種需求的完整規格。
6. 各題限定範圍審查結果，以及 E 的完整規格結果。
7. 能口頭說明：「一句是需求；四種需求合起來是規格。」

W06 可在四種需求中加入精確數量、比例或字數限制；不重新命名本週四種需求。
