## 教學目標

1. 學生能為自己的專案建立一個 Welcome Page，讓陌生人一眼理解專案是什麼
2. 學生能識別自己的專案需要改進的地方，並主動規劃三個升級目標
3. 學生能用 Copilot 完成自己規劃的新功能或修正，持續推進個人專案

---

## 三大核心概念對應

- 🎮 **遊戲化**：今天的 Welcome Page 是學生「對外展示專案」的第一塊磚——學生能直觀感受到作品從「只有自己看得懂」到「陌生人也能理解」的轉變，滿足感明顯
- 🤖 **AI 優先**：Copilot 協助設計 Welcome Page 的 HTML 結構與 CSS；Lab Terminal 用於排查 HTML/CSS 問題、理解連結語法；遇到問題的求助順序維持「學習單 → Lab Terminal → 助教 → 老師」
- 🔄 **翻轉教育**：先完成 Welcome Page 的學生擔任助教，引導同學思考「你的介紹頁讓不認識你的人看懂了嗎？」而非直接幫同學寫內容

---

## 課前準備

**教師：**
- 確認學生的 VS Code 工作環境正常（W09 後應已穩定）
- 在黑板或投影幕上展示一個「好的 Welcome Page」範例（可以是老師自己做的示範，包含：專案名稱、一句說明、功能列點、進入按鈕）
- 準備兩個對照示範：「沒有 Welcome Page 的頁面」vs「有 Welcome Page 的頁面」，幫助學生感受差異
- 課堂前 5 分鐘準備好自己的示範 `welcome.html` 或 `index.html` 頂端說明區塊

**學生：**
- 打開 VS Code，確認 W09 的專案資料夾正常
- 打開 `project-idea.md`，確認三個核心功能的名稱記得住

## 課堂流程

| 時間 | 活動 | 說明 | 教師角色 |
|------|------|------|---------|
| 0–5 分鐘 | 破題：為什麼你的作品需要 Welcome Page？ | 老師快速展示「沒有介紹頁的頁面」和「有介紹頁的頁面」的對比，問學生：「如果你把作品傳給朋友，哪個版本他更快知道這是什麼？」 | 主導提問，不講答案，讓學生說 |
| 5–10 分鐘 | 發放學習單 + 規劃三個升級目標 | 學生閱讀學習單，並在 `project-idea.md` 寫下今天要完成的三個升級項目 | 巡視確認每個學生都寫下了三個具體目標，遇到「不知道要改什麼」的學生，引導他回顧 W09 的最後反思問題 |
| 10–35 分鐘 | 任務 A：Welcome Page | 學生選擇 A 選項（在 index.html 加說明區塊）或 B 選項（新建 welcome.html）並實作 | 觀察學生的選擇；B 選項學生可能在「兩個 HTML 檔連結」上遇到問題，提示他們先問 Lab Terminal |
| 35–50 分鐘 | 任務 B：第一個升級 | 學生開始實作第一個新功能或修正 | 管理助教任務（W10-A 先行者開始協助同學） |
| 50–58 分鐘 | 任務 C：第二個升級 | 速度較快的學生繼續往 C、D 推進 | 觀察整體進度，若多數學生卡在 A，調整期望 |
| 58–60 分鐘 | 截圖 + 舉手告知老師 | 學生截圖所有完成的任務 | 快速確認成功條件 |
| 60–90 分鐘 | 🎮 自由遊玩時間 | 學生使用金幣在 Minecraft / Lab Terminal 小遊戲 / 其他介面自由活動 | 觀察，不介入 |

## Lab Terminal Prompt 建議

本週主要工具是 VS Code + Copilot，Lab Terminal 用於補充理解與排查問題。以下是本週可能用到的提問起點：

- 「HTML 頁面之間怎麼用連結跳轉？`<a href="">` 的路徑怎麼寫？」
- 「我想讓我的 HTML 頁面的標題很大、底色有顏色，基本的 CSS 怎麼寫？」
- 「我的 welcome.html 點了連結跳不到 index.html，可能是什麼原因？」
- 「JavaScript 函式寫好了，但點了按鈕沒有執行，怎麼排查？」

## 翻轉教育流程

**先行者（第一位完成任務 A 的學生）：**
1. 舉手告知老師
2. 老師指派他去協助一位尚未完成 Welcome Page 的同學
3. 助教的角色：問問題，不給答案
   - 「你選了哪個選項？為什麼？」
   - 「你的介紹頁，不認識你的人看得懂嗎？」
   - 「你有沒有試著把畫面給旁邊的同學看，問他『你知道這是什麼嗎？』」
4. 被幫助的同學完成 Welcome Page 後，先行者向老師申報 → 領取任務 A 50%（50 幣）

**進行中的學生：**
- 遇到問題先看學習單
- 再問 Lab Terminal（特別是 HTML/CSS/連結問題）
- 再問助教同學
- 最後才問老師（每節課最多 3 次）

**TA 金幣計算：**
| 助教對應任務 | 原任務金幣 | TA 金幣（50%） |
|------------|---------|--------------|
| 任務 A | 100 | 50 |

## 老師筆記

**常見問題：**
- **學生不知道三個升級目標要寫什麼**：引導他回顧 W09 的反思問題「如果下週要讓別人使用你的頁面，你現在最想先改進哪一個地方？」；也可以讓他打開自己的頁面，試用一次，自然就會發現問題
- **學生在 B 選項（新建 welcome.html）卡在「兩個 HTML 怎麼連結」**：這是本週最常見的卡點。提示語：「你知道 `<img src="圖片名稱">` 嗎？連結的邏輯一樣，`<a href="index.html">`，href 裡面放你要去的檔案名稱」
- **Welcome Page 做完但很醜**：這是正常的，不是失敗。引導學生問 Lab Terminal 「怎麼讓標題大一點、加底色、文字置中」。視覺優化是 W21 的重點任務，現在做到「有內容、能使用」就是成功

**翻轉教育提示：**
- 判斷哪個學生適合當助教：不只是「第一個做完的」，也要看他的 Welcome Page 是否真的讓陌生人看得懂。可以在指派前快速看一眼他的頁面，並問：「你覺得不認識你的人，看到這個頁面，5 秒內能知道這是什麼嗎？」

**延伸挑戰：**
- 做完 D 的學生：讓他思考「如果你要把專案的連結傳給朋友，你的 Welcome Page 還缺什麼？」（這是 S7 部署思維的前置練習）
- 或讓他幫 Welcome Page 加上動態效果（例如：滑鼠移到按鈕上顏色改變）

**教學重點提醒：**
- 本週的核心不是技術難度，而是讓學生體驗「讓作品對外可理解」的感受
- Welcome Page 的內容（文字、設計選擇）由學生自己決定，老師不要幫學生寫「你的專案說明應該這樣寫」
- 三個升級目標是學生自己規劃的，沒有標準答案。老師只確認「有寫下來、有完成」，不評價選擇的好壞
