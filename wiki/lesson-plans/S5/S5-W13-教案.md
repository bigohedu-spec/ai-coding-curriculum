## 教學目標

1. 學生能說出「本機儲存（localStorage）」與「雲端資料庫（Supabase）」的差別：前者只存在這台電腦的瀏覽器，後者存在雲端、換裝置也看得到。
2. 學生能用老師提供的 Supabase 連線資訊（Project URL + anon 金鑰），透過 Copilot Chat 把 Supabase 接進自己的程式，並把一筆資料寫上雲。
3. 學生能用 Copilot Chat 把上週的「存 / 讀」邏輯從 localStorage 改寫為 Supabase，並透過「換一台電腦 / 開無痕視窗也看得到資料」驗證雲端同步成功。

---

## 三大核心概念對應

- 🎮 **遊戲化**：本週是「記憶力」的最終形態——上週資料只存在自己這台電腦，這週資料飛上雲端，換一台電腦、開無痕視窗都看得到。學生看到「在 A 電腦新增、B 電腦立刻出現」的瞬間，會直接感受到「我做的東西是真的線上服務」的衝擊，這是模組三的關鍵 Hook。
- 🤖 **AI 優先**：連線資訊由老師提供（貼上即可）；程式整合（Supabase 用戶端初始化、雲端讀寫）由 Copilot Chat 實作；localStorage 與雲端的概念差異問 Lab Terminal。求助順序維持「學習單 → Copilot Chat（程式問題）/ Lab Terminal（概念問題）→ TA 同學 → 老師（每節最多 3 次）」。
- 🔄 **翻轉教育**：先完成「資料上雲」的學生擔任 TA，核心引導句是「你的 Project URL 和 anon 金鑰貼對位置了嗎？table 名稱跟老師白板上的一樣嗎？」——幫同學排查連線設定，不直接幫他寫程式。

## 課前準備

**教師（本週準備較多，務必課前完成）：**
- **建立一個 Supabase 專案**（用老師自己的帳號，學生不需註冊）：
  1. 到 supabase.com 建立一個 free tier 專案。
  2. 在 Table Editor 建立一張表，例如 `messages`（欄位：`id`、`created_at`、`name`、`content`），給全班共用；或每班一張表。
  3. 開啟該表的 **Row Level Security（RLS）**，新增一條**允許 anon 角色 insert 與 select** 的簡單政策（課堂練習用途）。
  4. 到 **Project Settings → API**，複製 **Project URL** 與 **anon（publishable）金鑰**。
- **把 Project URL、anon 金鑰、table 名稱寫在白板或發在 Lab Terminal**，讓學生複製貼上。
- 自己先完整走一遍：把連線資訊接進一個示範專案 → 寫一筆 → 讀一筆 → 開無痕視窗看到同一筆。
- 準備「換裝置同步」的震撼示範（兩個瀏覽器視窗：一般 + 無痕），這是本週 Hook。
- 確認每位學生的上週成果（localStorage 存 / 讀）可運作——**W13 是把上週的本機資料搬上雲**。

**學生：**
- 打開 VS Code，確認上週的專案與 localStorage 功能正常。
- 準備好複製老師提供的三樣東西：Project URL、anon 金鑰、table 名稱。

## 課堂流程

| 時間 | 活動 | 說明 | 教師角色 |
|------|------|------|---------|
| 0–10 分鐘 | Hook + 發連線資訊 | 老師用「A 視窗新增、B 視窗出現」的雲端同步示範破題，發下 Project URL / anon 金鑰 / table 名稱。學生閱讀學習單 | 主導同步示範，把三樣連線資訊寫清楚在白板/Lab Terminal |
| 10–40 分鐘 | 任務 A：接上 Supabase + 把資料寫上雲 | 學生貼上連線資訊，用 Copilot 接 Supabase 用戶端，把一筆資料寫進雲端 table | 巡視連線卡點（最常見：金鑰/URL 貼錯、table 名稱拼錯、RLS 擋住）；在投影幕用 Table Editor 展示「學生資料即時出現」 |
| 40–58 分鐘 | 任務 B：從雲端讀取顯示 + 跨裝置驗證 | 學生用 Copilot 把讀取改成從 Supabase 讀，頁面載入時顯示雲端資料；用無痕視窗 / 另一台電腦驗證同步 | 管理 TA 任務（W13-A 先行者開始協助）；重點巡視「跨裝置同步」是否真的成立 |
| 58–60 分鐘 | 截圖 + 舉手告知老師 | 截圖：A（你的網站畫面 + 老師投影幕上 Table Editor 看到你的資料，或 Copilot console 顯示寫入成功）、B（無痕視窗 / 另一裝置也看得到同一筆資料） | 快速確認成功條件，特別確認「跨裝置同步」 |
| **60–90 分鐘** | **🎮 自由遊玩時間** | 學生使用本週賺取的金幣，在 Minecraft / Lab Terminal 小遊戲 / 其他介面自由活動 | 觀察，不介入 |

> ⚠️ 任務必須在 60 分鐘內完成。連線設定（金鑰/URL/table 名稱貼對）是本週最大的時間風險點——若多數學生卡在連線，老師應在投影幕上即時帶一次貼上流程，把卡點集中解決。快速學生可挑戰學習單下方的進階任務（即時同步 / 多筆顯示 / 刪除雲端資料），進階不計入主線、不強制。

## Lab Terminal Prompt 建議

本週主要工具是 VS Code + Copilot Chat + Supabase，Lab Terminal 用於補充**概念理解**：

- 「localStorage 和雲端資料庫（像 Supabase）最大的差別是什麼？用一個簡單的比喻說明。」
- 「為什麼資料存到雲端後，換一台電腦也看得到，但 localStorage 不行？」

## 老師筆記

**關於工具與安全（重要）：**
- 本週**不使用 Firebase**（帳號年齡限制，學生無法登入）。改用 **Supabase，由老師統一建立專案、提供金鑰**，學生不需註冊（CLAUDE.md 第十六節：Supabase free tier，學校統一管理）。
- **anon 金鑰可以放在前端、公開是安全的——前提是老師有設好 RLS（Row Level Security）政策**。所以課前務必開 RLS 並設好允許 anon insert/select 的政策。這也是下週（W14）部署時，「為什麼能把這把金鑰放上公開網站」的伏筆。
- 老師的 **service_role / secret 金鑰絕對不可以給學生、不可放前端**（它會繞過 RLS）。只給 anon（publishable）金鑰。

**常見問題：**
- **連線失敗 / `Invalid API key`**：URL 或 anon 金鑰貼錯、多了空白或少字。引導學生逐字對照白板。
- **`permission denied` / `new row violates row-level security`**：RLS 政策沒設好。這是老師端的設定問題，課前要先測過；課中發生就由老師統一修政策。
- **table 名稱對不上**：學生程式裡的 `.from('xxx')` 和老師建立的 table 名稱不同。引導對照。
- **localStorage 與 Supabase 搞混**：澄清——上週資料存在「自己這台電腦的瀏覽器」；這週存在「雲端的資料庫」，所以換裝置也看得到。可請學生開無痕視窗親自驗證差別。

**翻轉教育提示：**
- 連線設定是本週最容易卡的地方，TA 最有價值的貢獻是**排查連線**（URL/金鑰/table 名稱對不對），而不是寫程式。提醒 TA：「你的任務是幫他把連線弄對，不是幫他寫程式喔。」

**延伸挑戰：**
- 完成 A + B 的學生可探索 Supabase 的**即時訂閱（Realtime）**：一邊新增，另一邊不用重整就自動更新。
- 或挑戰「刪除雲端某一筆」「一次顯示多筆資料（`.select('*')` + 排序）」。

**教學重點提醒：**
- 本週的技術核心是「把本機資料搬上雲」，但**不要直接講解 Supabase 用戶端 API 的語法**。連線資訊怎麼貼是工具操作（學習單給步驟），但「要把哪些資料搬上雲、怎麼搬」保持開放，讓學生透過提問 Copilot 自然完成（AI 優先 + 開放式學習目標）。
- 要把哪些資料上雲、資料結構怎麼設計，由學生依自己的專案決定，老師只設框架，不指定全班一樣的內容（作品導向原則二）。
- 確認每位學生的雲端功能都**整合進個人專案**（模組三起的硬性要求）。
