## 教學目標

1. 學生能說出「本機儲存（localStorage）」與「雲端存檔（平台 `BO`）」的差別：前者只存在這台電腦的瀏覽器，後者存在雲端、換裝置也看得到。
2. 學生能透過 Copilot Chat 用 `await BO.set('key', 值)` 把一筆資料寫上雲。
3. 學生能用 Copilot Chat 把上週的「存 / 讀」邏輯從 localStorage 改寫為 `BO.set / BO.get`，並透過「換一台電腦 / 開無痕視窗也看得到資料」驗證雲端同步成功。

---

## 三大核心概念對應

- 🎮 **遊戲化**：本週是「記憶力」的最終形態——上週資料只存在自己這台電腦，這週資料飛上雲端，換一台電腦、開無痕視窗都看得到。學生看到「在 A 電腦新增、B 電腦立刻出現」的瞬間，會直接感受到「我做的東西是真的線上服務」的衝擊，這是模組三的關鍵 Hook。
- 🤖 **AI 優先**：程式整合（用 `BO.set / BO.get` 做雲端讀寫）由 Copilot Chat 實作；localStorage 與雲端的概念差異問 Lab Terminal。求助順序維持「學習單 → Copilot Chat（程式問題）/ Lab Terminal（概念問題）→ TA 同學 → 老師（每節最多 3 次）」。
- 🔄 **翻轉教育**：先完成「資料上雲」的學生擔任 TA，核心引導句是「你的作品是不是已經放到平台上、打得開 `.bigoh.uk`？（本機開 `BO` 會是空的）你 `BO.set` 和 `BO.get` 用的 key 是同一個字嗎？」——幫同學排查，不直接幫他寫程式。

## 課前準備

**教師（本週準備大幅簡化——不需建任何雲端專案、不需發金鑰）：**
- 確認全班的作品都能**部署到 Big-Oh**、打得開各自的 `https://<名字>.bigoh.uk`（`BO` 只有在平台上、L2 以上才會注入；本機開檔沒有 `BO`）。若還沒部署過，先帶一次 W14 的部署（curl → login → deploy）。
- 自己先完整走一遍：在一個示範作品裡用 `await BO.set('demo', ...)` 寫一筆 → `await BO.get('demo')` 讀一筆 → 開無痕視窗、在同一個 `.bigoh.uk` 網址讀到同一筆。
- 準備「換裝置同步」的震撼示範（兩個瀏覽器視窗：一般 + 無痕），這是本週 Hook。
- 確認每位學生的上週成果（localStorage 存 / 讀）可運作——**W13 是把上週的本機資料搬上雲**。

**學生：**
- 打開 VS Code，確認上週的專案與 localStorage 功能正常。
- 確認自己的作品已經上過線、打得開 `.bigoh.uk` 網址（要在線上網址才有 `BO`）。

## 課堂流程

| 時間 | 活動 | 說明 | 教師角色 |
|------|------|------|---------|
| 0–10 分鐘 | Hook + 介紹 `BO` | 老師用「A 視窗新增、B 視窗出現」的雲端同步示範破題，說明平台自帶 `BO`（免金鑰、免註冊）。學生閱讀學習單 | 主導同步示範，說清楚「作品要在 `.bigoh.uk` 上才有 `BO`」 |
| 10–40 分鐘 | 任務 A：用 `BO.set` 把資料寫上雲 | 學生用 Copilot 把上週的 localStorage 存檔改成 `await BO.set('key', 值)`，寫一筆上雲 | 巡視卡點（最常見：作品沒上線所以 `BO` 是 undefined；`set` 和 `get` 用不同 key）；在投影幕示範 Console 用 `await BO.get()` 讀資料 |
| 40–58 分鐘 | 任務 B：從雲端讀取顯示 + 跨裝置驗證 | 學生用 Copilot 把讀取改成 `await BO.get('key')`，頁面載入時顯示雲端資料；用無痕視窗 / 另一台電腦驗證同步 | 管理 TA 任務（W13-A 先行者開始協助）；重點巡視「跨裝置同步」是否真的成立 |
| 58–60 分鐘 | 截圖 + 舉手告知老師 | 截圖：A（你的網站畫面 + Console 用 `BO.get` 讀到資料）、B（無痕視窗 / 另一裝置也看得到同一筆資料） | 快速確認成功條件，特別確認「跨裝置同步」 |
| **60–90 分鐘** | **🎮 自由遊玩時間** | 學生使用本週賺取的金幣，在 Minecraft / Lab Terminal 小遊戲 / 其他介面自由活動 | 觀察，不介入 |

> ⚠️ 任務必須在 60 分鐘內完成。**最大的時間風險點是「作品還沒上線，本機開 `BO` 是空的」**——若多數學生卡在這，老師應先帶一次部署（`node bigoh.mjs deploy`），把卡點集中解決。快速學生可挑戰學習單下方的進階任務（排行榜 / 登入 / 計數器），進階不計入主線、不強制。

## Lab Terminal Prompt 建議

本週主要工具是 VS Code + Copilot Chat + 平台 `BO`，Lab Terminal 用於補充**概念理解**：

- 「localStorage 和雲端存檔（像平台的 BO）最大的差別是什麼？用一個簡單的比喻說明。」
- 「為什麼資料存到雲端後，換一台電腦也看得到，但 localStorage 不行？」

> 程式碼層級的問題（`BO.set / BO.get` 怎麼寫、錯誤怎麼修）一律問 Copilot Chat（`BO` 的錯誤訊息是中文，可直接貼給 Copilot）。

## 老師筆記

**關於工具與安全（重要）：**
- 本週**不用 Firebase / Supabase / 任何外部資料庫**。雲端功能一律用平台自帶的 `window.BO`（存檔 `BO.set/get`、進階排行 `BO.score/top`、登入 `BO.account`）。
- **學生完全不需要金鑰**——以前接雲端資料庫要小心 anon/secret 金鑰、要設 RLS 政策，現在這些平台都在後台處理掉了。這正好是很好的機會告訴學生：「危險的東西（金鑰）不放在你手上，才是安全的做法」（RULES-FOR-AI：學生不能持有金鑰）。
- `BO` 只在作品**部署到平台上（L2 以上）**才會注入；本機直接開檔 `BO` 是 undefined。這是本週最常見的卡點。

**常見問題：**
- **`BO is not defined` / `BO` 是 undefined**：作品還沒上線，或在本機開檔。→ 先 `node bigoh.mjs deploy`，在 `.bigoh.uk` 網址上測。
- **存了讀不到**：`BO.set` 和 `BO.get` 用了不同的 key（key 要一字不差）。
- **無痕視窗看不到自己剛存的**：匿名訪客 `BO.visitor` 每個瀏覽器不一樣——要跨裝置綁「同一個人」需要 `BO.account` 登入（進階）。但**換一台電腦、同一個作品的雲端資料仍在**（只是綁不同訪客）；示範「資料在雲端」時，用「老師的帳號在 A、B 兩處讀同一筆」或先做登入更清楚。
- **localStorage 與 `BO` 搞混**：澄清——上週資料存在「自己這台電腦的瀏覽器」；這週存在「雲端」，所以換裝置也看得到。

**翻轉教育提示：**
- 「作品有沒有上線」是本週最容易卡的地方，TA 最有價值的貢獻是**確認同學的作品在 `.bigoh.uk` 上、key 有對**，而不是幫他寫程式。

**延伸挑戰：**
- 完成 A + B 的學生可探索 `BO.score/top`（排行榜）、`BO.account`（登入後跨裝置綁同一個人）、`BO.bump`（計數器）。

**教學重點提醒：**
- 本週技術核心是「把本機資料搬上雲」，但**不要直接講解 `BO` 的 API 語法**。`BO.set/get` 怎麼呼叫是工具操作（學習單給步驟），但「要把哪些資料搬上雲、怎麼搬」保持開放，讓學生透過提問 Copilot 自然完成（AI 優先 + 開放式學習目標）。
- 要把哪些資料上雲、資料結構怎麼設計，由學生依自己的專案決定，老師只設框架（作品導向原則二）。
- 確認每位學生的雲端功能都**整合進個人專案**（模組三起的硬性要求）。
