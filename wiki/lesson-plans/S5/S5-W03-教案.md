## 教學目標

1. 學生能在 VS Code 的整合終端機裡確認 Git 已安裝（`git --version`），並說出「終端機是用打字下指令的地方」。
2. 學生能用 `git init` 把自己的專案資料夾變成一個 Git 專案，並認得側邊欄檔案顏色/標記的變化。
3. 學生能用 `git status` 看出「哪些檔案被改過、還沒存進版本」，並在修改檔案後再次執行 `git status`，親眼看到輸出變化。

---

## 三大核心概念對應

- 🎮 **遊戲化**：用「**遊戲存檔點**」的類比貫穿整堂——`git init` 是「開啟這個遊戲的存檔功能」，`git status` 是「看看我從上個存檔點之後做了什麼」。下週（W04）才真正按下存檔（commit）與**讀取存檔（還原）**，本週是把存檔系統裝起來。
- 🤖 **AI 優先**：Copilot 尚未開通（W05），本週 AI 求助走 **Lab Terminal**（概念問題：版本控制是什麼？為什麼工程師都要用？）。求助順序：**學習單 → Lab Terminal → TA 同學 → 老師（每節最多 3 次）**。
- 🔄 **翻轉教育**：先完成的學生擔任 TA，核心引導句是「你的終端機現在是在**哪個資料夾**？前面那串路徑是不是你的專案資料夾？」——本週九成的錯都出在這，TA 最有價值的貢獻就是幫同學確認路徑。

## 課前準備

**教師：**
- **確認每台電腦已安裝 Git**（`git --version` 能跑出版本號）。若沒有，課前統一安裝（`git-scm.com`，一路下一步即可）——**這是本週最大的時間風險，務必課前處理**。
- 自己先完整走一遍：開整合終端機 → `git --version` → `git init` → 看 `.git` 出現 → `git status` → 改檔案 → 再 `git status` 看輸出變化。
- 準備「存檔點」的類比示範：打電動打到一半存檔、死掉可以讀檔回來——**本堂全程用這個比喻，不要講「版本控制系統」這種術語**。
- 確認學生 W01 建的專案資料夾還在，且 VS Code 能用「開啟資料夾」打開。

**學生：**
- 打開 VS Code，用**開啟資料夾**打開自己 W01 建的專案資料夾（側邊欄要看得到 `index.html`）。

## 課堂流程

| 時間 | 活動 | 說明 | 教師角色 |
|------|------|------|---------|
| 0–8 分鐘 | Hook：打電動忘記存檔 | 老師：「你打電動打到一半，電腦當機，忘記存檔——什麼感覺？」帶出「程式也要存檔點」。學生閱讀學習單 | 主導比喻，不講術語 |
| 8–20 分鐘 | 任務 A・Part 1–2：終端機 + 確認 Git | 開啟 VS Code 整合終端機 → `git --version` → 確認路徑在自己的專案資料夾 | 巡視：Git 沒裝、路徑不對（本週兩大卡點） |
| 20–35 分鐘 | 任務 A・Part 3：`git init` | 執行 `git init` → 側邊欄檔案出現顏色/字母標記 → 找到隱藏的 `.git` | 投影幕同步示範；解釋顏色是「還沒存進存檔點」 |

| 58–60 分鐘 | 截圖 + 舉手告知老師 | 截圖：終端機同時看得到 `git init` 成功與**兩次 `git status` 的輸出** | 確認成功條件，特別確認「兩次輸出不一樣」 |
| **60–90 分鐘** | **🎮 自由遊玩時間** | 學生使用本週賺取的金幣，在 Minecraft / Lab Terminal 小遊戲 / 其他介面自由活動 | 觀察，不介入 |

> ⚠️ 任務必須在 60 分鐘內完成。**兩大卡點：(1) Git 沒安裝（課前解決）；(2) 終端機的工作目錄不是專案資料夾**（學生會在隨便一個路徑下 `git init`，把家目錄變成 repo）。第 (2) 點若發生，引導學生用 `cd` 切回去，或直接關掉終端機、重新用「開啟資料夾」開專案後再開終端機。

## 老師筆記

**常見問題：**
- **`git : 無法辨識 'git' 詞彙 / 不是內部或外部命令`**：Git 沒安裝，或安裝時沒加入 PATH。課前確認；課中發生就由老師處理安裝。
- **在錯的資料夾 `git init`**：最常見也最麻煩。症狀是路徑顯示 `C:\Users\學生名>` 而不是專案資料夾。**處理方式**：關掉終端機 → 確認 VS Code 是用「開啟資料夾」開專案 → 重開終端機（會自動在專案資料夾）。若已誤建，刪掉那個位置的 `.git` 資料夾即可。
- **找不到 `.git` 資料夾**：它是隱藏資料夾。在 VS Code 側邊欄預設看不到是正常的；要看要在檔案總管開「顯示隱藏項目」。**不需要強求每個學生都找到**，看得到 `git init` 成功訊息就算數。
- **`git status` 輸出看不懂**：正常。本週只要求學生**比較兩次輸出的差別**（新增檔案後多了什麼），不要求讀懂每一行英文。可引導：「不用全看懂，只要找出**你剛新增的那個檔名**出現在哪裡。」
- **側邊欄檔案沒變色**：確認 VS Code 真的開的是那個資料夾，且 `git init` 是在同一個資料夾執行。

**延伸挑戰：**
- 完成的學生可以把 `about.html` 刪掉，看 `git status` 變回什麼樣子。
- 問 Lab Terminal：「`git status` 裡的 `Untracked files` 是什麼意思？」

**教學重點提醒：**
- **全程用「存檔點」比喻，不要講「版本控制系統」「工作區/暫存區」這些術語**。本週的目標是讓學生**手上跑得動**，概念到 W04 按下 commit、還原成功的那一刻才會真正長出來。
- **不要教 `git push` / GitHub**。部署已改用 Big-Oh，不需要遠端；本機 Git 就完整涵蓋本週的學習目標，而且不需要任何帳號（第十四節）。
- 模組一是技能習得階段（第十二節作品導向 W07 起生效），本週在自己的練習專案上操作即可。
