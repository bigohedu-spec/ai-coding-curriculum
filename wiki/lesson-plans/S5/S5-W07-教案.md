---

## 教學目標

1. 學生能在 VS Code 中成功啟用 GitHub Copilot，體驗第一次「注釋 → 生成建議」的流程
2. 學生能用一句話說明自己想做的專案（What + For who + Can do）
3. 學生能建立自己的專案資料夾，並在 `project-idea.md` 中寫下宣言與初步想法

---

## 三大核心概念對應

### 🎮 遊戲化
- W07-A 完成：150 金幣；W07-B 完成：100 金幣（主線合計 250）
- W07-B「專案宣言」完成後解鎖 Lab Terminal 的「創業家」限定圖示
- 黑板上展示「已宣告的專案」——每位學生的一句話方向，讓全班看到彼此的差異

### 🤖 AI 優先
- W07-A 的核心體驗：注釋驅動 Copilot → Tab 接受建議，不需要懂語法
- W07-B 的 AI 使用：學生用 Lab Terminal 探索自己的興趣，確認技術上可行性
- 老師固定回應模式：「你問過 Lab Terminal 了嗎？」

### 🔄 翻轉教育
- 老師開場 5 分鐘說明（Copilot 是什麼、今天兩個任務），之後學生自行推進
- W07-A 先行者立刻進入 W07-B，不等待其他人
- W07-B 沒有「標準答案」——每個人的方向都不一樣，老師不介入方向選擇
- 老師最多回答 **3 個問題**（黑板計分）

## 課前準備

**教師：**
- 確認所有學生 VS Code 已安裝 Copilot 擴充套件，授權有效
- 準備自己的示範：在 VS Code 裡打一行注釋 `// 顯示歡迎訊息`，展示 Copilot 建議出現的樣子（2 分鐘展示）
- 準備自己的「專案宣言」範例（展示 project-idea.md 的樣子）
- 黑板右上角：老師問題次數計分欄

**學生：**
- VS Code 開啟，Copilot 圖示正常
- Lab Terminal 可以連線

## Lab Terminal Prompt 建議

**W07-B：探索專案方向（幫助不知道要做什麼的學生）：**
```
我是小學生，我喜歡（填入興趣），請幫我想三個可以做成小程式的點子，每個點子用一句話描述。
```

**W07-B：確認技術可行性：**
```
我想做一個（描述你的想法），這個東西可以用 JavaScript + HTML 做出來嗎？大概需要什麼功能？
```

**W07-B：幫助寫宣言（結構化）：**
```
請幫我用這個格式寫一句話：「我要做一個＿＿，讓＿＿可以＿＿。」我的想法是（描述）。
```

## 翻轉教育流程

**W07-A 先行者（最早完成者）：**
1. 截圖存好 → 舉手 → 老師確認
2. 立刻進入 W07-B，不需等待

**W07-B 先行者：**
- 因為每個人方向不同，沒有傳統的「助教」角色
- 可以主動和旁邊的同學聊：「你要做什麼？」鼓勵互相啟發（不是指導）

**卡在不知道做什麼的學生：**
1. 翻一翻自己過去（S1–S4）的學習單，找找「我的興趣清單」
2. 問 Lab Terminal 上面的探索 Prompt
3. 老師最後才介入：「你最喜歡做什麼事情？遊戲？音樂？幫助別人？」

## 老師筆記

**最常見的卡點：**
- **「我不知道要做什麼」**：這是 W07-B 最常見的狀況。解法：先問 Lab Terminal 探索 Prompt；如果還沒有方向，翻之前的興趣清單；最後才由老師用問答引導
- **「我想做的東西好像很難」**：學生往往想做複雜的東西。引導問：「如果只保留最重要的一個功能，那是什麼？」這個核心功能就是 MVP
- **「Copilot 建議出現但是程式碼看不懂」**：W07-A 的重點不是看懂，是體驗。先接受，之後 W08 再深入

**W07-B 的品質標準（不是要完美，是要夠具體）：**
- 太模糊的宣言：「我要做一個遊戲」→ 請繼續具體化
- 夠好的宣言：「我要做一個猜謎遊戲，讓同學可以考考彼此的知識」
- 不用完美，之後可以調整

**教學重點提醒：**
- **不要評價學生的方向好不好**——只要在技術上可行，任何興趣都可以
- 宣言黑板公告的目的是製造「多樣性可見」的效果——每個人都不同，強化個人認同感
