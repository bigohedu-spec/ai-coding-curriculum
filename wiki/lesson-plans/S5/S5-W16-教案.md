## 教學目標
1. 能用 Copilot Chat 串接一個**免金鑰公開 API**，把真實資料顯示在自己的專案裡。
2. 能加一個使用者控制（按鈕/輸入）主動觸發抓新資料。
3. 理解「API＝跟別的服務要真實資料」，讓專案不再只有寫死的假資料。

## 三大核心概念對應
- 🎮 遊戲化：專案「連上真實世界」的成就感；主線 250。
- 🤖 AI 優先（Vibe Coding）：你是 PM、Copilot 是工程師——**描述功能 → Chat 實作 → 測試 → 迭代**；卡住先問 Lab Terminal / Copilot，不先問老師。
- 🔄 翻轉教育：先完成者當助教，**問「你怎麼描述給 Copilot 的？」**引導同學，不代寫。

## 課前準備
**教師**
- 準備一個 API 回傳資料的示範（例：dummyjson 名言的 JSON 長怎樣）。
- 確認學生專案能用 Live Server 跑；提醒**免金鑰、CORS 友善、https** 的 API 清單（見學習單）。
- 準備常見錯誤排解：CORS、mixed content（http vs https）、要金鑰的 API。

**學生**
- 已有可跑的個人專案（承 W07 起的作品導向）。

| 時間 | 活動 | 說明 | 教師角色 |

## Copilot Chat / Lab Terminal Prompt 建議
> - 「幫我用 fetch 抓 `https://dummyjson.com/quotes/random`，把 `quote`、`author` 顯示在 id 是 `quote` 的元素裡。」
> - 「讓 id 是 `newBtn` 的按鈕被點時重新抓一次並更新畫面。」
> - Bug：「畫面沒資料，Console 顯示 `Failed to fetch`，可能原因？怎麼改？」

## 老師筆記
- **常見問題**：CORS（換 dummyjson/thecatapi/randomuser）；mixed content（http 的 open-notify 部署後壞→換 https）；要金鑰的 API（依第十四節改免金鑰或老師統一給）。
- **作品導向（第十二節）**：驗收看「在**他的專案**裡運作」，不是獨立 demo。
- **延伸挑戰**：兩個 API 同頁；抓到的資料存 localStorage。
