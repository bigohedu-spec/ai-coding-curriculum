## 教學目標

1. 學生能說出「本機打開檔案」與「部署上線」的差別：部署後，任何人用網址都能打開你的網頁，不需要你的電腦。
2. 學生能用 **Git 指令（CLI）** 把專案推上 GitHub，並在 GitHub 開啟 Pages，拿到一個公開可訪問的網址。
3. 學生能說明網路廣告的基本運作（廣告平台給一段碼 → 放進網頁 → 有人看/點才有收入），並知道**廣告平台需年滿 18 歲、未成年須由家長以自己帳號申請**；能為自己的專案寫一份「未來廣告計畫」。

---

## 三大核心概念對應

- 🎮 **遊戲化**：拿到「一個真的網址、可以傳給爸媽和朋友打開」是本學期最大的成就感跳躍——作品從「只有我自己電腦看得到」變成「全世界都打得開」。這是 S8「市場驗證 / 獲利」長線劇情的第一個鉤子。
- 🤖 **AI 優先**：Git 指令與 GitHub Pages 設定由學習單詳細步驟帶；遇到 push 失敗、404 等問題先問 Copilot Chat；廣告與部署的概念問題問 Lab Terminal。求助順序維持「學習單 → Copilot Chat / Lab Terminal → TA 同學 → 老師（每節最多 3 次）」。
- 🔄 **翻轉教育**：上週已成功部署的同學是天然的 TA，核心引導句「你 push 上去了嗎？Pages 的 Source 分支選對了嗎？打開網址是 404 還是空白？」——幫同學排查，不直接代操作。

## 課前準備

**教師：**
- 確認全班的 GitHub 帳號（W3–W5 已配合 Copilot 建立，由學校統管）可登入，且每位學生的專案已是一個本地 Git repo（W4 已 commit 過）。
- **自己先完整走一遍**：在 GitHub 建立 repo（或用學生現有 repo）→ `git push` → Settings → Pages → 選 Source 分支 → 拿到網址 → 等幾分鐘打開確認。把每一步在投影幕上演示清楚。
- 準備對照示範：用 `file://` 在自己電腦打開一個網頁 vs 用 `https://xxx.github.io/...` 網址打開同一個網頁，讓學生感受「本機 vs 上線」的差別。
- **廣告部分課前想清楚立場**：本週只教「概念 + 未來計畫」，**不實際申請廣告帳號**（平台需 18 歲）。準備 1–2 個學生熟悉的網站截圖，指出上面的廣告位置作為討論素材。
- 安全提醒：GitHub Pages 的 repo 是**公開的**。提醒學生——這就是為什麼上週 Supabase 只給你們 **anon（公開）金鑰**、而且老師有設 RLS；**secret / 密碼類的東西永遠不要放進會被部署的程式裡**。

**學生：**
- 確認 VS Code 裡的專案正常、上週的雲端功能可運作。
- 想一想：如果有人問「你的網站網址是什麼？」你希望給他什麼。

## 課堂流程

| 時間 | 活動 | 說明 | 教師角色 |
|------|------|------|---------|
| 0–8 分鐘 | Hook：本機 vs 上線 | 老師用 `file://` vs `https://...github.io` 對照示範，問：「哪一個你可以用 LINE 傳給阿嬤，她點了就打得開？」帶出「部署」 | 主導對照示範 |
| 8–45 分鐘 | 任務 A：部署上線（CLI 優先） | 學生用 Git 指令 push 專案 → 在 GitHub 開 Pages → 拿到網址並打開確認 | 巡視 push / Pages 設定卡點（最常見：分支選錯、忘了等幾分鐘、路徑大小寫）；投影幕同步演示 |
| 45–58 分鐘 | 任務 B：認識廣告 + 寫廣告計畫 | 學生用 Lab Terminal 研究網路廣告怎麼運作、年齡規定，並為自己的專案寫一份「未來廣告計畫」 | 帶一段全班討論：「廣告太多會怎樣？」「為什麼平台要滿 18 歲？」 |
| 58–60 分鐘 | 截圖 + 舉手告知老師 | 截圖：A（瀏覽器網址列顯示你的 github.io 網址 + 你的網頁畫面）、B（你的廣告計畫） | 確認成功條件，特別確認「網址真的打得開」 |
| **60–90 分鐘** | **🎮 自由遊玩時間** | 學生使用本週賺取的金幣，在 Minecraft / Lab Terminal 小遊戲 / 其他介面自由活動 | 觀察，不介入 |

> ⚠️ 任務必須在 60 分鐘內完成。**部署成功 = 拿到一個打得開的網址**，這是本週主線；廣告是「認識 + 規劃」，不實作。若有學生上週的專案還沒做完（例如雲端還沒接好），**仍可部署現有版本**——部署不需要功能全部完成。

## Lab Terminal Prompt 建議

本週 Lab Terminal 用於**部署與廣告的概念理解**：

- 「把網頁『部署』是什麼意思？跟我在自己電腦打開 HTML 檔有什麼不同？」
- 「GitHub Pages 是什麼？為什麼它可以讓全世界看到我的網頁？」
- 「網站上的廣告是怎麼賺錢的？網站主人做了什麼，廣告才會出現？」
- 「為什麼放廣告的平台（像 Google AdSense）要滿 18 歲才能申請？如果我還沒 18 歲，可以怎麼辦？」

> Git push 失敗、網址打開是 404 / 空白等**技術問題**，問 Copilot Chat。

## 翻轉教育流程

**先行者（第一位成功部署、網址打得開的學生）：**
1. 舉手告知老師。
2. 老師指派他去協助一位卡在 push 或 Pages 設定的同學。
3. 助教的角色：問問題、排查，不代為操作。
   - 「你 `git push` 的時候有沒有跳錯誤？錯誤寫什麼？」
   - 「你在 GitHub 的 Settings → Pages，Source 的分支選對了嗎？」
   - 「你打開網址是 404、空白、還是舊版本？（不同症狀問題不一樣）」
4. 被幫助的同學成功部署後，先行者向老師申報 → 領取任務 A 50%（**75 幣**）。

- 遇到問題先看學習單 → 技術問題問 Copilot Chat、概念問題問 Lab Terminal → 問 TA 同學 → 最後才問老師（每節最多 3 次）。

## 老師筆記

**關於廣告主題的處理（重要）：**
- 本週廣告部分是**知識與未來規劃**，**不實際申請任何廣告帳號、不放真實廣告**。原因：Google AdSense 等廣告平台規定**發布者須年滿 18 歲**；未滿 18 歲須由**家長或監護人以自己的 Google 帳號**申請，且所有款項付給該成人。這正好接上 CLAUDE.md 第十六節 S8 的「家長參與框架」。
- 這個主題對應課程 S8「市場驗證 / 獲利嘗試」的長線目標，現在是**埋下種子**：讓學生理解「網站可以賺錢，但需要負責任地、在大人協助下進行」。
- 帶討論時強調**媒體素養**：廣告太多會趕走使用者；好的網站先有價值、廣告是輔助。避免把課程導向「塞滿廣告賺錢」。

**部署常見問題：**
- **`git push` 被拒 / 要求登入**：帳號或遠端 repo 設定問題。引導學生把錯誤訊息貼給 Copilot Chat。
- **網址打開是 404**：Pages 還在建置（等 1–10 分鐘）、或 Source 分支選錯、或進入點檔名不是 `index.html`。
- **打開是空白或舊版**：瀏覽器快取（`Ctrl+Shift+R` 強制重整）、或忘了 push 最新版本。
- **路徑大小寫**：GitHub Pages 區分大小寫，`Index.html` 和 `index.html` 不同。
- **雲端功能在線上版壞掉**：通常是相對路徑或 Supabase 設定問題；提醒這正是「上線後才會發現的問題」，是真實開發的一部分。

**安全提醒（連回 W13）：**
- repo 是公開的，程式碼裡的東西全世界看得到。**這就是為什麼上週只用 anon 公開金鑰 + RLS**。借這個機會讓學生理解「哪些東西可以公開、哪些不行」。

**家長協作任務（選做，帶回家）：**
- 課堂結束時發下 **《家長協作任務單》**（[[S5-W14-家長協作任務-AdSense]]），讓有意願的家庭由**家長用自己的成年帳號**協助孩子的網站設定 AdSense，放上真實廣告（合規路徑：18+ 帳號、款項給家長）。
- 向學生說清楚：**真的放廣告要滿 18 歲，所以這一步要爸媽幫忙**；而且**不管最後有沒有放廣告，「和爸媽一起做出決定 + 簽名帶回」就算完成**——這是 S8 家長參與框架的提前體驗。
- 老師收回簽名單即可，**不評價家庭的選擇**（要做 / 先用免費網址 / 不參與都同等完成）。
- 誠實提醒家長：審核不保證通過、收入通常極少、US$100 才付款、可能需自訂網域、不可點自己廣告——這些都寫在家長單裡，老師不需在課堂細講。

**教學重點提醒：**
- 本週主線是「拿到一個打得開的網址」的成就感，不是把專案做完美。哪怕專案還很陽春，能上線就是成功。
- CLI 優先：部署強調用 **Git 指令 push**（符合課程工作流），Pages 開啟才用 GitHub 網頁設定。
- 廣告計畫由學生依自己的專案決定，沒有標準答案；老師只確認「有寫、有想到家長與內容品質」。
