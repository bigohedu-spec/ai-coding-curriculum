# S3｜GAMMA＋答題卡學習單新架構總規格

> 狀態：S3 答題版課程的共通正典（architecture contract）  
> 基準樣本：[[S3-W01-課程規格-G1-G2]]、[[S3-W02-課程規格-G1-G2]]、[[S3-W03-課程規格-G1-G2]]、[[S3-W04-課程規格-G1-G2]]  
> 適用：S3 新增或重製的學生學習單、課程規格、內嵌答題卡 JSON、教案  
> 不適用：舊式 7-screen 單檔 HTML 課程、Minecraft 主線、S5 Step Flow 課程

---

## 0. 這份規格要保證什麼

每一週產出一組彼此可追溯、但不互相重複的三份文件：

1. **學生學習單**：只放故事、題面、學生能看的支架與提示。
2. **課程規格**：放答案鏈、狀態、判定、金幣、題前／題後檢核與唯一機器 JSON。
3. **教案**：放教學目標、時間、教師引導、差異化、備援與翻轉教育。

課程必須形成這個可觀察閉環：

```text
讀懂眼前任務 → 取得必要舊資料 → 自己或依支架寫 Prompt
→ 使用正確 Lab 工具 → 取得一個成果 → 回填／上傳
→ 本地規則判定 → 方向式修正 → 保存下一題需要的資料
```

任何新增機制都要回答：它是否讓學生更會「讀任務、說清楚、選工具、檢查與修正」？如果只增加故事難度或操作量，不能進主線。

## §G 規格治理

### G1. 正典與衝突裁決【規定】

| 層級       | 正典內容                          | 禁止承擔的內容                                |
| -------- | ----------------------------- | -------------------------------------- |
| 本總規格     | 全 S3 答題版共通架構、schema、生成與驗收規則   | 單週答案、單週故事細節                            |
| Semester | 跨週技能地圖、模組範圍、支架遞減節奏            | 單週答案、測驗選項、網站 JSON                      |
| 單週課程規格   | 單週 ID、答案、判定、資料鏈、狀態、金幣、內嵌 JSON | 重複學生版長文、逐分鐘教師話術                        |
| 學生學習單    | 故事、題面、原始資料、學生支架、卡住提示          | 答案、`passContent`、`answerIndex`、網站 JSON |
| 教案       | 教學目標、時間、教師引導、備援、差異化、翻轉教育      | 網站 JSON、另一套答案鏈                         |
| 上線成品     | 已實測的互動與視覺行為                   | 未回填文件的永久隱性規則                           |

衝突時依序處理：

1. 共通架構先服從本檔；單週內容先服從單週課程規格。
2. 學生題面與 `contentRef` 衝突時停止發布，不可猜測映射。
3. 上線成品若已通過實課，先標為「推定：成品現況」，再把差異回填規格；不可讓程式和文件永久分叉。
4. 任何答案、判定或資料鏈變動都要同時提高 `contentRevision` 與 `storageVersion`；只改文案且不影響映射時，至少提高 `contentRevision`。

### G2. 條款分級【規定】

- **【規定】**：ID、文件職能、答案隔離、資料與狀態、本地判定、金幣冪等、已實測內容。
- **【推定】**：從 W01～W04 歸納但尚未在新週實課驗證的互動配置；若與上線成品衝突，先保留成品並回填差異。
- **【假設，待實玩校準】**：題數、文字量、失敗鎖定秒數、媒體等待與難度手感。

### G3. 每次生成的必要交付物【規定】

```text
wiki/worksheets/S3/S3-WNN-學習單.md
wiki/labterminal-specs/S3/S3-WNN-課程規格-G1-G2.md
wiki/lesson-plans/S3/S3-WNN-教案.md
```

三份文件必須雙向連結。不得再新增手寫 `*-答題表設定.json`；唯一 JSON 放在課程規格的：

````text
<!-- LAB_TERMINAL_WORKSHEET_CONFIG_START -->
```json
{ ... }
```
<!-- LAB_TERMINAL_WORKSHEET_CONFIG_END -->
````

### G4. 版本與發布門檻【規定】

- 新課一律使用 `schemaVersion: 3`。
- 學習單檔頭必有唯一 `CONTENT_REVISION`。
- JSON 的 `contentRevision` 必須逐字相同。
- `contentSource.path` 必須指向實際學習單路徑。
- 每個 `contentRef`、`nextContentRef` 必須逐字命中唯一 `##` 標題。
- 外層任務、內嵌 JSON、Firestore 進度與金幣 `taskId` 必須使用同一組顯式 ID，不得用陣列位置推算。
- 發布前必須通過本 Skill 的 `validate_s3_answer_course.py` 與動作級耗時估算。

## §P W01～W04 的支架遞減模型

四週真正共通的規律是「學生責任逐週增加」，不是每週固定同一種題型。新課必須先選一個 `scaffoldProfile`，不可任意混搭。

| Profile            | 基準週 | 學生負責             | 題面支架                | 舊資料傳遞                  | 工具提示      | 適用情境          |
| ------------------ | --- | ---------------- | ------------------- | ---------------------- | --------- | ------------- |
| `onboarding`       | W01 | 走完工具→生成→回填       | 可直接複製完整 Prompt      | 題目彼此獨立                 | 明確指定      | 第一次接觸工具或全新操作  |
| `guided-chain`     | W02 | 從前題找對資料並放入句型     | 完整問題句型＋填入位置         | 學生回舊卡複製／筆記本暫存          | 可明確指定     | 第一次練跨題資料鏈     |
| `semi-open-chain`  | W03 | 自行輸入一次 Prompt    | 題面可提供「你可以這麼問」但輸入框空白 | `autoContextFrom` 背景帶入 | 四工具並列、不高亮 | 已會工具，練一題一問一成果 |
| `autonomous-chain` | W04 | 自己說清楚問題、工具、資料與修正 | 只有方向提示；禁止完整 Prompt  | 明確讀已通過的 `passContent`  | 不提示       | 練自主提問與方向式修正   |

### P1. Profile 不可變的邊界【規定】

- `onboarding` 可以讓學生複製 Prompt，不能用它評量自主提問。
- `guided-chain` 的難點在資料來源，不能同時要求完全自主 Prompt。
- `semi-open-chain` 的 Session 輸入框必須空白、可編輯；教師 `toolPrompt` 不得渲染或預填。
- `autonomous-chain` 的學生端與 JSON 都不得含可直接複製的完整 Prompt；只可用 `studentGuidance` 提醒資料類別與目標。
- 同一週若需要兩個 Profile，課程規格要逐題標明轉換理由，且不得在同一題同時「給完整 Prompt」又「評量自主提問」。

### P2. 跨週能力進程【規定】

```text
W01 看成果類型並走流程
→ W02 從前題取回正確資料
→ W03 把資料放進自己輸入的一次 Prompt
→ W04 自己辨認問題、選工具、提問並修改
```

後續課程可增加格式、受眾、精確限制或受控修復，但不能退回「學生只複製完整答案」作為主線評量。

## §GL 遊戲迴圈、成果鏈與判定

### GL1. 基礎遊戲迴圈【規定】

- **玩家角色**：由單週故事定義，但角色行動必須對齊 AI 任務工作流。
- **每回合**：讀場景 → 找資料 → 提問／生成 → 回填一個主成果 → 檢核 → 保存鑰匙。
- **獎勵**：每題解鎖一個可見進度；主線金幣合計固定 250。
- **Deliver**：最後成果必須實際使用前面保存資料，並以完成畫面、故事收束與「舉手告訴老師」完成儀式兌現開場承諾。

### GL2. 一題一個主要認知動作【規定】

每題只能有一個主要學習動作與一個主要成果，例如：

- 還原並分類文字 → 一份文字整理。
- 依前題條件生成圖片 → 一張圖片＋必要條件摘要。
- 比較規則找衝突 → 一份修正後條件＋一段音訊。
- 合併已保存成果 → 一段最終影片。

禁止把「解碼、選圖、寫 Prompt、生成媒體、反思」全部塞進同一張答題卡再以一個模糊審核通過。

### GL3. 資料鏈設計【規定】

設計題目前先寫教師／工程端資料鏈：

| 題 | 眼前可見資料 | 本題操作 | 保存的 `passContent` | 下一題為何需要 |
|---|---|---|---|---|
| A | 原始線索 | 一個主要動作 | 最小、結構化、可讀摘要 | B 的唯一選擇依據 |
| B | B 題規則＋A 保存資料 | 一個主要動作 | B 的成果與新鑰匙 | C 的唯一必要資料 |

資料鏈必須符合：

1. 後題缺少前題資料時不能完整完成。
2. 後題題面不重複展示前題正解。
3. `autoContextFrom` 只能引用已完成的前題或當前 `contentRef`。
4. `passContent` 只保存下一步真正需要的最小資訊，不保存整段聊天紀錄。
5. 媒體結果不作唯一技術鑰匙；必須另存 AI 可讀的文字摘要，避免圖片／音訊辨識失敗算成學生錯誤。

### GL4. 判定順序【規定】

```text
必要欄位／附件存在
→ 題前檢核已通過（若有）
→ Prompt 必要條件本地預審（媒體題）
→ 主成果本地可重現判定
→ 題後檢核本地判定
→ 寫入完成狀態、passContent 與金幣
→ 解鎖下一題
```

- AI 可以整理、生成、角色化回饋與提供方向，**不能單獨決定 pass/fail**。
- 語意品質真的無法只用本地規則表達時，可用平台 AI 作輔助審查，但逾時／失敗必須回到本地後備，不可卡死學生。
- 退件保留 Prompt、答案、小測、附件與修改次數；一次只回一個最重要的修改方向。

### GL5. 防硬答與防挫折分離【規定】

**防硬答**：

- 選擇題至少 3 個合理選項；干擾項來自同場景常見誤解。
- 不用荒謬選項，也不讓答案因長度、位置或語氣特別顯眼。
- 前題資料不得在後題 placeholder、錯誤回饋或預設值中洩漏。
- 媒體 Prompt 用「必要證據群組」檢查，不以字數作唯一門檻。

**防挫折**：

- 答錯、生成失敗、重新整理、切換題目都不清空成果。
- 媒體服務失敗時允許教師備援素材或分鏡，但保留學生原 Prompt 與覆寫紀錄。
- 錯誤回饋不羞辱、不直接給答案；學生永遠可以在同一題修正。
- 老師端可放寬或放行技術失敗，不能把模型失敗記成學生能力失敗。

## 1. 內容規劃流程

生成任何單週內容前，依序完成以下設計卡；沒有完成就不要先寫故事。

### 1.1 能力卡

- 本週只提升哪一個可觀察能力？
- 它位於哪一個 `scaffoldProfile`？
- 學生上一週已會什麼？本週明確不教什麼？
- 完成時，學生會做出什麼可驗證行為？

### 1.2 Hook／Deliver 卡

- 開場承諾一個 60 分鐘內每位學生都能完成的具體成果。
- 結尾必須讓學生看到該成果真的由自己的前題資料組成。
- 故事包裝不能改變題目正解，也不能讓視覺素材提前洩題。

### 1.3 任務鏈卡

先列資料依賴，再決定題數。建議 4～6 個主任務，但題數屬【假設，待時長驗證】。每題填：

```text
故事原因／眼前問題／可見資料／主要認知動作／成果類型
必要前題資料／保存鑰匙／本地判定／失敗方向／金幣
```

### 1.4 工具與媒體卡

- 文字：Lab Terminal。
- 圖片：Lab Image。
- 音訊：Lab Music。
- 影片：Lab Video。
- 學生不需申請外部帳號；學生版不出現第三方 AI 品牌。
- 選擇「即時生成」或「教師預製素材」並寫理由。不要在同一題把兩者當成隱性隨機行為。

### 1.5 評量卡

每題先定義「最小可重現證據」，再寫題目：

- 文字題：必要概念群組、長度範圍、禁止只貼題目。
- 圖片／音訊／影片：Prompt 證據群組、附件 MIME、來源／簽章或教師素材 ID。
- 串接題：前題 `passContent` 的哪一欄是必要證據。
- 題前與題後檢核只考讀題方法、資料來源與修正動作，不考尚未取得的正解。

## 2. 題目設計流程

### 2.1 題面四層

每個主題至少能回答：

1. **故事原因**：為什麼現在要做這件事？
2. **可操作資料**：學生要讀、比較或交給 AI 的原始內容是什麼？
3. **成果契約**：最後要交文字、圖片、音訊或影片？必要條件是什麼？
4. **方向提示**：卡住時回看哪類資料，不直接給答案。

`autonomous-chain` 的學生學習單固定使用「背景故事／謎題內容／通關條件／提示」四段；其他 Profile 可縮減，但不能漏掉成果契約。

### 2.2 題前讀題測試 `preReadChecks`

只在學生可能因支架撤除而不知道如何開始時使用。標準三題分別確認：

1. 眼前資料是什麼。
2. 最後要取得哪一類成果。
3. 開始前要回看哪裡或做哪一種處理。

題前測試不得詢問正確答案、工具名稱或下一題鑰匙。`onboarding` 可省略；`autonomous-chain` 每題固定 3 題。

### 2.3 題後讀題測試 `readChecks`

題後測試不是另一份作業，只做兩件事：

- `phase: review`：確認剛完成的可驗證事實或方法。
- `phase: next-reading`：先交代學生此刻位置，再確認下一題要做的事或去哪裡取資料。

`autonomous-chain` 可增加來源、修正方法與口訣情境題；口訣題必須用本題情境改寫，不能只背句子。

### 2.4 干擾項

- 每個錯誤選項都要能對應一種真實誤解：選錯資料源、選錯成果類型、顛倒操作順序、刪掉不該刪的條件。
- 選項長度與語氣盡量接近。
- 正解位置需分散；不能每題固定第一項。
- `retryFeedback` 只指向要回看的段落或資料類別。

### 2.5 Prompt 支架

| Profile | 學生學習單 | 答題卡 JSON |
|---|---|---|
| onboarding | 可放完整可複製 Prompt | 可放摘要，不另做自主 Prompt 評分 |
| guided-chain | 可放帶插槽的完整句型 | `studentPromptEditable: true`，明列前題來源 |
| semi-open-chain | 可放「你可以這麼問」 | `toolPrompt` 只供伺服器／教師，輸入框不得預填 |
| autonomous-chain | 禁完整 Prompt，只給思考方向 | 禁 `toolPrompt`；只可用不可複製的 `studentGuidance` |

## 3. 三份文件的內容規格

### 3.1 學生學習單

必含：

- 標題與 `CONTENT_REVISION`。
- 求助順序或卡住提示。
- Hook、口訣、任務 A～最後一題、完成收束、連結。
- 每題唯一 `任務 ID`。
- 若有 GAMMA 圖片，使用 `GAMMA_ASSET_PROMPT` 註解，並明寫「不要文字／數字／答案／浮水印」。

不得含：

- `LAB_TERMINAL_WORKSHEET_CONFIG`。
- `answerIndex`、`acceptedTerms`、`passContent`、教師答案、金幣配置細節。
- 未通關題目的完整正解或會直接複製通關的 Prompt（Profile 允許者除外）。
- 第三方 AI 品牌名稱。

### 3.2 單週課程規格

固定順序：

1. §G 規格治理。
2. §P 支架 Profile 與跨週定位。
3. §GL 遊戲迴圈與判定。
4. 後設資料與時長。
5. 題目／資料鏈／教師正解。
6. 每題審核標準。
7. 題前、題後檢核規則。
8. 內嵌 schema v3 JSON。
9. 資料、狀態、失敗與發布。
10. 老師端、翻轉教育、DoD、連結。

### 3.3 教案

必含：基本資訊、教學定位、課前準備、逐題教師引導、統一退件原則、時間流程、技術備援、差異化、翻轉教育、成功條件與跨週銜接。

教案可保存教師 Prompt 範例，但要明標「僅教師版」；不得再放一份 JSON，也不得創造與課程規格不同的答案鏈。

## 4. Schema v3 共通契約

完整模板見 `$s3-answer-sheet-course/references/course-spec-template.md`。以下為不可省略的語意。

### 4.1 頂層欄位

| 欄位 | 規則 |
|---|---|
| `schemaVersion` | 固定 `3` |
| `id` | `S3WNN` |
| `courseId` | `S3-WNN` |
| `semester`／`week` | `S3`／數字週次 |
| `source` | `gamma-answer-worksheet` |
| `contentRevision` | 與學習單完全相同 |
| `contentSource.path` | 實際學習單 repo path |
| `storageVersion` | 每次不相容資料變更提高 |
| `scaffoldProfile` | 本檔 §P 四選一 |
| `studentToolHints` | 依 Profile 設定 |
| `initialQuestionId` | 必須存在於 `questions[].id` |
| `reviewFeedbackMode` | 建議 `direction-only`；自主模式固定使用 |
| `questions` | 依學生流程排序，但語意一律由顯式 ID 決定 |

### 4.2 每題共通欄位

`id`、`taskId`、`contentRef`、`code`、`label`、`title`、`prompt`、`interactionMode`、`expectedKind`、`coins`、`reviewCriteria`。

- `contentRef` 必須命中學習單唯一 H2 標題。
- 只在右側顯示的序章仍要在 Markdown 保留可對齊標題，並加 `presentationSurface: answer-card-only`。
- `taskId` 必須是 `S3-WNN-*`；序章以 `-PROLOGUE` 結尾且 0 金幣。
- `coins` 的所有主線任務合計 250，入帳交易 ID 至少含 `worksheetId + uid + taskId + pass`。

### 4.3 類型映射

| `toolId` | `expectedKind` | 允許附件 |
|---|---|---|
| `terminal` | `text` | `text/plain` |
| `image` | `image` | PNG／JPEG／WebP |
| `music` | `audio` | MP3／WAV／M4A |
| `video` | `video` | MP4／WebM／MOV |

媒體題必須有：

- `promptReviewCriteria.explicitEvidenceGroups` 與最低命中數。
- `reviewCriteria.minAttachments/maxAttachments/allowedMimeTypes`。
- 即時生成時的同題來源／簽章驗證，或 `systemContext.assetMode: teacher-library-only` 的備援資產資訊。

文字題必須有可重現的 `reviewCriteria`：必要概念、最少命中數、合理長度與 `aiReviewMode: local-only`；不得只驗字數。

### 4.4 狀態與依賴

- `autoContextFrom` 只能指向更早的 `q*.passContent` 或當前 `contentRef:*`。
- `passContent` 是隱藏的結構化保存包，不得渲染到未解鎖學生畫面。
- `preReadChecks`、`readChecks` 以穩定 ID 保存草稿，不使用陣列 index。
- 調整 ID、任務數、答案語意或依賴時必須提高 `storageVersion` 並寫遷移／重置策略。

## 5. 媒體、生成失敗與資產安全

### 5.1 兩種媒體模式【規定】

| 模式 | 何時用 | 通過依據 |
|---|---|---|
| 即時 Lab 生成＋簽章 | onboarding、需要真正走一次生成流程 | Prompt 預審＋同 worksheet/task/tool 簽章＋MIME |
| 教師預製素材 | 自主提問、修正能力是重點，或 API 成本／穩定性高 | 學生 Prompt 通過本地預審後解鎖指定素材；答題卡再獨立審核 |

學生能力評量不得依賴生成模型是否剛好畫對、唱對或連線成功。

### 5.2 GAMMA 視覺素材【規定】

- 場景圖只表現「問題狀態」，不表現正確答案。
- 選項圖不得用亮度、位置、顏色或構圖暗示正解。
- 提示固定包含兒童友善、不恐怖、不要可閱讀文字／數字／標誌／浮水印。
- 關鍵角色與物件外觀跨頁一致；同一角色使用一份權威描述。

---

## 6. 資料、狀態、金幣與失敗

### 6.1 草稿與進度【規定】

- 草稿鍵至少包含 `storageVersion + worksheetId + userId`。
- 保存學生 Prompt、文字成果、附件 metadata、題前／題後作答、審核狀態與修改次數。
- 重新整理、退件、題目切換與短暫斷線都不可清空。
- 本地與雲端衝突取完成進度較遠者；不同學生不可共用草稿。

### 6.2 金幣【規定】

- 主線總額恰為 250；序章 0。
- 完成同一題只入帳一次。
- 建議交易 ID：`S3WNN:<uid>:<taskId>:pass`。
- 可允許無計分重玩，但不能重複發金幣；若完成即鎖，課程規格要寫明理由。

### 6.3 失敗情境【規定】

規格逐一寫出學生看到什麼、能否繼續：AI 逾時、媒體生成失敗、附件失敗、重新整理、離線、缺資產、老師覆寫。所有技術失敗都必須保留學生證據並有前進方案。

---

## 7. 時長與認知負荷

### 7.1 動作級估算【規定】

定稿前使用 `activity-time-estimator`，年級固定 4，主線目標 50～65 分鐘。至少拆入：

- 學生實際可見文字閱讀字數。
- 實際輸入 Prompt／答案字數，不用範例字數冒充。
- 每題讀題、工具切換、生成、回填、上傳、送出所需點擊。
- `preReadChecks`／`readChecks` 的選項總字數與點擊。
- 思考、頁面轉場、媒體等待、舉手告知老師。

課程規格與教案必須使用同一份動作假設；不能一份寫 64 分鐘、另一份用不同輸入字數算成 92 分鐘卻都宣稱正典。

### 7.2 太長時的刪減順序【規定】

1. 刪除重複讀題與重複口訣測驗。
2. 縮短故事與選項，不刪資料鏈。
3. 把非核心反思移到課後或選做。
4. 改用教師預製媒體，保留學生 Prompt 證據。
5. 仍超時才拆週；不可用「學生打快一點」解決。

### 7.3 課堂實測校準【規定】

記錄 P50／P80 完成時間、各題退件率、媒體等待與老師介入次數。若 80% 學生不能在 60～65 分鐘內完成，下一版先降低閱讀與介面步驟，再考慮改謎題。

---

## 8. 老師端與翻轉教育

老師端至少顯示：目前題目、題前／題後完成、主成果狀態、附件／備援、修改次數、需要協助、最後送出時間。

先完成者只能引導：

- 你現在看到的問題是什麼？
- 這題最後要交什麼成果？
- 需要的資料在哪一張答題卡？
- 系統請你補的是哪一類條件？

禁止代打、代選工具、代上傳、代送審或說出答案鏈。完成頁必須有「舉手告訴老師」與小老師行動；TA 金幣另計且使用獨立冪等交易 ID。

## 9. 生成與修訂工作流

1. 讀 Semester、前一週三份文件與本總規格。
2. 選定唯一 `scaffoldProfile`，寫 In／Out of Scope。
3. 先寫能力卡、Hook／Deliver、資料鏈與本地判定，再寫故事。
4. 先產學生學習單，鎖定所有 H2 與 `CONTENT_REVISION`。
5. 產課程規格與 schema v3 JSON；`contentRef` 直接取已鎖定 H2。
6. 產教案，不複製 JSON，不建立另一套答案。
7. 執行合約檢查器；任何 error 都不得發布。
8. 執行動作級耗時估算；不在 50～65 分鐘則調整後重跑。
9. 用「未看教師答案的學生視角」走一次；確認後題未洩漏前題答案。
10. 用教師視角走技術失敗、退件、重新整理與備援流程。

## 10. Definition of Done

### 文件與版本

- [ ] 三份文件齊全且互相連結。
- [ ] 學習單只有一個 `CONTENT_REVISION`；JSON 完全一致。
- [ ] JSON 只存在課程規格；schema 為 3。
- [ ] 所有 `contentRef`／`nextContentRef` 精確命中唯一 H2。
- [ ] `id`、`taskId`、測驗 ID 唯一且不靠陣列位置推算。

### 教學與資料鏈

- [ ] `scaffoldProfile` 與本週能力相符，沒有同題混用相反支架。
- [ ] 每題只有一個主要認知動作與一個主要成果。
- [ ] 後題需要前題保存資料，但未提前顯示前題正解。
- [ ] 媒體成果另有文字保存包，不以媒體辨識當唯一鑰匙。
- [ ] Hook 與 Deliver 對應，主線能力沒有被純解謎擠掉。

### 判定與狀態

- [ ] pass/fail 可本地重現；AI 不當唯一關主。
- [ ] 媒體題有 Prompt 證據群組、MIME 與來源驗證。
- [ ] 退件、重整、斷線與技術失敗不清空證據。
- [ ] 金幣主線恰為 250 且入帳冪等。
- [ ] 序章、題前與題後檢核不洩漏答案。

### 課堂可用性

- [ ] 動作級估算為 50～65 分鐘，課程規格與教案假設相同。
- [ ] 老師端、備援、翻轉教育與完成儀式已定義。
- [ ] GAMMA 素材不洩題，學生端沒有第三方 AI 品牌。
- [ ] 合約檢查器 0 errors；warnings 已逐項判斷並留下理由。

## 11. W01～W04 基準稽核：可繼承與不可複製

### 11.1 應繼承的穩定模式

- W01：成果類型→工具→生成→回填的第一次完整閉環。
- W02：前題資料成為後題必要輸入、筆記本只暫存、單題單次送審。
- W03：顯式 ID、`contentRevision/contentRef` 對齊、Session 空白輸入、`autoContextFrom`、一題一問一成果。
- W04：Profile 明確撤除完整 Prompt、題前讀題、方向式回饋、答案隔離、教師預製媒體與本地判定。

### 11.2 已發現的文件漂移，不得當模板複製

| 基準 | 漂移 | 新規則 |
|---|---|---|
| W01 | schema v2，且文字曾主張 JSON 放學習單 | 新課只用 schema v3，JSON 只放課程規格 |
| W02 | 規格引用 repo 中不存在的外部答題設定 JSON | 禁止新增外部手寫 JSON；內嵌區塊是唯一機器來源 |
| W03 | 課程規格的 A 題 `contentRef` 與目前學習單 H2 不同 | 精確 H2 合約，validator 必須阻擋發布 |
| W03 | 規格與教案曾用不同動作假設得到不同時長 | 同一份 ECT 動作清單同時供規格與教案引用 |
| W04 | 學習單 revision 與規格 JSON revision 不同 | revision 不一致即 error，不得發布 |
| W04 | 文字敘述曾寫「3 個小測」，JSON 實際為 4 個 | 可數單位由 JSON 與 DoD 自動核對，不手寫模糊數量 |

這些漂移不代表已上線課程不可用；它們說明未來生成必須靠合約檢查，而不是靠複製舊檔文字。
