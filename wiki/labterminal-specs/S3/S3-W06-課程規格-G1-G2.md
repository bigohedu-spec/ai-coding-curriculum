# [S3-W06] 太空基地的五次建造測試｜GAMMA＋答題卡課程規格 G1–G2

> 來源學習單：[[S3-W06-學習單]]｜對應教案：[[S3-W06-教案]]｜內容版本：`S3W06-2026-09-02-r6`

## §G 規格治理

- **正典聲明【規定】**：本檔是 W06 答案鏈、影片資產、Prompt 判定、概念／狀態／流程題庫、狀態、金幣與網站 JSON 的唯一來源；學生題面只讀 [[S3-W06-學習單]]。
- **綁定內容【規定】**：`wiki/worksheets/S3/S3-W06-學習單.md`，revision `S3W06-2026-09-02-r6`。
- **本週可觀察能力【規定】**：學生能先說出前一版已修好與仍有問題的部分，將問題判斷為「做什麼、怎麼做、不能做什麼、目標」其中一類，再保留正確內容，只追加或替換對應欄位。
- **學生的精確轉換【規定】**：A～D 是同名欄位的 `match-and-copy + retrieve`；E 是依明確舊值／新值進行一次 `revise`。不評量自由摘要、隱性推理或自主創作完整 Prompt。
- **In Scope【規定】**：辨別四需求概念邊界、回顧前一版狀態、同名值填入、保留與累積 Prompt、從固定影片判斷下一種缺漏、依正式變更單替換一個衝突值、保存五版 Prompt 與影片。
- **Out of Scope【規定】**：自由設計太空基地、即時影片美術品質、多輪自由修片、第五種需求、字數控制、受眾語氣改寫與完整自我檢查。
- **支架 Profile【規定】**：`guided-chain`；學習單提供權威值與同名空格，答題卡自動帶入已通過 Prompt，只開放本題新增行，E 才開放整份 Prompt 進行指定替換。
- **可數單位【規定】**：1 個序章、5 個主任務、7 題序章概念／流程檢核、5 版教師預製施工影片、4 張需求卡、20 題主任務狀態／概念檢核、5 次 Prompt 審查、250 金幣。
- **學生版邊界【規定】**：小測題幹、選項、答案索引、證據群組、`passContent`、reviewTicket、資產 ID、金幣與 JSON 不得加入學習單。
- **GAMMA 忠實呈現【規定】**：逐題保留學習單正式資料前的星野隊長短對白，不得合併或省略；所有 GAMMA 資產提示中的星野隊長固定呈現為中年日本女性，角色外觀依學習單提示保持一致。
- **假設，待實課校準**：27 題檢核在四年級主線中可於 63.9 分鐘完成；實課記錄 P50／P80、四需求各自錯誤率、缺漏／衝突題錯誤率與每題重試次數。若 P80 超過 65 分鐘，先縮短題幹／回饋與減少界面點擊，不刪除四需求概念或衝突替換題。

### 解題必要的四需求概念【規定】

| 需求 | 核心問句 | 可放入 | 不可混淆為 |
|---|---|---|---|
| 做什麼 | 要產出什麼？成果的身分是什麼？ | 基地名稱、用途、主體 | 位置與排列 |
| 怎麼做 | 要如何安排、連接或呈現？ | 位置、設備、連接、入口方位 | 給誰使用與希望效果 |
| 不能做什麼 | 哪些內容或結果禁止出現？ | 可逐項檢查的禁則 | 「要安全」這類模糊願望 |
| 目標 | 給誰使用？要產生什麼效果？ | 使用者、用途、理解與感受 | 物件的具體擺放位置 |

**最容易混淆的邊界**：「入口設在正面」回答位置，屬於「怎麼做」；「讓救援隊從正面快速進入」回答使用者與效果，屬於「目標」。共用關鍵字不代表屬於同一類，要看句子回答的問題。

### Hook／Deliver

- **Hook**：B-7 只能照 Prompt 施工，每次規格缺漏都會在測試影片中造成一個明確失敗。
- **Deliver**：學生讓同一份 Prompt 從一行長成四行，再修正入口位置衝突，使曙光站成功完工。

### 五版施工影片鏈【規定】

| 回傳   | 固定資產 ID                                    | 已修好          | 仍失敗原因             | 下一步     |
| ---- | ------------------------------------------ | ------------ | ----------------- | ------- |
| A／V1 | `s3w06-dawnbase-v1-subject-fail-layout`    | 基地名稱、用途、主體   | 艙體散落、通道未連接        | 新增怎麼做   |
| B／V2 | `s3w06-dawnbase-v2-layout-fail-safety`     | 部件位置、連接與背面入口 | 裸露電線、破裂玻璃、堵塞氣閘、火焰 | 新增不能做什麼 |
| C／V3 | `s3w06-dawnbase-v3-safe-fail-goal`         | 安全禁則         | 像無人倉庫，不知道使用者與效果   | 新增目標    |
| D／V4 | `s3w06-dawnbase-v4-goal-conflict-entrance` | 四種需求都存在      | 背面入口與正面救援目標衝突     | 修改入口位置  |
| E／V5 | `s3w06-dawnbase-v5-complete-success`       | 四種需求完整且一致    | 無                 | 完成儀式    |

影片由課程作者預製並透過 Lab Video 固定回傳；不得用即時生成的隨機結果決定教學順序或 pass/fail。

## §GL 遊戲迴圈與判定

```text
讀本題權威資料 → 保留前題已認證 Prompt
→ 把本題值放進同名空格 → 送出建造測試
→ 本地檢查目前需求 → 簽發 reviewTicket
→ Lab Video 回傳固定施工影片並自動綁定
→ 完成 4 題「上版結果與本題動作／需求概念／仍有問題／下一步」檢核
→ 保存需求卡與影片 → 下一題追加或 E 指定替換
```

- **一題一個主要動作【規定】**：A～D 各追加一種需求；E 只替換「怎麼做／入口位置」。影片與小測是同一修改結果的回饋，不是第二個主成果。
- **AI 定位【規定】**：可把本地缺漏說成角色化方向回饋；AI 不單獨決定 pass/fail。
- **答案傳遞【規定】**：每題通過後，系統依本題權威值整理出一份標準、可複製的累積 Prompt，作為學生看得到的 `passContent`；B～D 從前題 `passContent` 帶入已完成段落，E 載入 q4 的標準 Prompt 後只修改指定欄位。認證 token、reviewTicket 與影片 metadata 另存於隱藏狀態，不渲染在「通過內容」卡。
- **影片定位【規定】**：Prompt 通過才解鎖固定影片；影片美術品質不判分。技術失敗保留 Prompt 與 ticket，改用同版短文字施工回報。
- **題庫節奏【規定】**：A～D 每題固定 4 題：上一版結果／本題修的需求、新情境概念辨別、新影片仍有的問題、下一步。E 為修改欄位、欄位概念轉移、D／E 故事與成功原因對比、完成儀式。
- **退件【規定】**：保留 Prompt、影片、小測與修改次數；一次只指出一個未替換空格或缺漏群組，不提供完整 Prompt。
- **金幣【規定】**：A35＋B40＋C45＋D50＋E80＝250；交易 ID `S3W06:<uid>:<taskId>:pass`。

### 教師正確答案鏈

- A｜做什麼：`請建造名為曙光站的月面研究基地，主體是圓頂指揮艙。`
- B｜怎麼做：`中央放圓頂指揮艙，左側放生活艙，右側放植物艙，後方放兩組太陽能板，各艙使用密封通道連接，入口設在基地背面。`
- C｜不能做什麼：`不要有裸露電線、破裂玻璃、堵塞氣閘或火焰，也不要出現可閱讀文字。`
- D｜目標：`給基地研究員與緊急救援隊使用，讓救援隊從正面一眼找到入口並快速進入，並讓基地研究員感到安全與安心。`
- E｜唯一修改：把 B 的 `基地背面` 替換為 `基地正面`；其他三段保持學生已通過原文。

### 正確答案隔離規則【規定】

- 上述完整答案、影片資產 ID、證據群組與 `answerIndex` 不得渲染到未解鎖學生畫面。
- 學習單已公開的權威欄位值是本週 `guided-chain` 的合法輸入，不視為隱藏答案洩漏。
- 標準 Prompt 只能在該題通過後顯示於「通過內容｜可複製 Prompt」；不得在通關前預填或提前揭露。
- 後題的 `[任務X留下的需求]` 由前題已解鎖的標準 `passContent` 帶入；學生可直接複製，不必從 ticket 或 metadata 中整理文字。
- 主任務檢核只在學生看完當題影片後開啟；下一題正確資料仍以學習單正式資料區為準。

## 3. 每題審核標準

| 題 | Prompt 預審 | 主成果通過 | 方向式退件 |
|---|---|---|---|
| A | 曙光站／月面研究基地／圓頂指揮艙 | V1 同題綁定＋4 checks | 指出名稱、用途或主體中第一個缺漏 |
| B | 中央、左、右、太陽能板、密封通道、基地背面 | V2 同題綁定＋4 checks | 只指出一個位置、設備或連接缺漏 |
| C | 四項危險＋可閱讀文字 | V3 同題綁定＋4 checks | 只指出第一個未禁止內容 |
| D | 使用者、正面快速進入、安全安心 | V4 同題綁定＋4 checks | 只指出對象、理解或感受缺漏 |
| E | 四需求均在；基地正面存在；基地背面不存在 | V5 同題綁定＋4 checks | 先提示查看正式變更單，再指出修改欄位 |

所有題目先檢查是否仍有 `〔……〕` 或 `[任務X留下的需求]` 未被系統帶入；有空格時只回覆「還有一個欄位沒有換成正式資料」。不因標點、一般錯字或影片畫面風格退件。

## 4. 序章與主任務題庫

- 序章使用既有 H2「開始前｜同一份 Prompt 會一直長大」作為 `contentRef`，只呈現在右側答題卡，0 金幣；`initialQuestionId` 指向 `prologue`。
- 序章先在右側明說本週四需求的定義，再用 7 題確認：本週目標、做什麼、怎麼做、不能做什麼、目標、缺漏時追加、衝突時替換；全對才解鎖 A。
- 序章背景與 7 題全部由右側答題卡呈現，不把題目或逐步操作說明加進學生學習單；`responseCards: []` 且 `unlockOnPass: "q1"`，避免序章被當成一般成果題或完成後無法進入 A。
- A～D 每題完成影片綁定後開啟 4 題：`review-current`、`requirement-concept`、`current-problem`、`next-action`；第 1 與第 3 題必須明說前一版狀態。
- E 的 4 題為：修改欄位、欄位概念轉移、D／E 故事與成功原因對比、完成儀式。
- 全部使用本地 `answerIndex`；答錯不清空 Prompt 或影片，只指向已看過的影片、正式資料或變更單。
- A～D 第 4 題使用 `nextContentRef` 解鎖下一題；E 第 4 題指向「曙光站建造成功」。

## 6. 資料、狀態、失敗與發布

- 草稿鍵：`storageVersion + worksheetId + userId`；分開保存學生五版作答草稿、五份標準 `passContent`、需求卡、影片 metadata、reviewTicket、序章 7 題、20 題主任務檢核、修改次數與 E 欄位變更紀錄。
- A～D 只有在目前 Prompt scope 通過、固定影片自動綁定且 4 題檢核全對後，才解鎖該題標準 `passContent`；學生畫面只顯示可複製 Prompt，不顯示 token、ticket、assetId 或 metadata。
- B～D 的 `[任務X留下的需求]` 必須由前題標準 `passContent` 自動帶入，不得把提示字樣當有效 evidence；學生原始作答仍保存在修改紀錄中，但不作為下一題的預設文案。
- E 以 q4 學生 Prompt 為起點；只要 Prompt 仍含 `基地背面` 就不得簽發成功 ticket。
- 金幣以 `S3W06:<uid>:<taskId>:pass` 冪等入帳；重玩不重複發幣。
- AI 回饋逾時時改用本地 evidence groups；不得卡住學生。
- 影片載入失敗時保留有效 ticket 與 Prompt，顯示同版短文字施工回報並標記 `assetReturnPending`；服務恢復後回傳原題固定影片。
- 影片自動綁定失敗時保存 assetId、promptHash 與縮圖，允許重新綁定同次結果，不要求重打。
- Prompt 在 ticket 簽發後改動時，舊 ticket 與待綁定影片失效，需以新 Prompt 重新送出。
- 重新整理或斷線恢復最後題目、Prompt、需求卡、影片、小測與修改紀錄；不同 uid 不共用草稿。
- **r2 → r3 遷移【規定】**：依正式 `taskId` 保留 q1～q5 的 Prompt、影片 metadata、已簽發 pass token 與金幣交易；因檢核題 ID、數量與語意已變更，序章與 `readChecks` 作答狀態必須重置並重做。金幣仍以原 `taskId` 冪等交易處理，不重複入帳。
- **r3 → r4 遷移【規定】**：保留 q1～q5 的 Prompt、影片、pass token 與金幣交易；序章題目 ID 與答案不變，但因序章解鎖契約補上 `unlockOnPass: q1`，舊版尚未完成的序章狀態移入新 storage key，已完成序章可依 7 個穩定 check ID 恢復並直接解鎖 A。
- **r4 → r5 遷移【規定】**：保留 q1～q5 的 Prompt、影片、pass token、20 題主任務檢核與金幣交易；序章 7 題的 ID、情境與認知功能已重寫，不沿用 r4 序章答案，學生需重新完成 W06 專屬序章後才解鎖 A。
