- **綁定實作檔**：

  - `C:\Users\COSH\Desktop\CodingClass\ai-coding-curriculum\wiki\worksheets\S3\S3-W01-學習單.md`
- **In Scope**：左側題目卡呈現、右側 Lab Terminal 答題欄、四題任務切換、建議工具顯示、可複製提示詞顯示、Lab Terminal / Lab Image / Lab Music / Lab Video 工具切換、生成 / 示範結果、文字回填、多檔案附件回填、AI 審查回饋、完成進度顯示、學生操作動線測試。

  - `回填`：把文字貼入答案欄，或把圖片、音訊、影片、檔案加入附件。
  - `送 AI 審查`：檢查目前答案是否符合本題任務與產出類型。

## §GL 教學迴圈與判定

- **教學迴圈**：學生每題都走同一條路徑：看左側題目 → 看右側目前題目與建議工具 → 複製提示詞 → 切到指定 Lab 工具 → 生成或使用示範結果 → 回填文字或附件 → 送 AI 審查 → 進入下一題。
- **MVP 判定定位**：AI 審查在 prototype 階段可使用本地規則模擬，不要求正式後端。判定重點是「產出類型正確、不是空白、內容與題目相關」。
- **AI 不當關主**：MVP 的 AI 回饋只做教學提示；不負責正式發金幣、不刪學生答案、不阻止老師人工判斷。
- **防挫折**：
  - 工具 API 失敗時，提供 `生成/示範` fallback。
  - 審查不通過時保留原答案與附件。
  - 學生可重新生成、補附件、再送審。
  - 不使用刺眼紅色作為主要狀態；錯誤用文字說明缺什麼。
- **反硬 A**：
  - 空白文字不可通過。
  - Q1 必須像 3 點提醒。
  - Q2 至少要有圖片附件或明確小狗玩球圖片描述。
  - Q3 至少要有音訊附件或明確咖啡廳爵士樂描述。
  - Q4 至少要有影片附件或明確滑雪短影片描述。
  - 不以「是否自行輸入提示詞」作為通過條件。

- **Prototype 形態**：單一 HTML 頁，左側為題目卡 / placeholder，右側為 Lab Terminal 答題欄。
- **本輪不處理**：不要在本 spec 內要求 JSON 題庫、URL 自動建置、學習單入口後台流程或正式資料庫串接。
- **課堂用途**：小四上 S3W01，四題短任務，每題對應一種 AI 產出類型。
- **預估測試時長**：約 52.1 分鐘主線，判定「剛好」；已用 activity-time-estimator 於小四（grade 4）估算。若正式工具生成時間過長，允許使用示範結果完成流程測試。

- **完成感**：四題全部完成後顯示 4/4 完成與 250 金幣概念；MVP 不做正式錢包入帳。

## 2. MVP 畫面規格

### 2.1 整體版面

- 頁面採左右雙欄。
- 左側約 70%，顯示題目卡或模擬題目。
- 右側約 30%，顯示 Lab Terminal 答題欄。
- 頁面本身不應因左側內容滾動而整頁一起滾動；左側與右側各自控制可用空間。
- 上方 title label 必須壓低高度，讓答案欄有更多垂直空間。
- 右側答案欄需盡量吃滿可用高度，不再依賴內部小捲軸。
- 因題目已有標示，不需要上一題 / 下一題按鈕。

### 2.2 左側題目區

- 正式題目內容尚未完成時，必須能用 placeholder 題目卡測試流程。
- 左側每張任務卡可點擊，點擊後右側同步切到對應題目。
- 左側只負責任務閱讀，不放答案輸入欄。
- 若未來外部題目來源無法嵌入，本 MVP 仍可用抽出的題目卡繼續測試教學流程。

### 2.3 右側 Lab Terminal 答題欄

右側固定包含：

1. 目前題目狀態：第幾題、完成數。
2. 題目切換標示：1 / 2 / 3 / 4。
3. 題目摘要：任務名稱、建議工具、審查金幣概念。
4. 可複製提示詞區：顯示本題學習單指定提示詞。
5. 文字答案欄：可直接填入生成結果或說明。
6. 附件區：可加入多個檔案，顯示檔名、類型、來源。
7. 工具切換列：Terminal / Image / Music / Video。
8. 操作按鈕：複製提示詞、生成/示範、送 AI 審查。
9. AI 回饋區：顯示通過、缺漏、建議。
10. 儲存草稿狀態。

### 2.4 顏色規範

- 金幣 badge 不使用鮮黃底，避免與學生圈選色或作答標記衝突。
- 金幣 badge 使用中性深底、淺色文字、細框即可。
- 目前題目 active 狀態可用青綠色，但不可把整個答案內容區染成同色。
- 錯誤、缺漏、警告不可只靠顏色辨識，必須有文字。

### Q1｜AI 工具使用提醒

- **任務文字**：請把學習單提供的 AI 工具使用提醒文字，使用 Lab Terminal 整理成 3 點提醒，讓同學一看就懂。
- **建議工具**：Lab Terminal。
- **學習單指定提示詞**：
  ```text
  請把下面內容整理成 3 點提醒，對象是小四學生。每一點要短、清楚、容易懂。請只輸出 3 個條列。

  內容：
  使用 AI 工具前要先看清楚任務，不要亂輸入無關內容。
  如果不知道怎麼寫提示詞，可以先找出任務中的關鍵字。
  生成結果後要自己檢查，不能直接交出去。
  如果結果不符合需求，要修改提示詞再試一次。
  生成的關鍵詞很重要請善用你的複製貼上快捷鍵。
  ```
- **答案欄 placeholder**：`請貼上你整理出的 3 點提醒...`
- **審查條件**：
  - 至少 3 行或 3 個清楚分點。
  - 提到任務、提示詞、檢查結果或修改其中至少一類。
  - 不可只貼無關文字。

### Q2｜小狗玩球圖片

- **任務文字**：生成可愛動物的圖片，今天要的圖片是小狗玩球，請使用 Lab Image 生成一張清楚可愛的小狗玩球圖片。
- **建議工具**：Lab Image。
- **學習單指定提示詞**：
  ```text
  一張可愛插畫風圖片：一隻小狗在綠色草地上開心玩紅色球。畫面明亮、乾淨、可愛，適合小四學生的學習單。請讓小狗和球都很清楚，不要出現文字。
  ```
- **答案欄 placeholder**：`請附上圖片，或簡短描述你產生的小狗玩球圖片...`
- **審查條件**：
  - 有圖片附件，或答案文字明確描述已產生圖片結果。
  - 圖片描述或附件 metadata 需符合「小狗」「球」「玩」至少兩類；若有可用圖片辨識，畫面不得出現明顯文字。
  - 不要求作品美醜評分。

### Q3｜咖啡廳爵士樂

- **任務文字**：請使用 Lab Music 生成一段 30 秒音樂。今天要的音樂是適合在咖啡廳聽的爵士樂，聽起來要放鬆、溫暖，適合在咖啡廳看書或聊天時播放。
- **建議工具**：Lab Music。
- **學習單指定提示詞**：

- **答案欄 placeholder**：`請附上音訊，或簡短描述你產生的咖啡廳爵士樂...`
- **審查條件**：
  - 有音訊附件，或答案文字明確描述已產生音樂結果。

  - 不要求音樂品質評分。

## 4. 支援檔案類型

MVP 答案附件需支援多檔案加入，至少包含：

| 類型 | MIME | 用途 |
|------|------|------|
| 圖片 | `image/png`, `image/jpeg`, `image/webp` | Q2 圖片結果 |
| 音訊 | `audio/mpeg`, `audio/wav`, `audio/mp3` | Q3 音樂結果 |
| 影片 | `video/mp4`, `video/webm` | Q4 影片結果 |
| 文件 | `application/pdf`, `text/plain` | 補充結果或老師測試 |

Prototype 階段附件可只保存 metadata 與本機預覽 URL。正式版才需要上傳 Storage。

附件 metadata：

```ts
type AnswerAttachment = {
  id: string;
  name: string;
  kind: 'image' | 'audio' | 'video' | 'file';
  mimeType: string;
  size: number;
  source: 'upload' | 'lab-tool';
  toolId?: 'terminal' | 'image' | 'music' | 'video';
  previewUrl?: string;
  createdAt: string;
};
```

- 學生仍可手動切換其他工具，以測試是否會迷路。
- 若切到非建議工具，介面只提示「目前題目建議使用 X」，不禁止操作。
- `生成/示範` 必須能在沒有正式 API 的情況下產生可回填結果，避免 MVP 測試卡死。

## 6. AI 審查 MVP

### 6.1 審查輸入

每次送審使用目前題目的：

- 題目 ID
- 題目文字
- 建議工具
- 文字答案
- 附件 metadata
- 該題審查條件

### 6.2 審查輸出

```ts
type ReviewResult = {
  passed: boolean;
  score: number;
  feedback: string;
  missing: string[];
  suggestions: string[];
  reviewedAt: string;
};
```

### 6.3 回饋文案規則

- 通過：明確說「這題可以通過」，並指出做對哪一點。
- 未通過：只指出 1-3 個最重要缺漏，例如「還缺圖片附件」或「看不出這是音樂結果」。
- 不評作品美醜，不使用「很爛、失敗」等否定人格語氣。
- 審查失敗不得清空答案。

## 7. 課堂測試流程

老師 MVP 測試時照此流程觀察：

1. 開啟 prototype。
2. 學生先看左側第一題。
3. 右側確認目前題目與建議工具。
4. 按 `生成/示範` 或自行使用對應 Lab 工具。
5. 回填文字或加入附件。
6. 按 `送 AI 審查`。
7. 通過後切到下一題。
8. 四題完成後確認完成數為 4/4。

測試觀察重點：

- 學生是否知道目前正在做第幾題。
- 學生是否能依學習單指示打開指定工具。
- 學生是否能找到並複製每題提示詞。
- 學生是否能從工具結果回到右側答案欄。
- 右側答案欄高度是否足夠，不需要一直捲動。
- 多檔案附件是否容易理解。
- AI 審查退件文字是否能讓學生知道下一步。
- 取消上一題 / 下一題按鈕後，題號切換是否仍清楚。

```js
};
```

- 狀態變更後寫入 `localStorage`。
- 附件在 prototype 可用本機 object URL 或 demo metadata。
- 重整後需保留文字答案、附件 metadata、審查狀態。
- 正式 Firestore / Storage schema 不在本輪規格內。

## 9. 防挫折 vs 反硬 A

### 防挫折

| 情境 | 作法 |
|------|------|
| 題目內容尚未生成 | 使用左側 placeholder 任務卡測試流程 |
| 工具 API 尚未串好 | `生成/示範` 產出 demo 結果 |
| 學生附件放錯題 | 允許刪除後重新加入 |
| AI 審查未通過 | 保留答案，顯示缺漏，允許再送審 |
| 頁面重整 | 從 `localStorage` 還原 |

### 反硬 A

| 手法 | 擋法 |
|------|------|
| 空白送審 | 顯示缺漏，不通過 |
| 任意亂字 | 需符合題目產出類型或關鍵描述 |
| Q1 只寫一句 | 提醒補成 3 點 |
| Q2 沒圖片也沒描述 | 提醒補小狗玩球圖片附件或圖片結果描述 |
| Q3 沒音訊也沒描述 | 提醒補咖啡廳爵士樂音訊附件或音樂結果描述 |
| Q4 沒影片也沒描述 | 提醒補滑雪短影片附件或影片結果描述 |
