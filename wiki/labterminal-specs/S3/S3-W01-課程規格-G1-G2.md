> 來源學習單：[[S3-W01-學習單]]　|　難度版本：G1–G2（小四低文字互動版）　|　生成日期：2026-07-17

## §G 規格治理

- **正典聲明**：本 spec 是 S3-W01 Lab Terminal 實施版的唯一真相；程式、教案、學習單跟著本檔走。若後續改展示台或適配工具內容，先改本檔再改成品。
- **綁定實作檔**：`public/games/s3-w01-tool-map.html`（待建立；成品檔頭需回指本 spec）。
- **MC 移除紀錄**：2026-07-17 起，S3-W01 完全移除 MC / Minecraft 主線定位與文件依賴。原因：本週學習目標是「認識任務與適配工具的對應」，Lab Terminal 虛擬工具地圖已可達成同一目標，且能降低 Minecraft 場景佈建、告示牌維護與人工截圖驗收成本。
- **In Scope（本課教）**：辨認 5 類 AI 工具；知道每個適配工具「叫什麼、怎麼用」；把適配工具與使用情境配對；遇到任務時先判斷「該找哪一類工具」。
- **Out of Scope（不教）**：Minecraft 場地建造、告示牌導覽、截圖打卡、Canva 排版、實際開啟 Suno、實際開啟 VS Code、Copilot Chat 操作、Lab Image/Lab Video 的生成細節。這些屬後續週次。
- **跨週技能地圖**：W01 先建立工具地圖；W02 進入 Lab Video 影片初體驗；W03 進入 Suno 音樂創作；W04 做多工具情境試用；W05 做主力工具宣言。
- **可數單位**：screen（7 個頁面）、展示台（5 類工具）、任務卡（10 張情境卡）、技能磚（5 個）、總複習題（10 題）。
- **互動詞彙表（單一真相）**：
  - 「展示台」＝一個工具類型區塊。
  - 「適配工具」＝最適合某一類任務的工具，不是單純工具名稱列表。
  - 「工具介紹卡」＝遊戲開始前必看的短卡，包含工具叫什麼、怎麼用。
  - 「任務卡」＝一個學生可能遇到的任務情境。
  - 「分流」＝把任務卡放到正確展示台。
  - 「工具徽章」＝完成一類工具理解後得到的圖示徽章。
  - 顏色：文字類紫、圖像類青、影片類藍、音樂類橘、程式類綠。
- **DoD + 參考範例**：成品必須讓學生先看完 5 張工具介紹卡，再進入工具地圖遊戲；介紹卡必須同時回答「叫什麼」與「怎麼用」。成品還需包含 5 個清楚的虛擬展示台、10 張任務卡、完成後的「我的工具地圖」與 250 金幣結算。任一展示台不得只放工具名，必須同時顯示「用在什麼任務」。
- **跨切面需求**：使用 `localStorage` 記錄進度；金幣以 `s3-w01-main-250` 交易 ID idempotent 入帳號錢包；不得儲存學生真名；無網路時仍可完成本地互動，錢包同步失敗則顯示「已完成，待同步」。
- **素材規格**：所有圖示存 `assets/icons/`；統一 flat vector sticker 風格；圖示未載入時退回 CSS 向量圖形與文字標籤。
- **老師端 + 翻轉教育**：老師端需顯示每位學生所在 screen、完成展示台數、是否按下「我可以當小老師」。Done 頁必須有「舉手告訴老師」與「我去幫同學」兩個按鈕。

## §GL 遊戲迴圈與判定

- **遊戲迴圈**：玩家扮演「AI 工具調度員」。每回合讀一張任務卡，判斷它需要哪一類工具，把卡片送到正確展示台。成功後展示台亮起，工具徽章進入自己的工具地圖。
- **本地判定 + distractor**：所有配對、選擇、句子接龍都用本地規則判定；AI 只用 Lab Terminal 角色口吻給回饋，不判定、不當關主。
- **真實應用鐵則**：任務卡從真實任務情境出發，例如「想做背景音樂」「想讓圖片動起來」。選項不得寫成「這題答案是影片類」這種洩題文案。
- **時長靠深度不靠重複**：用 5 類展示台、10 張任務卡、我的工具地圖、10 題總複習建立深度；不靠重複拖同一張卡灌時間。全程保留「我卡住了」救援按鈕，按下後給提示但不直接過關。
- **防硬 A 參數**：每題至少 3 個選項；錯誤選項永久鎖定並顯示刪除線；連錯時提示延遲採 2＋N 秒；拖錯卡片會回彈，不扣金幣；同一題連錯 3 次顯示縮小範圍提示。
- **金幣**：主線合計 250，發放時綁定帳號且不可重複刷。
- **角色設定圖鑑**：固定 AI 角色「小導覽員 Labo」，外觀為圓角終端機小機器人，紫色螢幕臉、青色耳機、手拿任務卡。跨頁一致。
- **虛擬地圖拓撲**：中心為「任務卡堆」，周圍五個展示台呈星形排列。學生以點擊/拖拉探索。
- **UI-UX 底線**：大按鈕、強對比、每則文字提示不超過 25 字；所有長說明拆成短卡或折疊說明；不用 emoji。

## 0. 建置摘要

- **目標**：做一個可在 Lab Terminal 內嵌分頁執行的單檔 HTML 互動課程，移除 S3-W01 原本對 Minecraft AI 工具廣場的依賴。
- **技術**：原生 HTML / CSS / JS；單檔；可用 `localStorage` 記住 screen、金幣、已完成展示台；圖示放 `assets/icons/`。
- **核心訊息（key message）**：先看任務，再選工具。
- **核心訊息出現位置**：start Hook、recall 結語、taskA 每站完成、taskB 分流提示、Rehearsal、summary、done 徽章。
- **防作弊原則**：內容驗證非字數；hint 框 `user-select:none`；輸入框攔 `paste` / `drop`；錯誤選項永久鎖定；拖錯卡片回彈並留下錯誤紀錄。
- **金幣**：主線合計 250。

## 3. Screen 規格

### Screen 0 — start

- **目的**：在正式開始遊戲前，先介紹 5 個適配工具「叫什麼、怎麼用」，再建立遊戲情境與 Hook。
- **顯示文案**：
  - 主標：「任務來了，選對工具！」
  - 短句 1：「先看任務。」
  - 短句 2：「再選工具。」
  - 短句 3：「點亮 5 個展示台。」
- **遊戲前工具介紹卡**：開始按鈕預設 disabled；學生需依序點開 5 張卡，按「我知道怎麼用」後才可開始。

| 類型 | 適配工具叫什麼 | 怎麼用（給學生看的短句） | 本週限制 |
|------|----------------|--------------------------|----------|
| 文字類 | Lab Terminal | 打字問問題，幫你整理想法。 | 本週會用它跑課程與求助 |
| 圖像類 | Lab Image | 說角色或場景，做出圖片。 | 本週只認識，不生成 |
| 影片類 | Lab Video | 讓圖片動起來，做短影片。 | 後續影片週會使用 |
| 音樂類 | Suno | 說主題和感覺，做音樂。 | 本週只認識，不登入 |
| 程式類 | VS Code | 打開程式，之後幫你修改作品。 | 不講 IDE / Copilot 細節 |

- **互動**：點開 5 張工具介紹卡 → 每張按「我知道怎麼用」→ 按「開始調度」。
- **通過條件**：5 張介紹卡都被讀過，且點擊確認。
- **setup()**：顯示 5 張工具介紹卡、5 個未點亮展示台與任務卡堆；若有 `localStorage` 進度，顯示「繼續上次」。

### Screen 1 — recall：起點回顧

- **目的**：W01 沒有上週素材，因此用日常任務建立工具類型印象。
- **互動類型**：G1–G2 拖拉配對。
- **內容**：把 5 張日常任務卡拖到 5 類工具圖示。

| 任務卡 | 正確類型 |
|--------|----------|
| 我卡關了，想問 AI | 文字類 |
| 我想做角色圖 | 圖像類 |
| 我想讓圖片動起來 | 影片類 |
| 我想做主題曲 | 音樂類 |
| 我想改互動作品 | 程式類 |

- **理解題**：
  1. 「遇到任務前，先做什麼？」正解：先看任務。干擾：先背工具名、先亂點、先問老師答案。
  2. 「為什麼要分工具類型？」正解：不同任務適合不同工具。干擾：因為顏色好看、因為越多越厲害、因為每次都用同一個。
- **通過/驗證邏輯**：5 對配對全正確 + 2 題理解題正確。
- **防硬 A**：5 對配對有 120 種排列；錯誤選項永久鎖定。
- **錯誤訊息**：「這張卡不是這一類。想一想它要做文字、圖、影片、音樂，還是程式？」
- **setup()**：洗牌任務卡與展示台位置。

### Screen 2 — taskA：五個工具展示台

- **目的**：認識 5 類工具、適配工具、使用情境。
- **互動類型**：五站式短卡 + 拖拉 + 理解題 + 句子積木。
- **通過/驗證邏輯**：每站完成 4 步才點亮展示台：
  1. 讀短卡（每張短句 ≤25 字）
  2. 把適配工具拖到正確展示台
  3. 完成 2 題理解題
  4. 用句子積木組出白話求助句
- **完成後**：進入 Rehearsal Modal A。

| 展示台 | 適配工具 | 短卡文案 | 理解題焦點 | 句子積木正解 | goal | 預覽變化 |
|--------|----------|----------|------------|--------------|------|----------|
| 文字類 | Lab Terminal | 「卡關時，先問文字 AI。」 | 文字 AI 用於問問題、整理想法 | 我卡關了，請先問我想做什麼。 | 能表達求助與整理想法 | 紫色展示台亮起 |
| 圖像類 | Lab Image | 「想要圖，找圖像工具。」 | 圖像工具做角色、場景、插圖 | 我想做角色和場景圖。 | 能表達要做圖片素材 | 青色展示台亮起 |
| 影片類 | Lab Video | 「圖片要動，找影片工具。」 | 影片工具做短片、動態畫面 | 我想讓圖片動起來。 | 能表達圖片轉影片 | 藍色展示台亮起 |
| 音樂類 | Suno | 「主題曲，找音樂工具。」 | 音樂工具做 BGM、主題曲 | 我想做背景音樂。 | 能表達音樂需求 | 橘色展示台亮起 |
| 程式類 | VS Code | 「要改程式，找程式工具。」 | VS Code 作為程式類工具入口 | 我想理解或修改程式。 | 能表達程式任務 | 綠色展示台亮起 |

- **程式類說明限制**：只把 VS Code 定位為「程式類 AI 工具入口」，不向學生解釋 IDE、Copilot Chat、擴充套件細節。
- **Suno 說明限制**：本週只認識情境，不要求登入或實際生成音樂。
- **防硬 A**：
  - 拖錯適配工具回彈。
  - 理解題答錯永久鎖定。
  - 句子積木必須含對應任務語意，例如圖像類需含「圖、角色、場景、插圖」之一。
- **setup()**：依序開放 5 站；可允許學生自由選站，但完成紀錄需獨立保存。

### Screen 3 — taskB：任務卡分流

- **目的**：把「工具名稱」轉成「看到任務會選工具」。
- **互動類型**：10 張任務卡分流 + 我的工具地圖。
- **內容/題目**：學生把任務卡送到正確展示台。

| 任務卡 | 正確展示台 | 可接受適配工具 |
|--------|------------|----------------|
| 我不知道這個任務要用什麼工具 | 文字類 | Lab Terminal |
| 我想把我的想法整理成清單 | 文字類 | Lab Terminal |
| 我想做冒險故事主角圖 | 圖像類 | Lab Image |
| 我想做城堡場景插圖 | 圖像類 | Lab Image |
| 我想讓角色圖片動起來 | 影片類 | Lab Video |
| 我想做作品開場短影片 | 影片類 | Lab Video |
| 我想做遊戲背景音樂 | 音樂類 | Suno |
| 我想做一首主題曲 | 音樂類 | Suno |
| 我想看懂一段程式 | 程式類 | VS Code |
| 我想修改互動作品按鈕 | 程式類 | VS Code |

- **主觀選擇掛勾客觀驗證**：完成 10 張分流後，學生選一張「我最想做的任務卡」，再必須選出正確工具類型與適配工具；兩者正確才可存入「我的工具地圖」。
- **通過/驗證邏輯**：10 張任務卡分流正確 + 個人任務卡的類型/工具正確。
- **防硬 A**：每張卡至少 5 個投放區；拖錯回彈並記錄；同卡錯 2 次給提示「看它要做文字、圖、影片、音樂，還是程式」。
- **完成後**：進入 Rehearsal Modal B。
- **setup()**：任務卡洗牌；展示台位置可固定，降低小四工作記憶負擔。

### Screen 4 — summary：總複習考試

- **目的**：確認學生能將工具類型、適配工具與任務情境配對。
- **互動類型**：10 題選擇題；答完顯示成績 X/10、錯題正解與一句說明。
- **題庫**：
  1. 「想問 AI 幫我整理想法，找哪一類？」正解：文字類。
  2. 「Lab Image 最適合做什麼？」正解：角色、場景、插圖。
  3. 「想讓圖片動起來，找哪個工具？」正解：Lab Video。
  4. 「想做背景音樂，找哪個工具？」正解：Suno。
  5. 「VS Code 這週先當成哪一類？」正解：程式類。
  6. 「先看任務，再做什麼？」正解：選工具。
  7. 「Canva 本週是不是 AI 工具展示台？」正解：不是，本週不列入。
  8. 「我想修改互動作品按鈕，應找哪一類？」正解：程式類。
  9. 「我想做作品開場短影片，應找哪一類？」正解：影片類。
  10. 「忘記工具用途時，先去哪裡求助？」正解：Lab Terminal。
- **干擾項原則**：干擾項使用相近但錯的工具，例如把 Lab Image 放進影片題，或把 Suno 放進圖像題。
- **通過條件**：答完 10 題即可前進；錯題需顯示正解。低於 7/10 顯示「再看一次工具地圖」按鈕，但不卡死。
- **setup()**：選項洗牌；錯誤選項鎖定。

### Screen 5 — wall：技能牆

- **目的**：把本課技能轉成可見成就。
- **互動類型**：G1–G2 浮動磚塊點擊飛入。
- **技能磚**：
  - 我會先看任務
  - 我認得文字類
  - 我認得圖像類
  - 我認得影片類
  - 我認得音樂類
  - 我認得程式類
  - 我會選適配工具
- **通過條件**：點擊全部技能磚，飛入工具地圖。
- **setup()**：已解鎖的技能磚從工具地圖中發光；未點擊磚塊浮動。

### Screen 6 — done

- **目的**：兌現 Hook，完成金幣結算與翻轉教育。
- **顯示**：
  - 標題：「你完成工具地圖了！」
  - 徽章：「工具調度員」
  - 成果：「5 個展示台已點亮」
  - 金幣：「本週主線 250」
- **金幣結算**：觸發 `awardCoins('s3-w01-main-250', 250)`；若已發過，顯示「已領過，本次不重複入帳」。
- **翻轉教育按鈕**：
  - 「舉手告訴老師」
  - 「我可以當小老師」
- **小老師提示**：「去問同學：你現在要找哪一類工具？不要直接幫他點。」
- **setup()**：播放展示台全亮動畫；若錢包同步失敗，保留本地完成紀錄。

## 4. Rehearsal Modal 規格

> 句子接龍，必須答對才能關閉，呼應 key message。

**Modal A（taskA 後）**

- 題幹：「看到任務時，我要先看 ____，再選 ____。」
- 正解：任務／工具。
- 反例：
  1. 先看顏色，再亂點。
  2. 先背工具名，再做任務。
  3. 每次都用同一個工具。
  4. 不看任務，直接問老師答案。

- 反例：
  1. 做圖找 Suno。
  2. 做影片找 VS Code。
  3. 做音樂找 Lab Image。
  4. 所有任務都找 Canva。

## 5b. 防挫折 vs 反硬 A

**防挫折（全域不變式）**

| 情境 | 作法 |
|------|------|
| 拖錯卡片 | 卡片回彈，不扣分，不播失敗音 |
| 連錯 2 次 | 給縮小範圍提示 |
| 連錯 3 次 | 顯示「再看一次展示台」按鈕 |
| 閱讀負荷 | 每則提示 ≤25 字，長說明拆短卡 |
| 網路或錢包失敗 | 本地完成照常顯示，金幣標記待同步 |

**反硬 A（防亂點）**

| 手法 | 擋法 |
|------|------|
| 亂點選項 | 選項洗牌 + 錯誤永久鎖定 |
| 亂拖卡片 | 拖錯回彈，錯誤紀錄不清除 |
| 複製提示 | hint 區 `user-select:none` |
| 貼上答案 | 所有輸入框攔 `paste` / `drop` |
| 靠單一選項猜 | 每題至少 3 選項，拖拉區 5 類 |

## 6b. 老師端 + 翻轉教育

- **老師端資料**：
  - 學生目前 screen
  - 已點亮展示台數
  - 已完成任務卡數
  - 總複習分數
  - 是否按下「舉手告訴老師」
  - 是否按下「我可以當小老師」
- **老師端操作**：
  - 可標記「已驗收」
  - 可標記「派任小老師」
  - 可查看學生錯最多的工具類型
- **翻轉教育流程**：
  1. 學生完成 done 頁。
  2. 按「我可以當小老師」。
  3. 老師派他協助一位同學。
  4. 小老師只能問：「這張任務卡要做什麼？」與「它像文字、圖、影片、音樂，還是程式？」
  5. 不可代點、不可直接告知答案。
