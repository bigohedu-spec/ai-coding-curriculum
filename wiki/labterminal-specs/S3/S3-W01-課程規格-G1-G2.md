## §G 規格治理

- **正典聲明**：本 spec 是 S3-W01 Lab Terminal 實施版的唯一真相；程式、教案、學習單跟著本檔走。若後續改任務類型、輕量工具 API、prompt 審查規則或金幣，先改本檔再改成品。
- **綁定實作檔**：`public/games/s3-w01-tool-map.html`（待建立；成品檔頭需回指本 spec）。
- **MC 移除紀錄**：2026-07-17 起，S3-W01 完全移除 MC / Minecraft 主線定位與文件依賴。原因：本週學習目標是「先看任務是什麼，再用對的工具」，Lab Terminal 內建互動頁已可達成同一目標，且能降低 Minecraft 場景佈建、告示牌維護與人工截圖驗收成本。
- **2026-07-20 教材邏輯修正**：本版由「看展示台認識工具」改為「先試用四個輕量 Lab 工具，再處理分發任務」。任務循環固定為：拿到任務 → 選擇工具 → 根據需求下提示詞 → 看結果 → 下一個任務。學生不只知道工具名稱，還要通過具體任務與 prompt 關鍵字審查，確認自己真的讀懂任務。
- **任務類型更改**：S3-W01 只保留四類任務：文字類、圖片類、影片類、音樂類。程式類 / VS Code 從本週移除；VS Code 仍屬後續課程內容，不在本週提前練習。
- **In Scope（本課教）**：辨認四類任務；知道四個 Lab 工具「叫什麼、怎麼用」；先用預設提示詞試用四個工具；四個工具都試用後，才進入分發任務循環；送出前通過 prompt 審查。
- **Out of Scope（不教）**：Minecraft 場地建造、告示牌導覽、截圖打卡、VS Code / Copilot Chat 操作、外部 API 帳號、API 金鑰、Lab Image/Lab Video/Lab Music 的真實生成參數細節。這些屬後續週次或工程端。
- **跨週技能地圖**：W01 建立四類工具與 prompt 審查直覺；W02 進入圖片轉影片與 Lab Video；W03 進入音樂任務與 Lab Music；W04 做多工具組合；W05 做主力工具宣言。
- **可數單位**：screen（7 個頁面）、Lab 工具站（4 類）、工具介紹卡（4 張）、工具試用回合（4 回）、分發任務卡（8 張）、prompt 審查（每次送出前 1 次）、技能磚（6 個）、總複習題（8 題）。
- **互動詞彙表（單一真相）**：
  - 「任務卡」＝一個學生可能遇到的任務情境。
  - 「任務類型」＝文字類 / 圖片類 / 影片類 / 音樂類。
  - 「適配工具」＝最適合某一類任務的 Lab 工具，不是外部服務名稱背誦。
  - 「輕量 Lab 工具」＝Lab Terminal 內的簡化工具入口：Lab Terminal（文字類）/ Lab Image / Lab Video / Lab Music。
  - 「預設提示詞」＝學生可點選的 prompt 起手式，用來降低空白輸入難度。
  - 「Prompt 審查」＝送出前檢查 prompt 是否包含任務要求的用途、輸出、關鍵元素；它是「看結果」前的門檻，不是任務循環中的額外主步驟。
  - 「結果」＝學生完成 prompt 審查後看到的預覽示意；若 API 尚未接上，使用 mock preview。
  - 顏色：文字類紫、圖片類青、影片類藍、音樂類橘。
- **DoD + 參考範例**：成品必須讓學生先完成 4 個工具試用循環：理解使用情境 → 使用預設提示詞嘗試 → prompt 審查通過 → 看結果。四個工具都試過後才分發任務卡。任務卡循環必須固定為「拿到任務 → 選擇工具 → 根據需求下提示詞 → 看結果 → 下一個任務」。任務卡必須具體，例如「收到任務了！現在要製作 30 秒音樂，用在抽卡動畫配音」。
- **跨切面需求**：使用 `localStorage` 記錄進度；金幣以 `s3-w01-main-250` 交易 ID idempotent 入帳號錢包；不得儲存學生真名；API 金鑰一律在伺服器端，不得寫入單檔 HTML；無網路或 API 失敗時仍可完成本地 prompt 審查與 mock preview，錢包同步失敗則顯示「已完成，待同步」。
- **素材規格**：所有圖示存 `assets/icons/`；統一 flat vector sticker 風格；圖示未載入時退回 CSS 向量圖形與文字標籤。
- **老師端 + 翻轉教育**：老師端需顯示每位學生所在 screen、完成任務卡數、錯最多的任務類型、是否按下「我可以當小老師」。Done 頁必須有「舉手告訴老師」與「我去幫同學」兩個按鈕。

## §GL 遊戲迴圈與判定

- **遊戲迴圈**：玩家扮演「AI 工具調度員」。前半段逐一理解並試用 4 個 Lab 工具；後半段才收到任務卡。每張任務卡都固定走「拿到任務 → 選擇工具 → 根據需求下提示詞 → 看結果 → 下一個任務」，通過後取得徽章碎片與金幣。Prompt 審查放在「看結果」前作為送出門檻。
- **本地判定 + distractor**：工具選擇、prompt 審查、選擇題、句子接龍都用本地規則判定；AI / API 只生成或回饋，不判定、不當關主。
- **真實應用鐵則**：任務卡從客觀任務需求出發，例如「製作 30 秒音樂，用在抽卡動畫配音」。選項不得寫成「這題答案是音樂類」這種洩題文案。
- **時長靠深度不靠灌水**：本課的 repetition 是「同一判斷流程在不同具體任務中重複」，不是重複同一題。8 張任務卡的用途、輸出、關鍵元素都不同，讓學生建立選工具與寫 prompt 的直覺。
- **救援與跳關**：全程有「我卡住了」按鈕。前兩次給縮小範圍提示；第三次播放同類範例 autoDemo。學生不能靠 autoDemo 自動得分，老師端可放行並記錄 assist。
- **防硬 A 參數**：每題至少 3 個選項；錯誤選項永久鎖定並顯示刪除線；連錯時提示延遲採 2＋N 秒；拖錯卡片會回彈，不扣金幣；同一任務連錯 3 次顯示同類範例。
- **金幣**：主線合計 250，發放時綁定帳號且不可重複刷。
- **角色設定圖鑑**：固定 AI 角色「小導覽員 Labo」，外觀為圓角終端機小機器人，紫色螢幕臉、青色耳機、手拿任務卡。跨頁一致。
- **虛擬地圖拓撲**：中心為「任務卡堆」，周圍四個 Lab 工具站呈十字排列。學生以點擊、拖拉、提示詞積木與送出前審查探索。
- **UI-UX 底線**：大按鈕、強對比、每則文字提示不超過 25 字；所有長說明拆成短卡或折疊說明；不用 emoji。

## 0. 建置摘要

- **目標**：做一個可在 Lab Terminal 內嵌分頁執行的單檔 HTML 互動課程，讓學生先試用四個輕量 Lab 工具，再用固定任務循環處理具體任務。
- **技術**：原生 HTML / CSS / JS；單檔前端；可用 `localStorage` 記住 screen、金幣、已完成任務卡；圖示放 `assets/icons/`；工具生成走後端 API adapter，前端不得放 API key；API 未就緒時使用 mock preview。
- **核心訊息（key message）**：先看任務是什麼，再用對的工具。
- **核心訊息出現位置**：start Hook、recall 結語、taskA 每站完成、taskB 任務卡提示、Rehearsal、summary、done 徽章。
- **防作弊原則**：內容驗證非字數；prompt 審查必須檢查任務用途、輸出、關鍵元素；hint 框 `user-select:none`；輸入框攔 `paste` / `drop`；錯誤選項永久鎖定；prompt 不完整時明確指出缺什麼。
- **金幣**：主線合計 250。

### 3.5 Prompt 審查機制

```js
function validateTool(card, selectedTool) {
  return card.correctTool === selectedTool;
}

function validatePrompt(card, promptText) {
  const normalized = normalizePrompt(promptText);
  const missing = card.requiredKeywords.filter(keyword => !normalized.includes(keyword));
  const vagueOnly = /^(幫我做|做一個|好看一點|隨便|aaaa|1234)+$/i.test(normalized.replace(/\s/g, ''));
  return {
    pass: missing.length === 0 && !vagueOnly,
    missing,
    vagueOnly
  };
}
```

錯誤訊息：

- 工具錯誤：「先看任務是什麼。這張任務不適合用這個工具。」
- Prompt 缺漏：「還沒提到：{missing.join('、')}。」
- Prompt 太空泛：「這句太像亂下指令。請補上任務裡的用途、輸出和關鍵內容。」
- 連錯提示：「先找任務要求裡的名詞和數字，例如 30 秒、抽卡動畫、寶箱。」

## 4. Screen 規格

### Screen 0 — start：工具介紹與 Hook

- **目的**：遊戲開始前先介紹四類 Lab 工具「叫什麼、怎麼用」，並建立核心口訣。
- **顯示文案**：任務來了，先看任務！
- **畫面**：中央 8 張鎖住的任務卡；周圍 4 個未亮 Lab 工具站；小導覽員 Labo 提示：「先看任務是什麼，再用對的工具。」
- **工具介紹卡**：4 張，依序顯示文字類、圖片類、影片類、音樂類。每張都含 `任務類型`、`工具叫什麼`、`適合什麼任務`、`會檢查哪些 prompt 關鍵字`。
- **互動**：學生點開 4 張卡，逐張按「我知道怎麼用」。4 張都確認後，「開始工具試用」按鈕才解鎖。
- **通過條件**：`introSeen = ['text','image','video','music']` 全部為 true。
- **防硬 A**：開始按鈕 disabled；亂點不能進入下一頁。
- **setup()**：載入進度；若已完成 intro，顯示「繼續上次」。

### Screen 1 — recall：四類任務快速回顧

- **目的**：確認學生能先看任務要求，再判斷任務要產出什麼。
- **互動類型**：G1–G2 拖拉配對 + 2 題選擇。
- **拖拉卡片**：

| 任務 | 正確類型 |
|------|----------|
| 整理三點想法 | 文字類 |
| 做角色圖片 | 圖片類 |
| 讓圖片動起來 | 影片類 |
| 做背景音樂 | 音樂類 |

- **理解題**：
  1. 「看到任務卡第一步做什麼？」正解：先看任務是什麼。
  2. 「任務要求『30 秒音樂』時，要找哪個工具？」正解：Lab Music。
- **通過條件**：4 張拖拉全正確 + 2 題答對。
- **錯誤訊息**：「這張卡要做出的東西不是這一類，再看一次任務。」
- **setup()**：任務卡與類型區洗牌；錯誤拖拉回彈。

### Screen 2 — taskA：四類工具試用

- **目的**：讓學生逐一理解每個工具的使用情境，再用預設提示詞試用。
- **互動類型**：四站工具試用。每站固定流程：理解工具使用情境 → 試用預設提示詞 → prompt 審查 → 看結果 → 下一個工具。四站全完成後才進入任務卡。
- **站設計表**：

| 站 | 工具 | 試用任務 | 理解題焦點 | prompt 審查 | 結果變化 | 金幣 |
|----|------|----------|------------|-------------|----------|------|
| 文字類 | Lab Terminal | 把抽卡活動規則整理成 3 點提示 | 文字工具處理整理、改寫、提示 | 必含：抽卡活動規則、3 點提示、新同學 | 右側長出三點文字卡 | 20 |
| 圖片類 | Lab Image | 製作金色寶箱圖片 | 圖片工具處理主體、用途、風格 | 必含：金色寶箱、抽卡按鈕、圖片 | 右側長出圖片示意卡 | 20 |
| 影片類 | Lab Video | 製作寶箱打開冒光 5 秒影片 | 影片工具處理素材、動作、秒數 | 必含：5 秒、寶箱打開冒光、抽卡動畫 | 右側長出短影片時間軸 | 20 |
| 音樂類 | Lab Music | 製作抽卡動畫配音 30 秒音樂 | 音樂工具處理長度、用途、情緒 | 必含：30 秒、抽卡動畫配音、期待感 | 右側長出音波預覽 | 20 |

- **通過條件**：每站 2 題理解題答對，prompt 審查通過，並看過結果。
- **防硬 A**：理解題錯誤選項永久鎖定；prompt 若缺漏，顯示缺漏項，不可直接下一站；generate 按鈕在審查通過前 disabled。
- **完成後**：觸發 Rehearsal Modal A。
- **setup()**：每站載入 `TOOL_TRIALS`；結果區預設為灰色輪廓，prompt 審查通過後亮起。

### Screen 3 — taskB：分發任務與工具使用

- **目的**：所有工具都試用後，再分發具體任務，要求學生用固定任務循環完成每張卡。
- **互動類型**：8 張任務卡。每張都走同一流程：
  1. 拿到任務。
  2. 選擇 Lab Terminal / Lab Image / Lab Video / Lab Music。
  3. 根據需求下提示詞。
  4. 看結果。
  5. 下一個任務。
- **Prompt 審查位置**：系統在第 3 步後執行 `validatePrompt()`；審查通過才允許第 4 步看結果。學生端主流程仍顯示五步循環，不把審查拆成第六步。
- **內容**：使用 §3.4 的 8 張分發任務卡。
- **通過條件**：每張卡必須先 `validateTool()` 通過，再 `validatePrompt()` 通過，最後看過結果才算完成。
- **主觀選擇掛勾客觀驗證**：完成 8 張後，學生可選「我最想先試哪一個工具」。選完後必須再完成一張同工具 mini card，避免隨便選。
- **防硬 A**：每張卡工具選錯會回彈；prompt 缺漏會列出缺少關鍵字；同一卡錯 3 次啟動同類 autoDemo。
- **完成後**：觸發 Rehearsal Modal B。
- **setup()**：任務卡每次洗牌；已完成卡片放入「完成堆」並顯示工具色條、結果縮圖與 prompt 審查通過章。

### Screen 4 — summary：總複習考試

- **目的**：確認學生不是背名字，而是知道任務與介面的對應。
- **互動類型**：8 題選擇題；答完顯示成績 X/8、錯題正解與一句說明。
- **題庫**：

| 題目 | 選項 | 正解 |
|------|------|------|
| 想整理故事想法，進哪一類？ | 文字類 / 圖片類 / 影片類 / 音樂類 | 文字類 |
| 想做角色圖，進哪一類？ | 文字類 / 圖片類 / 影片類 / 音樂類 | 圖片類 |
| 想讓圖片動起來，進哪一類？ | 文字類 / 圖片類 / 影片類 / 音樂類 | 影片類 |
| 想做背景音樂，進哪一類？ | 文字類 / 圖片類 / 影片類 / 音樂類 | 音樂類 |
| Lab Image 的工具會要求什麼？ | 主體、用途、風格 / 主題、感覺、曲風 / 素材、動作、秒數 | 主體、用途、風格 |
| Lab Video 的工具會要求什麼？ | 素材、動作、秒數、用途 / 主題、感覺、曲風 / 問題、答案、提示 | 素材、動作、秒數、用途 |
| Lab Music 的工具會要求什麼？ | 長度、使用情境、情緒、風格 / 主體、場景、風格 / 素材、動作、秒數 | 長度、使用情境、情緒、風格 |
| 這堂課的核心口訣是什麼？ | 先看任務是什麼，再用對的工具 / 亂點→猜答案→重試→跳過 / 背名稱→開程式→截圖→交作業 | 先看任務是什麼，再用對的工具 |

- **通過條件**：答完 8 題即可前進；錯題需顯示正解。低於 6/8 顯示「再看一次四類介面」按鈕，但不卡死。
- **setup()**：選項洗牌；錯誤選項鎖定。

### Screen 5 — wall：技能牆

- **目的**：把本課技能轉成可見成就。
- **互動類型**：G1–G2 浮動磚塊點擊飛入。
- **技能磚**：
  - 我會先看任務是什麼

- **setup()**：已解鎖的技能磚從工具地圖中發光；未點擊磚塊浮動。

## 5. Rehearsal Modal 規格

> 句子接龍，必須答對才能關閉，呼應 key message。

**Modal A（taskA 後）**

- 題幹：「看到任務時，我要先看任務是什麼，再用對的 ____。」
- 正解：工具。
- 反例：
  1. 先看顏色，再亂點。
  2. 先背工具名，再做任務。
  3. 每次都用同一個介面。
  4. 不看任務，直接問老師答案。

**Modal B（taskB 後）**

- 題幹：「每張任務卡都要：拿到 ____ → 選擇 ____ → 根據需求下 ____ → 看 ____ → 下一個 ____。」
- 正解：任務／工具／提示詞／結果／任務。
- 反例:
  1. 看顏色 → 亂拖 → 重試 → 跳過。
  2. 背名稱 → 開程式 → 截圖 → 交差。
  3. 問老師 → 等答案 → 點答案 → 下一題。
  4. 選喜歡的 → 不看結果 → 直接完成。

## 7. 防挫折 vs 反硬 A

**防挫折（全域不變式）**

| 情境 | 作法 |
|------|------|
| 類型選錯 | 回彈，不扣分，不播失敗音 |
| 欄位選錯 | 顯示「還缺什麼」，允許重選 |
| 連錯 2 次 | 給縮小範圍提示 |
| 連錯 3 次 | 顯示同類 autoDemo |
| 閱讀負荷 | 每則提示 ≤25 字，長說明拆短卡 |
| 網路或錢包失敗 | 本地完成照常顯示，金幣標記待同步 |

**反硬 A（防亂點）**

| 手法 | 擋法 |
|------|------|
| 亂點選項 | 選項洗牌 + 錯誤永久鎖定 |
| 亂拖卡片 | 拖錯回彈，錯誤紀錄不清除 |
| 亂選欄位 | 必須通過 `requiredSelections` |
| 複製提示 | hint 區 `user-select:none` |
| 貼上答案 | 所有輸入框攔 `paste` / `drop` |
| 靠單一選項猜 | 每題至少 3 選項，任務類型 4 類 |

## 9. 老師端 + 翻轉教育

- **老師端資料**：
  - 學生目前 screen
  - 已完成任務卡數
  - prompt 審查通過數
  - 四類任務各錯幾次

  - 可標記「已驗收」
  - 可標記「派任小老師」
  - 可對個別學生按「同類範例提示」
- **翻轉教育流程**：
  1. 學生完成 done 頁。
  2. 按「我可以當小老師」。
