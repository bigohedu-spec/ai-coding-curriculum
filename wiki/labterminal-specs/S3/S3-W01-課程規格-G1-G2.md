## §G 規格治理

- **正典聲明**：本 spec 是 S3-W01 GAMMA答題版 MVP 的唯一真相；本輪目標是驗證教學流程，不驗證後台建置流程。程式、prototype 與測試觀察若偏離此方向，先回填本檔再調整實作。
- **綁定實作檔**：
  - `C:\Users\COSH\Desktop\CodingClass\gpt-clone\public\courses\gamma-mixed-worksheet-demo.html`
  - `C:\Users\COSH\Desktop\CodingClass\ai-coding-curriculum\wiki\worksheets\S3\S3-W01-學習單.md`
- **In Scope**：左側 Gamma / Gamma placeholder 題目呈現、右側 Lab Terminal 答題欄、四題任務切換、建議工具顯示、Lab Terminal / Lab Image / Lab Music / Lab Video 工具切換、生成 / 示範結果、文字回填、多檔案附件回填、AI 審查回饋、完成進度顯示、學生操作動線測試。
- **Out of Scope**：JSON 題庫 schema、Gamma URL 自動注入、學習單入口後台建置、Firebase Storage / Firestore 正式儲存、正式 API 金鑰與額度管理、正式錢包入帳、長期作品歸檔、老師端批次檢視。這些留到教學流程通過 MVP 測試後再開新規格。
- **跨週技能地圖**：W01 只教「先看任務，再用對工具」與第一次生成回填；W02 再做任務線索判斷；W03 再做半開放提示詞；W04 再做混合任務反應；W09 以後才做正式 AI 評審與退件修正模組。
- **可數單位**：頁面 = 1；左右主要區塊 = 2；題目 = 4；Lab 工具 = 4；每題答案 = 文字欄 1 個 + 附件 0..N；AI 審查結果 = 每題 1 筆。
- **互動詞彙表**：
  - `Gamma 任務`：左側題目內容或 placeholder 卡片。
  - `Lab 工具`：右側可切換的 Terminal / Image / Music / Video。
  - `生成/示範`：呼叫工具或使用 prototype fallback 產出測試結果。
  - `回填`：把文字貼入答案欄，或把圖片、音訊、影片、檔案加入附件。
  - `送 AI 審查`：檢查目前答案是否符合本題任務與產出類型。
- **DoD**：一位小四學生能在同一頁完成四題：讀左側任務、知道要用哪個工具、產生或使用示範結果、回填到右側、送審並看懂通過或缺漏原因。
- **跨切面需求**：MVP 使用 `localStorage` 續填；正式登入儲存、檔案上傳與錢包入帳不在本輪。MVP 不得要求學生登入外部 AI 服務。

## §GL 教學迴圈與判定

- **教學迴圈**：學生每題都走同一條路徑：看左側 Gamma 任務 → 看右側目前題目與建議工具 → 切到合適 Lab 工具 → 生成或使用示範結果 → 回填文字或附件 → 送 AI 審查 → 進入下一題。
- **MVP 判定定位**：AI 審查在 prototype 階段可使用本地規則模擬，不要求正式後端。判定重點是「產出類型正確、不是空白、內容與題目相關」。
- **AI 不當關主**：MVP 的 AI 回饋只做教學提示；不負責正式發金幣、不刪學生答案、不阻止老師人工判斷。
- **防挫折**：
  - 工具 API 失敗時，提供 `生成/示範` fallback。
  - 審查不通過時保留原答案與附件。
  - 學生可重新生成、補附件、再送審。
  - 不使用刺眼紅色作為主要狀態；錯誤用文字說明缺什麼。
- **反硬 A**：
  - 空白文字不可通過。
  - Q1 必須像 3 點提醒。
  - Q2 至少要有圖片附件或明確圖片生成描述。
  - Q3 至少要有音訊附件或明確音樂生成描述。
  - Q4 至少要有影片附件或明確影片生成描述。

- **目標**：製作可開給學生測試的 S3-W01 GAMMA答題版 MVP，驗證「任務閱讀、工具選擇、生成結果回填、AI 審查」是否順暢。

- **本輪不處理**：不要在本 spec 內要求 JSON 題庫、URL 自動建置、學習單入口後台流程或正式資料庫串接。

- **完成感**：四題全部完成後顯示 4/4 完成與 250 金幣概念；MVP 不做正式錢包入帳。

## 2. MVP 畫面規格

### 2.1 整體版面

- 頁面採左右雙欄。
- 左側約 70%，顯示 Gamma 內容或模擬 Gamma 題目。
- 右側約 30%，顯示 Lab Terminal 答題欄。
- 頁面本身不應因左側內容滾動而整頁一起滾動；左側與右側各自控制可用空間。
- 上方 title label 必須壓低高度，讓答案欄有更多垂直空間。
- 右側答案欄需盡量吃滿可用高度，不再依賴內部小捲軸。
- 因題目已有標示，不需要上一題 / 下一題按鈕。

### 2.2 左側 Gamma 區

- Gamma 正式內容尚未完成時，必須能用 placeholder 題目卡測試流程。
- 左側每張任務卡可點擊，點擊後右側同步切到對應題目。
- 左側只負責任務閱讀，不放答案輸入欄。
- 若未來正式 Gamma iframe 無法嵌入，本 MVP 仍可用抽出的題目卡繼續測試教學流程。

### 2.3 右側 Lab Terminal 答題欄

右側固定包含：

1. 目前題目狀態：第幾題、完成數。
2. 題目切換標示：1 / 2 / 3 / 4。
3. 題目摘要：任務名稱、建議工具、審查金幣概念。
4. 文字答案欄：可直接填入生成結果或說明。
5. 附件區：可加入多個檔案，顯示檔名、類型、來源。
6. 工具切換列：Terminal / Image / Music / Video。
7. 操作按鈕：AI 提示、生成/示範、送 AI 審查。
8. AI 回饋區：顯示通過、缺漏、建議。
9. 儲存草稿狀態。

### 2.4 顏色規範

- 金幣 badge 不使用鮮黃底，避免與學生圈選色或作答標記衝突。
- 金幣 badge 使用中性深底、淺色文字、細框即可。
- 目前題目 active 狀態可用青綠色，但不可把整個答案內容區染成同色。
- 錯誤、缺漏、警告不可只靠顏色辨識，必須有文字。

## 3. 四題任務規格

| 題號 | 任務 | 建議工具 | 期待產出 | 回填方式 | 通過重點 |
|------|------|----------|----------|----------|----------|
| Q1 | AI 工具使用提醒 | Lab Terminal | 3 點文字提醒 | 貼上文字 | 有 3 點、短、清楚、與 AI 工具使用相關 |
| Q2 | 班級公告封面圖 | Lab Image | 圖片 | 上傳或回填圖片結果 | 有圖片結果，符合藍白、科技感、乾淨清楚 |
| Q3 | 作品展示開場音樂 | Lab Music | 約 30 秒音樂 | 上傳或回填音訊結果 | 有音訊結果，明亮、有節奏、不恐怖 |
| Q4 | 簡報開場動態畫面 | Lab Video | 約 5 秒影片 | 上傳或回填影片結果 | 有影片結果，畫面有動、發光或放大 |

### Q1｜AI 工具使用提醒

- **任務文字**：老師要在上課前提醒大家怎麼正確使用 AI 工具。請把內容整理成 3 點提醒，讓同學快速看懂。
- **建議工具**：Lab Terminal。
- **生成提示方向**：把長段文字整理成 3 點，語氣適合同學上課前閱讀。
- **答案欄 placeholder**：`請貼上你整理出的 3 點提醒...`
- **審查條件**：
  - 至少 3 行或 3 個清楚分點。
  - 提到任務、提示詞、檢查結果或修改其中至少一類。
  - 不可只貼無關文字。

### Q2｜班級公告封面圖

- **任務文字**：老師要發一篇班級公告，主題是「本週開始使用 AI 工具」。請產生一張 AI 工具介紹封面圖。
- **建議工具**：Lab Image。
- **生成提示方向**：藍白色、科技感、乾淨清楚、適合公告或學習單開頭。
- **答案欄 placeholder**：`請附上圖片，或簡短描述你產生的封面圖...`
- **審查條件**：
  - 有圖片附件，或答案文字明確描述已產生圖片結果。
  - 圖片描述需包含 AI 工具、封面、科技感、藍白或公告用途之一。
  - 不要求作品美醜評分。

### Q3｜作品展示開場音樂

- **任務文字**：班上要展示今天做出的作品。請產生一段 30 秒開場音樂，用在作品展示開始前。
- **建議工具**：Lab Music。
- **生成提示方向**：約 30 秒、明亮、有節奏、不恐怖、不太吵。
- **答案欄 placeholder**：`請附上音訊，或簡短描述你產生的開場音樂...`
- **審查條件**：
  - 有音訊附件，或答案文字明確描述已產生音樂結果。
  - 描述需包含開場、音樂、明亮、節奏或 30 秒之一。
  - 不要求音樂品質評分。

### Q4｜簡報開場動態畫面

- **任務文字**：老師要在簡報開始時放一段短動畫。請產生一段 5 秒動態畫面，讓 AI 工具圖示發光、放大，看起來像簡報正在開始。
- **建議工具**：Lab Video。
- **生成提示方向**：約 5 秒、畫面有動、AI 工具圖示發光或放大、像簡報開場。
- **答案欄 placeholder**：`請附上影片，或簡短描述你產生的開場動畫...`
- **審查條件**：
  - 有影片附件，或答案文字明確描述已產生影片結果。
  - 描述需包含動畫、影片、發光、放大、簡報開場或 5 秒之一。
  - 不要求影片美術品質評分。

## 4. 支援檔案類型

MVP 答案附件需支援多檔案加入，至少包含：

| 類型 | MIME | 用途 |
|------|------|------|
| 圖片 | `image/png`, `image/jpeg`, `image/webp` | Q2 圖片結果 |
| 音訊 | `audio/mpeg`, `audio/wav`, `audio/mp3` | Q3 音樂結果 |
| 影片 | `video/mp4`, `video/webm` | Q4 影片結果 |
| 文件 | `application/pdf`, `text/plain` | 補充結果或老師測試 |

Prototype 階段附件可只保存 metadata 與本機預覽 URL。正式版才需要上傳 Storage。

附件 metadata：

```ts
type AnswerAttachment = {
  id: string;
  name: string;
  kind: 'image' | 'audio' | 'video' | 'file';
  mimeType: string;
  size: number;
  source: 'upload' | 'lab-tool';
  toolId?: 'terminal' | 'image' | 'music' | 'video';
  previewUrl?: string;
  createdAt: string;
};
```

## 5. 工具切換與生成/示範

| 工具 | 用途 | MVP 行為 |
|------|------|----------|
| Lab Terminal | 文字整理、改寫、列重點 | Q1 按生成/示範後回填 3 點文字 |
| Lab Image | 做封面圖、插圖、圖示 | Q2 按生成/示範後加入圖片型附件 |
| Lab Music | 做背景音樂、開場音樂 | Q3 按生成/示範後加入音訊型附件 metadata |
| Lab Video | 做短動畫、動態開場 | Q4 按生成/示範後加入影片型附件 metadata |

操作規則：

- 進入每題時，自動切到該題建議工具。
- 學生仍可手動切換其他工具，以測試是否會迷路。
- 若切到非建議工具，介面只提示「目前題目建議使用 X」，不禁止操作。
- `生成/示範` 必須能在沒有正式 API 的情況下產生可回填結果，避免 MVP 測試卡死。

## 6. AI 審查 MVP

### 6.1 審查輸入

每次送審使用目前題目的：

- 題目 ID
- 題目文字
- 建議工具
- 文字答案
- 附件 metadata
- 該題審查條件

### 6.2 審查輸出

```ts
type ReviewResult = {
  passed: boolean;
  score: number;
  feedback: string;
  missing: string[];
  suggestions: string[];
  reviewedAt: string;
};
```

### 6.3 回饋文案規則

- 通過：明確說「這題可以通過」，並指出做對哪一點。
- 未通過：只指出 1-3 個最重要缺漏，例如「還缺圖片附件」或「看不出這是音樂結果」。
- 不評作品美醜，不使用「很爛、失敗」等否定人格語氣。
- 審查失敗不得清空答案。

## 7. 課堂測試流程

老師 MVP 測試時照此流程觀察：

1. 開啟 prototype。
2. 學生先看左側第一題。
3. 右側確認目前題目與建議工具。
4. 按 `生成/示範` 或自行使用對應 Lab 工具。
5. 回填文字或加入附件。
6. 按 `送 AI 審查`。
7. 通過後切到下一題。
8. 四題完成後確認完成數為 4/4。

測試觀察重點：

- 學生是否知道目前正在做第幾題。
- 學生是否知道要用哪個工具。
- 學生是否能從工具結果回到右側答案欄。
- 右側答案欄高度是否足夠，不需要一直捲動。
- 多檔案附件是否容易理解。
- AI 審查退件文字是否能讓學生知道下一步。
- 取消上一題 / 下一題按鈕後，題號切換是否仍清楚。

## 9. 防挫折 vs 反硬 A
