# S3 W05 課程規格｜失落規格的溪谷（Lab Terminal Quest）

> 狀態：R20 正式課程規格  
> Runtime Release：`S3W05-LTQ-R20-CLEAR-SPEC-LOGIC-20260915`

## 1. 課程定位

S3 W05 是 S3 第一個採用 **Lab Terminal Quest** 的地圖探索課程。學生在 Phaser 地圖中走近 NPC 或觀察點，以自然問句調出資訊；再用自己讀到的原句，手動整理成能讓 AI 少猜測、也能自己檢查的 prompt。

本週不採用 GAMMA iframe、四格分類卡或固定句子排序。內容端會檢查「用途、做法、限制、成果」是否被覆蓋；學生端不需要替句子貼分類標籤，也不必依固定順序排列。

| 項目 | 定義 |
|---|---|
| 年級／週次 | S3 小四上 W05 |
| 課程名稱 | 失落規格的溪谷 |
| 關卡形式 | Phaser 可步行地圖＋React 右側答題／筆記區 |
| 核心能力 | 從自然對談取得可檢查條件，組成清楚 prompt |
| 主線獎勵 | 250 金幣 |
| 正式內容來源 | `gpt-clone/src/config/s3w05QuestData.json` |

## 2. 學習目標與承重問題

學生完成後能：

1. 看見設施壞掉造成的具體問題，而不是先背需求分類名稱。
2. 選擇一句正常、自然的提問，從 NPC 對話或固定觀察圖找到所需資訊。
3. 判斷漏掉某個條件會造成什麼具體失敗，並選出更清楚、可驗收的寫法。
4. 手動複製、貼上或輸入自己選定的原句，完成 prompt 並檢查產出是否符合。

承重問題：**因為 prompt 漏掉可檢查的條件，所以橋、葉片、路標與節慶徽章無法真正完成它們的任務。**

## 3. 學生體驗循環

```text
走近問題 → 按 E 與 NPC 對話／觀察固定圖 → 選一句想問的自然問題
→ 讀到並可重聽的原句 → 完成內容、漏寫後果、加入理由、清楚寫法四項確認
→ 手動整理 prompt → 提交 Lab Image 結果 → 完成該站挑戰，讓世界改變
```

- 「選擇」只讓學生選擇要對 NPC 說的自然問句；不是猜答案，也沒有固定提問順序。
- 「填充」只用於自由 prompt 的手動收錄；系統只檢查已取得的證據是否被使用，不強迫分類或句序。
- NPC 只說自己的處境與來源原句；題目、來源句與可複製句卡必須一致。每站的完整行為依 `npcProtocol` 執行。
- 所有來源可重看。答錯提供具體誤解回饋，不能扣金幣、清除紀錄或自動代填。

## 4. 關卡編排

| 段落 | 地點與問題 | 學生取得的資訊 | 完成後的世界後果 |
|---|---|---|---|
| 序章／A | 河畔農場：菜車過不了窄而危險的橋 | 用途、尺寸與安全限制的自然說法 | 藤橋能通行，開放運菜林道 |
| 路途 | A→B 運菜林道：菜車遭小豬阻擋 | 保護菜車的操作情境 | 小豬進入安全草地，抵達工坊 |
| B | 山腰工坊：風車葉片大小不一且破損 | 外形、中央組合、完整度；固定正誤觀察圖 | 組合葉片轉動，完成轉動檢查 |
| C | 霧谷山徑：路標方向不清 | 讓路標可辨識、可使用的條件 | 霧散開，完成 Skill Check |
| D | 溪谷鎮古老遺跡：修復節缺少成果徽章 | 節慶徽章的可檢查條件 | 徽章點亮四座燈台，完成修復節閉幕 |

每個主站有 3 組資訊；每組依「內容回憶、漏寫後果、加入規格理由、清楚寫法」完成 4 項客觀確認。全關共 12 組、48 題確認。這四項是讓學生理解規格品質的檢核順序，不是 prompt 的分類或書寫順序。

## 5. 新 Lab Terminal Quest 參考架構

| 層級 | 責任 | S3W05 的實作邊界 |
|---|---|---|
| Quest 資料 | 站、對白、提問、答案證據、進度與關卡配置 | `s3w05QuestData.json` 是唯一機讀來源 |
| React | 對話、問題、手動收錄、prompt、附件驗收、金幣帳 | 不讓學生看到內部覆蓋分類 |
| Phaser | 地圖、移動、碰撞、NPC／設施狀態、完成挑戰與世界改變 | 不持有答案資料，也不依內容 ID 分支 |
| 課程文件 | 說明教學目標、流程、風險與驗收入口 | 不重抄題目、答案或 NPC 原文 |

後續改動的正確順序是：先改機讀內容 → 跑資料驗證 → 由內容正典檢視器校對 → 跑 runtime 驗證。不得再從課程文件回寫手抄題庫。

## 6. 教學與課時邊界

老師應觀察學生是否能說明「這句話放進 prompt 後，可以避免 AI 猜錯什麼」，而非要求學生背出四個分類名稱。可協助學生重回 NPC 原句或固定圖像，但不代選問句、不代寫 prompt。

R20 的完整活動估時為 **99.8 分鐘**（含 48 項確認與 4 次 Lab Image 流程），不符合 50–65 分鐘主線目標。若要改為單節課，課程負責人必須明確選擇拆成兩段、指定可選支線或縮減內容；不得藉由跳過對話、理解確認或手動整理流程縮時。

## 7. 發布與驗收

內容或 runtime 有任何變更後，必跑：

```text
npm run test:s3w05-release
npm run test:s3w05-phaser-data
npm run test:s3w05-phaser-runtime
npx tsc --noEmit
```

驗收重點：

- 題目答案在同一互動點的玩家已讀內容中可找到，且可重看。
- 題型只使用 `choice` 或 `fill`；NPC 行為依資料協議完整執行。
- 學生畫面不出現需求分類、固定四格或強制排序。
- 每站完成造成可見的物理世界改變，而非只顯示「答對」。
- Phaser 不含答案資料，React 不接管地圖世界規則。
