# S3 W08｜四耳妖精與黏成一團的願望（題材與難度討論稿）

## 本週不能漂移的學習核心

- Semester 定位：模組二「任務規格與品質驗收」的收束週。
- 本週主題：好答案自我檢查。
- 主要工具：Lab Terminal、Lab Image、Lab Video；每題只使用其中一種。
- 前置能力：學生已接觸做什麼、怎麼做、不能做什麼、目標、受眾語氣與指定修改。
- 本週新增能力：拿任務條件逐條比對 AI 答案，找出未通過項目，只修需要修的地方，再做一次完整複查。
- 暫不納入：自由設計完整評分規準、評論文采、依個人喜好評分、同時操作多種媒體工具。

## 已確認的設計方向

- 題材：奇幻冒險。
- 題數：四個主任務。
- 每題只生成一種內容，不在同一題混用多個 Lab 工具。
- 媒體路線暫定：文字 → 圖片 → 影片 → 最終影片；本週不使用音樂。
- 每題送出的 Prompt 都要完整包含四需求：做什麼、怎麼做、不能做什麼、目標。
- 難度逐題增加，最後讓學生把一句沒有分段的長需求轉換成四需求規格。

## 玩家幻想與怪角色

學生是**規格解咒師**。幻想王國的願望被「黏句詛咒」黏成一大團，Lab 工具聽不懂，生成結果開始失控。學生要把每個願望拆成四枚規格符文，逐關修好文字、圖片與影片，最後解除整座城堡的詛咒。

### 四耳妖精｜規規

規規有四隻大小不同的耳朵，每隻耳朵只聽得懂一種需求。只要某一種需求不清楚，對應的耳朵就會打結、冒煙或開始唱反調。

- 教學功能：把四需求變成穩定、可見的檢查介面。
- 個性：極度愛分類，連早餐都要分成「吃什麼、怎麼吃、不能加什麼、吃完要去哪裡」。
- 邊界：規規只指出哪一類聽不清楚，不替學生說出答案。

### 一口氣魔女｜噗嚕婆婆

噗嚕婆婆堅持所有願望只能一口氣說完，中途換氣就會忘記自己講到哪裡。她的需求通常正確但全黏在一起，還會混入抱怨、笑聲與無關小事。

- 教學功能：提供逐步變難的自然語句，最後交付完整長需求。
- 個性：語速飛快，講完才發現自己把茶壺一起許進願望裡。
- 邊界：無關語句只用來增加辨認難度，不可改變正解。

### 差不多騎士｜馬虎爵士

馬虎爵士總是大喊「差不多就能通關啦！」，會把缺一項、放錯欄位或互相衝突的規格直接送出去，再被奇怪結果追著跑。

- 教學功能：示範真實錯誤，讓學生看見為什麼送出前要自我檢查。
- 個性：盔甲永遠少扣一顆扣子，地圖永遠拿反，但被退件時很願意改。
- 邊界：笑點對準錯誤結果，不羞辱角色或學生。

## 難度落點

主線採 `semi-open-chain`。四題都使用同一套四需求標籤，但線索整理支架逐步撤除。難度放在學生的轉換動作，不靠增加故事專有名詞或延長閱讀。

四題的主要轉換依序是：

1. **配對**：四段資料已切開，學生把資料放到正確需求欄位。
2. **抽取與分類**：需求藏在短對話裡，學生自己找出並分類。
3. **保留與修正**：需求順序混亂且有一處衝突，學生保留正確內容，只修錯誤部分。
4. **獨立轉換**：只給一句完整長需求，學生自行拆成四需求規格並完成總檢查。

預計的學生責任邊界：

- 四需求名稱全程保留，因為本週評量的是轉換與檢查，不是背名詞。
- A 題可見四段已切開資料，但不顯示配對答案。
- B 題拿掉切段；C 題加入語序混亂與單一衝突；D 題拿掉標色、切段與對應提示。
- 每題送出前都要逐項指出 Prompt 中的四需求證據，不能只勾「我有檢查」。
- 系統以可重現條件判定 Prompt 與成果是否齊全；生成模型不能單獨決定通關。

## 四關任務鏈

### 任務 A｜會吃字的入城公告

**生成類型：文字**

城門的公告卷軸會把不完整的願望吃掉。噗嚕婆婆交出四段已分開但沒有欄位名稱的資料，學生把它們配到四需求規格，請 Lab Terminal 生成一份入城公告。

- 主要動作：配對。
- 支架：四段資料卡、四個固定欄位、短小測確認配對理由。
- 通關證據：完整四需求 Prompt＋符合四項條件的文字公告。
- 失敗回饋：規規只有對應耳朵打結，指出需求類別，不貼出正解。

### 任務 B｜長腳蘑菇的英雄肖像

**生成類型：圖片**

一群長腳蘑菇想留下英雄肖像，卻把需求藏在一段會插嘴的對話裡。學生找出四類需求，整理成圖片規格，再請 Lab Image 生成肖像。

- 主要動作：從自然對話抽取並分類。
- 支架：保留四需求欄位；不切段、不直接加粗答案。
- 通關證據：完整四需求 Prompt＋一張同題生成圖片。
- 規格風險：蘑菇的怪設定最多保留三項必要視覺特徵，避免記憶世界觀變成主難點。

### 任務 C｜倒著行駛的月光馬車

**生成類型：影片**

馬虎爵士把月光馬車的影片規格拼錯：三類需求正確，一類需求與委託人的新要求衝突。學生要從順序混亂的對話中找出衝突，只替換錯誤內容，再請 Lab Video 生成短片。

- 主要動作：保留正確內容，只修衝突需求。
- 支架：顯示現有四需求規格；對話不依欄位順序出現，並混入一小段無關抱怨。
- 通關證據：修訂後四需求 Prompt＋一段同題生成影片。
- 失敗回饋：指出「仍有新舊值並存」或「已通過內容被刪除」，不提供正確新值。

### 任務 D｜黏句城堡的最後願望

**生成類型：最終影片**

黏句詛咒把整座城堡封住。噗嚕婆婆只來得及一口氣說出一句長需求，沒有換行、標色、欄位提示或資料卡。學生要自行找出四類資訊，改寫成四需求規格，完成送出前總檢查，再生成城堡甦醒的最終影片。

- 主要動作：把一句長需求獨立轉換成四需求規格。
- 支架：只保留空白的四需求欄位與方向式提示，不給完整 Prompt 句型。
- 通關證據：四需求完整且彼此不衝突的 Prompt＋同題生成影片＋四項證據確認。
- Deliver：四隻耳朵同時亮起，城堡解咒；學生能指出影片中四需求各自留下的可見證據。

## 核心遊戲循環

```text
聽見奇怪願望
→ 找出四類資訊
→ 整理成四需求規格
→ 逐項自我檢查
→ 使用指定 Lab 工具生成一種成果
→ 對照需求找成果證據
→ 解開下一道詛咒
```

每關都讓玩家看見「漏掉或放錯一類需求」造成的怪結果。進步不是來自猜中答案，而是更少依賴規規的提示，直到能獨立完成長句轉換。

## 尚待確認

1. 第四題是否接受再次生成影片，讓結尾有最強視覺回報；若不想重複媒體，可改成 Lab Terminal 生成「解咒宣言」，但高潮感較弱。
2. 最終長需求要控制在多少字；初始建議為小四可掃描的一句 70～90 字，正式值要經 Grade 4 動作級耗時估算。
3. C 題要不要保留「新舊需求衝突」；它能銜接 W06–W07 的局部修改能力，但也會讓第三題難度明顯跳升。
