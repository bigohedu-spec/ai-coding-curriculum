## 今天的冒險

上週，你的專案已經會「記住」使用者的資料了——但那些資料只存在**你這一台電腦的瀏覽器**裡。換一台電腦打開，全部不見。

今天，你要讓資料**飛上雲端**。

做完之後：你在學校電腦新增的資料，回家用另一台電腦打開、甚至開一個無痕視窗，**資料都還在**。這就是真正的線上服務在做的事。

**W13 的目標：把上週存在本機的資料，搬到 Supabase 雲端資料庫。**

> 🔑 今天用的雲端資料庫叫 **Supabase**。老師已經幫全班建好了，你不需要註冊任何帳號。老師會給你三樣東西，先抄下來：
>
> ```
> Project URL：__________________________
> anon 金鑰：__________________________
> table（表）名稱：__________________________
> ```

## 任務 A｜把你的資料寫上雲端 ⭐ 150 金幣

**任務 ID**：S5-W13-A

### 目標

用老師給的連線資訊把 Supabase 接進你的專案，並成功把一筆資料寫進雲端的 table。

---

### Part 1：確認你手上有三樣東西（工具操作）

開始前，確認你已經抄下老師給的：**Project URL**、**anon 金鑰**、**table 名稱**。三樣缺一不可。

> **如果還沒拿到** → 看白板，或在 Lab Terminal 問老師發的連線資訊；沒有這三樣，後面做不下去。

---

### Part 2：開啟 Copilot Chat

> 快捷鍵 `Ctrl+Shift+I`（Windows）/ `Cmd+Shift+I`（Mac），或點左側邊欄的 Copilot 圖示，右側出現對話框 = 成功。

---

### Part 3：用 Copilot Chat 把雲端接進專案

你是 PM，Copilot Chat 是你的工程師。把連線資訊和「我要做什麼」清楚告訴它。

如果你遇到以下情況，可以這樣問 Copilot Chat（把你的三樣連線資訊一起貼進去）：

> 「我要把我的網頁專案接上 Supabase 雲端資料庫。Project URL 是 `[貼上]`，anon 金鑰是 `[貼上]`，我要用的 table 叫 `[貼上]`。請幫我用 `@supabase/supabase-js`（用 CDN import，不要用 npm，因為我是純 HTML 專案）初始化連線。然後我上週是用 localStorage 存資料，現在改成：當使用者新增一筆資料時，把它 insert 到這個雲端 table。幫我寫這段程式。」

> 「我照你給的做了，但 Console 出現紅字錯誤 `[把錯誤訊息貼上]`，幫我看是什麼問題。」

> 「我想確認資料有沒有寫進雲端，可以教我在 Console 印出 insert 的結果嗎？」

收到程式碼後：

1. 把程式碼貼到對應位置，存檔（`Ctrl+S`，標題列沒有 `●` 表示已存）
2. 在瀏覽器執行你的新增動作
3. 按 `F12` 打開 Console，確認沒有紅字錯誤，且 insert 成功
4. 舉手請老師在投影幕的 Supabase Table Editor 確認你的資料出現了

### 成功的樣子

- 在專案裡新增了一筆資料
- Console 顯示寫入成功、沒有錯誤（老師投影幕的 table 也看得到你的資料）
- 截圖包含：**你的網站畫面 + 寫入成功的證據（Console 或老師投影幕）**
- 舉手告知老師 ✋

完成後進任務 B。

## 任務 B｜從雲端讀回來 + 換裝置驗證 ⭐ 100 金幣

**任務 ID**：S5-W13-B

### 目標

任務 A 完成了**寫上雲**。任務 B 要完成**從雲端讀回來**——頁面打開時，自動去 Supabase 拿資料並顯示給使用者看。最後用「換一個視窗 / 換一台電腦」證明它真的在雲端。

---

### 用 Copilot Chat 實作雲端讀取

繼續描述你要的讀取行為。說清楚三件事：**什麼時候去拿** + **從哪個 table 拿** + **拿到後顯示在哪裡**。

> 「在頁面載入時，從 Supabase 的 `[你的 table]` 用 `select` 讀取資料，然後把資料顯示到 `[你的 HTML 元素，例如 <ul id="list">]` 裡面。如果雲端還沒有資料，顯示空白不要報錯。」

> 「我想讓資料一更新就自動顯示在畫面上，不用重新整理，Supabase 有辦法做到嗎？」（這是進階，可選）

> 「我從雲端讀資料，但畫面上沒東西，Console 也沒錯誤，可能是什麼問題？」

---

### 跨裝置驗證（這是今天最關鍵的一步）

收到程式碼、整合到專案後，做這個測試：

| 步驟 | 操作 | 預期結果 |
|------|------|---------|
| 1 | 在你的專案新增一筆資料 | 畫面出現，Console 顯示寫入成功 |
| 2 | 開一個**無痕視窗**（`Ctrl+Shift+N`），打開同一個專案頁面 | 剛剛那筆資料**也在！** |
| 3 | 在無痕視窗再新增一筆，回到原本視窗重整 | 新資料也出現 |

> 如果無痕視窗看不到資料 → 把情況描述給 Copilot：「我在無痕視窗打開頁面，讀不到雲端資料，原本視窗可以，可能是什麼原因？」

### 成功的樣子

- 在**無痕視窗或另一台電腦**打開你的專案，看得到同一筆雲端資料
- 截圖包含：**兩個不同視窗（或兩台電腦）都顯示同一筆資料**
- 舉手告知老師 ✋

> 「我想把上週的 localStorage 程式整段改成 Supabase，可以幫我看哪些地方要改嗎？」

### Lab Terminal（概念問題）

> 「localStorage 和雲端資料庫（像 Supabase）最大的差別是什麼？用一個簡單的比喻說明。」

> 「為什麼資料存到雲端，換一台電腦也看得到，但 localStorage 不行？」

→ 完成助教任務，向老師申報，領取**任務 B 50% 金幣（50 幣）** 🪙

## ⚡ 進階挑戰（完成 A + B 後）

任選一個方向，繼續用 Vibe Coding 方式實作：

1. **即時同步**：用 Supabase Realtime，讓一個視窗新增、另一個視窗**不用重整**就自動更新
2. **刪除雲端資料**：加一個按鈕，點了刪除雲端某一筆
3. **多筆顯示**：把雲端的多筆資料一次全部顯示，並按時間排序

完成後截圖讓老師另外計入獎勵，本週不強制。
