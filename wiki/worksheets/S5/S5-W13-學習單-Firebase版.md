## 今天的冒險

上週，你的專案已經會「記住」使用者的資料了——但那些資料只存在**你這一台電腦的瀏覽器**裡。換一台電腦打開，全部不見。

今天，你要讓資料**飛上雲端**。

做完之後：你在學校電腦新增的資料，回家用另一台電腦打開、甚至開一個無痕視窗，**資料都還在**。這就是真正的線上服務在做的事。

**W13 的目標：把上週存在本機的資料，搬到 Firebase 雲端資料庫。**

## 任務 A｜把你的資料寫上雲端 ⭐ 150 金幣

**任務 ID**：S5-W13-A

### 目標

確認你的 Firebase 專案就緒，把它接進你的程式，並成功把一筆資料寫上雲。

---

### Part 1：確認你的 Firebase 已就緒（工具操作）

開始前，確認你已經有：

1. 一個 Firebase 專案（你之前用 Google 帳號建好的）
2. 已開啟 **Realtime Database**，而且規則是 **測試模式**（讀寫皆可）
3. 手邊有你的 **firebaseConfig**（在主控台 ⚙️ 專案設定 → 你的應用程式 → `</>` 那段程式碼）

> **如果規則不是測試模式** → 到主控台 Realtime Database → 規則頁，改成測試模式，否則資料寫不進去（會出現 `permission denied`）。
>
> **如果 config 裡沒有 `databaseURL`** → 回 Realtime Database 頁，複製最上方 `https://....firebaseio.com` 網址，等下告訴 Copilot。

---

### Part 2：開啟 Copilot Chat

> 快捷鍵 `Ctrl+Shift+I`（Windows）/ `Cmd+Shift+I`（Mac），或點左側邊欄的 Copilot 圖示，右側出現對話框 = 成功。

---

### Part 3：用 Copilot Chat 把雲端接進專案

你是 PM，Copilot Chat 是你的工程師。把「鑰匙」和「我要做什麼」清楚告訴它。

如果你遇到以下情況，可以這樣問 Copilot Chat（把你的 `firebaseConfig` 一起貼進去）：

> 「我要把我的網頁專案接上 Firebase Realtime Database。這是我的設定：`[貼上你的 firebaseConfig]`。請幫我在 HTML 裡加入 Firebase 的 SDK 並初始化。然後我上週是用 localStorage 存 `[你的資料 key]`，現在改成：當使用者新增資料時，**寫到 Firebase**。幫我寫這段儲存到雲端的程式。」

> 「我照你給的做了，但 Console 出現紅字錯誤 `[把錯誤訊息貼上]`，幫我看是什麼問題。」（提示：`permission denied` 通常是規則沒開測試模式）

> 「我想確認資料有沒有寫上雲，要去 Firebase 主控台的哪裡看？」

收到程式碼後：

1. 把程式碼貼到對應位置，存檔（`Ctrl+S`，標題列沒有 `●` 表示已存）
2. 在瀏覽器執行你的新增動作
3. 回到 **Firebase 主控台 → Realtime Database**，看你的資料節點有沒有出現

### 成功的樣子

- 在專案裡新增了一筆資料
- Firebase 主控台的 Realtime Database 頁面**看得到那筆資料**
- 截圖包含：**你的網站畫面 + 主控台裡的雲端資料**
- 舉手告知老師 ✋

完成後進任務 B。

---

## 任務 B｜從雲端讀回來 + 換裝置驗證 ⭐ 100 金幣

**任務 ID**：S5-W13-B

### 目標

任務 A 完成了**寫上雲**。任務 B 要完成**從雲端讀回來**——頁面打開時，自動去 Firebase 拿資料並顯示給使用者看。最後用「換一個視窗 / 換一台電腦」證明它真的在雲端。

---

### 用 Copilot Chat 實作雲端讀取

繼續描述你要的讀取行為。說清楚三件事：**什麼時候去拿** + **去哪個路徑拿** + **拿到後顯示在哪裡**。

> 「在頁面載入時，從 Firebase Realtime Database 的 `[你的路徑]` 讀取資料，然後把資料顯示到 `[你的 HTML 元素，例如 <ul id="list">]` 裡面。如果雲端還沒有資料，顯示空白不要報錯。」

> 「我想讓資料一更新就自動顯示在畫面上，不用重新整理，可以用 `onValue` 做嗎？」（進階，可選）

> 「我從雲端讀資料，但畫面上沒東西，主控台裡明明有資料，可能是什麼問題？」

---

### 跨裝置驗證（這是今天最關鍵的一步）

收到程式碼、整合到專案後，做這個測試：

| 步驟 | 操作 | 預期結果 |
|------|------|---------|
| 1 | 在你的專案新增一筆資料 | 畫面出現，主控台也看到 |
| 2 | 開一個**無痕視窗**（`Ctrl+Shift+N`），打開同一個專案頁面 | 剛剛那筆資料**也在！** |
| 3 | 在無痕視窗再新增一筆，回到原本視窗重整 | 新資料也出現 |

> 如果無痕視窗看不到資料，但主控台看得到 → 把情況描述給 Copilot：「我在無痕視窗打開頁面，但讀不到雲端資料，原本視窗可以，可能是什麼原因？」

### 成功的樣子

- 在**無痕視窗或另一台電腦**打開你的專案，看得到同一筆雲端資料
- 截圖包含：**兩個不同視窗（或兩台電腦）都顯示同一筆資料**
- 舉手告知老師 ✋

> 「我想把上週的 localStorage 程式整段改成 Firebase，可以幫我看哪些地方要改嗎？」

### Lab Terminal（概念問題）

> 「localStorage 和雲端資料庫（像 Firebase）最大的差別是什麼？用一個簡單的比喻說明。」

> 「為什麼資料存到雲端，換一台電腦也看得到，但 localStorage 不行？」

## ⚡ 進階挑戰（完成 A + B 後）

1. **即時同步**：用 `onValue` 監聽，讓一個視窗新增、另一個視窗**不用重整**就自動更新

3. **多筆顯示**：把雲端的多筆資料一次全部顯示在頁面上
