## 今天的冒險

你的專案現在有了導航列，使用者可以在各個頁面之間跳來跳去了。

但還有一個問題：**每次打開瀏覽器，一切都從頭開始。** 你的專案不認識使用者，也不記得他上次做了什麼。

今天要解決這個問題。

**W12 的目標：讓你的專案有「身份識別」和「記憶力」。**

你要做三件事：

**一、製作登入頁面**
使用者進來先輸入自己的名字（或暱稱），點「進入」後才能開始使用你的專案。

**二、用 localStorage 記住使用者名稱**
把使用者輸入的名字存到瀏覽器裡，下次打開頁面，名字還在——不需要帳號、不需要伺服器，資料就存在使用者的瀏覽器裡。

**三、加入登出功能**
讓使用者可以清除自己的資料，下次開啟可以換一個名字。

做完這三件事之後，你的專案就有了第一個「使用者系統」。

## 任務 A｜製作登入頁面（login.html）⭐ 75 金幣

**任務 ID**：S5-W12-A

### 目標

建立一個獨立的登入頁面。使用者打開你的專案時，先到這個頁面輸入名字，點「進入」後才會跳到你的 Welcome Page 或首頁。

登入頁面不需要複雜——一個輸入框、一個按鈕、一點基本樣式就夠了。

---

### 你要做的事

1. 在 VS Code 左側欄，在你的專案資料夾裡新建一個檔案：
   - 點選單 `File → New File`，或按 `Ctrl+N`（Windows）/ `Cmd+N`（Mac）
   - 存檔時命名為 `login.html`，確認和你其他 HTML 檔案放在同一個資料夾

2. 開啟 Copilot Chat（左側欄的對話圖示），描述你要做的登入頁面，請它幫你寫 HTML + CSS + JS

3. 把 Copilot 給的程式碼貼進 `login.html`，存檔，在瀏覽器測試

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「幫我做一個 `login.html` 登入頁面。只需要一個輸入框讓使用者輸入暱稱（**不需要密碼欄位**），還有一個『進入』按鈕。點按鈕的時候，**先檢查輸入框不是空的**：如果是空的，在輸入框下方顯示紅色的『請輸入你的名字』提示，不跳頁；如果有輸入名字，才跳到 `index.html`（換成你的首頁檔案名）。頁面風格用深色背景、白色文字。」

> 「我的登入頁面做好了，輸入名字可以跳頁，但輸入空白還是可以進去，怎麼修正？」

> 「我想讓我的 `login.html` 和其他頁面的風格一樣，可以幫我加上和 `index.html` 類似的配色和字體嗎？（把你現有的 CSS 貼給 Copilot 參考）」

---

### 測試方式

1. 在瀏覽器打開 `login.html`
2. 輸入一個名字（例如「酷炫冒險家」）
3. 點「進入」按鈕
4. 確認有跳到你的首頁（或你指定的頁面）

---

### 完成條件

1. `login.html` 在 VS Code 左側欄看得到，且沒有密碼欄位
2. 輸入框是空的時點「進入」→ 出現提示訊息，不跳頁
3. 輸入名字後點「進入」→ 成功跳到你的首頁
4. 截圖：登入頁面的外觀（顯示輸入框和按鈕）

完成後進任務 B。

## 任務 B｜用 localStorage 記住登入的使用者 ⭐ 100 金幣

**任務 ID**：S5-W12-B

### 目標

讓你的專案「記住」使用者輸入的名字。

`localStorage` 是瀏覽器內建的一個小倉庫，你可以用 JavaScript 把資料存進去。只要使用者沒有清除瀏覽器資料，這個倉庫的東西就不會消失——關掉視窗再打開，資料還在。

這個任務要做兩件事：
1. **存**：使用者點「進入」的時候，把他的名字存到 localStorage
2. **讀**：在你的首頁（或某個頁面），讀取 localStorage 裡的名字，顯示「歡迎，[名字]！」

---

### 什麼是 localStorage？

在你問 Copilot Chat 之前，可以先用 Lab Terminal 問一個問題，讓自己有個基本理解：

> 問 Lab Terminal：「我是小學生，localStorage 是什麼？它怎麼跟一般的變數不一樣？用一個簡單的比喻說明。」

你不需要記住所有細節，只要知道「它是一個可以存資料的地方，關掉瀏覽器還在」就夠了。

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「我的 `login.html` 有一個輸入框（id 是 `username-input`）和一個『進入』按鈕。我想在使用者點按鈕的時候，把輸入框的值存到 localStorage 的 `userName` 這個 key，然後跳到 `index.html`。可以幫我寫這段 JavaScript 嗎？」

> 「我想在我的 `index.html` 頁面最頂端加一段 JavaScript：讀取 localStorage 的 `userName`，**如果沒有值（代表使用者沒有登入），立刻跳回 `login.html`，不讓他直接進來**；如果有值，就在頁面上顯示『歡迎，[名字]！』。可以幫我寫這段程式嗎？」

> 「我的 localStorage 存進去之後，用 `console.log` 可以看到，但頁面上顯示不出來，可能是什麼問題？」

---

### 測試方式

1. 在瀏覽器打開 `login.html`，輸入你的名字，點「進入」
2. 跳到首頁後，確認看到「歡迎，[你的名字]！」
3. **關掉瀏覽器標籤**，重新打開你的 `index.html`（或 `welcome.html`）
4. 確認名字還在（這就是 localStorage 的魔法）

⚠️ **常見問題**：如果重開後名字消失了，先確認你的 JS 程式碼裡有寫 `localStorage.setItem`，不是只用了普通的變數。可以問 Copilot Chat 幫你檢查。

---

### 完成條件

1. 在登入頁面輸入名字後，首頁（或你指定的頁面）顯示「歡迎，[名字]！」
2. **關掉瀏覽器重新打開**，名字還在（這一步很重要！）
3. 截圖兩張：
   - 第一張：登入頁面輸入名字的狀態
   - 第二張：首頁顯示「歡迎，[名字]！」

完成後進任務 C。

## 任務 C｜加入登出功能 ⭐ 75 金幣

**任務 ID**：S5-W12-C

### 目標

讓使用者可以「離開」目前的身份，清除 localStorage 裡的名字，回到登入頁面。

登出功能通常是一個按鈕——可以放在導航列、首頁上，或你覺得合適的地方。

---

### 想清楚再問 Copilot Chat

在描述之前，先決定這幾件事：

1. **登出按鈕放哪裡？** 導航列最常見（每個頁面都看得到）；也可以只放在首頁。
2. **登出之後要跳到哪裡？** 通常是跳回 `login.html`。
3. **登出前要不要確認？** 有些設計會跳出「確定要登出嗎？」的提示；有些直接登出。

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「我想在我的導航列右側加一個『登出』按鈕。點下去之後，清除 localStorage 裡的 `userName` 這個 key，然後跳回 `login.html`。可以幫我寫這個按鈕的 HTML 和對應的 JavaScript 嗎？」

> 「我想在登出之前彈出一個確認訊息（用 JavaScript 的 `confirm`），使用者確認之後才真的登出，要怎麼做？」

> 「我在導航列加了登出按鈕，但其他頁面的導航列沒有更新，我要一個一個頁面手動加嗎？有沒有更簡單的方式？」

---

### 測試完整流程

做完任務 C 之後，測試你的整個登入 / 登出流程：

1. 打開 `login.html`，輸入名字，點「進入」
2. 確認首頁顯示「歡迎，[名字]！」
3. 點「登出」按鈕，確認跳回 `login.html`
4. **在瀏覽器網址列直接輸入 `index.html` 的路徑，強制開啟** — 確認它自動跳回 `login.html`，進不去
5. 重新輸入另一個名字，確認換名字後整個流程正常

---

### 完成條件

1. 頁面上看得到「登出」按鈕（導航列或其他你選擇的地方）
2. 點「登出」後，localStorage 的使用者名稱被清除
3. 自動跳回 `login.html`
4. 截圖：顯示登出按鈕的所在位置

完成所有任務後，舉手告知老師。

## 今天學到什麼？

完成後，想一想：

1. `localStorage` 和你在 JavaScript 裡宣告的普通變數（`let name = "..."`)，有什麼最大的差別？
2. 安全性檢查的第 3 項（登出後直接開首頁會跳回登入頁）是這個系統裡最重要的一道防線。你覺得如果沒有這個設計，會發生什麼事？
3. 你的登入頁沒有密碼欄位，只有暱稱——這個設計讓你的系統少了什麼、但也避免了什麼問題？
4. 如果你的專案讓兩個人輪流使用（例如先登出，再讓另一個人登入），整個流程順暢嗎？有沒有什麼地方感覺卡卡的？
