## 今天的冒險

你現在的專案有了 Welcome Page，還有幾個可以操作的功能。

但現在的狀態是這樣的：
- 所有功能可能還塞在同一個 HTML 檔案裡，或散落在幾個互不相連的頁面
- 使用者打開你的專案，不知道還有其他頁面
- 從功能頁沒辦法回到 Welcome Page，也沒辦法跳到其他功能

今天要解決這個問題。

**W11 的目標：讓你的專案從「一堆散頁面」變成「一個有導航的完整產品」。**

你要做三件事：

**一、確認你有至少 3 個 HTML 頁面**
導航列要有意義，你的專案至少需要 3 個可以跳轉的地方。如果不夠，這個任務幫你拆出來。

**二、確認所有頁面都可以互相到達**
不管使用者從哪個頁面進來，他都能找到路去其他地方。

**三、加上一個導航列（Navigation Bar）**
每個頁面頂端都有同一排連結，讓使用者隨時跳到任何一個功能。

做完這三件事之後，你的專案下週就可以拿去 MVP Demo 了。

## 開始前：盤點你的頁面清單

在開始之前，先搞清楚你的專案現在有哪些 HTML 檔案。

在 VS Code 的**左側檔案欄**看一下你的資料夾，列出所有 `.html` 結尾的檔案：

打開你的 `project-idea.md`，在最底部新增一個區塊：

```
## W11 頁面清單
- [ ] ___________.html（說明：這是 ___________ 頁面）
- [ ] ___________.html（說明：這是 ___________ 頁面）
- [ ] ___________.html（說明：這是 ___________ 頁面）
（有幾個填幾個）

## W11 導航列要包含哪些連結？
- ___________（連到 ___________）
- ___________（連到 ___________）
- ___________（連到 ___________）
```

填完之後存檔（`Ctrl+S` / `Cmd+S`）。這份清單是你今天任務的地圖。

數一下你的 HTML 檔案有幾個：**少於 3 個就先做任務 A**，3 個以上可以直接跳任務 B。

## 任務 A｜確認你的專案有至少 3 個 HTML 頁面 ⭐ 75 金幣

**任務 ID**：S5-W11-A

### 目標

導航列要有意義，你的專案至少需要 3 個可以跳轉的頁面。

先確認你目前的狀況：如果已經有 3 個以上的 HTML 檔案，這個任務對你來說很快——截圖確認後就進任務 B。如果還不夠，這個任務幫你把功能拆成獨立頁面。

---

### 盤點你現在有幾個頁面

打開 VS Code，看左側檔案欄，數一數有幾個 `.html` 結尾的檔案：

- **已經有 3 個以上** → 直接跳到完成條件，截圖後進任務 B
- **只有 1–2 個** → 繼續往下，你需要把功能拆到新的頁面

---

### 怎麼拆頁面？

想一想你的專案現在有哪些「功能」或「區塊」。每一個功能或主要區塊，都可以做成一個獨立的 HTML 頁面。

常見的拆法：
- **首頁**（`index.html` 或 `welcome.html`）：介紹頁，讓人知道這是什麼
- **功能頁一**（`feature1.html`）：你的第一個主要功能
- **功能頁二**（`feature2.html`）：你的第二個主要功能
- 還有其他功能的話，繼續加

你不需要把每個小東西都拆，但目標是**至少讓導航列有 3 個地方可以跳**。

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「我目前把所有功能都放在 `index.html`，想把其中一個功能拆出去，做成獨立的 `feature1.html`。這個功能的程式碼是這樣的：（把功能的 HTML + JS 貼上來）。可以幫我把它搬到一個新的獨立頁面嗎？」

> 「我想新建一個 `history.html`，用來顯示歷史紀錄，基本的 HTML 結構（含 `<head>`、`<body>`、中文 `charset`）要怎麼寫？」

> 「我有一個 `index.html` 裡面有三個功能，我想讓每個功能用各自的 HTML 檔案，應該怎麼規劃檔案名稱比較好？」

---

### 完成條件

1. VS Code 左側欄看得到**至少 3 個 `.html` 檔案**
2. 每個頁面用瀏覽器打開都有實際內容（不是空白頁）
3. 截圖：VS Code 左側欄顯示你所有的 HTML 頁面（看得到檔案名稱）

完成後，回到上方的「W11 頁面清單」，把所有 HTML 頁面填進去，然後進任務 B。

## 任務 B｜功能整合：讓所有頁面可以互相連結 ⭐ 100 金幣

**任務 ID**：S5-W11-B

### 目標

讓你專案裡的每一個頁面，都能讓使用者找到路到其他頁面。

這不是規定每個頁面要有完整的導航列（那是任務 C），而是先確認**沒有「孤島頁面」**——某些頁面進得去、出不來，或根本沒有任何連結指向它。

---

### 怎麼確認有沒有孤島？

對照你剛才填的頁面清單，問自己每一個頁面：

1. **「有沒有辦法從首頁到達這個頁面？」** — 如果沒有，需要在首頁加連結
2. **「在這個頁面，使用者可以去哪裡？」** — 如果答案是「哪裡都去不了」，這個頁面就是孤島

找到孤島之後，你的任務是：**讓每個孤島頁面至少有一個出口**（連結到其他頁面或回到首頁）。

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「我有這些 HTML 檔案：`index.html`、`feature1.html`、`feature2.html`（換成你的真實檔案名）。我想讓它們互相可以到達，現在 `feature2.html` 進去之後出不來，可以幫我在頁面底部加一個『回到首頁』的連結嗎？」

> 「我想在 `index.html` 加入三個按鈕，分別連到 `welcome.html`、`quiz.html` 和 `result.html`，可以幫我寫這個 HTML 嗎？」

> 「我想在每個功能頁加一個固定在右下角的『回首頁』按鈕，不要影響頁面原有的版面，要怎麼做？」

> 「我在 `feature1.html` 底部加了一個連結指向 `feature2.html`，但點了沒有反應，可能是什麼問題？」

---

### 測試方式

用瀏覽器打開你的 `index.html`（或 `welcome.html`），然後試著：

1. 從首頁出發，只靠點連結，看能不能到達你所有的功能頁面
2. 在每個功能頁面，確認至少有一個連結可以帶你離開這個頁面
3. 如果有任何地方「卡住」了（想去但沒有連結），回到 VS Code 補上連結

---

### 完成條件

1. 在 `project-idea.md` 的 W11 頁面清單裡，每個頁面加上 ✅
2. 打開瀏覽器，從首頁出發，**只靠點連結**可以到達你所有的 HTML 頁面
3. 沒有任何一個頁面是「進得去、出不來」的
4. 截圖：展示你從某個頁面連到另一個頁面的過程（兩張截圖分別顯示跳頁前後即可）

完成之後，請直接舉手告知老師。

## 任務 C｜加入導航列（Navigation Bar）⭐ 75 金幣

**任務 ID**：S5-W11-C

### 目標

在你的**每一個頁面頂端**加上同一排導航列，讓使用者不管在哪個頁面，都能看到一致的選單，隨時跳到他想去的地方。

導航列的內容由你決定——通常包含你所有頁面的名稱。格式和樣式也由你決定。

---

### 在你的描述裡，要告訴 Copilot Chat 這些事：

想清楚這幾個問題，再去描述：

1. **你的導航列要有哪些選項？**（每個連結的文字和對應的 html 檔案）
2. **你的網站叫什麼名字？**（通常放在導航列的最左邊）
3. **你的導航列要什麼風格？**（深色背景白字、淺色、跟頁面顏色一致……）

如果你說不出「什麼風格」，也可以說「跟我現有的配色一樣就好」，然後把你的 CSS 顏色代碼告訴 Copilot。

---

### 如果你遇到以下情況，可以這樣問 Copilot Chat：

> 「幫我寫一個 HTML + CSS 的導航列，要包含這些連結：首頁（連到 index.html）、計算機（連到 calc.html）、紀錄（連到 history.html）。風格是深藍色背景、白色文字，左邊顯示我的專案名稱。」

> 「我想在我所有的 HTML 頁面頂端加上同一個導航列，但我的 HTML 檔案有四個，有什麼方式可以不要複製貼上四次都改一遍？」

> 「我的導航列加上去之後，在手機縮小畫面的時候跑版了，可以幫我調整讓它在小螢幕上也看起來正常嗎？」

> 「我的導航列目前我在哪個頁面，那個連結就加上底線或其他標示，讓使用者知道自己現在在哪裡，怎麼做到這個效果？」

---

### 把導航列加到所有頁面的步驟

Copilot Chat 給你導航列的 HTML + CSS 之後，你需要自己把它加到每一個頁面。這個步驟需要手動操作：

1. **確認你的 CSS** — Copilot 可能給你 `<style>` 標籤裡的 CSS，或建議你建立獨立的 CSS 檔案。如果是獨立 CSS 檔案：
   - 在 VS Code 新建一個檔案（`File → New File` 或 `Ctrl+N` / `Cmd+N`）
   - 存成 `nav.css`（位置和你的 html 檔案同一個資料夾）
   - 把 Copilot 給的 CSS 貼進去，存檔

2. **在每個 HTML 檔案加入導航列**：
   - 打開第一個 HTML 檔案
   - 找到 `<body>` 這一行，把導航列的 HTML **貼在 `<body>` 的正下方**（所有其他內容的上面）
   - 如果你用了獨立的 `nav.css`，在 `<head>` 裡加入這一行：
     ```html
     <link rel="stylesheet" href="nav.css">
     ```
   - 存檔（`Ctrl+S` / `Cmd+S`），在瀏覽器確認導航列出現在頁面頂端
   - **對每個 HTML 檔案重複這個步驟**

3. **每加完一個頁面就在瀏覽器測試一次** — 確認：導航列看起來正確、連結點了會跳到對的頁面

⚠️ **注意**：如果你在加第二、三個頁面時發現導航列跑版了，先確認你有正確 link 到 CSS 檔案（在 VS Code 左側欄確認 `nav.css` 和 html 檔案在同一個資料夾）。

---

### 完成條件

1. 打開瀏覽器，**每一個頁面頂端**都看得到導航列
2. 點導航列的每個連結，都能到達對應的頁面
3. 每個頁面的導航列**樣式一致**（不是每頁長得不一樣）
4. 截圖包含至少兩個不同頁面，都能看到導航列

完成之後，請直接舉手告知老師。
