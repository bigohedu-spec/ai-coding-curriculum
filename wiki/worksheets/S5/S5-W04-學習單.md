## 今天的冒險

上週你幫專案**裝好了存檔系統**，可是你還沒真的按下存檔。

今天你要做三件事：

1. 按下你的**第一個存檔點**
2. **故意把檔案改壞**
3. 用存檔系統**把它救回來**

做完之後你會知道：只要有存檔點，改壞了一點都不可怕。

> 今天一樣只在**你自己的電腦上**做，不用註冊任何帳號、不用上傳到任何網站。

## 任務 A｜按下存檔點，把改壞的檔案救回來 ⭐ 250 金幣

**任務 ID**：S5-W04-A

### 目標

在你的專案按下**兩個存檔點**，並且親手把一個改壞的檔案**救回存檔時的樣子**。

---

### Part 1：打開專案，確認上週的存檔系統還在

1. 打開 VS Code → 上方選單 **File → Open Folder**（檔案 → 開啟資料夾）→ 選你的專案資料夾
2. 按 `Ctrl` + `` ` `` 打開 Terminal，確認路徑**結尾是你的專案資料夾名字**
   - 沒反應 → 上方選單 **Terminal → New Terminal**（終端機 → 新增終端機）
3. 打這一行、按 `Enter`：

```
git status
```

**完成後你會看到**：跟上週一樣的輸出，裡面有 `Untracked files:`，列出 `index.html`、`about.html`（還有 `messy.html`）。

> **如果不對怎麼辦**
> - 跑出 `fatal: not a git repository` → 這個資料夾還沒裝存檔系統（上週沒做完，或是開錯資料夾）。先確認路徑對，再打 `git init`，然後重打一次 `git status`。
> - 沒有 `about.html` → 在左邊 Explorer 的空白處按**右鍵** → **New File**（新增檔案），命名為 `about.html`，裡面打 `<h1>關於我</h1>`，存檔。

---

### Part 2：告訴 Git 你是誰

每個存檔點都會寫上「**是誰存的**」。第一次存檔之前，要先告訴 Git 你的名字。

一行一行打，每打完一行按 `Enter`（引號裡換成**你的英文名字或暱稱**）：

```
git config user.name "Amy"
```

```
git config user.email "amy@student.local"
```

**完成後你會看到**：**什麼都沒跑出來**——沒有訊息就是成功了。

想確認的話，打 `git config user.name`，它會把你的名字念回來給你。

> ⚠️ **email 不要填真的 email**，照上面的格式「名字@student.local」就好。這個只是寫在存檔點上的簽名，不會寄信給任何人。
>
> 💡 我們**沒有**加 `--global`，意思是「只在這個專案用這個名字」。學校的電腦大家輪流用，這樣才不會蓋掉別人的名字。

> **如果不對怎麼辦**
> - 跑出 `error` 或 `unknown option` → 檢查是不是少打了空格，或引號只打了一邊。整行重打一次。

---

### Part 3：把檔案放進「存檔箱」（`git add`）

存檔分兩步：**先選要存哪些檔案，再按下存檔**。第一步是這行：

```
git add .
```

⚠️ 最後面有一個**空格加一個點**。那個點的意思是「**這個資料夾裡全部的檔案**」。

然後再看一次：

```
git status
```

**完成後你會看到**：剛剛的 `Untracked files:` 不見了，變成 `Changes to be committed:`，下面的檔名前面寫著 `new file:`，通常是**綠色**的。

意思是：「這些檔案已經放進存檔箱了，等你按下存檔。」

> **如果不對怎麼辦**
> - 輸出沒變 → 你可能漏了最後的點，或點跟 `add` 之間沒空格。重打 `git add .`。
> - 跑出一堆 `warning: LF will be replaced by CRLF` → 這是正常的提醒，**不用理它**。

---

### Part 4：按下第一個存檔點（`git commit`）

```
git commit -m "first save"
```

`-m` 後面引號裡的字，是你幫這個存檔點取的**名字**，像遊戲存檔欄位上寫的「第一關打完」。

**完成後你會看到**：

1. Terminal 跑出幾行，裡面有 `root-commit`、`first save`，還有 `files changed`（有幾個檔案被存進去）
2. **左邊 Explorer 裡檔名的顏色和 `U` 不見了**——意思是「這些檔案都已經存好了」

> **如果不對怎麼辦**
> - 跑出 `Please tell me who you are` → 你還沒做 Part 2。回去做完，再打一次 `git commit -m "first save"`。
> - 跑出 `nothing added to commit` → 你跳過了 Part 3。先打 `git add .`，再 commit。
> - Terminal 突然變成一個奇怪的畫面，很多 `~` 符號、打字沒反應 → 你忘了打 `-m "..."`，跑進了一個文字編輯器。按 `Esc`，再打 `:q!`，按 `Enter` 就能離開，然後重打完整的那一行。
>
> 💡 存檔點的名字用**英文**，有些電腦的 Terminal 顯示中文會變亂碼。

---

### Part 5：看看你的存檔紀錄（`git log`）

```
git log --oneline
```

**完成後你會看到**：一行字，像 `a1b2c3d (HEAD -> master) first save`。

- 前面那串亂碼一樣的字母數字，是這個存檔點的**編號**（每個人都不一樣）
- 後面的 `first save` 就是你剛取的名字

> **如果不對怎麼辦**：如果最下面出現 `(END)` 或 `:` 打不了指令 → 按一下 `q` 就會回來。

---

### Part 6：故意把檔案改壞（今天最好玩的一步）

1. 打開 `index.html`
2. **大膽地改壞它**：把一半的內容刪掉，或是亂打一串字（例如 `asdfghjkl`）
3. 存檔（`Ctrl + S`）
4. 回到 Terminal：

```
git status
```

**完成後你會看到**：出現 `modified: index.html`（通常是**紅色**）。

🤔 **還記得上週嗎？** 上週你改 `index.html`，`git status` 一點反應都沒有。**今天它看出來了！** 因為現在有了存檔點，Git 會拿你的檔案跟存檔點比，一有不一樣就知道。

再打這一行，看看**到底改了什麼**：

```
git diff
```

**完成後你會看到**：**紅色**、前面有 `-` 的是被你刪掉的；**綠色**、前面有 `+` 的是你新打的。看完按 `q` 離開。

> 🔍 把 `git diff` 的畫面**截圖**。

---

### Part 7：用存檔點把它救回來（`git restore`）

```
git restore index.html
```

**完成後你會看到**：

1. Terminal 什麼都沒跑出來（又是「沒訊息就是成功」）
2. 回去看編輯器裡的 `index.html`——**你刪掉的內容全部回來了，亂打的字不見了！**
3. 再打 `git status`，會看到 `nothing to commit, working tree clean`，意思是「跟存檔點一模一樣，沒有任何改動」

> **如果不對怎麼辦**
> - 編輯器裡看起來還是壞的 → 在左邊 Explorer 點一下 `index.html` 重新打開它。
> - 跑出 `'restore' is not a git command` → 你的 Git 版本比較舊，改打 `git checkout -- index.html`，效果一樣。
> - 跑出 `did not match any file` → 檢查檔名有沒有打錯，大小寫和 `.html` 都要一樣。

---

### Part 8：按下第二個存檔點

真正的工程師會**改好一點就存一次**。現在來存第二個：

1. 打開 `about.html`，在 `<h1>關於我</h1>` 下面加一行，寫一句你自己的介紹，例如 `<p>我喜歡打 Minecraft</p>`
2. 存檔（`Ctrl + S`）
3. 在 Terminal 一行一行打：

```
git add .
```

```
git commit -m "add about me"
```

```
git log --oneline
```

**完成後你會看到**：`git log` 現在有**兩行**了，最上面是最新的 `add about me`，下面是 `first save`。

你的專案現在有兩個存檔點了 🎉

---

### 成功的樣子

- `git log --oneline` 看得到**兩個存檔點**（`first save` 和 `add about me`）
- 你親手把改壞的 `index.html` 救回來了，`git status` 顯示 `working tree clean`
- 你說得出：**為什麼上週改 `index.html` 看不出差別，今天看得出來**
- 截圖包含：**`git diff` 的畫面 ＋ 最後 `git log --oneline` 的兩行**
- 舉手告知老師 ✋

## 問 AI 的方式（Lab Terminal）

概念問題問 Lab Terminal：

> 「`git add` 和 `git commit` 差在哪裡？為什麼存檔要分兩步？用打電動來比喻。」

> 「commit 是什麼意思？為什麼每個存檔點都要取名字？」

> 「`git restore` 是怎麼知道檔案原本長什麼樣子的？」

📌 **Prompt 小技巧**：卡住的時候，把 Terminal 的**整段英文**複製貼給 Lab Terminal，再加上「**我剛剛打的指令是＿＿＿，我想做到＿＿＿，這段在說什麼？下一步該打什麼？**」。告訴它你**想做什麼**，它才知道要怎麼幫你。

## 老師筆記

（給老師的提示，不顯示給學生）

- **常見問題**：
  - `Please tell me who you are`：沒做 Part 2。本週刻意用**不加 `--global`** 的 repo 層級設定，避免共用電腦互相覆蓋；若學生自己加了 `--global` 也能用，不必糾正。email 一律用假的 `名字@student.local`，**不要讓學生填真實 email**。
  - 忘記 `-m` 掉進 Vim：`Esc` → `:q!` → `Enter`。這是本週最容易嚇到學生的地方，巡視時留意畫面滿是 `~` 的學生。
  - `git log` / `git diff` 停在 `(END)` 或 `:`：按 `q`。
  - W03 沒完成的學生：Part 1 的「如果不對」會引導補 `git init` 和 `about.html`，約多 5 分鐘。
  - `LF will be replaced by CRLF` 警告：正常，忽略。
  - Git 版本太舊沒有 `restore`（2.23 以前）：用 `git checkout -- index.html`。
  - 預設分支名可能是 `master` 或 `main`，都正常，不用解釋。
- **本週的核心概念**：W03 的 🤔 留了伏筆「沒有存檔點就看不出改了哪裡」，Part 6 是收線的地方。能用自己的話說出「Git 拿檔案跟存檔點比」的學生，就達成本週目標。
- **翻轉教育提示**：Part 7 救回來那一刻是全班最有反應的時候，可以請先做完的學生示範給旁邊同學看。
- **延伸挑戰**：刪掉整個 `about.html` 再 `git restore`；`git log` 完整版裡找自己的名字；問 AI 怎麼回到更早的存檔點（只問不做，`git checkout <編號>` / `git reset` 留到之後）。
