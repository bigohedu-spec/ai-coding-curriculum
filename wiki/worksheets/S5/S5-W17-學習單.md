# S5 W17｜進階功能二（自選）：由你決定專案的下一塊拼圖 學習單

> 模組三 進階功能（W13–W18）。W16 大家一起做「外部 API」；**W17 換你當家**——從下面的菜單挑**一個**你專案最需要的進階功能，自己做進去。

## 今天的冒險

到這週，你的專案**已經上線了**（Big-Oh 平台），而且**雲端資料（平台的 `BO`）也在線上**、你也做過**真實登入**——這代表你的功能不用再只存在自己電腦裡了。

今天沒有規定做哪個功能。**你是 PM，你決定「我的專案接下來最需要什麼」**，從菜單挑一個，用 Copilot Chat 幫你實作、整合進專案。

> **這週的新規矩（因為你的專案已經上線 + 有雲端 BO + 有登入）**：
> - 需要「記住」的東西 → **存到平台的 `BO`（`await BO.set/get`），不要只存 localStorage**（這樣換裝置、重新登入都還在）。
> - 能綁使用者的 → **綁登入的使用者**（每個人看到自己的資料）。
> - 做完要能在**已部署的網站（`.bigoh.uk`）**上運作——`BO` 由平台自動注入，**不需 import、不需金鑰、不需網址**（第十四節）。

## 任務 A｜從菜單挑三個進階功能，做進你上線的專案 ⭐ 250 金幣

**目標（開放，自己決定）**：從下面菜單挑三個跟你專案有關的**功能，用 Copilot Chat 實作、整合進專案，並確認它在**上線的網站**上運作。

> 每個功能都附一段**起手 prompt**——這是「起點」不是「答案」（第十七節）。你要把 `___` 換成你自己的檔名／存檔名／使用者 id，再依 Copilot 給的結果**測試、修正、迭代**。
> 用到雲端存讀時，直接用平台的 `BO`（`await BO.set('key', 值)` / `await BO.get('key')`）——**不需 import、不需金鑰、不需網址、不需申請帳號**，平台自動注入。

**📌 起手 prompt 裡的 `___` 怎麼找**

| 要填的 | 是什麼 | 去哪找 |
|--------|--------|--------|
| **檔名**（`#file`、檔名） | 這個功能要改的檔案 | 看 VS Code 左邊「檔案總管」，找你一直在編輯的那個檔（通常是 `index.html`、`app.js`，遊戲則是 `game.js`）。在 Chat 打一個 `#` 會跳出檔案清單，直接選就好。 |
| **存檔名**（`BO` 的 key） | 資料要用哪個名字存上雲端 | 這是**你自己決定的名字**（例如 `theme`、`achievements`、`scores`）。存的時候用 `BO.set('存檔名', 值)`，讀的時候用同一個名字 `BO.get('存檔名')`——**不需開帳號、不需金鑰**。 |
| **使用者 id** | 現在登入的是誰 | 你之前做「真實登入」時，登入成功後系統就記住了目前使用者。不知道它存在哪 → 直接問 Copilot：「我登入後，現在這位使用者的 id 存在哪個變數？怎麼在程式裡拿到？」 |
| **條件／清單**（例：成就的達成條件、隨機事件清單） | 這是**你自己決定的內容** | 不用「找」——照你專案想要的規則填（例如「破 10 關」「打敗 Boss」；事件清單自己想 3–5 個）。 |

> 找不到、或不確定填得對不對 → 先問 **Lab Terminal / Copilot**，再問同學，最後才問老師（第十七節求助順序）。

### 🅰️ 存雲端 `BO`、綁使用者的功能（記得住、跨裝置）

**1. 使用者設定（深色模式／個人偏好）**
- 更新後做法：偏好存雲端 `BO`（綁登入使用者），登入後自動套用——不再只存 localStorage。
- 起手 prompt：
  > 「我的專案已上線、有登入（使用者 id 是 `___`），平台提供一個全域的 `BO`：`await BO.set('key', 值)` 存上雲端、`await BO.get('key')` 讀回來，不需 import／金鑰／網址。幫我做一個深色模式切換鈕：使用者選了之後，用 `BO.set('theme-使用者id', 主題)` 把主題存上雲端，下次他從任何裝置登入都自動套用上次的主題。」

**2. 成就系統**
- 更新後做法：達成條件解鎖成就 → 存雲端 `BO`（綁登入使用者），跨裝置保留。
- 起手 prompt：
  > 「平台提供全域 `BO`（`await BO.set/get`，免金鑰）。幫我做成就系統：當使用者達成某條件（例如 `___`）就解鎖一個成就，用 `BO.set('achievements-使用者id', 成就清單)` 存上雲端，並用 `BO.get` 讀回來、在頁面上顯示這位使用者已解鎖的成就清單。」

**3. 商店系統**
- 更新後做法：金幣餘額與已購道具存雲端 `BO`（綁登入使用者），買完即時更新畫面與雲端。
- 起手 prompt：
  > 「做一個商店：玩家用遊戲金幣買道具。用平台的 `BO`（`await BO.set/get`，免金鑰）把 `coins` 餘額和 `owned_items` 存上雲端（綁登入使用者），按下購買時檢查金幣夠不夠、扣款、把道具加入 owned_items，並即時更新畫面。」

**4. 升級系統**
- 更新後做法：等級／經驗值存雲端 `BO`（綁登入使用者），達標升級並保存。
- 起手 prompt：
  > 「幫我做升級系統：使用者累積經驗值 `xp` 到門檻就升一級。用平台的 `BO`（`await BO.set/get`，免金鑰）把 `level`、`xp` 存上雲端（綁登入使用者），每次變動就更新，畫面顯示目前等級和離下一級還差多少。」

**5. 雲端排行榜（取代本地排行榜）**
- 更新後做法：用平台內建的排行榜功能送分／讀榜——因為資料在雲端，大家看得到彼此。
- 起手 prompt：
  > 「平台提供全域 `BO` 的排行榜功能（免金鑰）：`await BO.score('main', 分數)` 送分、`await BO.top('main', 10)` 拿前 10 名（名字由平台決定，不用自己傳）。遊戲結束時送出玩家分數，再讀出前 10 名，顯示成排行榜。」

### 🅱️ 純前端 / 平台 `BO` 動態功能（不需另接資料庫）

**6. 隨機事件**
- 做法：純前端 `Math.random()`，不需雲端。
- 起手 prompt：
  > 「幫我在遊戲每一回合用 `Math.random()` 從我給的事件清單（`___`）隨機挑一個事件，顯示事件說明並套用它的效果。」

**7. 多人輪流模式（同一台電腦）**
- 做法：用狀態管理記「輪到誰、各自分數」；想保留對戰結果可再用 `BO.set` 存上雲端；想做「不同電腦連線的線上多人」可用平台的 `BO.room`。
- 起手 prompt：
  > 「幫我做兩個玩家在同一台電腦輪流的模式：用狀態管理記錄現在輪到哪位玩家、兩人各自的分數，畫面清楚顯示現在輪到誰、目前比分。」

**8. 題庫問答（自備題庫 + 雲端排行）**
- 做法：外部網站的題庫 API 會被平台的安全機制（CSP）擋掉，改成**把題目直接寫在專案裡**（自己準備一組題目陣列），「活的資料」用平台 `BO` 的排行榜達成——記錄大家的答題分數。
- 起手 prompt：
  > 「幫我做一個問答遊戲：題目直接寫在專案裡（我給你一個包含題目和四個選項的陣列，正確答案和錯的要打散），答對加分。遊戲結束用平台的 `await BO.score('quiz', 分數)` 送分、`await BO.top('quiz', 10)` 顯示排行榜（免金鑰、免網址）。」

> 想做**天氣／匯率**之類「即時變動的資料」？在 Big-Oh 平台上，作品不能去抓別人網站的 API（會被平台安全機制擋掉）。想讓作品「有活的資料」，改用平台 `BO` 的動態功能達成同樣效果：排行榜（`BO.score/top`）、計數器（`BO.bump`）、留言板（`BO.post/list`）、多人房間（`BO.room`）——不算新功能，但也歡迎自選。

**成功的樣子**：打開你**上線的專案**，這個新功能可以被實際操作；需要記住的資料**重新整理或換裝置後還在**（存進雲端 `BO` 了）。

## 工具操作（照做，不用問老師）
1. **開啟 Copilot Chat**：`Ctrl+Shift+I`（Mac：`Cmd+Shift+I`）。
2. **用 `#file` 把要改的檔案帶進對話**（讓 Copilot 接到你現有專案），貼上你選的起手 prompt（填好 `___`）。
3. 要雲端存讀／排行 → 直接用全域的 `BO`（`await BO.set/get`、`BO.score/top` 等），**不需 import、不需金鑰、不需網址**（平台自動注入）。
4. **插入程式碼 → 存檔（`Ctrl+S`）→ Live Server 測試**（`BO` 功能要到線上版才測得到，本機沒有 `BO`）。
5. **推上線（Big-Oh）**：在專案根目錄的終端機跑 `node bigoh.mjs deploy`（沿用之前設定好的專案；還沒登入過就先跑 `node bigoh.mjs login`，照畫面到 `bigoh.uk/cli` 輸入代碼授權——這一步要你本人做）。成功會印出 `https://<你的名字>.bigoh.uk`，打開確認**線上版**也能用（重跑同 slug＝更新、網址不變、免審核即時上線）。
6. **截圖**線上運作畫面，舉手告知老師。

**如果不對怎麼辦**：
- 本機好、上線壞 → 記得 `BO` 只有在 `.bigoh.uk` 線上版才有（本機開 `BO` 是空的）；若是去抓別人網站的 API，會被平台擋掉，改用 `BO` 的動態功能。把 Console 紅字貼回 Chat（`BO` 的錯誤訊息是中文）。
- 資料沒存進去 → 檢查 `BO.set` 和 `BO.get` 用的是不是同一個 key、有沒有加 `await`，把錯誤訊息貼回 Chat。

## 老師筆記
- **本週重點是「選擇 + 用對持久化」**：專案已上線（Big-Oh）、雲端 `BO` 可用，學生要練「這個資料該存雲端 `BO` 還是前端」的判斷，不是照抄功能。
- **工具政策（第十四節）**：雲端一律用平台自帶的 `BO`（免 import／金鑰／網址，平台自動注入）；作品內不能去抓外部 API（CSP 會擋），改用 `BO` 動態功能（排行／計數／留言／多人）；**不要 Firebase／Supabase、不要學生自己申請帳號、不要在前端放任何金鑰**。
- **作品導向（第十二節）**：驗收看「功能在**他上線的專案（`.bigoh.uk`）**裡運作、資料真的用 `BO` 存進雲端」，不是本機 demo（本機沒有 `BO`）。
- **常見問題**：本機 `BO` 是空的（要在 `.bigoh.uk` 線上版測）；去抓外部 API 被 CSP 擋 → 改用 `BO` 動態功能；資料存不進 → 檢查 key 一致、有沒有 `await`。
- **延伸挑戰**：把這週的功能和舊功能串起來（例如成就 + 雲端排行榜）。
