# [S5-W15] AI 對話閱讀理解：遊戲開發模擬器（躲隕石）｜Lab Terminal 互動課程 開發規格

> 給工程 LLM（Copilot / Claude）的建置文本。產出**單一 HTML、純前端、可離線**的 Lab Terminal 互動課程；視覺/音效全程序化（不依賴外部圖片音檔）。
> 難度：**G3（高年級 Step Flow）**　|　修訂：2026-06-24（依開發團隊「教案設計指南」重構）
> 設計準則：`skills/labterminal-course-spec/reference/lesson-design-guide.md`（站結構 + 十大原則）＋ CLAUDE.md 第二十節。

## 0. 建置摘要（先讀）
- **目標**：一條「有產出的旅程」——AI 帶學生把「**躲隕石遊戲**」（太空船左右閃避掉落隕石）從一句話想法做到正式發布。每站教一個開發概念，學生**讀懂 → 動手下白話指令 → 看到遊戲一塊塊長出來**。
- **每站結構**：① 讀懂（AI ~150 字，術語配比喻）② 理解題×2（混淆干擾項、答錯永久鎖定、選項洗牌）③ 填空（該專有名詞）④ **白話下指令 prompt**（學生用一句白話說這步想讓遊戲做到什麼 → **AI 判讀**清晰/方向/相關）⑤（可選）二選一決策 → 完成後**左側資料夾多一個檔案、右側遊戲預覽長出一塊**。
- **硬性修正（對照舊版）**：prompt **白話、不逼學生講術語或檔名**（術語只用②③考）；通過與否**交 AI 判讀，不用關鍵字窮舉**。
- **技術**：原生 HTML/CSS/JS 單檔、純前端、離線；`localStorage` 記進度；金幣**綁帳號**（跨裝置、不重複刷）。禁 emoji，圖示程序化或 `assets/icons/`。
- **核心訊息（key message）**：「看懂 AI 對話裡的專有名詞，用白話把想法交給 AI，一款遊戲就一步步做出來、上線。」出現 ≥5 處。

## 2. 核心訊息與遊戲化承諾
- **key message**：見 §0。**5 處**：start Hook／每站白話 prompt 過場／Rehearsal／總複習考試前引言／done 徽章。
- **Hook 視覺承諾（start）**：畫面左側「專案資料夾」（空的）＋右側「遊戲預覽視窗」（只有一艘不會動的太空船）。承諾：你會親手把資料夾填滿、把這個遊戲做到能玩、上線。
- **Deliver（done）**：資料夾長滿檔案、右側躲隕石遊戲**可實際試玩幾秒**（程序化）、顯示「你的遊戲上線了！」＋徽章牆。

## 3. Screen 規格

### 3.1 站結構（taskA/taskB 內每一站共用；遵循 lesson-design-guide）
每站 4–5 步，全繁中、術語配比喻：
1. **讀懂**：AI 對話泡泡 ~150 字，情境中解釋概念（例：框架＝蓋狗屋不必請建築師）。
2. **理解題 ×2**：選擇題，干擾項＝似是而非混淆點；**答錯永久鎖定、選項洗牌**。
3. **填空**：填該專有名詞（接受中英/同義）。
4. **白話下指令 prompt**：學生打一句白話（例「幫我做一個讓太空船左右移動的功能」）→ **AI 判讀**（清不清楚、方向對不對、跟這遊戲相不相關；用該站 goal 當判準，**不做關鍵字窮舉**）→ 過關並「動手」。
5. **（可選）二選一決策**：每選項附一句後果；無答錯鎖；選擇反映到後面產物與預覽。
6. **產出**：左側資料夾新增指定檔案、右側遊戲預覽長出對應一塊。

### 3.2 12 站設計表（工程 LLM 依此撰寫；已合併近義站、前置決策）
> 格式：**站. 概念〔填空答案〕**｜AI 段落要點｜理解題×2 焦點｜白話 prompt 範例（goal）｜產物檔／預覽變化｜特殊（決策/再說一次/示意）

**taskA（站 1–6，A=120 金幣）**
1. **需求〔需求 requirement〕**｜「你想做什麼遊戲？」把方向整理成使用者要什麼｜①需求 vs 功能 ②想法 vs 需求｜prompt「我想做一個太空船躲隕石的遊戲」(goal: 講出想做的遊戲方向)｜產物 `需求.txt`／預覽出現遊戲名
2. **產品經理〔PM／產品經理〕**｜決定做什麼、把需求排清單的人＝PM；今天你就是 PM｜①PM 做什麼 ②PM vs 工程師｜prompt「先做太空船會動，再做隕石」(goal: 排出先後順序)｜產物 `功能清單.txt`／預覽出現清單
3. **核心玩法〔核心玩法〕**｜一款遊戲最關鍵、拿掉就不好玩的那件事｜①核心玩法 vs 裝飾 ②躲隕石的核心是什麼｜prompt「核心是左右移動閃過掉下來的隕石」(goal: 說清楚核心玩法)｜產物 `玩法.txt`／預覽隕石開始掉落示意｜**決策**：〔A 只閃避／B 閃避+撿道具〕各附後果
4. **單人/多人〔多人 multiplayer〕**｜一個人玩 vs 揪人一起玩（比喻：自己投籃 vs 揪人打球）｜①單人 vs 多人差別 ②多人要多做什麼｜prompt「這個版本先做單人」(goal: 決定人數模式)｜產物 `模式.txt`｜**決策**〔A 單人／B 多人〕＋**誠實示意**：選 B 也只顯示「多人今天先做示意，實際連線之後才做」，不假裝連線
5. **技術選型〔技術選型〕**｜用什麼做：網頁+畫布就夠，不必搬大框架（比喻：蓋狗屋不請建築師）｜①框架是什麼 ②何時該用/不用框架｜prompt「用網頁和畫布做就好」(goal: 選出合適技術)｜產物 `game.html`／預覽出現畫布黑底｜**決策**〔A 純網頁畫布／B 大框架〕＋後果｜*註：檔名 game.html 從這站後才出現（原則④）*
6. **原型〔原型 prototype〕**｜先做能動但還沒真功能的版本，用來試方向｜①原型 vs 成品 ②為何先做原型｜prompt「先讓太空船出現在畫面下方」(goal: 做出可見雛形)｜產物 `game.js`／預覽太空船出現

**taskB（站 7–12，B=130 金幣）**
7. **UI/UX〔UI／UX〕**｜UI＝畫面長相；UX＝順不順手｜①UI vs UX（分數字太小是哪種問題）②好看 vs 好用｜prompt「把背景改深藍、放一個大大的開始按鈕」(goal: 調整外觀)｜產物 `style.css`／預覽套色+開始鈕
8. **功能〔功能 function〕**｜把清單上一項做成真的能用（這步就是在跟 AI 協作）｜①功能 vs 想法 ②一次做一個功能｜prompt「幫我做讓太空船左右移動的功能」(goal: 做出一個可操作功能)／預覽太空船可左右移動｜**再說一次**：學生若沒說方向 → AI 反問「往左右還是上下？」→ 補述才過
9. **變數〔變數 variable〕**｜會變的值（分數、生命）用變數存（比喻：便條紙）｜①變數 vs 固定值 ②分數該用什麼存｜prompt「加一個分數，每閃過一顆隕石加 1 分」(goal: 用變數記錄分數)｜產物更新／預覽出現分數
10. **迭代〔迭代 iteration〕**｜測一次不夠好就改、再測、再改的循環｜①迭代 vs 一次做完 ②為何要迭代｜prompt「隕石太快了，幫我調慢一點」(goal: 依測試結果修正)／預覽隕石變慢｜**再說一次**：AI 反問「慢多少？一點還是很多？」
11. **測試與除錯〔bug／除錯 debug〕**（合併 bug/除錯/測試）｜程式出錯＝bug，找出並修掉＝除錯，全部試一遍＝測試｜①bug vs 功能 ②除錯 vs 重寫｜prompt「分數有時候不會加，幫我修好」(goal: 描述並修正一個 bug)／預覽分數正常｜*理解：發布前要測試*
12. **部署與發布〔部署 deploy／發布 release〕**｜放上網拿到網址＝部署；正式公開讓人玩＝發布｜①部署 vs 發布 ②本機 vs 上線｜prompt「我要把遊戲公開讓同學玩」(goal: 表達上線意圖)／預覽「發布」火箭動畫、遊戲可試玩｜**決策**〔A 存本機／B 放雲端〕＋**誠實示意**「今天是本機示意，真正上線步驟見下方卡」＋**深入了解折疊卡**「🔧 真實世界怎麼上線？」→ GitHub Pages / Vercel（靜態）、資料庫 Firebase/Supabase 的簡述

## 4. Rehearsal Modal（taskA / taskB 後各一，句子接龍，答對才關）
- **A 後**：「做遊戲先搞清楚使用者要什麼＝____；決定一個人玩還是揪人玩＝____；選用什麼做＝____。」正解：需求／單人或多人／技術選型。反例×3：先寫程式再說、原型＝成品、框架一定要用。
- **B 後**：「程式出錯＝____，修好＝____；放上網拿網址＝____，正式公開＝____。」正解：bug／除錯／部署／發布。反例×3：有 bug 就直接發布、部署＝發布、除錯＝重寫整個程式。

## 5. 總複習考試（Screen 4 summary，取代句子接龍）
- **9 題**橫跨整條流程（需求→PM→玩法→技術→原型→UI/UX→功能→變數→迭代→測試→部署→發布）＋真實服務（部署用什麼、資料庫用什麼）。
- 每題 4 選項，干擾項＝混淆點（原型 vs 成品、部署 vs 發布、UI vs UX、單人 vs 多人）。
- 答完顯示 **成績 X/9 + 評語（依分數分級）+ 獎勵金幣**；**每題錯的標出正解**與一句說明。
- 例：「把遊戲放上網、拿到一個公開網址，這一步叫什麼？」A 發布 B 部署✓ C 原型 D 迭代。

## 7. 資料結構與狀態（給工程 LLM）
- `STAGES`：12 筆 `{concept, term, synonyms[], passage, quiz2[], answerBlank, promptExample, goal, produces(file), previewDelta, decision?, reAsk?, honestStub?, deepDiveCard?}`。taskA 用 0–5、taskB 用 6–11。
- `SCREENS = ['start','recall','taskA','taskB','summary(exam)','wall','done']`，線性不可跳關。
- **左側資料夾 UI**：每站 `produces` 的檔名逐一出現；**右側遊戲預覽**：每站依 `previewDelta` 程序化長出一塊（太空船→可移動→分數→隕石變慢→可試玩）。
- **AI 判讀白話 prompt**：以該站 `goal` 為判準（clarity/direction/relevance）；不做關鍵字比對。`reAsk` 站第一次不足時觸發追問。
- **金幣綁帳號**：完成 checkpoint 記入帳號進度（`localStorage` + 可匯出對應第九節 Progress Record），不重複發。
- 防作弊輔助：`lockWrongOption`、`shuffleOptions`、`blockPaste`。
