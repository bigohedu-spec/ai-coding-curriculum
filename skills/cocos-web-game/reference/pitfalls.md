# 踩坑與處理

> 每一條都是**真的踩過**的，格式：**症狀 → 原因 → 怎麼處理 → 怎麼預防**。只講方法，不含任何遊戲原始碼；範例用 hc-pilot 是因為那是踩到的地方。
> 來源：負責 Cocos 的 session 交接【實做】、專案記憶【記憶】、2026-09-29 開案紀錄【紀錄】。可信度標記見 `../SKILL.md`。

## A. 建置與 Babel

### 1. `[...new Set(x)]` 讓答案比對永遠 0 分【實做】
- **症狀**：麥克風答案比對（或任何用展開 Set 的邏輯）永遠失敗；`tsc` 完全不報錯。
- **原因**：Cocos 3.8.8 的 loose Babel 把它轉成 `[].concat(set)`，得到「裝著一個 Set 的陣列」。
- **處理**：改成 `Array.from(new Set(x))`；對舊程式碼全專案搜尋展開運算子 `...` 後接可迭代物件的寫法。
- **預防**：建置後不要只信型別檢查，要實際玩到那段邏輯（見 `verification.md`）。

### 2. 對「會被重新賦值的陣列」做 `for...of` 讓整個建置中止【實做】
- **症狀**：建置失敗，錯誤指向型別推論；`tsc` 也抓不到。
- **原因**：class 欄位被 `.filter()` 重新賦值、又被 `for...of` 迭代時，Babel 的型別推論會失敗。
- **處理**：避開這個模式（建議改用傳統 `for (let i...)` 或 `forEach`，【建議，該 session 只記錄「要避開」，未逐一驗證替代寫法】）。
- **預防**：寫新程式時避開這個模式；現有程式裡仍有幾處類似寫法，目前沒爆，是否會爆**未驗證**。

### 3. 建置完用「關掉所有 CocosCreator」清殘留，會把使用者自己開的編輯器一起關掉【記憶】
- **症狀**：負責人的編輯器突然消失；`~/.CocosCreator/editor/window.json` 變成 0 bytes。
- **原因**：兩邊共用同一個執行檔名稱，用名稱關程序分不出是誰開的。
- **處理**：建置**前**記下已存在的 CocosCreator PID，建置**後**只關新出現的，再用 `taskkill /T` 關建置用的 PowerShell；等 log 出現 `gzip` 那行（代表 robocopy 已完成）才清。
- **預防**：腳本裡不要寫 `Stop-Process -Name CocosCreator`。

### 4. 編輯器開著時建置：`EPERM project.log`／`ENOTEMPTY`，結果不穩定【實做】
- **症狀**：建置印 `EPERM: open '...\temp\logs\project.log'` 或 Chromium cache 搬不動；有時仍成功（2026-09-29），有時失敗（2026-10-21）。
- **原因**：編輯器與命令列建置共用同一個專案目錄（`temp/`）。
- **處理**：關掉編輯器再建置；必須開著時，建置完務必確認結束碼與產物（grep 新程式碼）。
- **預防**：**CLI 建置也算寫入**——同一時間只能一個 session 跑建置；先確認編輯器是否開著；多個 AI session 要用訊息約定誰建置（曾有人的建置把另一人匯入一半的模型打包進去）。

### 5. 建置產物灌錯地方【實做】
- **症狀**：別人的 gpt-clone 分支多出一堆建置檔。
- **原因**：建置腳本不帶網站路徑時，預設灌進 gpt-clone **主資料夾**，而主資料夾常被其他工作占用。
- **處理**：一律明確帶 `-GptClone <要灌的 worktree 路徑>`；灌錯了要把那邊還原（【建議】`git status` 確認變更範圍後用 `git checkout`／`git clean`），並通知占用它的人。
- **預防**：腳本預設值不要指向會被占用的資料夾，或改成沒帶參數就中止。

### 6. 建置指令帶 `-ExecutionPolicy Bypass` 被自動模式擋掉【記憶】
- **處理**：直接 `& build-web.ps1 -GptClone ...` 執行；一般模式下帶 Bypass 也跑得動。

### 7. PowerShell 5.1 讀「無 BOM 的 UTF-8」腳本變亂碼【實做】
- **症狀**：腳本裡的中文字串輸出亂碼或解析錯。
- **原因**：5.1 預設用系統碼頁。
- **處理**：腳本字串用英文，或存成 **UTF-8 BOM**。

### 8. 在 worktree 跑 `npm ci` 把別人的 `node_modules` 清空【記憶】
- **症狀**：別的 session 突然整個壞掉（找不到套件）。
- **原因**：worktree 的 `node_modules` 若是 junction（捷徑）指向主資料夾，npm 會順著捷徑清掉目標。
- **處理**：先確認 `node_modules` 是不是 junction（`dir` 看有沒有 `<JUNCTION>`）；是的話不要跑 `npm ci`，改在主資料夾處理，或先移除捷徑再裝。
- **預防**：任何 worktree 動 `node_modules` 之前先檢查。

### 9. Windows 上 commit 建置產物的 `LF will be replaced by CRLF` 警告【實做】
- **處理**：這不是錯誤，可忽略。

## B. 引擎與場景

### 10. 合併網格超過 65535 頂點就壞【實做】
- **症狀**：金幣山堆太高時網格錯亂或消失。
- **原因**：單一合併網格的頂點上限 65535；一枚金幣約 70 頂點 → 約 880 枚就爆。
- **處理**：加數量上限（超過不再增加或改用多個網格）；設計時先算頂點預算。

### 11. 隱藏的物件還留著碰撞，造成「鬼擋牆」【實做】
- **症狀**：看不見的東西擋住玩家（例：被隱藏的展示台）。
- **原因**：碰撞體清單沒跟節點的顯示狀態連動。
- **處理**：碰撞體綁節點，判定時節點無效或 `activeInHierarchy=false` 就跳過。

### 12. 開物理引擎模組讓下載多 0.5～2 MB【實做】
- **處理**：不開；需要的物理（例如一顆球）自己寫簡易剛體。引擎模組在專案設定的「功能裁剪」裡關。

### 13. 素材太大、超過預算
- **預算**：建置 gzip 後首次可玩前 ≤ 5 MB、整款 ≤ 8 MB、單檔 ≤ 500 KB。
- **處理**：素材進專案前轉 WebP、縮到實際顯示尺寸的 1～2 倍；原檔（AI 生圖、`.blend`）放專案外或 `_source/`，不參與建置；多零件的 glb 拆成一個零件一個檔案可再省數百 KB。

## C. 存檔與進度（最容易出大事）

### 14. 讀檔順序有依賴，導致某週沒開、已付一半的錢消失【實做】
- **症狀**：學生進度回到錯的週次；展示品付了一半的錢不見。
- **原因**：週次旗標、過關紀錄、已購買清單的讀取順序，會影響「現在輪到誰」，某個旗標被存檔值蓋回預設。
- **處理**：改存檔結構時**逐欄確認「存了、讀了、讀的順序」**，並用真實學生存檔做前進推演（見 `verification.md`）。

### 15. 存檔檢查的白名單把「新值域」刪掉【實做】
- **症狀**：升級後讀檔，任務進度歸零、重新打勾。
- **原因**：存檔檢查程式只接受舊值域（只收 1、2），遇到新值（3）就當成壞資料刪掉。
- **處理**：新增存檔欄位或擴大值域時，**同步改存檔檢查的白名單**；改完用升級前的舊存檔讀一次。

### 16. 離線獎勵、金額鎖在讀檔完成前就算【實做】
- **症狀**：獎勵照錯的目標算（例如算到不該有的解鎖格價錢）。
- **處理**：等週次、過關紀錄、已購買清單都讀完才計算。

### 17. 寫了總完成鎖，學生隔週進不來【實做】
- **處理**：多週共用一個遊戲時，**不要寫整個遊戲的完成鎖**；每週過關各記一筆（`prog.weeks[週]` 與網站的 `game:<系列>wNN`）。寫了鎖又沒登記後台重做入口，破關即永久鎖死（資料庫規則禁刪）。

### 18. 遊戲的週標題、教案、進課動畫三邊分叉【實做】
- **症狀**：教案寫「輸送帶」，遊戲已是「蛋糕自動化」。
- **處理**：改遊戲的**同一個 commit** 一併改教案、學習單、進課動畫與 `implementation-status.md`；以遊戲程式為準。

## D. 檔案與協作

### 19. 工具回報「寫入成功」但檔案沒變、或被別的 agent 蓋掉【實做】
- **處理**：寫完**重新讀取**確認；改超大檔案時，用「舊字串必須恰好出現一次才替換」的修補腳本（預檢全部通過才寫入），避免 `sed` 在 CRLF／中文／反引號上出事。

### 20. 學生資料出現在公開網址【實做】
- **症狀**：測試頁把學生存檔直接嵌在 `public/` 下，部署後公開。
- **原因**：`.git/info/exclude` 對 `vercel --prod`（從本機上傳）**無效**。
- **處理**：寫進 `.vercelignore`；測試頁與存檔放在 repo 外。（【建議】若已部署過，立刻移除該檔並重新部署，評估是否需要通知負責人。）

### 21. 重匯 Blender 模型後，其他模型的位元組也變了【記憶】
- **症狀**：只改一頂帽子，卻有好幾個 glb 出現差異。
- **原因**：匯出參數與 Blender 版本相關；Blender 4.5 的 glTF 匯出參數與腳本不相容。
- **處理**：用 **Blender 3.6** 跑；重匯後沒改到的檔案用 `git checkout` 還原。

### 22. 規格書落後程式【實做】
- **處理**：衝突時以程式與任務表為準，再回填規格；規格裡沒實測的數值標【假設】。

## E. 安全（要負責人決定的）

### 23. 公開 API key 可讀寫存檔
- **現況**：`firestore.rules` 的 `gameProgress` 目前 `allow read, create, update: if true`，拿到公開 API key 的人都能讀改學生存檔；有加強規則的分支存在，何時上線未定【未驗證現況】。
- **處理**：不要在文件、PR 或截圖裡貼學生 uid／存檔；測試只讀、且不寫回。
