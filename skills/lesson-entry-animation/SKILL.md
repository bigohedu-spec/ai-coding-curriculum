# 進課動畫製作（lesson-entry-animation）

目標：**之後 200 支以上**的進課動畫都用同一套製程做，每堂課幾乎只寫「腳本＋資料」。活範例：**P 系列看 P1U-W13「小熊麵包坊」**（`/entry/play/P1U-W13`）；**S 系列看 S2-W03「阿問偵探社・第三話」**（`/entry/play/S2-W03`，負責人 2026-10-12：「這次的內容我滿喜歡的」）。做新課前先打開對應系列的範例看一遍。

> 使用者是負責人：**他要親眼看到、親手玩到才算通過**。我自己驗的只能說「我驗了什麼」，不能說「通過」。回覆一律繁體中文（台灣用語）。

## 1. 流程（每一關通過才進下一關）

```
S0 資料盤點 → Gate A 腳本 → Gate K 主題包 → 動態（頁面）→ 旁白＋字幕 → 配樂 → 版面掃描／自檢 → Gate G 真實 Chrome 驗收
```

1. **S0 資料盤點**：從 wiki 找本週學習單、教案、角色設定、上週重點。**缺資料就明講缺什麼與預設**，不要編成官方內容。（P1U W12 就缺學習重點，所以複習改成「技能複習」：用鍵盤打名字。）
   - **一定要打開遊戲本體看**（`public/games/…`）：規格文件常和成品不一樣（S2-W03 規格寫小美、阿民、長度滑桿、8:30；遊戲是老陳等五人、兩個追問按鈕、8:40）。**動畫一律照遊戲**，差異寫進腳本。可派 Explore 子代理讀遊戲檔，回報角色、開場台詞、色票、美術檔、劇透位置；回來的重點自己抽查原檔。
   - **畫風照遊戲本體，美術優先直接用遊戲現成的圖**（縮成 WebP 放進主題包，不改遊戲原檔）；遊戲裡沒有的角色才另外生圖，圖到之前用暫代。
2. **建骨架**：`node scripts/lesson-entry/new-lesson.mjs --code <堂代號> --title "<標題>" --cuts <頁數> [--grade 1] [--kit bakery] [--interactive 2,8] [--chant 6]`（加 `--dry-run` 先看）。會產生腳本、審稿紀錄、頁面骨架並登記路由與配樂計畫。
3. **Gate A 腳本**：填 `docs/lesson-entry/<代號>/script.md`，附「待你決定」並標推薦。**負責人說「通過」才往下做**。他會要求修改，逐項照做、改版號、記錄在審稿紀錄。
4. **Gate K 主題包**：確認要用的主題包（`public/lesson-entry/kits/<名>/`）有沒有缺的角色／道具。缺就給負責人 ChatGPT 提示詞（見 THEME-KIT.md），他生圖後我用 `scripts/lesson-entry/slice_sheet.py` 切圖。**缺的先用暫代素材並標註**。
5. **做頁面**：改 `src/components/lessonEntry/lessons/<ID>.ts`。大部分頁用 `makeTalkPage`（設定即可）；特殊頁自己寫元件（範例見 `flow/steps.tsx`）。
6. **旁白＋字幕**：P 系列動物語；S 系列語音生成配音（先出試聽頁選聲線，見 VOICE-TTS.md）。字幕＝旁白的字。
7. **配樂**：`config/lessonEntry/musicPlan.ts` 的 `autoPlan` 是起點，之後依腳本手調。
8. **自檢**：版面掃描、音樂自檢、定格看每一頁（見 CHECKLIST）。
9. **Gate G**：請負責人在真實 Chrome 玩一輪；他會逐項回報要改的，逐項處理並回報「做了哪些、沒做哪些」。

## 2. 不可違反的規則（都是負責人定的）

**內容與教學**
- **資訊提供完整才開放作答**（負責人 2026-10-19）：情境、具體內容、題目及必要說明／示範尚未完整呈現，或對應旁白尚未播完時，答案按鈕必須保持鎖定；滑鼠、觸控、Enter／空白鍵與快捷鍵都不能提前判答、截斷說明或換題／換頁。鎖定中的輸入不得排隊，在開放作答後補送。以實際內容與音檔完成時間解鎖，每題重設；提示倒數從開放作答起算。答題回饋／解說播完前也不得靠連點跳過。驗收要涵蓋播報中搶按、按住鍵盤到解鎖、正常作答及下一題重新鎖定。
- **直接進主題**，不說「上課囉」。流程：直接進主題 → 複習上週 → 故事與今天目標 → 課程重點 → 口訣 → 出發。
- **P 系列（小一）**：比例約 故事 60／重點 30／複習 10；**複習要隱晦**（不出題、不說「這是複習」，讓小朋友做上週學的事，例如用鍵盤打名字）。
- **S 系列（小三以上）**：負責人要求**明確的「上週複習」與「本週重點」**（S2-W03：複習約 20%、重點約 45%）——上週重點全部複習＋互動題＋上週口訣；本週重點頁像筆記一條條寫上去、打勾。
- **互動頁沒人操作就指引**；選錯不扣分、可重選。**每按一次（按錯也算）就重新計時，亂點永遠不會觸發提示**。
  - P 系列（小一）：約 9 拍（5.4 秒）沒動作 → 角色再說一次或提示、對的按鈕外圍跳光圈。
  - **S 系列（小三以上）**（負責人 2026-10-12：要等久一點，S2 應該要有基本判別的邏輯）：**25 拍（約 15 秒）沒按 → 只重念題目、不標答案；再 15 秒還沒按 → 才念提示句＋正確按鈕發光**；換題重新算。用 `DetKit.HINT_AFTER`（`makeChoicePage` 已內建）。
- **選擇題每次播放都要重新排順序**（負責人 2026-10-12：照順序點下去就全對，學生沒有真的複習）：題目順序隨機、每題按鈕順序隨機；3 個以上選項時相鄰兩題的正確答案不在同一顆、不能剛好 1、2、3、4 依序；2 個選項每題獨立隨機。用 `DetKit.planOrder()`（`makeChoicePage` 已內建）。
- **題目卡片要有題目內容**（負責人：只有一行情境＋問號太奇怪，學生連結不到）：卡片三段＝**情境 → 對方說的話／眼前的東西（具體內容）→ 題目句**（例：「弟弟跌倒了」→ 弟弟「嗚嗚……膝蓋好痛……」→「要用哪一種語氣跟他說？」）；答對後中間換成正確的結果。
- **防洩漏**：不預先演出正確順序／答案／失敗後果；用轉場雲、問號遮住過程。
- **個資**：打的名字只留記憶體；只回報「相符與否、次數、舉手」，不上傳名字內容。
- 打字互動：只收英文字母、一定按 Enter、打不對只說「你的名字好怪喔：〔內容〕」讓他再打，次數不限。

**畫面**
- 風格：**照該課遊戲本體的畫風**（P1U-W13 麵包坊＝風格 C 剪影色塊；P1U-W07＝遊戲的紙＋墨；S2＝遊戲的深藍＋紙色＋金、直接用遊戲美術）。**不要 SVG 手畫、不要 3D**（負責人否決過）。
- **文字絕不能超出舞台**（字幕自動縮小；使用者輸入要限制顯示）。**UI（字幕、對話框、卡片）與道具／角色不可互相遮擋**。每頁都要跑版面掃描、遮擋檢查、旁白間距檢查（`__scan`、`__sweepOverlap`、`__cueCheck`，見 CHECKLIST B／B2）。
- 動作用「兩格一動」＋擠壓拉伸；場景物件**跟著音樂拍子晃動**；背景與店面要有環境動畫（煙、香氣、光暈、小鳥、蝴蝶…），**淡淡但不停**，避開字幕區。
- 字型：P 系列用 `Bpmf GenSen`（注音畫在字右側）；**S 系列遊戲沒注音，動畫也不加**（`Noto Sans TC`，`Sub` 傳 `font`）。**每個元素都要自己設 font-family**（全站 CSS 會把所有元素設成等寬字）。

**聲音**

- **S5 沿用 W01／W02 的旁白（2026-10-20 定案）**：採小宇 `fQj4gJSexpu8RDE2Ii5m`＋`eleven_v4`，自然口語抑揚頓挫。先讀 [references/S5-YU-NATURAL.md](references/S5-YU-NATURAL.md)，依其中參數、後製及誤讀處理沿用；負責人已否決興奮／喜悅等情緒太滿的版本。此方案優先於下方舊的一般 TTS 做法，不改其他課已選定的角色聲線。
- **音樂是主時鐘**：從頭播到尾不中斷；畫面與旁白讀「音樂現在第幾拍」。樂器隨進度**逐層加入**；等學生操作的頁（如打名字）**不改編曲、音樂迴圈**。
- **P 系列旁白＝動物語（像動物森友會）**，不用 TTS 念整句（太空洞、有恐怖谷）。慢速咕噥效果差，所以靠**卡拉 OK 字幕**：動物一發聲，對應的字一定亮起；一次一個短句；亮起時間與發聲共用 `tokenTimes`。英文名字依音節念（`englishSyllables.ts`）。
- **S 系列旁白＝語音生成配音**（gpt-4o-mini-tts，台灣口音、堅定自然，不能有明顯非人感）；**機器人角色＝語音＋後製**（不要環形調變／降取樣，會「太電、破音」）。**台詞用完整的句子**（一句約 15～25 字），不要切得太短。細節見 [VOICE-TTS.md](references/VOICE-TTS.md)。
- **每一句旁白都要有字幕列**；口訣頁的大字跟著亮起，也不能取代底下的字幕列。
- **卡拉 OK 字幕不顯示標點，只留驚嘆號與問號**（負責人 2026-10-12：不會用逗號結尾、句號也不要有）。`，、；：。～` 一律不顯示；台詞原文照留（配音停頓、字幕切段靠它），由 `Sub`（`TRAIL_HIDE`）與大字用的 `trimTrail()` 在顯示時處理（大字行中間的標點換成空格）。自己寫的大字／口訣元件也要套 `trimTrail`。
- 說話時音樂自動壓低；峰值不爆音。

**互動頁的回饋（負責人 2026-10-12 定）**
- 學生**每按一下都要馬上有反應**：看得到（按鍵按下去、光圈）＋聽得到（`flow/sfx.ts` 的 tap）。讓他知道「有按到」。
- 按對／沒按對要**明顯不同但不罵人**：按對＝上升三音＋「撿到了！」之類的跳字＋東西飛走；沒按對＝柔和的咕嚕＋提示往哪做（對的鍵發亮），不說「錯」。完成＝小號角。
- 已開放的操作練習，動作還沒做完又按：**不要吃掉**，記起來做完照著做；此排隊規則不適用於資訊／旁白尚未完成的作答鎖定期，鎖定期不得預存答案。示範「同時按」的頁也讓學生能跟著試（`flow/feedback.tsx` 的 `useTwoHands`），做到就「做到了！」，不擋換頁。
- **兩手一起的畫面：沒按下去的鍵和滑鼠是灰色，按到了才變黃色**（`KeyCap dim`、`LiveMouse`）。
- **要學生練的動作，一定要學生真的做到才換頁**（不能只放示範、時間到就過）；每招做到不只一次（目前 2 次），進度點看得到；很久沒做到，該按的那一邊閃黃框。
- 共用元件：`useFx`＋`FxLayer`（光圈、跳字、亮晶晶）、`useTwoHands`（按住哪些 WASD、滑鼠點左／右／兩下／滾輪）、`useBeatSfx`（示範動畫的音效跟拍）。

**換頁**
- 每頁內容播完**等 2 拍就切換**，**沒有轉場、不用點**。最後一頁兩個按鈕：**開始遊戲**、**再看一次**（再看一次會讓音樂重新同步、整支重來）。

## 3. 常用指令

```bash
# 開發（在主資料夾 gpt-clone 根目錄）
npx next dev -p 3210                      # 審稿頁：http://localhost:3210/entry/play/<堂代號>
node scripts/lesson-entry/new-lesson.mjs --code P1U-W14 --title "…" --cuts 8 --dry-run
npx tsc --noEmit -p .                     # 型別檢查
uv run --with pillow --with numpy --with scipy python scripts/lesson-entry/slice_sheet.py <png> <輸出資料夾> …   # 切姿勢表
node scripts/lesson-entry/voice-build.mjs S2-W03   # S 系列：生成／更新配音（只重生改過的句子）
node scripts/lesson-entry/voice-check.mjs S2-W03   # S 系列：whisper 聽寫檢查
```
（2026-10-14 起 P1、S2 都在主資料夾 `gpt-clone` 做，不再分 worktree；審稿 dev server 一律用 port 3210，跟主站 3000 分開。）

審稿頁的「製作列」：跳到任一頁、從第幾拍開始、**定格**（看某一刻）、音樂開關與音量。瀏覽器 console：`window.__scan()`（版面）、`window.__musicCheck(8)`（音樂）、`window.__A`（音訊 API）。

## 4. 回報方式

- 做完一個階段：說明「**我驗了什麼**（具體數字／截圖）」與「**沒驗什麼**」；提供可點的網址；列出需要負責人判斷的項目（音質、好不好看）。
- 要負責人決定時：選項標編號／字母、標推薦。
- 每個里程碑 commit（訊息繁中＋英文前綴 feat/fix/docs）（`docs/lesson-entry/` 是製作規格，已列入 .gitignore、只留本機，**不要 commit、不要 `git add -f`**；commit 只放程式與素材），並把文件同步到審稿用的複本（`gpt-clone/docs/lesson-entry/`，**不要在那邊 commit**）。
- 需要 Cocos 小遊戲用同一首音樂時，傳訊息給 Cocos 負責的 session（見 PITFALLS 的「跨 session」）。

## 5. 2026-10-12～13 新增（P1U-W07 字母要塞、W15、學習單接線）

- **先看遊戲、照遊戲**（W07 第一版自己想像成深色霓虹，被負責人說「跟遊戲有點差別」）：讀遊戲的繪圖程式，配色形狀照抄；能用遊戲的圖（LOGO、徽章）就直接用。
- **遊戲有 3D 模型就預先渲染成姿勢圖**（負責人：「用 3D 模型吧，看起來挺酷」）：`scripts/lesson-entry/boss-render/`（`render.html` 用 three.js 從 CDN 渲染、正交相機、遊戲的 palette.png 貼圖；`pack.py` 裁成共用畫布＋腳底錨點的 WebP）。不要在動畫裡跑 3D。
- **遊戲機制照程式碼演**：W15 召喚＝齒輪自動飛進召喚台、放滿＋星星爆開＋煙＋震動後巨型機器人才升起、先喘氣；預警＝砸地大圓／掉鐵塊小圓／衝撞長條。不確定就問 Cocos 負責的 session（它會對照遊戲回報）。
- **P 系列互動頁沒人動就指引**：約 9 拍（5.4 秒）沒操作 → 角色指一下＋說一句（換句話說輪流）＋箭頭（目標物）或光圈（鍵盤上的鍵，不要擋到別的鍵）；有人按了就收起。
