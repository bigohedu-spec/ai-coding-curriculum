# 驗收與自檢清單

> 原則：先用「不用耳朵也能驗」的方式把能驗的都驗掉，剩下的才交給負責人。回報時分開寫「我驗了什麼」與「請你判斷什麼」。

## A. 每次改完（我自己）

- [ ] `npx tsc --noEmit -p .` 沒有錯誤。
- [ ] dev server 回 200：`curl -s -o /dev/null -w "%{http_code}" http://localhost:3210/entry/play/<堂代號>`。
- [ ] 沒有新的 console 錯誤（`read_console_messages` 只看錯誤；注意舊訊息會殘留）。
- [ ] 文件有同步到審稿複本，並重新讀取確認。

## B. 每頁都要做的版面掃描（文字不可超出舞台）

1. 開 `/entry/play/<堂代號>`，**真實點擊**「點一下開始」。
2. 製作頁已內建 `window.__sweep(頁號, 內容長度拍, 間隔拍)`：自動定格、逐拍跳到該頁並掃描，回傳超出舞台的文字（`{ "文字|方向超出px": [拍數…] }`）。例：`await window.__sweep(4, 6, 0.5)`。**也會檢查文字以外的元素**（標籤框、鍵帽、角色、道具圖，結果前面標「元素:」；負責人 2026-10-12：不要讓東西超出螢幕外）——角色從畫面外游進來也算超出，要改成在畫面裡淡入。單次用 `window.__scanAll()`。單次跳頁用 `await window.__go(頁號, 拍數)`，再 `window.__scan()`。
3. 結果必須是空陣列。互動頁另外用超長輸入再掃一次（例如 20 個字母）。
4. CSS 動畫做的頁（例如 CUT 1）在分頁被隱藏時不會前進，要在可見時掃。

## B2. 遮擋與旁白速度檢查（每頁都要做）

- **遮擋**：`await window.__sweepOverlap(頁號, 長度拍, 間隔拍)`。字幕、對話框、卡片（`data-ui`）不可蓋住角色與道具（`data-spr`，遮蓋超過 18% 就回報）；角色之間、角色與道具之間重疊超過 40% 也回報。結果必須是空的（刻意的重疊，例如小熊跑過麥子，要在回報時說明）。新加的卡片／對話框記得加 `data-ui` 屬性。
- **字幕區**：畫面底部約 45～54（cqw）是字幕區，**道具與角色的腳不要落在這個帶狀區域**；結尾這類角色會走動的頁，字幕改放上方。
- **旁白速度與間距**：`await window.__cueCheck(頁號)` 回傳每句的開始／結束拍，不可「撞到下一句」或「超過頁長」。旁白速度是 `steps.tsx` 的 `SPEECH_PER_BEAT`（目前 0.32 拍／字，負責人 2026-10-08 要求放慢）；改了速度要重跑每頁的 `__cueCheck`，並把撞到的句子往後挪。

## C. 音樂自檢（不出聲）

- `await window.__musicCheck(8)`：全部樂器 8 小節，**峰值 < 0.9**、各小節 RMS 穩定。
- 各頁的編曲計畫：逐頁加一層；互動頁不改；口訣頁只留 bass/clap/pad；最後一頁柔和。
- 對時：`window.__A.beatNow()` 與頁切換時間：內容播完後 **2 拍**切換（CUT 1：第 8 拍播完 → 第 10 拍切換）。

## D. 旁白與字幕

- [ ] 每一句旁白都有對應字幕，字幕＝旁白的字。
- [ ] **字幕與大字口訣沒有 `，、；：。～`**（只留 ！？）：逐拍跳頁讀 `[data-ui=sub]` 的文字，用 `/[，、；：。～,;:.~]/` 檢查要是 0 筆；大字行中間的標點應該變成空格，而且空格後面的字亮起時間沒錯開。
- [ ] 一次一個短句、每句 ≤ 年級上限、念到哪亮到哪（一次只亮一個字）。
- [ ] 英文名字依音節亮起。
- [ ] 沒有缺注音字（缺字會在字幕標示「字典沒有」）。
- [ ] 旁白時音樂有壓低。

## D2. 語音生成配音（S 系列，見 VOICE-TTS.md）

- [ ] `node scripts/lesson-entry/voice-check.mjs <堂代號>`：每句相似度 ≥ 0.9，或不一致只是字形差（周／週、麽／麼、哦／喔、BB）。
- [ ] `read_network_requests` 過濾 `/lesson-entry/voice/<堂代號>/`：每個 mp3 都 200。
- [ ] **每句都有字幕**：在製作頁 console 定義下面的函式，一次跑一兩頁，回傳空陣列才算過（每句在 20%／50%／85% 時間點，畫面上的字幕要包含那句的字）。
  ```js
  window.__subChk = async (n) => { const miss = []; await __go(n, 0);
    for (const c of __stepInfo.cues) { const chars = [...c.text].filter((ch) => !/[，。！？、：； ]/.test(ch));
      for (const k of [0.2, 0.5, 0.85]) { await __go(n, Math.round((c.beat + (c.dur / 0.6) * k) * 2) / 2);
        const t = document.querySelector("[data-stage] [data-ui=sub]")?.textContent || "";
        if (!chars.some((ch) => t.includes(ch))) miss.push(c.text); } }
    return miss; };
  ```
- [ ] 畫面對準關鍵字的索引正確（把台詞去標點與空白後取第 i 個字核對）。

## E. 互動頁（若有）

- [ ] **資訊完整才解鎖作答**：情境、具體內容、題目、必要說明／示範及對應旁白完成前，答案保持 disabled，滑鼠、觸控、Enter／空白鍵／快捷鍵都不能判答或跳題。鎖定期連點、按住鍵盤到解鎖後放開，不得自動送出答案；解鎖後新的操作可以正常作答；回饋播完才換題，下一題重新鎖定，提示從解鎖起算。

- [ ] **提示時機**：每 3 秒亂按錯的、持續 30 秒以上 → 全程沒有發光提示；停手 15 秒 → 只重念題目、沒發光；再 15 秒 → 提示句＋發光（S 系列）。⚠ 窗格顯示時負責人可能正在操作：用 `click` 事件的 `isTrusted` 分辨是不是真人點的，別誤判成 bug。
- [ ] **順序有打亂**：照「卡片內容」決定答案（不是照位置）作答，記錄每題按鈕順序與正確答案在第幾顆；同一頁重新整理再玩一次，順序要不一樣。3 個以上選項時相鄰題正確答案不同顆、不是 1234 依序。
- [ ] **題目卡片有三段**：情境、對方說的話／具體內容、題目句；答對後換成正確結果；卡片裡的字沒被切掉（`scrollHeight > clientHeight`）。
- [ ] 選擇題式互動（S2-W03 選格式／追問）：選錯有軟回饋（紙條擠回去、泡泡更爆）＋提示句、不扣分；選對有整理好的畫面＋回饋句；做完自動接下一頁；約 9 拍沒操作就指引＋按鈕光圈。互動頁的字幕是即時出現的，用「邊播邊每 0.5 秒 `__overlap()`／`__scan()`」抽查。
- [ ] 打名字：只收 A～Z、1～10 字母、一定按 Enter；打錯顯示「你的名字好怪喔：〔內容〕」並清空可再打；空白 Enter 只提示。
- [ ] 回報只有「相符與否、次數、舉手、老師放行」，沒有名字內容。
- [ ] 10 秒／20 秒／5 秒沒按 Enter 的溫柔提示；連續 3 次不符舉手。
- [ ] 老師備用出口 Ctrl＋Shift＋Enter。

## G. 交給負責人判斷（我驗不了）

- 音質（動物語／配音自不自然、破音字讀音、配樂好不好聽、會不會吵）。
- 片長能不能接受（S 系列台詞用完整句子後，S2-W03 約 2.5～3 分鐘，不含互動）。
- 動作與拍子的「感覺」、晃動幅度、環境動畫會不會干擾看字。
- 可不可愛、是否符合品味與風格。
- 在真實 Chrome 的表現（內建瀏覽器順不代表他那邊順）；不同解析度。
