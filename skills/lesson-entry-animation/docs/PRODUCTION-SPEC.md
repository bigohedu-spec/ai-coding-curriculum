# 進課動畫製作流程與規格 v0.2（取代 v0.1）

> 版本 v0.2　**狀態：DRAFT，等負責人審**　日期 2026-10-07
> 目標：**之後所有課程、所有主題**都用同一套製程做出進課動畫；不是每個主題各做一次 3D、也不是每堂課各寫一次程式。
> 第一個實例：P1U W13（小熊麵包坊）。實作所在分支 `feat/lesson-entry-system`。

---

## 0. 為什麼要改（v0.1 的問題）

v0.1 把每堂課的角色與場景都用程式碼畫出來，結果：

1. **品質上限低**：用程式碼拼圖形，角色天生僵硬、簡陋；負責人看過兩版都說「有點糟糕」。
2. **無法量產**：每換一個主題（馬雅星門、午夜車站、博物館、小熊麵包坊…）就要重畫整套角色與場景。
3. **瓶頸找錯了**：好看與不好看的差別在**美術素材**，不是在動畫程式。換成 3D 也只是把同樣的問題搬進 Blender，每個主題還是要重做。

**結論**：把「美術」和「動畫」拆開。美術是**每個主題做一次的素材包**；動畫是**所有課程共用的範本加腳本**。每堂課不再寫任何繪圖程式。

---

## 1. 核心原則

1. **美術與動畫分離**。美術進「主題包」，動畫由「場景範本」加「課程腳本」組出來。
2. **一個主題包服務很多堂課**。例：小熊麵包坊一包用 W13～W18 六週；S3 的任務簿一包用 W1～W6。
3. **動態靠鏡頭與節奏，不靠逐格角色動畫**。用姿勢切換、擠壓彈跳、視差滑動、鏡頭推拉、文字特效、粒子，踩在音樂拍點上。這跟你參考的影片（插畫質感加強節奏的換場）是同一類做法。
4. **先便宜、後昂貴**：風格鎖定 → 腳本 → 靜態分鏡（animatic）→ 動態 → 音效 → 配樂 → 整合。每一關通過才進下一關。
5. **每堂課幾乎只改資料**（腳本 JSON）。需要新的動態才擴充「範本」，並且之後所有課程都能用。
6. **素材可追溯**：每張圖的來源、提示詞、授權都記錄在主題包裡。

## 2. 三層結構

```
┌────────────────────────────────────────────────────────┐
│ 層 A｜主題包 Theme Kit     （每個主題／模組做一次，要人審）│
│   風格定義、色票、角色姿勢表、背景分層、道具貼紙、主題配樂  │
├────────────────────────────────────────────────────────┤
│ 層 B｜場景範本 Scene Templates + 動態預設 （做一次，所有課共用）│
│   開場卡、角色說話、目標清單、口訣文字特效、操作示範、互動輸入、出發│
├────────────────────────────────────────────────────────┤
│ 層 C｜課程腳本 Lesson Script （每堂課一份資料，要人審）     │
│   選範本、填文字（含注音）、指定主題包素材、以拍為單位排時間   │
└────────────────────────────────────────────────────────┘
        ↓ 引擎（HTML／CSS／Web Animations，不加 npm 套件）↓
                    進課動畫（網頁）
```

### 層 A｜主題包

| 內容 | 規格 |
|---|---|
| 風格定義 | 一頁：畫風關鍵字、描邊／無描邊、陰影方式、色票（≤ 12 色）、字型、情緒（童趣、溫暖、不嚇人） |
| **角色姿勢表** | 每個角色至少 5 個姿勢：待機、說話、揮手／指向、開心、困惑；各自是**透明背景 PNG／WebP**；另附 3 種嘴型與眨眼的疊層 |
| 背景分層 | 3～5 張：遠景、中景、近景（各自透明，才能做視差）＋ 1 張完整場景當封面 |
| 道具貼紙 | 該主題常用的物件（招牌、鍵盤鍵、麵包…），透明背景 |
| 主題配樂 | 1 段可迴圈的主旋律與分層（鼓／低音、旋律、和聲），速度與拍號固定 |
| 檔案預算 | WebP；長邊 ≤ 1600 px；單檔 ≤ 250 KB；整包 ≤ 3 MB |
| 紀錄 | `KIT.md`：每張圖的來源、提示詞或作者、日期、授權 |

> **角色一致性**是最大風險。做法：**同一個角色的姿勢表用「一次生成一張姿勢表」的方式做**（同一張圖裡的角色天生一致），再切成單張；不是一張一張各自生成。

### 層 B｜場景範本（v1 清單）

| 範本 | 用途 | 動態預設 |
|---|---|---|
| T1 開場卡 | 「課程要開始了」標題與招牌進場 | 彈入、鈴聲點 |
| T2 角色說話 | 角色姿勢切換＋對話框＋字幕（含注音） | 擠壓彈跳、嘴型切換、慢半拍跟隨 |
| T3 目標清單 | 今天要做的 3 件事，依序亮起 | 逐項彈出、打勾 |
| T4 口訣特效 | 口訣一字一拍出現 | 文字彈跳、拍手點 |
| T5 操作示範 | 鍵盤按鍵、滑鼠、遊戲畫面（截圖或實錄） | 按鍵下壓、箭頭指示 |
| T6 互動輸入 | 小朋友輸入文字（例：打英文名字、按 Enter）、判斷與提示 | 逐字彈入、成功慶祝 |
| T7 出發 | 結尾與「開始上課」按鈕 | 呼吸閃動 |
| 動態預設 | bounce-in、squash-stretch、parallax-drift、camera-push、sway、sparkle、wipe 換場 | 全部以「拍」為單位 |

### 層 C｜課程腳本

沿用 v0.1 的腳本格式（分鏡表、旁白、字幕字數上限、防洩漏檢查），**多兩欄**：`範本`（T1～T7）、`素材`（用主題包的哪個姿勢／背景）。

## 3. 流程與關卡

### 主題包流程（每個主題一次）

| 關 | 做什麼 | 審核 |
|---|---|---|
| K1 風格定義 | 我提出 2～3 個風格方向，附文字描述與參考 | 你選一個 |
| K2 試畫 | 用選定風格試畫 **6～8 張**（1 個角色 3 個姿勢、1 張背景、2 個道具），先看風格與角色一致性 | **Gate K：風格鎖定**（通過才批量做） |
| K3 完整主題包 | 補齊姿勢表、背景分層、道具、嘴型疊層，整理成檔案 | Gate K3 你審 |

### 每堂課流程

| 關 | 做什麼 | 審核 |
|---|---|---|
| L0 立項輸入 | 取 wiki 來源、標缺口（同 v0.1 的 S0） | — |
| L1 腳本 | 寫腳本並選範本 | **Gate A** |
| L2 **Animatic（靜態分鏡）** | 用主題包素材排出每一格的靜態畫面＋時間＋字幕，**沒有任何動態與聲音** | **Gate B**：先審構圖、節奏、字數 |
| L3 動態 | 套範本與動態預設，踩拍點；全程靜音 | **Gate C** |
| L4 旁白與字幕 | 先出試聽樣本，你選聲線才全錄；禁用機械聲 | Gate D |
| L5 音效層 | 逐場景加，音效清單記在 `sfx.md` | Gate E |
| L6 配樂層 | 逐層加（鼓與低音 → 旋律 → 變化），每層可單獨開關 | Gate F |
| L7 整合 | 接進 `/today` 的「開始上課」前；互動與紀錄 | — |
| Gate G | 你在自己的 Chrome 實機驗收（第 5 節清單） | **Gate G** |
| L8 封存 | 腳本、素材、紀錄 commit | — |

> **Animatic 是新增的關卡**：用靜態圖＋時間就能先看出「這支動畫好不好看、節奏對不對」，比等做完動態才發現不行便宜很多。

## 版面安全檢查（每個 CUT 都要做，2026-10-08 新增）

**規則**：任何看得見的文字都不可以超出舞台邊界（含帶注音的字幕、泡泡、標題、輸入框、卡片）。

- **字幕自動縮小**：`flow/Sub.tsx` 會量字幕寬度，放不下就縮小，不用手動調。
- **使用者打的字**要限制顯示（只顯示最後 14 個字母、超長用小字換行），不能因為他亂打就衝出畫面。
- **字的「砸進來」動畫**起始放大倍率不可超過 1.7，否則靠邊的字會衝出舞台。
- **自動掃描**：製作頁會掛上 `window.__scan()`（`toolkit.scanOverflow`），回傳超出舞台的文字與超出幾 px。流程：開 `/entry/play/<堂代號>`、勾「定格」，每個 CUT 每 0.5 拍掃一次，結果必須是空的才算過。互動步驟另外要用「很長的輸入」再掃一次。
- 以 CSS 動畫做的 CUT（例如 CUT 1）在瀏覽器分頁被隱藏時動畫不會前進，掃描要在分頁可見時做。

## 配樂與時間（2026-10-08 新增）

- **音樂是主時鐘**：從頭播到尾，不中斷、不重新對拍。畫面動作與旁白去對齊音樂（`useClock` 讀的是音樂現在第幾拍），不是音樂去配合畫面。
- **每個 CUT 的切換點落在整拍上**（內容結束後等 2 拍）；音樂不中斷，畫面的拍數一律讀音樂的絕對拍數，所以不論從哪一拍開始，晃動與強拍都和音樂對得上。
- **樂器逐層加進來**（`config/lessonEntry/musicPlan.ts`）：每個 CUT 寫「第幾拍開哪些層」。等學生操作的 CUT **不寫項目**＝編曲不變、音樂迴圈。
- **場景物件跟著拍子晃動**（`toolkit.groove` / `useAbsBeat`）：角色與道具每拍落地壓扁、起跳拉長、左右微傾（第 1、3 拍較大）；灌木、花草、麥穗每拍換邊搖；招牌在強拍彈一下；一拍切 4 格（兩格一動）。已有自己彈跳動作的物件幅度減半。
- **環境動畫**（`flow/Ambient.tsx`，做在共用場景層，換課只換主題包的點位）：遠景＝太陽光暈與光束、小鳥；店面＝煙囪冒煙（店面圖上畫死的那團煙用 `SHOP_CLIP` 挖掉）、櫥窗飄麵包香氣、櫥窗閃光、門上鈴鐺；前景＝花粉、落葉、蝴蝶；景深＝遠景與店面用不同速度緩慢漂移。規則：淡淡但不停、動作用階梯式、位置避開字幕區、全部跟著音樂拍子。新增需要新美術的項目（雲朵、路人小動物、顧客進出店門、節慶裝飾）另列待辦。
- **翻頁規則（2026-10-08 定案：沒有轉場、不用點、每頁結束等 2 拍）**：每頁內容（旁白與動畫）播完後，字幕留在畫面上，**等 2 個整拍就直接切換到下一頁**，切換點落在整拍上，音樂不中斷。（曾試過雲轉場與「4 拍停留」，負責人測試後都不要。）最後一頁有兩個按鈕：**開始遊戲**、**再看一次**；再看一次會從 CUT 1 重來，**音樂同時重新起算（重新同步）**，名字與打字結果清掉。
- 旁白時音樂自動壓低；結尾（按下「開始上課」）停在 C 大調和弦。

## 旁白方案（2026-10-08 改版：動物語）

- **旁白＝動物語（像動物森友會）**，不用 TTS 念整句。TTS 念整句對小朋友太空洞、有恐怖谷；電腦合成的咕噥也試過，同樣有恐怖谷，已淘汰。
- 做法：用 OpenAI tts-1 **逐個注音音節預錄**（小兔 nova、小熊 onyx），各取前 0.23 秒，執行時升調、加速、串起來；音高隨機浮動，句尾「？！」上揚。素材在 `public/lesson-entry/animalese/`（每角色一個 sprite wav＋索引 json），引擎見 `src/lib/lessonEntry/animalese.ts`。
- **英文名字**：切成「子音＋母音」音節（`englishSyllables.ts`），所以小朋友打的英文名字也念得出節奏。
- **對拍**：旁白時間表在 `src/config/lessonEntry/narration.ts`（第幾拍開始、每字幾拍），字的發聲對上畫面動作點。
- 取捨：動物語**不是真的念字**，小一靠畫面大字與注音理解；必須聽懂的句子（操作說明）另請真人錄音。
- 試聽頁：`/entry/audition/animalese`。edge-tts 試聽樣本方案已作廢。
- 素材檔目前各約 4 MB，定案後要壓縮。
- **字幕規則（卡拉 OK 式）**：動物一發聲，畫面一定要有對應的字且那個字亮起；字幕就是旁白的字，一次一個短句（≤10 字）；亮起時間與發聲時間共用同一份時間表（`animalese.tokenTimes`），不可能對不上。慢速也靠它成立：小朋友看到亮起的字，會自然把咕噥聽成那個字。

## 5. 驗收清單（每堂都要過）

**內容**（同 v0.1）
- [ ] 比例接近 60 / 30 / 10；字幕不超過年級字數上限；P 系列關鍵字有注音。
- [ ] 不洩漏答案、不預先講解學習重點；複習是隱晦的小動作；輸入內容不存檔。

**美術（新增）**
- [ ] 所有素材來自該主題包，**風格一致**（色票、描邊、光影）。
- [ ] 同一角色在每個畫面看起來是同一個。
- [ ] 沒有 AI 常見瑕疵（多手指、扭曲文字、奇怪的臉）；**畫面中的中文字一律用網頁字型疊上去，不用 AI 畫的字**（AI 畫的中文常常寫錯）。

**體驗與技術**（同 v0.1）
- [ ] 可跳過、可重播、可暫停；第一次點擊才開始；無大音量、無機械聲。
- [ ] 不新增 npm 套件；單支動畫總資源 ≤ 3 MB；尊重 `prefers-reduced-motion`；1366×768 與 1920×1080 完整顯示。

## 8. 動態語言（Motion Language）：卡通手遊「高光時刻」（2026-10-07 選定）

來源：skillry.dev 的 Opus 5.5 作品庫（MIT 授權的提示詞收藏庫 yihui-dev/awesome-opus5-5-videos；選用 @op7418「高光時刻」的**視覺語言**，**不用它的 3D**）。用在課程裡的「高光時刻」：口訣、目標完成、出發。

**規則**
1. 高飽和暖色、**統一的深色粗描邊**、圓胖厚重的字。字一個字一個字「砸」進畫面：先放大下砸 → 擠壓 → 拉伸 → 回彈，踩在拍點上。
2. 演出分五段：**預備 → 進場 → 蓄力 → 爆發 → 揭曉**，缺一不可。爆發＝閃光（強度 ≤ 0.8，不可整屏過曝）＋三圈衝擊波＋粒子＋短暫震動；彩帶只在最高潮用一次。
3. 光效必須柔和：背景光芒用漸層錐形（不要一刀切），粒子帶低透明度外暈。
4. 所有動作都要有擠壓拉伸與回彈，不要匀速。
5. 角色用主題包素材（ChatGPT 生成、去背），**不是程式畫的**。
6. 音效與配樂全部程式合成（Web Audio），第一次點擊才啟動、可靜音；依流程在音效／配樂關卡才加。
7. **交付前自檢**：在爆發前、爆發中、揭曉後各定格一張，逐項檢查：主角有沒有被光或字擋住？有沒有過曝？注音看得見嗎？字有沒有被擠出畫面？

## 9. 實作注意（踩過的坑，之後每堂都要遵守）

| 坑 | 做法 |
|---|---|
| 全站樣式把所有元素設成等寬字，**子元素不會繼承**字型 | 注音字型（`Bpmf GenSen`）要**直接寫在每個要顯示的字自己身上** |
| 全站對 `<img>` 設了 `max-width:100%`，父層寬度 0 時圖被壓成 0 | 素材圖一律加 `max-width: none` |
| 描邊太粗會蓋住字右側的小注音 | 描邊 ≤ 字級的 7%；改完一定要看注音 |
| 一行字太多會被擠出畫面（尤其口訣最後的標點） | 長句拆成 3 行，每行 ≤ 5 字 |
| 預覽窗格閒置時不繪製、dev server 剛改檔會暫時 404 | 驗證時先截一張小圖喚醒再截正式的；404 就等幾秒重試 |
| CSS 動畫播完會從動畫清單消失，事後無法跳回 | 預覽頁的「拍點滑桿」用重新載入再定格，不要事後硬跳 |
