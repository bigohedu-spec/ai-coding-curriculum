# 成果頁

> 本 skill **只放方法、設計基準、踩到的坑與處理**，不含頁面原始碼（檔名只當位置說明）。
> 資料來源：2026-10-29 向負責 P1U 小熊麵包坊 W18 成果頁的 session（「Restyle W18 recap page to bakery art style」）取得的交接，加上對 gpt-clone 程式的核對（`lessonCatalog.ts`、`studentWorks.ts`、`s3w06Showcase.ts`、各 recap 頁檔頭註解）。
> 可信度標記：**【實做】**做過並驗證、**【程式】**我讀過程式確認、**【文件】**來自註解／文件、**【未驗證】**沒確認。

## 一句話

成果頁是**給家長看的**：講「這門課為什麼這樣設計」與「孩子做到了什麼（用次數和個數說，不用時間說）」，手機往下滑就看完；資料來自學生存檔，缺欄位要補齊，**畫面上不能出現 NaN、undefined、空白卡片、一排 0**。

## 一定要守的規則

1. **成果頁讀的是遊戲存下來的資料，不是另抄一份題庫**：孩子寫的、AI 回答的內容，收錄當下就寫進存檔（存文字、不存 id），成果頁直接畫（`labterminal-course-spec/reference/shipped-benchmarks.md` C7）。
2. **遊戲端改了存檔欄位或每週紀錄的寫法，成果頁要同步檢查**（見 `pitfalls.md` 的「銜接約定」）。
3. **不放學生花了多少時間、遊戲內進度細節（關卡、等級、遊戲金幣、週次標籤）**；家長不知道遊戲內容，看了沒用。
4. **每一格都要有數字**；數字是 0 的格子整格不放；有存檔但一週都沒過的學生，顯示「先過第一週再回來看」，不畫一整頁 0。
5. **畫面不能依賴動畫才看得到**：浮現動畫要漸進增強（預設可見）。
6. **美術與遊戲一致**：色票與形狀從遊戲 UI 讀出來，不另外發明。
7. **`?uid=` 的連結任何拿到網址的人都看得到**（Firestore 規則目前讀寫全開）；新做的成果頁**不要放比現有更敏感的內容**，需要私密分享用 token 模式（見 `forms-and-data.md` §3）。
8. 改完要給負責人**親眼看**：改前改後對照圖、他自己的 Chrome 可看的預覽；同意後才 commit。
9. commit 只 add 自己的檔案；commit 前先看 `git log`／`git status`（別的 session 會把你沒 commit 的改動一起 commit 進去）。

## 範圍與已知缺口

- 本 skill 以 **P1U 小熊麵包坊 W18 成果頁**的經驗為主；其他系列（P1U 字母要塞、S2、S3、家長作品頁）只確認了位置與機制，內容未逐頁驗證。
- 文案（這門課在練什麼、為什麼現在學、給家長的話）是草稿，負責人只定了方向，沒有逐字定稿。
- 課後複習成績只存在從複習頁帶過來的網址上（`?rv=`），家長之後從作品頁打開就看不到；要不要存進 Firestore 沒定。
