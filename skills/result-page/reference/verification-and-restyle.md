# 驗證與改風格的流程

> 來源：成果頁 session 的改版流程【實做】。原則：**只有文字的「已完成」不算完成**，要親眼看、親手觸發；數值用算的。可信度標記見 `../SKILL.md`。

## 1. 改風格（只換外觀，不動資料與內容）的流程

1. **先讀目前的檔案**，確認工作區有沒有別人還沒 commit 的改動。成果頁與遊戲建置常常是好幾個 session 一起在動。
2. **改之前先截「改前」**：每一頁都截，作為對照。
3. **資料邏輯與樣式／markup 分開改**。資料邏輯＝統計函式、對照表、Firestore 讀取。改完用 diff 確認 script 裡只動到 markup。
4. **自動截圖**（見第 3 節）。
5. **給負責人看**：
   - 改前改後並排成一張對照圖；
   - 開一個**本機預覽頁**：只讀、成果頁用測試資料、可切換情境，讓負責人用**自己的 Chrome** 看（內建瀏覽器順不代表他那邊順）；
   - **負責人同意了才 commit**。
6. **commit 完，從 commit 把檔案取出來再跑一次**，確認落地的是對的版本。
7. commit 時**只 add 自己的檔案**，別人灌進來的遊戲建置檔不碰；commit 前先看 `git log`／`git status`。

## 2. 測試資料要像真的

- **用遊戲實際存下來的存檔**，再刪掉新欄位做出「舊紀錄」。手寫的假資料（只有一個主題、兩位員工）會讓人誤以為頁面算錯。
- 情境要涵蓋，每種都跑三種尺寸：
  - 全部新欄位；
  - 前幾週是舊紀錄、後幾週是新紀錄；
  - 整週沒有紀錄（跳關）；
  - 補齊的週（`sec`、`earn` 為 0）；
  - 資料最少的學生；
  - 有存檔但一週都沒過的學生。
- 目前測過的真實資料只有 10/20 撈的存檔（只到 W14）加遊戲跳關產生的存檔；**真實學生打完 W18 的資料還沒看過**【未驗證】。
- **重撈學生存檔會被自動模式擋下**（理由：學生個資）：不要繞過，改用現有測試環境裡的存檔加遊戲跳關實際產生的存檔。

## 3. 自動截圖與檢查（Playwright＋本機 Chrome）

- 擋掉 Firebase，注入假的 `prog`，從磁碟提供 `public/`。
- 每頁截一張 420×860。
- 同時量**每個元素有沒有超出那一頁**，並掃描畫面文字有沒有 `NaN`、`undefined`、「0 分鐘」等字樣。
- 驗證動畫要用**前景的無頭瀏覽器**，不要用藏起來的預覽分頁（背景分頁的 `IntersectionObserver` 與 `requestAnimationFrame` 不會跑）。
- 要截 Cocos 遊戲畫面時，Playwright 的 `screenshot` 會卡在「等字型」直到逾時（軟體繪圖下主執行緒被吃滿），改用 CDP 的 `Page.captureScreenshot`。

## 4. 整條流程測試（W18 → 課後複習 → 成果頁 → 結束）

- 寫一個**模擬外層頁**：回 `config`、收 `save`、收 `review` 後整頁換頁。
- 遊戲裡「打贏」用測試掛鉤直接呼叫遊戲元件（無頭瀏覽器沒辦法真的打王）。
- **嵌入版與直接開遊戲兩種都要走完**。
- 無頭瀏覽器的時序：遊戲要 20～30 秒才載完（「準備中」蓋板）；有存檔先跳「歡迎回來」離線收入視窗，沒存檔先跳 4 頁開場教學；**任何視窗開著，結束畫面都會排隊等**。順序：等「準備中」消失 → 確認到了 W18 → 關掉或點過視窗 → 最後才觸發打贏。
- 在建置版裡找遊戲元件不能用類別名（被壓縮了）；改找「有某個特定欄位（例如 `weekRecs`）的元件」。

## 5. 驗收清單

- [ ] 420×860、360×740、1280×800 三種尺寸，每頁無元素超出。
- [ ] 畫面文字掃描沒有 `NaN`、`undefined`、空白卡片、一排 0。
- [ ] 全部測試情境都跑過（含「先過第一週再回來看」）。
- [ ] 背景分頁打開時不會整頁空白（3 秒退路有效）。
- [ ] 「減少動態效果」時動畫全關。
- [ ] 列印預覽每頁完整、沒有按鈕與地板。
- [ ] 沒有 `?uid=` 時顯示「這個連結少了一個代號」，不是白畫面。
- [ ] 分享模式下「回學習單」變成「回作品頁」，不會把家長導去學生登入頁。
- [ ] 整條流程（遊戲 → 複習 → 成果頁 → 結束）嵌入與直接開兩種都走過。
- [ ] 負責人用自己的 Chrome 看過並同意；commit 後取出檔案重跑確認。
