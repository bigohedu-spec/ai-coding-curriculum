# Lab Terminal 互動課程 — 教案設計指南（開發團隊回饋，2026-06）

> 來源：開發團隊實作 S5-W15「遊戲開發模擬器」後的回饋，整理成可重用的設計原則與檢核表。
> 本檔為 labterminal-course-spec skill 的**權威設計準則**；產出開發規格時，「概念/模擬器型」課程一律遵循本檔（與 CLAUDE.md 第二十節並行，本檔補充「一條有產出的旅程」的站結構與 prompt 設計）。
> 對象：國小 3–6 年級．單堂約 50–65 分鐘．單一 HTML、純前端、可離線．

---

## 0. 一句話定位
一堂好的互動概念課，是讓學生「邊讀懂、邊動手、邊看到成果長出來」，最後有一個他真的做得出來、玩得到／用得到的成品。不是投影片、不是純問答，而是**一條有產出的旅程**。

> ⚠️ **最貴的教訓（見 game-course-design.md）**：寫學習目標的**同時**就要附一條**遊戲迴圈**（玩家扮演誰／每回合做什麼有趣的事／贏了拿到什麼）。**禁「先寫純練習、做完才補遊戲性」**——那是最貴的彎路。

## 1. 每一站的標準結構（4–5 步）
```
① 讀懂          AI 用「我們正在做你的遊戲」的口吻，情境中自然帶出並解釋概念（約 150 字）
② 理解確認 ×2   2 題選擇題，考「有沒有讀懂」（非背名詞）。答錯永久鎖定、選項洗牌
③ 填空          把段落裡那個專有名詞填出來（接受中英/同義）
④ 白話下指令    用「一句白話」告訴 AI 這一步想讓遊戲做到什麼 → **本地規則判 pass/fail（含 distractor）**、AI 只做角色化回應/潤飾/歸檔（不當關主，見 game-course-design.md）
⑤ (可選) 做決定 產品/技術決策用「二選一按鈕」拍板（例：單人 or 多人）
   → 完成後：左側資料夾多一個檔案、遊戲預覽長出對應的一塊
```

**每站設計表（交付工程端必附）**：概念/專有名詞、AI 對話段落(150字含比喻)、理解題×2(似是而非干擾項)、填空提示、**白話 prompt 範例(學生真的會打的話)**、這一步的 goal(給 AI 當判準)、產物檔案、預覽變化、(決策)。

## 2. 十大設計原則（要／不要）
1. **Prompt 白話**：不要逼學生講術語或檔名；術語用理解題+填空教，prompt 不再考一次。學生打「幫我做一個讓太空船左右移動的功能」就好。
2. **判定本地化，AI 只陪伴**〔2026-06 修正，見 game-course-design.md〕：**pass/fail 一律用本地規則 + 預寫 distractor 清單**（可離線、可重現）——實測 AI 會把完美答案誤判失敗，**不得讓 AI 當關主**。AI 對「清不清楚/方向對不對」的判讀只能當**體驗回饋/潤飾/鼓勵**，不作及格線。設計端要寫清楚「這一步該做的事」＋「哪些是錯的（distractor）」。
3. **30 秒亂點/亂打過不了**：理解題答錯永久鎖定 + 選項洗牌；填空要對；prompt 要 AI 點頭；擋貼上。自己亂打一輪測試。
4. **教真實流程順序**：該先決定的放前面（核心玩法 → 單人/多人 → 技術選型 → 規格）再動手；檔名（game.js…）要在「技術選型」站之後才出現。
5. **產出看得見地長出來**：每站完成 → 左側資料夾多一檔、成品多一塊；學生一步步看到東西被做出來。
6. **加「再說一次」修正環節**：設計 1–2 站，第一次指令不夠清楚 → AI 反問（「往哪個方向動？左右還上下？」）→ 補一句才過。教「跟 AI 協作第一次常不夠精準，要會補述」。
7. **做不到的誠實示意**：多人連線/雲端資料庫課堂做不出真的 → 畫面示意 + 明確標「今天先做單人/本機示意」，不假裝可玩。誠實示意 > 假可玩。
8. **決策用二選一按鈕**：產品/技術取捨用按鈕，每選項配一句後果說明；沒有標準答案不設答錯鎖，但要反映到後面產物與預覽。
9. **進階細節放「深入了解」折疊卡**：Firebase/Supabase、GitHub Pages/Vercel 步驟等 → 點開才看。主線淺白，好奇者自己深入。
10. **用語配比喻、合年級、估時**：框架＝蓋狗屋不請建築師、變數＝便條紙 vs 資料庫＝雲端成績簿、多人＝揪人打球。時間 50–65 分：二選一代打字、prompt 預填白話骨架、近義站合併、理解題必要時降 1 題。**務必估時**。

## 3. 評量設計
- **理解題**（每站 2 題）：考懂不懂；干擾項是「似是而非的混淆點」（原型 vs 成品、部署 vs 發布、UI vs UX）。
- **總複習考試**（最後一關）：8–10 題橫跨整條流程 + 真實服務（資料庫/部署用什麼）；答完給**成績 X/N + 評語 + 獎勵**，錯的標出正解。
- **金幣**：主線平均分配（例 250），完成即得；考試獎勵另計。金幣要**綁定帳號**（跨裝置、不重複刷）。

## 4. 交付工程端（LLM）附件
1. 每站表格（§1）。2. 成品規格（核心玩法、操作、計分/多人、存哪、視覺風格）。3. 哪幾站要「再說一次」及各缺什麼細節。4. 哪些概念是「示意」及怎麼標。5. 總複習考題 8–10 題。6. 年級與時間預算 + 合規檢查。
> 工程端據此產出**單一 HTML、純前端、可離線**互動課；視覺/音效全程序化（不依賴外部圖片音檔）。

## 5. 設計者自我檢核表
- [ ] 每站走「讀懂 → 理解題×2 → 填空 → 白話 prompt →（決策）→ 產物 + 預覽變化」
- [ ] Prompt 白話，沒有逼學生講術語或指定檔名
- [ ] 理解題干擾項是混淆點；每站 2 題、答錯鎖定、選項洗牌
- [ ] 流程順序貼近真實開發，前段有「該先決定的事」
- [ ] 每站完成都有看得見的產出（檔案/成品長一塊）
- [ ] 至少 1–2 站有「AI 反問、再說一次」
- [ ] 做不到的用「誠實示意 + 標註」，沒有假裝可玩
- [ ] 決策用二選一按鈕，每選項有後果說明
- [ ] 進階細節放「深入了解」折疊卡
- [ ] 用語配比喻、合年級；估時落在 50–65 分鐘
- [ ] 有總複習考試（8–10 題）+ 成績/獎勵；金幣綁帳號
- [ ] 自己「亂打/離題/複製範例」跑一輪，每關都擋得住
