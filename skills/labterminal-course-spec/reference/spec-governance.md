# 規格治理準則（Spec Governance）

> 來源：P1U-W01「書面規格 vs 交付成品」偏離分析（低年級動作技能課實作回饋）。**去蕪存菁後的通用治理規則**——與 `lesson-design-guide.md`（高年級概念課設計）併列，本檔補上「規格 ↔ 交付對齊」的治理視角，適用所有課程 spec。
> 目的：避免「無人察覺的大偏離」——實作在一連串即時需求下越長越大，主題/技能/結構/時長全偏，卻從未回到 spec 對齊。

## 核心病灶（為何會偏）
1. **spec 與實作無追溯關係**：兩份文件互不指向，偏離無人察覺。
2. **範圍無邊界**：單週 spec 把別週的技能都吸過來（首週過載）。
3. **定性需求無驗收定義**：「像專業遊戲／情緒給滿」沒有可驗收邊界，工程端只能往「更多／更炫」猜。

## 十條治理規則（每份 spec 都要做到）
1. **正典聲明 + 追溯表**：spec 綁定實作檔名；明寫「**spec 是唯一真相，程式跟著 spec 走；要改方向先改 spec**」。任何偏離必須回填 spec（change control）。
2. **In / Out of Scope 寫死**：明列「本課教什麼」＋「**不教什麼、屬哪一週**」。範圍蔓延就有依據擋。
3. **跨週技能地圖**：附該模組各週技能總表，讓單週 spec 不各自把別週內容吸過來。
4. **可數單位表**：站／關／回合／次／圈 一律定義清楚，避免「10 關」被誤解成「10 回合／10 站」。
5. **互動詞彙表（單一真相）**：每個操作的「詞／顏色／動作」一次定死（例：右鍵＝橘色＝「點右鍵」；滾輪往前＝上升；雙擊＝×2＝藍色）。防「文案不對稱／方向不一致」的 bug。
6. **DoD（完成的定義）＋參考範例**：把定性形容詞翻成**可勾選條目**＋一張參考畫面/影片。定性詞必配可驗收定義。
7. **「防挫折」與「反硬 A」拆成兩張獨立表**：語義不同、不可混。低年級**先立全域不變式「失敗絕不懲罰」**（失誤靜音、不用紅框否定、逾時放行），**再**談防假動作（位移門檻、沿線時間、過場時間）。
8. **認知/識字負荷預算**：標明每畫面最多幾字、是否需識字；若引入閱讀理解，**標注前置識字能力假設**（呼應 CLAUDE.md 第十九節）。
9. **時長預算表**：每站分鐘 × 反覆次數 = 加總，對齊課堂 90 分；**並以課堂實測校準**（模型對低年級快速互動課可能高估，如 S2-W01 實測 15 分 vs 模型 41 分）。
10. **老師端 + 翻轉教育 = 一級需求**：進度總覽、需協助/舉手狀態、小老師派任、Deliver 的「舉手告訴老師／我是小老師」——寫進交付範圍，**不是附錄**。

## 條款分級（每條 spec 必標；2026-07 新增，見 low-grade-game-spec.md）
> 事後證明：spec 的內容/敘事幾乎全被忠實實作；凡規定底層輸入/失敗代價/難度數值/狀態資料的地方幾乎全被實測推翻。
- **規定**：親測 or 內容/敘事/視覺 → 工程必照做、寫死寫具體。
- **推定**：從他章/前作推得 → **與已上線成品衝突一律以成品為準**，附正典實作檔路徑；交付附「待核對推定清單」。
- **假設（待實玩校準）**：難度/失敗/手感 → 標明並排一輪目標年齡實玩校準節點，不當定論。
> meta 原則：**內容/敘事/視覺寫死；難度/失敗/手感標假設待校準；狀態/資料/容錯升級成一等公民正式章節。**

## 資料與工程＝一等公民章節（2026-07 新增）
- 過去 spec 整段留白、事後被迫補。以後**必寫**：「資料與狀態」（分數/進度存哪、綁 uid、跨裝置還原、衝突取進度較遠者）＋「失敗與離線」（操作失敗看到什麼/0HP 出口/斷線續玩/缺檔後備/載入逾時放行）。
- **分數冪等**：每次入帳有固定交易 ID、發放前查重（「同一成就只計分一次」）。
- **「計分冪等」與「玩家重玩權」拆兩個決策**：先答「分數是不是學習憑證」，再決定「能否重玩已完成關卡」；二選一並記錄理由（別讓「保底出口」與「完成即鎖」互相矛盾）。

## 跨切面需求（第一版就寫，別後補）
存檔續玩 / 帳號綁定 / 金幣入錢包 / 資安。後補會導致 schema 反覆改與版本遷移。

## 素材 / AI 生圖規格（硬需求）
統一風格指南 + 透明背景 + 自動裁切 + **未載入要能退回向量**（不依賴外部圖檔也能顯示）。
- **素材條款寫「下限」不寫「上限」**：AI 生圖成本已可負擔（每張數分鐘），別用舊成本假設限制設計。「一圖複用」是**角色識別一致性**需求（理解題地基），**不是數量上限**——敵人/場景可「每關一種可辨識外觀、每頁一張整幅圖」。

## 值得保留的既有優點（別因偏離否定 spec）
動作技能週 M1–M5 原則（動作品質、失誤靜音、進度視覺化、判定放大、反饋即節奏）、Hook/Repeat/Deliver 三段式、反硬 A 對照表、明確資料 schema、驗收對照表、判定放大、游標呼叫——對 6–7 歲極到位，應保留並回灌成品。

## 從 P1U-W03 學到（2026-07 新增：規格自洽、忠實執行、DoD 全過，產品仍失敗）
> W03 的病灶比 W01 隱蔽：**spec 內部自洽、開發忠實執行、驗收清單全過，但被真實學生推翻**（spec 寫的「持續同步兩手、難度地板高於 W02」被忠實做成彈幕版，全班過不了）。以下四條要在紙上就攔下這件事。

1. **難度用「學生通過率」定義，不用「相對上一堂」定義。**〔本次失敗根因〕
   - 「每堂比上一堂難」會單調遞增到超出學生能力，而且**每堂單看都合規**；還把「太難」變成合規行為（開發自測覺得不難 → 依規定必須退回加難）。
   - 難度的**驗收條件**一律寫成可觀測學生行為（例：目標班級 80% 於 15 分鐘內過關 1、90% 過 ≥3 關；未達 → 一律往下調）。相對於前一堂只能寫在「**設計意圖**」，**不得寫進驗收條件**。

2. **橫切需求（存檔/帳號/金幣/離線）要附「驗收情境腳本」，寫「怎麼測」不只「要做到」。**
   - 「綁 uid」四個字有寫、也標【規定】，但**單機自測碰不到**它沒做到 → 污染正式資料庫（W03 存檔用固定鍵沒綁 uid，實查 7 筆跨遊戲污染，涵蓋 W01/S2W01/S2W02）。對照：同章「金幣冪等」在遊戲內看得到效果，就有被實作。
   - 凡「單機自測碰不到、要多使用者/多裝置才顯現」的條款，DoD 必附情境腳本：
     ```
     □ 共用電腦：A 玩到第 2 關 → 登出 → B 登入開同一遊戲
       → B 全新進度，且 B 的雲端紀錄不得含 A 的資料
     ```

3. **「跳過學習內容」不屬於 A 層安全網。**
   - A 層只保留「**不卡死、不倒退、不羞辱**」（0 血不淘汰、可重試、連敗自動放寬）。
   - 「能否跳過劇情/教學/關卡」是**老師的教學決定**，移 B 層/老師端、**預設關閉**，別做成學生端常駐按鈕（否則學生一路點過去、不看劇情不做檢核）。
   - 釐清 low-grade §3：不可移除的是「**非懲罰性前進路徑（自適應出口）**」，不是「跳過學習」。兩者別混。

4. **spec 修訂要記錄「被否決的方案」與否決理由。** W03 二修否決掉的「漸進入門」設計，最後才是對的；保留否決紀錄，回頭檢討能快速定位（而非重新發明一次）。

5. **「一級需求」連續兩堂沒交付＝它其實不是一級需求。** 定期回頭清 DoD，別讓它變願望清單（老師端全班總覽/狀態燈/派任已連兩堂未交付 → 該補做或誠實降級）。

## 從 S2-W03 學到（2026-07 新增：解謎課的文字互動與謎題邏輯）
> 來源：S2-W03《消失的慶典皇冠》實作團隊回饋。適用所有含劇情/謎題的 spec。

1. **每段文字都要配一個「互動確認」，沒有純「按過去」的文字。** 每段旁白/對話/揭曉後面都要註明「讀完接什麼確認互動」（把關鍵字拖回句子、選出重點、判斷對錯）——用一個小動作證明讀懂，否則玩家一路按「繼續」什麼都沒記住。（延伸 low-grade §2：不只劇情段，是**每一段**。）

2. **謎題必附「正解推理鏈」，多張資訊表不得互相矛盾。** 出任何推理謎題，spec 要寫得出「玩家從哪些線索、怎麼一步步推到答案」；寫得出來邏輯才成立。一關有多張資訊表/線索時，標明每張各回答什麼問題、彼此不衝突。
   > **檢查法**：找個聰明小孩認真推這題，他推得通嗎？兩張表擺一起會不會打架？
   > 反例（本案已修）：原「時間軸把嫌疑人排在不同時間」不成立——不在場證明是「**同一案發窗口、每人在哪、誰能證明**」；且另有一張巡邏表與它矛盾。

3. **角色要在「成為謎題核心」之前先登場。** 為每個角色標「第一次登場」與「在謎題中被使用」的先後；關鍵角色（尤其真兇/答案）至少先出現 2–3 次（哪怕只是被提到名字），再拿來當謎題核心。（本案真兇到解謎關才第一次具名，玩家不認識就被要求把她排進謎題。）

4. **要玩家推理的關卡，先把「已知資訊」攤給他，不要設計成瞎猜。** 凡排列/配對/比對關卡，spec 列出玩家動手前手上已有哪些資訊（如四人供詞先全部攤開），讓他「用讀到的資訊推理」，不是排上去才顯示、逼他試錯。

## 從 S2-W04 學到（2026-07 新增：spec 進版控、交付 > spec 的回填）
> 來源：S2-W04《語氣變身術》交付差異對照。

1. **spec 從第一版就進版控。** S2-W04 原書面 spec 沒進版控，交付後想做逐行 diff 卻拿不到原文、只能「據記憶」對照。所有 spec（課程規格／故事線）一律進 repo，偏離才追得動、回填才精準。
2. **「交付 > spec」是常態，要定期回填。** 開發中會依即時需求長出大機制（S2-W04 就多長出第三幕、走路探索地圖、遇怪戰鬥、AI 語氣審核、訪談追問）。這不是違規，但 spec 必須事後**回填成正式章節**（成品即真相），別讓 spec 停在早期版本。
3. **經濟（金幣／TA 比例）在開發中改變 → 回填課綱。** S2-W04 因三幕＋追問，金幣 35→73、TA 從 50% 變 ~30%。凡量變就更新學期頁數字＋記待對齊，別讓課綱與成品對不上。
4. **「一級需求」又一次連堂未交付（老師端班級總覽）。** 呼應「從 W03 學到」#5：連兩堂沒交付＝該補做或誠實降級，別讓 DoD 變願望清單。

## 從 P1U-W06 ＋ Arc2《字母要塞》學到（2026-08 新增：形式重構、前端信任、發獎封頂）
> 來源：P1U W06 成果發表 ＋ W7–W12 單一遊戲《字母要塞》最終實作回填。適用所有 Lab 遊戲 spec。

1. **前端的判定/密碼＝不可信任，過關·權限·發獎判定必須能搬後端。**
   - 本案「過關判定」與「老師強制通關密碼」都寫在前端（F12 可見）；根因是 app 用自訂 localStorage 登入、**沒有後端身分**（Firestore 規則只能做到禁止刪除、讀寫全開）。
   - 通則：凡「作弊有動機、或牽涉權限（過關/發幣/老師操作）」的判定，**spec 必須標明它是否在後端**；沒有後端身分就先寫成【已知落差・待補後端】，別假裝安全。橫切需求「資安/身分」要第一版就寫（呼應跨切面需求）。

2. **發獎必須有上限，以「任務段」結算，不逐項無限累加。**
   - 本案問答每題 ＋3 金、題庫 15 題全問完＝45，**超出該堂 75 上限**（金幣無上限 bug）。
   - 通則：任何「可重複觸發」的獎勵（問答/擊殺/收集）都要**該段封頂**，且與該堂主線總額（§21：一般週 250；本課 P1U 尚未遷移）對齊。發獎冪等（既有規則）＋發獎封頂（本次新增）＝兩件事都要。

3. **交付可能把「世界觀/玩法形式」整個換掉，不只是加機制——spec 要能承受形式重構。**
   - 本案 Arc 2 從「恐龍叢林側視打字」→「字母要塞打字防守 roguelite」，世界觀、檔名、美術（改極簡幾何程序化、零素材圖）全換。這比「交付 > spec 多長機制」更劇烈。
   - 通則：形式重構後，**舊 spec 整份改寫、舊世界觀標作廢**（成品即真相），並回頭修所有指向它的連結（姊妹 Arc、學期頁、學習單）。既有素材若不再引用，列「待決定刪除」而非默默留著。

4. **多入口收斂成單一入口是合法簡化，但要在課綱標「未發布 ≠ 刪除」。**
   - 本案 6 張學習單收成 1 張（ws_p1u_w07 唯一入口、週次遊戲內選），W08–W12 設為**未發布、未刪除**（一行可還原）。
   - 通則：入口收斂要在學期頁註明；逐週金幣/任務拆分若還原得回來，保留參照、別直接刪。

5. **渲染/注音等基礎方案要單一真相，避免多套並存變技術債。**
   - 本案注音出現三處不同實作（W06 `zhuyin.js` DOM ruby、Arc2 自帶注音字體、recap.html 注音字體）。呼應「互動詞彙表＝單一真相」：**跨頁共用的底層渲染器也該單一真相**，多套並存要列待統一。

6. **過關條件擴充（本案 2→4）要同步三處：spec、教案流程、學習單勾選格。** 條件從「成就＋分數」加到「＋玩滿 40 分＋緊急任務 3 題」，三份文件的驗收/勾選/流程都要一起改，否則學生端與老師端對不上。

## 研究型/AI-使用課：把「問的深度」與「內容豐富度」規格化（2026-08 新增）
> 來源：S2-W07（用兩個真模型深度研究一個學業題目）。適用任何「用 AI 做研究/探究」的課——別讓「問得深、研究得豐富」停在憑感覺，做成可設計、可驗收、可調的規格。

1. **問的深度＝一條固定的深度階梯（Question Depth Ladder）**，不是「隨便再問一次」。
   - 建議三層：**D1 是什麼（事實）→ D2 為什麼/怎麼（機制）→ D3 連到生活/其他（連結）**。
   - 「追問挖深」＝沿階梯往下；每層系統只給**該層的關鍵字方向鷹架**（往「為什麼」或「生活例子」挖），**是鷹架不是答案**（呼應第十七節開放式學習目標）。
   - 深度可驗收：標「每個探究點挖到第幾層」；深度徽章＝挖到底。低年級只**選/打關鍵字**（第十九節），別要求整句。

2. **內容豐富度＝可量測的 rubric（Content Richness Rubric）**，當作解鎖/過關門檻，別用「感覺夠了」。
   - 三尺度：**單一回答**（含事實＋原因或例子，用長度/分行/原因詞近似判）→ **單一探究點**（挖到 ≥D2 且 ≥1 重點入筆記）→ **整份成品**（涵蓋 ≥N 個探究點、≥K 個挖到 D3、≥M 張重點、≥1 個跨點連結）。
   - **豐富度儀表**即時顯示（涵蓋數 × 平均層級 × 重點數 × 連結數）；**達門檻才解鎖下一階段**（如「先研究夠深夠廣、才准比較/總結」）。
   - 門檻數字列 **B 層（老師可調、依實測校準）**；「用可觀測門檻定義豐富度」本身列 A 層（呼應本檔「難度/門檻用學生可觀測條件，不用感覺」）。

3. **深度與豐富度不該靠灌水**：深度來自「同一點挖三層」、豐富來自「多點×多層×連結」，**不是換一堆不相干的題目**或重複同動作。與時長模型（§22）搭配時，深度階梯通常不新增動作（追問次數已計），跨點連結約 +1 拖拉。
