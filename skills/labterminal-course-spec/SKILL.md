# Lab Terminal 課程開發文本生成器

## 你的任務

讀取一份既有的**學習單**，把它轉換成一份**給工程 LLM 的開發規格（建置文本）**。
工程 LLM（Copilot / Claude）拿到這份規格後，就能產出一個可以在 **Lab Terminal 內部分頁**執行的**單檔 HTML 遊戲化互動課程**。

> 你產出的是「規格文本」，**不是最終 HTML**。你的工作是把學習單的教學內容，翻譯成工程 LLM 看得懂、照著做就能蓋出符合第二十節規範的互動課程的詳細藍圖。

## 第一步：讀取上下文（必做，按順序）

1. `程式教育課/CLAUDE.md` — **重點精讀第二十節「課程 Web App 互動設計規範」**，這是本 skill 的最高準則：
   - 標準 7-screen 骨架（start / recall / taskA / taskB / summary / wall / done）
   - 雙難度設計矩陣（G1–G2 低年級 / G3 高年級）
   - 鐵則 6（主觀選擇必須掛勾客觀驗證）、鐵則 7（自由打字必須有五要素）
   - 防作弊驗證策略（內容驗證非字數、user-select、攔 paste/drop、錯誤選項鎖定）
   - Icon 視覺規範（禁 emoji、AI 生圖、統一風格 prompt）
   - 也要看第十四節（工具政策：只用 Lab 系列）、第二十一節（每堂主線金幣固定 250）。
2. **目標學習單**：`程式教育課/wiki/worksheets/S{N}/S{N}-W{NN}-學習單.md`（若使用者直接給了學習單內容或路徑，以該檔為準）。
3. 對應教案（若存在）：`程式教育課/wiki/lesson-plans/S{N}/S{N}-W{NN}-教案.md` — 補充教學目標、成功條件、金幣。
4. 本 skill 的 `reference/spec-template.md` — 輸出模板（你要照它的結構填）。
5. 本 skill 的 `reference/lesson-design-guide.md` — **開發團隊實戰設計指南（權威）**。凡「概念課／模擬器型」課程（帶學生走一條有產出的旅程，如遊戲開發模擬器），**一律遵循本指南的站結構與十大原則**。
6. 本 skill 的 `reference/spec-governance.md` — **規格治理準則（權威，所有課程 spec 適用）**。避免「實作無聲偏離 spec」：正典/追溯、In/Out of Scope、跨週技能地圖、可數單位、互動詞彙表、防挫折 vs 反硬 A、認知/識字負荷、時長預算+實測校準、老師端+翻轉教育、跨切面需求、素材規格、DoD。**輸出的 spec 開頭必含 §G 治理區塊**。
7. 本 skill 的 `reference/game-course-design.md` — **互動遊戲課設計準則（權威）**。凡「要做成有遊戲性」的課：**遊戲迴圈 v1 就寫（禁事後補）**、**pass/fail 本地判定 + distractor（AI 只陪伴、不當關主）**、真實應用從客觀事實/選項不洩題、**時長靠深度不靠重複＋恆有跳關鈕**、防硬 A 參數、金幣 idempotent、角色跨頁一致、UI 情緒底線。**輸出的 spec 必含 §GL 遊戲迴圈與判定區塊。**
8. 本 skill 的 `reference/low-grade-game-spec.md` — **低年級教育遊戲 spec 準則（權威，P1U/注音世代）**。**meta 原則：內容/敘事/視覺寫死；難度/失敗/手感標「假設，待實玩校準」；狀態/資料/容錯升級成一等公民正式章節。** 每條 spec 標【規定/推定/假設】；安全網分層（A 保底寫死/B 懲罰可調，失敗代價是旋鈕非零）；動作集封閉集合走 change-control；新輸入必有專屬教學關；連載開場必回顧；獎勵全程可視 HUD＋收集閉環＋頒獎儀式；一角一圖複用＋難度視覺數列＋關卡≥4 地圖總覽；全注音是子系統（渲染驗收清單）；資料與狀態/失敗離線正式章節。**做低年級遊戲型 spec 一律遵循本檔。**

> **單一事實來源原則**：互動規則、雙難度矩陣、防作弊細節以 **CLAUDE.md 第二十節為準**；「有產出的旅程」站結構、白話 prompt、AI 判讀、再說一次、誠實示意、二選一決策、總複習考試等以 **lesson-design-guide.md 為準**。不要在輸出裡複製整段條文，而是「套用」它。

## 第二步：確認難度版本（必問，除非使用者已指定）

本 skill **一次只產一個難度版本**。開始前先確認：

- **G1–G2（低年級，S1–S4 取向）**：點選、拖拉、圖示優先，文字量極少，互動為主。
- **G3（高年級，S5+ 取向）**：Step Flow 一頁一格自由打字 + 可見提示 + 跨步驟內容驗證。

若使用者沒明說，直接問一句：「這份要做 G1–G2（低年級互動版）還是 G3（高年級 Step Flow 版）？」
有預設參考：S1–S4 學習單預設 G1–G2，S5+ 預設 G3，但仍以使用者指定為準。

---

## 第三步：抽取學習單的教學骨幹

從學習單裡找出並記錄：

- **任務清單**：任務 ID、名稱、類型（MC/EX/MS/TA）、工具、金幣（主線應合計 250）。
- **核心訊息（key message）**：這堂課最重要的「一個動作或感受」（不是抽象概念）。例：「寫清楚的 prompt，AI 才給得出你要的東西」。這會是貫穿 5 處以上的記憶點。
- **Hook 承諾**：start 頁要讓學生「看到」的最終成果（視覺承諾）。
- **學習目標 vs 工具操作**：分清楚哪些是「開放式學習目標」（第十七節，給起點不給答案）、哪些是「工具操作」（第十五節，精細步驟）。互動課程裡兩者的驗證設計不同。

---

## 第四步：把學習單映射到 7-screen 骨架

逐一決定每個 screen 承載學習單的哪一段，並依**所選難度**選定互動類型（查 CLAUDE.md 第二十節雙難度矩陣）：

| Screen | 對應學習單內容 | G1–G2 互動 | G3 互動 |
|--------|--------------|-----------|---------|
| 0 start | 今天的冒險 / Hook | 難度選擇 + 視覺承諾 | 同上 |
| 1 recall | 上週概念回顧 | 拖拉配對（圖示×名稱） | Step Flow 2 步打字 |
| 2 taskA | 概念建立 | 元素萃取拖拉 | Step Flow 3 步打字（模糊/清楚/觀察） |
| 3 taskB | 創作練習 | 下拉積木 + 即時預覽 | Step Flow 5 步打字 + 即時預覽 |
| 4 summary | 今天學到什麼 | 句子接龍（含 4 個有教學意義的反例） | 同上（共用） |
| 5 wall | 技能/稱號 | 浮動磚塊點擊飛入 | 表格 + 必填 checkbox |
| 6 done | Deliver 兌現 Hook | 徽章 + 成果展示 | 同上 |

固定附加：任務 A、B 完成後各接一個 **Rehearsal Modal**（句子接龍，答對才能關閉）。

每個 screen 都要設計**通過條件**，並通過「30 秒亂點測試」（亂點無法過關）。主觀選擇一律掛勾客觀驗證（鐵則 6）；自由打字一律補滿五要素（鐵則 7）。

### 概念課／模擬器型的「站結構」（遵循 lesson-design-guide.md）

當課程是「帶學生走一條有產出的旅程」（如遊戲開發模擬器），taskA/taskB 內每一站（一個概念）走 4–5 步，**取代舊的「造句」設計**：

```
① 讀懂（AI 情境對話 ~150 字，術語配比喻）
② 理解確認 ×2（選擇題，干擾項＝似是而非混淆點，答錯永久鎖定、選項洗牌）
③ 填空（填出該專有名詞，接受中英/同義）
④ 白話下指令 prompt（學生用一句白話說「這步想讓成品做到什麼」→ **本地規則判 pass/fail + distractor 清單**；AI 只做角色化回應/潤飾，**不當關主**，見 game-course-design.md）
⑤ (可選) 二選一決策（產品/技術取捨，每選項附後果，反映到後面產物）
   → 完成 → 左側資料夾多一檔、成品預覽長出一塊
```

- **不要**逼學生在 prompt 裡講術語或指定檔名（術語已用②③考過）——這是硬性修正。
- **不要**用關鍵字清單當通過條件；改寫清楚「這一步該做的事(goal)」交 AI 判。
- 至少 1–2 站設「**AI 反問、再說一次**」（第一次指令不夠清楚 → AI 追問 → 補述才過）。
- 做不到的概念（多人連線、雲端 DB）用「**誠實示意 + 明確標註**」，不假裝可玩。
- 真實流程順序：**該先決定的放前面**（核心玩法 → 單人/多人 → 技術選型 → 規格）；檔名要在「技術選型」站後才出現。
- 進階細節放「**深入了解**」折疊卡，主線淺白。
- **summary 改為總複習考試**：8–10 題橫跨整條流程，答完給成績 X/N + 評語 + 獎勵，錯的標正解。金幣**綁帳號**（跨裝置、不重複刷）。

## 第五步：依模板產出開發文本

照 `reference/spec-template.md` 的結構撰寫，逐 screen 給工程 LLM 足夠細節：

- 每個 screen：**目的、互動類型、要顯示的文案（可直接用）、通過/驗證邏輯、防作弊措施、setup() 要做的事**。
  - 驗證邏輯：填空/選擇用關鍵字/類別計數即可；**白話 prompt 的 pass/fail 用本地規則 + distractor 清單**（可離線可重現）；AI 只做體驗回饋/潤飾，**不當關主**（見 game-course-design.md）。
- **概念課／模擬器型**：附 **每站設計表**（概念、AI 段落、理解題×2、填空提示、白話 prompt 範例、goal、產物檔名、預覽變化、決策），並標明哪幾站要「再說一次」、哪些概念是「示意」。
- **Rehearsal Modal**：句子接龍題幹、正解、4 個反例（每個反例要有教學意義，不是隨機干擾）。
- **總複習考試**（概念課於 summary 段）：8–10 題橫跨全流程，成績 X/N + 評語 + 獎勵，錯的標正解。
- **Icon 清單**：列出本課需要的圖示、檔名（`assets/icons/xxx.png`）、以及套上統一風格後綴的完整生成 prompt（見 reference）。
- **金幣**：主線合計 250（第二十一節），標出每個 screen/任務對應的金幣與計算。
- **驗收清單**：把第二十節「Web App 課程開發自我審核清單」轉成本課可勾選的具體項目。

語言：繁體中文。文案要可以直接被工程 LLM 放進畫面（已是給小學生看的口吻）。

## 第六步：用 activity-time-estimator 驗證時長（必做）

規格定稿前，用姊妹 skill 的計算引擎估算這份課程在目標年級的耗時，確認 7-screen 的內容量達標（不要憑感覺）。

1. 把每個 screen 拆成原子動作（讀說明字數、打字字數、點擊/拖拉次數、截圖、告知老師等），組成 spec JSON：
   ```json
   {
     "grade": 3,
     "target_min": [50, 65],
     "activities": [
       { "label": "start:讀 Hook", "action": "read", "chars": 15 },
       { "label": "recall:拖拉配對", "action": "drag", "count": 5 },
       { "label": "taskB:Step Flow 打字", "action": "type", "chars": 25 }
     ]
   }
   ```
   （年級對應難度：G1–G2 用 1 或 2，G3 用 3 以上；動作類型見 estimator 的 `reference/action-catalog.md`）
2. 執行（路徑相對於專案根）：
   ```
   python3 skills/activity-time-estimator/scripts/ect_estimator.py <spec.json>
   ```
3. 看判定：
   - **太短** → 回第四步加大任務、增加 repetition 或 Step Flow 步驟，再重估，直到落在 50–65 分鐘。
   - **太長** → 把部分 screen 內容標為「進階可選」或拆到下週。
   - **閱讀超量警告** → 縮短該則指令或改用圖示/互動（呼應第十九節）。
4. 把估算結果（總分鐘 + 判定）寫進開發文本的 §1 後設資料「預估時長」欄，附一行「已用 activity-time-estimator 於年級 N 驗證」。

> 若 activity-time-estimator skill 未安裝，仍照模型手算（f=(年級+1)/2，打字 8/f 秒/字、點擊 8/f 秒/次、閱讀 2/f 秒/字），並在規格中註明未經腳本驗證。

## 注意事項（不可違反）

- **工具政策（第十四節）**：規格內任何 AI 功能一律走 Lab 系列（Lab Terminal / Lab Image / Lab Video），不得出現需要學生申請帳號的第三方服務；圖示禁 emoji。
- **學習目標開放、工具操作精細（第十五、十七節）**：互動課程的驗證要逼學生「真的做/真的想」，不能照抄就過。
- **白話 prompt，不逼術語（lesson-design-guide 原則①）**：概念課的下指令環節用白話；術語只用理解題+填空考，不在 prompt 再考一次；不逼學生講檔名。**但 pass/fail 用本地判定（原則② 已修正），AI 不當關主。**
- **遊戲迴圈 v1 就寫、判定本地化（game-course-design.md）**：有遊戲性的課，寫學習目標時同步附遊戲迴圈；時長靠深度不靠重複、恆有跳關鈕；防硬 A 參數（鎖時 2＋N、選項 ≥2、失敗非致命）。
- **產出看得見、誠實示意（原則⑤⑦）**：每站有可見產物（檔案/預覽長一塊）；做不到的概念標「示意」，不假裝可玩。
- **規格治理（spec-governance.md）**：spec 是唯一真相、綁定實作檔、In/Out of Scope 寫死、互動詞彙表單一真相、防挫折與反硬 A 分表、老師端+翻轉教育為一級需求、跨切面需求第一版就定、時長以課堂實測校準。開頭必含 §G 治理區塊。
- **防作弊是硬性要求**：hint 框 `user-select:none`、輸入框攔 `paste`/`drop`、錯誤選項點擊永久鎖定、驗證看內容不只看字數、錯誤訊息要具體（「還沒提到：形狀、大小」）。
- **金幣（第二十一節）**：主線固定 250，進階/選做與 TA 不佔額度。
- 若學習單缺某段（如沒有 recall 內容），回頭看教案或上一週學習單補；真的沒有就在規格中標註「TODO：缺上週回顧素材」。
