# Lab Terminal Quest｜故事與題目設計

## 你的產出是什麼

**兩種 Markdown 規格文件**，交給 Phaser agent 實作：

| 產出 | 何時做 | 位置 |
|---|---|---|
| 世界觀規格 | **只有要開新劇本時**（約 4 週一個單位） | `specs/lab-terminal-quest/S{N}/S{N}-世界觀規格-{劇本代號}.md` |
| 週建置規格 | 每週一份 | `specs/lab-terminal-quest/S{N}/W{NN}/S{N}-W{NN}-Lab-Terminal-Quest-建置規格.md` |

範本在本 skill 的 `reference/` 底下，**照結構填，不要自創章節順序**。

> 你不寫程式碼。寫完規格就交棒給 `skills/labterminal-quest-phaser/`。
> 如果使用者要的是「一題一卡的分頁互動課」而不是地圖探索關卡，那不是本 skill，改用
> `skills/labterminal-course-spec/`。

## 第一步：讀取正典（必做，按順序）

1. `specs/lab-terminal-quest/standards/lab-terminal-quest-narrative-standard.md` — **本 skill 的最高準則**。
   鐵則 K（知識轉譯）／N（敘事）／D（對白）／G（小遊戲選型）、§6 同齡教材校準、§7 內容量預算。
2. `specs/lab-terminal-quest/standards/lab-terminal-quest-level-design-standard.md` — 下游驗收條件。
   §2 線索交易五階段、鐵則 A/B/C、§6 資料模型、§7.1 的 V-1～V-14。**你的產出必須天生通過這些。**
3. `specs/lab-terminal-quest/standards/lab-terminal-quest-question-npc-contract.md` — 題型與 NPC 行為契約。每題只能是 `choice` 或 `fill`，每站須有完整 `npcProtocol`。
4. `specs/lab-terminal-quest/standards/lab-terminal-quest-phaser-runtime-standard.md` — 只需讀 §11 與 §5，知道下游會怎麼吃你的規格。
5. 若沿用既有劇本：讀該份**世界觀規格**（角色卡在裡面，對白風格要對得上）。
6. 本週既有素材（若有）：`wiki/worksheets/S{N}/`、`wiki/lesson-plans/S{N}/`。
7. 本 skill 的 `reference/世界觀規格-範本.md` 與 `reference/週建置規格-範本.md`。

> **單一事實來源**：不要在規格裡複製正典條文。引用寫條款編號（如「依 A-1」），條文只有一份。

---

## 第二步：收方針（必問，除非使用者已指定）

**劇本單位由負責人決定，不要自己判斷。** 開始前確認四件事：

1. **本週知識點**是什麼？（一句話，具體到可以寫成「因為沒有〇〇，所以〇〇做不到」）
2. 本週屬於**哪個劇本單位**？沿用現有世界觀規格，還是要開新劇本？
3. 這是該劇本的**第幾週**？（決定要不要寫開場回顧，N-7）
4. 有沒有既有的學習單／教案要對齊？

沒問清楚就開始編故事，最後常常整份重來。

---

## 第三步：定閱讀量預算（硬門檻，不可跳過）

**目的是定出這一關可以放多少字、什麼樣的字。不是決定教學深度。**

為什麼是硬門檻：這套關卡的答案全部藏在對白裡（D-3），所以對白**只能加不能減**。一旦超出學生的
閱讀負荷，學生不會讀慢一點，而是**直接跳過對白亂猜**，「讀在問前」的整套設計就空轉。

參考同年齡層（小四／9–10 歲）的既有讀物與教材，訂出這幾個數字：

| 指標 | 這一步要做什麼 |
|---|---|
| 每句 ≤ 25 字、每節點 ≤ 3 句 | 已由正典固定（V-1、D-4），不用校準 |
| 每張來源卡總字數 | ✔ 訂上限 |
| 全關卡對白總字數 | ✔ 訂上限（這會直接決定站數與交易數） |
| 生詞數上限 | ✔ 訂上限 |
| 可讀性年級 | 這裡訂目標值，**第九步用 CRIE 實測回填** |

工具（起手清單見 narrative-standard §6）：

- [TBCL 臺灣華語文能力基準](https://coct.naer.edu.tw/page.jsp?ID=10) 分級詞語表／漢字表——逐詞比對，抓超齡生詞。
- **同齡讀物與現有教材實量**——直接數字數：同年級課文一課多少字、既有週次學習單多少字。最貼近實況的一種。
- [可讀性預測於中小學國語文教科書及優良課外讀物之研究](https://aclanthology.org/O15-1008.pdf)——總量基準的旁證。
- [CRIE 中文文本可讀性自動化分析系統](http://www.chinesereadability.net/CRIE/publish.html)——第九步實測用，是拿來讀**自己寫的對白**，不是讀別人的。

產出**閱讀量預算表**（附進建置規格）＋**生詞清單**（每個超齡詞配一句 ≤25 字的當場解釋，D-7）：

| 項目 | 本週上限 | 實際 | 依據 |
|---|---|---|---|
| 每張來源卡字數 | | | |
| 全關卡對白總字數 | | | |
| 生詞數 | | | |
| CRIE 可讀性年級 | ≤ 目標年級 | 第九步回填 | |

**四件不准做**：超標時把句子縮到看不懂（要刪的是站與交易，不是可讀性——對白是答案來源，砍到
看不懂等於拿掉答案）；把參考來源的文案直接搬進對白；抄定義；憑感覺說「小四應該讀得完」而沒有數字。

---

## 第四步：知識轉譯（K）

把知識點變成「這個世界裡非它不可的問題」。

**驗收方法（K-1）**：寫出一句「因為沒有〇〇，所以〇〇做不到」。句子不成立，代表知識只是裝飾，重做。

- ✅ 因為沒有把四種需求講清楚，所以木匠做出來的橋不能用。
- ❌ 因為沒有四種需求，所以村民很難過。（難過不是做不到）

同時決定 **K-4 缺席示範**：每一站要讓玩家**看見**「沒有這個知識會怎樣」。S3W05 的做法是反派丟出爛
prompt，產出一張明顯不對的圖。失敗要可見，學生才知道自己在修什麼。

其餘：具體先於抽象（K-3，用小推車不用「運輸受阻」）、一週一知識（K-5）。

---

## 第五步：世界與角色（新劇本才做）

沿用既有劇本就跳過，直接用該份世界觀規格的角色卡。

要開新劇本時，照 `reference/世界觀規格-範本.md` 填。重點：

- **角色卡**每人一張：名字、身分、和玩家的關係、說話習慣（用詞、句長、口頭禪）、一句話動機。
  說話習慣要具體到「下週別人來寫也寫得出同一個聲音」。
- **反派是錯誤示範不是壞人**（N-6）：他失敗的原因必須正好是本劇本知識的缺席。
  禁止用霸凌、羞辱、傷害當衝突來源。
- 開頭寫明**接續或取代哪一份**，以及學生視角上這個轉換怎麼被解釋（§0 第 4 點）。

---

## 第六步：站鏈與閘門因果（N）

- 每站＝**一個壞掉的東西 ＋ 一個說不清楚的人**（N-2）。站的變化來自「壞掉的是什麼」，
  不是換一種互動方式。
- 每站內部五段式：遇到問題 → 看見失敗示範 → 蒐集線索 → 湊成規格 → 世界改變（N-3）。
- **閘門開啟要有物理後果**（N-1）：湊齊規格 → 木匠照著做出橋 → 橋能走了。
  ❌ 禁止「答對四題，門開了」。
- 任何一站的解法不得要求記得前一站的細節（N-4）。
- 結局讓核心訊息**由角色說出來**（N-5）。
- 連載第 2 週起，開場要有 ≤3 句回顧（N-7）。

建議規模：4–5 站（含序章），每站 3–4 筆交易，總計 14–18 筆（§7）。

---

## 第七步：角色對白與線索交易（D）

這是最容易出錯的一步。**先寫對白，再從對白挑答案句，最後才寫題目**——反過來寫一定會出現
「題目問的東西世界上不存在」。

每筆交易要交出：

| 欄位 | 注意 |
|---|---|
| `sourceLabel` | 站內唯一，**不得與該站 NPC 同名**（V-12） |
| `sourceCard.lines` | 角色講的話，逐句一元素，**每句 ≤ 25 字、每節點 ≤ 3 句**（D-4、V-1） |
| `question` | 只能是 `choice` 或 `fill`；choice 的錯誤選項要能被來源卡排除（A-7），fill 的唯一空格回填後要逐字還原來源句 |
| `npcProtocol` | 站級固定行為：靠近、指向來源、choice、fill、答對、答錯、完成；NPC 的來源對白一律由 `sourceCard.lines` 輸出 |
| `answerEvidence` | `{ lineIndex, keywords }`；keywords 必須**同時**出現在該來源句與正解選項裡（V-3、V-4） |
| `clueText` | 中性線索，能從來源卡完整取得（V-7），**不標分類** |

寫對白時反覆確認：

- **D-3 逐字含答案**：題目要問的那句話，逐字出現在對白裡，且就是 `lines[answerEvidence.lineIndex]`。
- **D-5 不洩分類**：對白不得出現「做什麼／怎麼做／不能做什麼／目標」，也不得用「第一件事、第二件事」
  這種等價暗示。
- **D-8 計量詞要對得上**：題幹寫「哪一張運貨牌」，同一張來源卡上就必須並列三張。
  做不到就把題幹改成單數。**這是 S3W05 六題出錯的地方，寫的時候就要防。**
- **D-2 角色講自己的事**：❌「我們要學的是四種需求」 ✅「我推車過不了河，你幫我問問木匠。」
- **D-7 生詞當場解釋**：由角色在同一節點內用一句 ≤25 字解釋，不靠註解或 tooltip。

---

## 第八步：小遊戲選型（G）

**G-1 同構原則：玩家的手在做的事，要跟腦裡要學的事同構。** 手做的事跟知識無關（打地鼠、接東西）
就是純填時間，不合格。

| 知識的形狀 | `kind` |
|---|---|
| 有先後順序的流程 | `order` |
| 要辨識／分類 | `pick` |
| 空間、方位、角度 | `rotate` |
| 路徑、連續動作 | `path` |
| 對應、配對、歸位 | `drag-snap` |
| 純閱讀理解就夠 | `none` |

- **G-3 覆蓋率一致**：同站內三選一——每筆交易各有／全站共用一個／全站都沒有。禁止部分有部分沒有。
- **G-4**：8–20 秒可完成，題幹每卡 ≤ 25 字。
- **G-5**：`kind` 是封閉清單。要新增型別，先更新 level-design-standard §5 的 C-3，再說。
- 小遊戲的獎勵是**解鎖提問**，不是直接得到線索（C-1）。規格裡的「成功獎勵」欄一律寫「解鎖〇〇的提問」。

---

## 第九步：實測與預檢

1. **CRIE 可讀性實測**：把第七步寫好的**對白全文**丟進
   [CRIE](http://www.chinesereadability.net/CRIE/publish.html)，得出可讀性年級，回填第三步的預算表。
   高於目標年級就回第七步——先換掉超齡詞（生詞清單），還是不行就刪交易。
2. **字數與生詞數對帳**：實際值填進預算表，逐項不得超過第三步訂的上限。
3. **金幣合計 250**（跨週固定，不得調整）。
4. **ECT 50–65 分鐘**：呼叫 `skills/activity-time-estimator/`。超時就**刪站或刪交易**，
   不要縮短對白到看不懂，也不要加重複回合灌時長。
5. **V-1～V-14 自我預檢**（清單見 level-design-standard §7.1）。最常被擋下的三項：
   - **V-3** 關鍵詞不在來源句裡（回第七步改對白，不是改題目）
   - **V-5** 計量詞題幹配單一項目（D-8）
   - **V-14** 雙正解：正解與來源句的字元重疊率，必須嚴格高於每個錯誤選項（建議差距 ≥ 0.15）
6. 走一次 narrative-standard §8-2 的人工審查清單。

---

## 第十步：交付

照範本產出規格檔，確認含：閱讀量預算表（含 CRIE 實測結果）、生詞清單、來源清單（標題＋網址＋
查閱日期）、站鏈與閘門因果、角色與對白全文、每筆交易的五個欄位、小遊戲清單與選型理由、
金幣分配、ECT 結果、預檢結果（V-1～V-14 逐條通過與否）。

然後告訴使用者：可以交給 `skills/labterminal-quest-phaser/` 實作了。

## 不要做的事

- 不要先寫題目再回頭補對白。順序反了就會生出「世界上不存在的題幹」。
- 不要在週建置規格裡重寫世界設定。引用世界觀規格，一行帶過。
- 不要因為這一站「想做得特別一點」就自創 `kind`。要新增先改正典。
- 不要把參考來源的文案搬進對白。校準的是**量**，不是文字。
- 不要為了塞進閱讀量預算而把對白縮到看不懂。對白是答案來源，砍到看不懂等於拿掉答案——要刪的是站與交易。
- 不要在對白裡出現課堂語言或四個分類詞。
- 不要用加回合數的方式湊時長。
