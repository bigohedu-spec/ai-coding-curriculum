# Lab Terminal Quest｜美術素材規格表（角色／物件／陰影，手動生成用）

> 給負責人手動生成美術素材時對照的規格表。目的：素材一次做對「共用畫布＋共用基準線」
> （見 [[lab-terminal-quest-production-workflow]] §3），不要等進了程式才發現尺寸或錨點
> 不一致，事後只能用 runtime 校正表補洞。
>
> 本檔是**可複製的規格範本**：S3W05「失落規格的溪谷」是目前唯一已落地的具體實例，其欄位
> 已填好現行值；下一個 Lab Terminal Quest 關卡沿用同一份表格，只改「本週實際值」欄。

## 1. 通用規則（所有素材共同遵守）

- 透明背景 PNG，不要文字／數字／浮水印／品牌標誌。
- 不使用 emoji 作為正式素材；需要圖示一律生成。
- 兒童友善：不恐怖、不血腥、不含武器／戰爭意象。
- 統一風格：溫暖童話冒險遊戲、柔和厚描邊、單一物件置中構圖。
- 同一角色／同一物件跨站、跨週維持同一份權威外觀描述，不要中途換畫風。
- 每個素材輸出後，先用「不透明像素外框（bounding box）」量測一次，確認底部基準線對齊
  （見 §2、§3），不要用肉眼估。

## 2. 角色動畫素材（可移動主角）

| 項目       |                                                                              規格 | 本週（S3W05）現行值                                                                    |
| -------- | ------------------------------------------------------------------------------: | ------------------------------------------------------------------------------- |
| 共用畫布尺寸   |                                          正方形，邊長依角色實際內容最大外框抓（建議 ≥ 內容最大寬高＋2px 邊界） | `52 × 52` px                                                                    |
| 接地基準線    |                                                       全部影格的腳底不透明像素最底列，固定對齊畫布同一列 | 第 `49` 列                                                                        |
| 水平置中方式   |                                         每張影格各自依自己的內容外框中心點置中，不用單一固定 x 座標（保留姿態差異） | 同左                                                                              |
| 方向數      |                                                                            8 方向 | north / north-east / east / south-east / south / south-west / west / north-west |
| Idle 影格數 |                                                                             每方向 | 4                                                                               |
| Walk 影格數 |                                                                             每方向 | 8                                                                               |
| 檔案路徑慣例   | `public/assets/lab-terminal-quest/player/{idle,walk}/<direction>/frame_XXX.png` | 同左                                                                              |
| 匯出檢查     |                         同一批次（idle 全部、walk 全部）原生畫布尺寸必須完全一致，不能有的方向 64×64、有的 68×68 | —                                                                               |

**給生成工具的風格提示（可直接複製，依角色調整主體描述）**：

```
top-down / 3-4 view whimsical adventure game character sprite, warm storybook
colors, soft thick outline, single character centered, transparent background,
no text, no watermark, child-friendly, 8-directional walk cycle consistent
proportions across all frames
```

**製作順序建議**：先出一套完整方向／狀態，再統一跑一次裁切＋重新置中的正規化腳本
（裁到不透明外框 → 貼到共用畫布、底部對齊基準線），不要跳過正規化直接進 runtime。

## 3. NPC／地標／互動物件素材

| 項目 | 規格 |
|---|---|
| 視角 | Top-down 或固定 3/4 top-down，與 Gamma 地圖構圖一致，不與角色側視動畫混用 |
| 背景 | 透明 |
| 構圖 | 單一物件置中，四周留白（可互動物旁至少保留 100×100 世界座標的空白點擊區） |
| NPC 需要幾張 | 1 張 top-down 地圖小人（放在地圖上）＋ 1 張對話頭像（右欄／對話框用），2 種表情框（正常、完成）即可，不需逐週新增動畫 |
| 命名慣例 | 依角色／物件語意命名，避免用序號當唯一識別（例如 `npc-village-chief.png`，不要只用 `npc1.png`） |

**給生成工具的風格提示（可直接複製，依物件調整主體描述）**：

```
top-down 3/4 view game map prop icon, warm storybook adventure style, soft
thick outline, single object centered, transparent background, no text, no
label, child-friendly, consistent with a whimsical valley village setting
```

## 4. 陰影素材（前瞻規格，供未來偽物理拖動解謎關卡使用）

> 目前 S3W05 尚未有可拖動物件；本節是負責人已預告的未來需求先寫好的規格，讓陰影素材從
> 第一版就避免重蹈角色動畫「先出素材、後補 runtime offset」的覆轍。真正開始開發偽物理
> 關卡時，先回來確認／補完本節，再動手做素材。

| 項目 | 規格 |
|---|---|
| 用途 | 用陰影大小／位置表現物件的高低差錯覺（例如：物件被拿起／拖曳中 vs. 落地靜止） |
| 素材形式 | 獨立圖層（跟物件本體分開輸出的一張 PNG），不要畫進物件本體圖裡 |
| 錨點慣例 | 陰影圖的「陰影中心」必須對齊畫布上固定的一列／一點（比照 §2 的「接地基準線」概念），
  讓陰影的錨點跟物件的「地面接觸點」在美術端就先對齊，不要等進了程式才用 offset 校正 |
| 高度變化的表現 | 建議至少準備 2–3 級陰影尺寸（例如：貼地／半空／高處），尺寸變化用縮放，
  縮放中心固定在同一個錨點，不要縮放時連錨點位置也跟著偏移（這正是角色「腳浮空」bug
  的成因，陰影不能重複同一個錯誤） |
| 顏色與透明度 | 純黑或深色橢圓，半透明（建議 30–45% 不透明度），不需要漸層細節，保持辨識度優先 |
| 與物件本體的對應 | 每個可拖動物件至少需要：本體美術（可能含多個高度狀態）＋ 對應的陰影組，
  兩者用同一組座標系統設計，不要分開兩個人各自抓座標 |

## 5. 交付與驗收方式

負責人手動生成完素材後，交付時建議附上：

1. 檔案本身（依 §2／§3 路徑與命名慣例存放）。
2. 每組素材的「原生畫布尺寸」（讓後續正規化腳本知道要不要重新裁切）。
3. 若同一角色／物件有多個狀態（idle／walk，或未來的陰影高度分級），註明是否為**同一批次
   匯出**（同批次原生尺寸應完全一致；不同批次要特別註明，好讓正規化流程知道要分開處理）。

不需要負責人自己手動對齊像素基準線——正規化（裁切＋重新置中＋統一基準線）由後續程式流程
處理，負責人只需要確保：同一角色的 idle 與 walk 分開匯出時，**畫布大小可以不同，但同一
批次內部（例如 8 個方向的 walk）畫布大小要一致**，方便正規化腳本批次處理。
