# Lab Terminal Quest｜故事與題目設計標準（知識轉譯、敘事、對白、小遊戲選型）

> 給「內容作者 AI／負責人」共用的正典：規定**拿到「本週學生要學會什麼」之後，怎麼把它變成一個
> 有世界、有角色、有對白、有小遊戲的關卡內容**，最後交出一份 Phaser agent 可以直接實作的建置規格。
>
> 這是整條生產鏈最上游的一份。四份文件的分工：
>
> | 文件 | 管的事 | 誰吃它的產出 |
> |---|---|---|
> | **本檔** | 知識點 → 世界、角色、對白、題目、小遊戲 | 建置規格 |
> | [[lab-terminal-quest-level-design-standard]] | 題目與互動的**設計正確性**（A/B/C、V-1～V-14） | 本檔的產出必須通過它 |
> | [[lab-terminal-quest-production-workflow]] | 四層內容的順序與存放位置 | 本檔遵守它的順序 |
> | [[lab-terminal-quest-phaser-runtime-standard]] | 落地成程式的工程契約（R、P-1～P-14） | 吃本檔的建置規格 |
>
> **本檔不重新定義 A/B/C/V 任何一條。** 那些是驗收條件，本檔是生產方法——目標是讓產出「天生就通過」，
> 而不是做完再回頭補。
>
> 建立原因：2026-09-09。已有的三份正典都是「拿到內容之後」的層，沒有任何一份說明「內容從哪裡來」。
> 實務上這一段最耗時也最容易失控——S3W05 的題目之所以會問到世界上不存在的東西（警示牌從未渲染）、
> 之所以會有六題計量詞題幹配單一項目，根因都是內容作者沒有一套從知識點長出世界的固定方法。

## §0 兩層文件模型【規定】

內容分成兩份文件，**分屬不同的生命週期**。這是負責人 2026-09-09 給的方針：劇本以**約四週為一個單位**
更換，換劇本時開新檔，不在舊檔上疊改。

| 文件 | 範圍 | 位置 | 換的頻率 |
|---|---|---|---|
| **世界觀規格** | 一個劇本單位（預設約 4 週）共用的世界、反派、角色設定集、語氣基調 | `specs/lab-terminal-quest/S{N}/S{N}-世界觀規格-{劇本代號}.md` | 換劇本時**開新檔**，舊檔保留 |
| **週建置規格** | 本週的地區、NPC、線索交易、題目、小遊戲、座標、金幣 | `specs/lab-terminal-quest/S{N}/W{NN}/S{N}-W{NN}-Lab-Terminal-Quest-建置規格.md` | 每週一份 |

規則：

1. **週規格不得重複定義世界設定**，只能用一行標明「本週屬於 `{劇本代號}`」並引用世界觀規格。
   世界設定散成好幾份、彼此漂移，是這套教材最貴的錯誤類型（見 `level-design-standard` §1 缺陷 1）。
2. **世界觀規格不得寫任何一週的題目**。它只回答「這個世界是什麼、有誰、他們怎麼講話」。
3. **劇本單位的長度由負責人給方針**，本檔只規定預設值（約 4 週）與換檔機制，不自行決定何時換。
4. 換劇本時，新世界觀規格的開頭必須寫明**接續或取代哪一份**，以及學生視角上這個轉換怎麼被解釋
   （「搭船去了另一座島」也算解釋，「什麼都沒說直接換場景」不算）。

## §1 生產順序（不可跳步）

```text
1. 收方針：本週知識點、屬於哪個劇本單位、沿用哪份世界觀規格（或要開新的）
2. 定閱讀量預算：參考同齡讀物與分級詞表，訂出本關可以放多少字、多少生詞（§6）
3. 知識轉譯：把知識點變成「這個世界裡非它不可的問題」（§2 鐵則 K）
4. 世界與角色：新劇本才做；沿用就跳過（§0）
5. 站鏈與閘門因果：本週走幾站、每站解決什麼、門為什麼開（§3 鐵則 N）
6. 角色與對白：把答案原文寫進角色嘴裡（§4 鐵則 D）
7. 線索交易與題目：sourceCard / choice 或 fill question / answerEvidence / clueText / npcProtocol（§5 前半）
8. 小遊戲選型：知識形狀決定 kind（§5 鐵則 G）
9. 實測與預算：CRIE 跑對白全文驗可讀性、金幣合計 250、ECT 50–65 分鐘（§6、§7）
10. V-1～V-14 自我預檢 → 產出建置規格 → 交給 labterminal-quest-phaser
```

**閱讀量校準分兩段**：第 2 步先用同齡讀物與分級詞表**訂出預算**（可以放多少字），第 9 步再用 CRIE
對寫好的對白**實測驗證**。只做後者的話，超標時已經整份寫完，要砍的是自己捨不得砍的東西；只做前者
則沒有客觀證據。兩段都要。

## §2 【鐵則 K】知識轉譯【規定】

> 一句話：**世界要讓知識變成承重牆，不是背景裝飾。**

| 條款 | 規則 |
|---|---|
| **K-1 知識是承重牆** | 把該知識從世界裡拿掉，故事必須**走不下去**。如果拿掉之後劇情照樣推進、只是少了幾句台詞，那知識就只是裝飾，重做。檢驗方法：寫一句「因為沒有〇〇，所以〇〇做不到」，句子若不成立就是失敗 |
| **K-2 閱讀量有上限且要有數字** | 這一關能放多少字、多少生詞，由 §6 的閱讀量預算表決定，並以 CRIE 實測驗證。禁止憑感覺說「小四應該讀得完」。超標時刪內容，不是縮短句子到看不懂 |
| **K-3 具體先於抽象** | 世界裡的東西必須是九歲小孩摸得到的：小推車、河、風車、木板。禁止「運輸受阻」「資訊不對稱」這類抽象名詞當作場景元素 |
| **K-4 缺席示範** | 每一站都要有「沒有這個知識會發生什麼」的**具體可見後果**（S3W05 的做法：阿修丟出爛 prompt → 產出一張明顯不對的圖）。學生要先看見失敗，才知道自己在修什麼 |
| **K-5 一週一知識** | 一週只承載一個核心知識點。相關但不同的概念留給別週，不得夾帶 |
| **K-6 事實正確** | 世界裡陳述為事實的東西必須正確（風車怎麼轉、橋怎麼承重）。小孩會當真。不確定就查，或改成不需要斷言事實的設計 |

## §3 【鐵則 N】敘事結構與進行邏輯【規定】

> 一句話：**門打開的理由要是故事因果，不能是「你答對了」。**

| 條款 | 規則 |
|---|---|
| **N-1 閘門要有物理後果** | 每個閘門的開啟必須是玩家在世界裡造成的具體改變（湊齊規格 → 木匠照著做出橋 → 橋能走了）。禁止「答對四題，門開了」這種純計數解鎖 |
| **N-2 每站＝一個壞掉的東西＋一個說不清楚的人** | 這是本架構的標準站型：某人有需求但講不清楚，玩家幫他把需求問清楚、湊成規格。站的變化來自「壞掉的是什麼」，不是來自換一種互動方式 |
| **N-3 五段式因果** | 每站內部：遇到問題 → 看見失敗示範（K-4）→ 蒐集線索 → 湊成規格 → 世界改變。五段缺一，該站就會變成「走過去答四題」 |
| **N-4 不依賴跨站記憶** | 任何一站的解法不得要求記得前一站的細節。這是 A-2 的敘事層對應：劇情可以有前後呼應，**解題不行** |
| **N-5 結局回扣核心訊息** | 最後一段必須讓核心訊息被說出來一次，且是**角色說的**，不是旁白或系統提示 |
| **N-6 反派是錯誤示範，不是壞人** | 反派（S3W05 的阿修）示範的是「做法不對」，不是「品格不好」。他失敗的原因必須正好是本週知識點的缺席。禁止用霸凌、羞辱、傷害等行為當作衝突來源 |
| **N-7 劇本單位邊界** | 一個劇本單位（約 4 週）內共用世界與角色；跨單位換場景時，開場要交代轉換（§0 第 4 點）。連載時每週開場需一段 ≤3 句的回顧 |

## §4 【鐵則 D】角色與對白【規定】

> 一句話：**對白是角色在講自己的事，順便把答案講出來——不是旁白在教書。**

| 條款 | 規則 |
|---|---|
| **D-1 角色設定集住在世界觀規格** | 每個角色一張卡：名字、身分、和玩家的關係、說話習慣（用詞、句長、口頭禪）、一句話動機。週規格只引用，不重寫 |
| **D-2 角色講自己的事** | 對白內容是這個角色的處境、困擾、想要什麼。禁止角色講出「我們要學的是四種需求」這種課堂語言 |
| **D-3 逐字含答案** | 題目要問的那句話，必須**逐字**出現在對白裡，且該句就是 `sourceCard.lines[answerEvidence.lineIndex]`。這是 A-1 與 V-3 能通過的唯一寫法 |
| **D-4 句長與節點長度** | 每句 ≤ 25 個中文字；一個對白節點 ≤ 3 句。超過就拆節點，不要把三件事塞進一句 |
| **D-5 不洩分類** | 不得把「做什麼／怎麼做／不能做什麼／目標」當成對白的分類名稱、按鈕標籤或排序提示，也不得用「第一件事、第二件事」這種等價暗示。角色在自然提問裡可說「這座橋是拿來做什麼的？」；四種需求只供內容作者檢查資訊有沒有說完整。學生以自然提問取得原句，直接組成 prompt，不得被強制分類、排序或放入四格。 |
| **D-6 跨週一致** | 同一角色在不同週的說話方式必須一致。改了要回頭改世界觀規格的角色卡，不能只改這一週 |
| **D-7 生詞當場解釋** | 出現學生沒學過的詞，必須由角色在同一節點內用一句話解釋，且解釋句同樣 ≤ 25 字。不得靠註解或 tooltip |
| **D-8 每站的可讀項目數要對得上題幹** | 題幹若用「哪一張／哪一組／哪三樣」，同一張來源卡上必須並列足夠數量的同類項目。做不到就把題幹改成單數（A-3、V-5）——這是 S3W05 六題出錯的地方，寫對白時就要防 |

## §5 線索交易與小遊戲選型

### §5-1 一筆交易的內容產出

一筆交易 = 一個互動點 = 一張來源卡 = 一題 = 一條線索。內容作者要交出：

| 欄位 | 怎麼想 |
|---|---|
| `sourceLabel` | 玩家在地圖上看到的名字。站內唯一，且**不得與該站 NPC 同名**（V-12） |
| `sourceCard.lines` | 角色講的話，逐句一元素。答案原文就在其中一句（D-3） |
| `question` | 只能是 `choice` 或 `fill`（見 [[lab-terminal-quest-question-npc-contract]]）；choice 的錯誤選項要能被來源卡排除（A-7），fill 回填後要還原來源句 |
| `npcProtocol` | 每站固定描述 NPC 的靠近、來源卡、兩題型等待、答對、答錯與完成行為；來源對白由 `sourceCard.lines` 唯一供應 |
| `answerEvidence` | `{ lineIndex, keywords }`；keywords 必須同時出現在該來源句與正解選項裡 |
| `clueText` | 中性線索，能從來源卡完整取得（V-7）。**不標分類** |

### §5-2 【鐵則 G】小遊戲選型【規定】

`level-design-standard` §5 的鐵則 C 管小遊戲的**定位**（它在流程裡是什麼、不能做什麼）。
本節管**選型**（該選哪一種），兩者互補不衝突。

| 條款 | 規則 |
|---|---|
| **G-1 同構原則** | **玩家的手在做的事，要跟腦裡要學的事同構。** 學排序就排東西，學分類就分東西，學方位就轉東西。手做的事跟知識無關的小遊戲（打地鼠、接東西）是純填時間，不合格 |
| **G-2 依知識形狀選型** | 見下表 |
| **G-3 覆蓋率一致** | 同一站內：每筆交易各有小遊戲／全站共用一個／全站都沒有，三選一。禁止站內部分有部分沒有（C-4、V-10） |
| **G-4 時長與閱讀量** | 8–20 秒可完成；題幹每卡 ≤ 25 中文字（C-5） |
| **G-5 新型別要先改正典** | `kind` 是封閉清單。要新增型別，先更新 `level-design-standard` §5 的 C-3，再寫 renderer（C-3、V-9） |

| 知識的形狀 | 建議 `kind` | 例 |
|---|---|---|
| 有先後順序的流程 | `order` | 先量尺寸再鋸木頭 |
| 要辨識／分類 | `pick` | 從三句話裡挑出真正的事實 |
| 空間、方位、角度 | `rotate` | 路標要指向哪邊 |
| 路徑、連續動作 | `path` | 小推車怎麼走過去 |
| 對應、配對、歸位 | `drag-snap` | 材料放進對應的格子 |
| 純閱讀理解就夠 | `none` | 短對話直接提問 |

> 選型卡住時，「不插電」教學活動（把概念變成一個純手做動作的課堂活動）是很好的靈感來源——
> 它們設計的正是「手要做什麼」，跟 G-1 同構原則要的東西一樣。這是選型參考，不是 §6 的必查項目。

## §6 閱讀量校準【規定】

負責人方針：**參考同年齡層的既有材料，目的是定出學生的閱讀量上限。** 這一步不決定教學深度，
只決定**這一關可以放多少字、什麼樣的字**。

理由：這套關卡的答案全部藏在對白裡（D-3），所以對白只能加不能減——一旦超出學生的閱讀負荷，
學生不會「讀慢一點」，而是**直接跳過對白亂猜**，整套「讀在問前」的設計就空轉。閱讀量是這個
架構的硬性上限，不是風格偏好。

### 要定出來的六個數字

| 指標 | 來源 | 備註 |
|---|---|---|
| 每句上限字數 | 已定：**≤ 25 字** | V-1、D-4，不需重新校準 |
| 每對白節點句數 | 已定：**≤ 3 句** | D-4 |
| 每張來源卡總字數 | **本週校準決定** | 一次呈現在畫面上的量 |
| 全關卡對白總字數 | **本週校準決定** | 決定站數與交易數上限（§7） |
| 生詞數上限 | **本週校準決定** | 超出年級分級的詞，每個都要吃掉一句解釋（D-7） |
| 可讀性年級 | **實測**，須 ≤ 目標年級 | 用 CRIE 跑對白全文 |

### 怎麼量（起手工具，不限於此）

| 工具／來源 | 用途 |
|---|---|
| [CRIE 中文文本可讀性自動化分析系統](http://www.chinesereadability.net/CRIE/publish.html)（臺師大） | **把寫好的對白全文丟進去**，得出可讀性年級。這是唯一能對自己產出直接下判斷的工具，不是拿來讀別人的 |
| [TBCL 臺灣華語文能力基準](https://coct.naer.edu.tw/page.jsp?ID=10)（國教院）分級詞語表／漢字表 | 逐詞比對，抓出超齡生詞，列進生詞清單 |
| [可讀性預測於中小學國語文教科書及優良課外讀物之研究](https://aclanthology.org/O15-1008.pdf) | 中小學教科書與課外讀物的實際可讀性落點，作為總量基準的旁證 |
| 同齡讀物與現有教材實量 | 直接數字數：同年級課文一課多少字、既有週次的學習單多少字。**最貼近實況的一種** |

### 產出：閱讀量預算表（必附在建置規格）

| 項目 | 本週上限 | 實際 | 依據 |
|---|---|---|---|
| 每張來源卡字數 | | | |
| 全關卡對白總字數 | | | |
| 生詞數 | | | |
| CRIE 可讀性年級 | ≤ 目標年級 | | 實測日期 |

外加**生詞清單**：每個超齡詞 ＋ 它在對白裡的那句 ≤25 字解釋（D-7）。
來源清單（標題＋網址＋查閱日期）一併附上，供日後複查。

### 禁止事項

1. **超標的正確處理是刪內容，不是縮短句子到看不懂。** 刪站、刪交易、合併角色都可以（§7）。
2. **不得把參考來源的文案直接搬進對白。** 校準的是量，不是文字。
3. **不得抄定義。** 世界裡不出現定義句；知識靠情境呈現（K-3）。
4. **不得只憑感覺說「小四應該讀得完」。** 這一步要有數字，且數字要能複查。

## §7 內容量預算

| 項目 | 值 |
|---|---|
| 主線金幣 | 合計 **250**（跨週固定，不得調整） |
| ECT 動作級估算 | **50–65 分鐘** |
| 建議站數 | 4–5 站（含序章） |
| 建議每站交易數 | 3–4 筆 |
| 建議總交易數 | 14–18 筆 |

**上表是建議值，真正的硬上限是 §6 的閱讀量預算。** 兩者衝突時以閱讀量為準——寧可 3 站讀得完，
不要 5 站讀不動。

超時或超量的正確處理是**刪站或刪交易**，不是縮短對白到看不懂（對白是答案來源，砍到看不懂等於
拿掉答案）。時長靠深度不靠重複——加回合數灌時長是已被明文否決的做法。估算呼叫
`skills/activity-time-estimator/`。

交給 `labterminal-quest-phaser` 之前，內容作者自己先跑完：

- [ ] 有任何一站的解法要求記得前一站的細節嗎？（N-4）
- [ ] 核心訊息在結局由角色說出來了嗎？（N-5）
- [ ] 反派示範的是做法錯誤，不是品格惡劣？（N-6）
