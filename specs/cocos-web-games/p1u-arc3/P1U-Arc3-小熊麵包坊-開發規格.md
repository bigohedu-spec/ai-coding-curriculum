# P1U Arc 3｜小熊麵包坊｜開發規格（W13–W18 單一遊戲・Cocos）

> **狀態：原型可玩，已上課實測（2026-10-01），依原型回填（成品即真相）**。最新的週次與過關條件見 §4、§3-11。2026-09-29 負責人決定：**以現在的原型框架跑六週**，原規格中原型沒有的設計（熊奶奶、搗蛋浣熊、打字接訂單、重複卡、2D 畫面、接力／蛋糕／外送／蛋糕節）**全部作廢**（見 §11 否決紀錄）；之後再往這個框架加內容、切週次進度。
>
> **spec 是唯一真相**：程式跟著 spec 走，要改方向先改 spec；開發中長出的機制要回填本檔（見 §13 追溯表）。
> 工程面一律服從 [`cocos-web-game-standard.md`](../standards/cocos-web-game-standard.md)（版本、目錄、`lt-game/1` 協定、預算、AI 規則、驗收 K-1～K-10）；本檔只寫**這一款遊戲**的教學目標、玩法與內容。
> 低年級設計準則沿用 `skills/labterminal-course-spec/reference/low-grade-game-spec.md`。教學面見 wiki [[P1U-Arc3-教案]]。
>
> 條款分級：**【規定】** 不可違反；**【推定】** 預設值，可改但要記錄；**【假設】** 待小一實玩校準。
> 依低年級準則：內容／故事／畫面寫死；難度／門檻／數值一律標【假設】，單一真相在 `ArcadeConfig.ts`。

| 項目 | 內容 |
|---|---|
| 課程位置 | P1 上（小一上）模組三 W13–W18，接在 Arc 1《海底城》（滑鼠）、Arc 2《字母要塞》（鍵盤 A–Z）之後；**取代原本的 Minecraft 課程** |

| 附帶練習 | WASD 走路＋空白鍵（取代原 Minecraft 的 WASD 練習）、滑鼠拖曳（複習模組一）、用麥克風問 AI |

### §0-1 整款遊戲唯一的核心學習動作【規定】

雇到員工後，**學生必須自己把步驟卡拖進順序板、排對順序**，員工才會照著做（排好會一直重複做）。不得被「付錢就自動」取代。

### §0-2 學習節奏：先問、再自己做、做過才教別人【規定】

每一種新東西都照這個順序（負責人 2026-09-29）：

1. **問 AI**：第一次做之前，先到 AI 機器人那裡用麥克風問 3 個問題，知道自己要做什麼、順序為什麼重要（§3-4）。
2. **自己做**：學生自己一站一站做過幾次。
3. **才考流程、才雇員工**：解鎖格的流程題只考**已經做過**的東西；自己做過幾次後才能雇員工，用排卡片教員工做。

## §1 小一適配【規定】

| 限制 | 對策（as-built） |
|---|---|
| 識字量少 | 畫面上**所有文字都有注音**（遊戲自帶注音子集字型，§7-3）；選項寫短、兩行內 |
| 手眼協調還在練 | 走進站點的框就自動拿東西；放東西只要按空白鍵（按住會一個一個放）；拖曳卡片放開時自動吸附最近的格子 |
| 耐挫力低 | **出錯不扣任何東西**：順序錯只做出看得出壞掉的失敗品，要自己撿去丟、打掃乾淨；答錯只鎖 2 秒、重新洗選項 |
| 不知道下一步去哪 | 紅色箭頭永遠指著下一步；目標很遠時小熊腳邊多一個指路箭頭（§3-10）；右上角任務表寫現在要做什麼（§3-11） |
| 受不了重複作業 | 重複的事交給員工；升級讓員工和站點越來越快 |

## §2 世界與角色【規定】

- **故事**：小熊接手森林裡的麵包坊。店在中間，麥田圍住整家店，店前面有一條馬路，客人從左右兩邊走過來買東西。小熊先學會做麵包，再請小兔、小松鼠幫忙，店越開越大。
- **角色**：

| 角色 | 身分 | 外觀 |
|---|---|---|
| 小熊 | 玩家（戴白色廚師帽） | 背後疊著手上的東西（背包 2 個起，可升級到 28 個【假設】） |
| AI 機器人 | 問 AI 的地方（§3-4） | 店中間，有還沒問的問題時頭上跳橘色驚嘆號 |
| 小兔 | 麵包員工（紅帽） | 一開始很慢，可升級 |
| 小狐狸 | 果醬員工（2026-09-30 新增，**已實作**） | 摘田裡的莓果 → 煮果醬 → 上架；一樣要排步驟卡，可升級 |
| 小松鼠 | 三明治員工（黃帽、紅圍裙） | 一開始很慢，可升級；缺麵包、果醬會先拿工具旁現成的，沒有就自己做（§3-5） |
| 小羊 | 顧雞員工（綠帽）（2026-09-30 新增，**已實作** hc-pilot 9000541） | 摘田裡的莓果、餵雞、撿雞蛋、把雞蛋上架；一樣要排步驟卡（§3-5），可升級 |
| 雞 | 雞舍裡的雞（2026-09-30 新增，**已實作** 7862a5d：三隻，一直低頭啄、下蛋中啄比較快） | 吃莓果、過一陣子下蛋；雞蛋是第二層收入 |
| 顧客 | 從馬路走來 | 現況：頭上顯示想要什麼，拿到對的打勾付錢、拿到壞的皺眉丟掉。**2026-09-30 改為**：推購物車、拿一張多樣商品的清單逛商品專區，缺貨就停在貨架前等，買齊了去收銀台付錢（§3-9，未實作） |

### §2-1 地圖【規定；座標為推定】

- 鏡頭水平轉 **45 度**斜角俯視（負責人：比較立體）。WASD 是**畫面上的**上下左右。
- 中間是麵包店（店面 60×31.5 公尺；站點之間的距離放大 1.4 倍，負責人 2026-09-30：所有物件再排開一點），**麥田圍住整家店**，由內而外一級、二級、三級。麥田是**一整塊農田**（翻過的土、零散雜草），等級之間留一排沒有麥子；地上不寫等級字（2026-09-30 移除，靠麥穗顏色分等級）。
- 店裡站點**刻意散開、不排成一條線**，下一步去哪只靠紅色箭頭提示。**文字、互動框、升級圈互相不碰到**（2026-09-30 負責人，版面檢查 0 處重疊）。
- 店前面是馬路（有車道線），客人從左右兩邊沿著馬路走過來。
- （2026-09-30 新增，**已實作** hc-pilot 0de9575）**莓果叢種在麥田裡**：種在二級與三級之間那排小路（本來就沒有麥子），大約每 3 格一叢，共 30 叢、每叢 3 顆，店的左、右、後三邊平均分布；麥子數量與位置不動。果醬區解鎖後才長出來。原本店裡的單一莓果叢與「摘莓果」框拿掉。（三級外圈沒種：外圈已經到地圖邊界。）
- （2026-09-30 新增，**已實作** hc-pilot 7862a5d）**雞舍**：店的右後角靠麥田（原本店裡莓果叢的位置），木頭小屋＋紅屋頂＋稻草地，三隻雞。
- （2026-09-30 新增，**已實作** hc-pilot 47b8400、a00cf50）**商品專區＋收銀台**：店的左前方，照**畫面**排成整齊三排——上排是各貨架的放入框＋名字（貨架後面補貨）、中排是貨架一列（〔雞蛋架預留〕→ 果醬架 → 麵包架 → 三明治櫃 → 收銀台）、下排是客人走道＋每個貨架的「加一層」升級圈。工具架因此搬到垃圾桶左邊、烤爐往畫面右移 2 公尺。

| 線 | 站點 | 做什麼 |
|---|---|---|
| 麵包線 | 工具架（拿鐮刀）、麥田、磨粉、揉麵、烤、上架（展示櫃）、收錢 | 麥 → 麵粉 → 麵糰 → 麵包 → 上架 → 客人付錢 |

## §3 核心機制（as-built）

### §3-1 操作【規定】

| 動作 | 怎麼做 |
|---|---|
| 走路 | WASD／方向鍵（畫面上的上下左右） |
| 割麥子 | 拿著鐮刀走進麥田就自動割（不用按鍵）；背包滿了照樣割，割下來的麥子掉在地上（放大、浮著、有光圈），之後走過去撿，要麥子的員工也會撿 |
| 拿東西（拿成品、撿地上的東西） | 走進框裡自動拿 |
| 收錢 | 碰到收銀台的金幣，金幣**全部飛起來追著小熊進背包**（小熊走開也追得上）；金幣山碰一次就持續收完（§3-12） |
| 放東西（放進站點、上架、放櫃檯、放麵包盒、丟垃圾桶、付錢解鎖、付錢升級） | 站在框（或升級圈）裡按**空白鍵**，按住會一個一個放 |
| 題目、順序板、問 AI | 滑鼠；選擇題也可按 1／2／3；**填空題一律拖拉**（負責人要求） |

### §3-2 站點的框：放入／拿取【規定】

- 每個加工站用一個**正方形框框住機台**（45 度鏡頭下看起來是菱形），沿菱形的垂直對角線切成畫面上的**左右兩半**：**左半藍色「放入」、右半綠色「拿取」**（負責人：不要用圓形實體、框住模型、切成左右兩塊）。
- 框裡有**流動的小箭頭**（特效）：左半往機台流進去、右半從機台流出來。站進哪一半，那一半的三角形淡淡亮起來。
- 其他範圍（拿鐮刀、上架、櫃檯、垃圾桶、收錢、順序板…）也都用框：放東西藍框、自動拿綠框、員工順序板橘框。
- 同一站做出來的東西不會被放回同一站。
- （2026-10-01，**已實作** hc-pilot ccc9410）**小熊和員工共用同一排**：每站只有一堆「放入」、一堆「拿取」，每層 3×3 往上疊；拿取區的東西誰都能拿（**小熊優先**）。堆放量＝`stationBuffer` 6，「放更多」每級 +2【假設】；拿取區滿了機台就停，等人拿走。
- 每站上方有**進度條**。

### §3-3 順序錯＝做出失敗品【規定】

每一站收什麼、做出什麼（表外的東西這站不收，按空白鍵會跳紅色 ✕）：

| 站 | 放對 | 放錯會變成（失敗品） |
|---|---|---|
| 磨粉 | 麥 → 麵粉 | 麵糰 → 糊糊；麵包 → 麵包屑 |
| 揉麵 | 麵粉 → 麵糰 | 麥 → 麥稈團；麵包 → 糊糊 |
| 烤 | 麵糰 → 麵包 | 麥 → **烤焦的麥子**；麵粉 → 白粉塊 |
| 煮果醬 | 莓果 → 果醬 | — |
| 切開 | 麵包 → 切開的麵包 | 切開的 → 麵包屑；塗好果醬的 → 果醬糊麵包 |
| 塗果醬 | 切開的 → 塗好果醬 | 沒切的麵包 → 果醬糊麵包（**還會噴出果醬灘**）；塗好的再塗 → 果醬糊麵包 |
| 組合 | 塗好果醬的 → 三明治 | 只切沒塗 → 乾巴巴三明治；沒切 → 壓扁的麵包 |
| 雞舍（2026-09-30 新增，**已實作**：跟加工站同一套放入／拿取框，下蛋 4 秒【假設】；雞蛋放回雞舍＝破掉的蛋） | 莓果 → 雞吃掉、過一陣子下一顆**雞蛋**（在雞舍的「拿取」那半） | 小熊放錯東西：跳 ✕、不收【推定】。小羊排錯順序：帶著雞蛋去餵雞 → **破掉的蛋**；帶著莓果去上架 → **壓爛的莓果**【推定】 |

- 失敗品**顏色暗、形狀歪、頭上有紅色 ✕**，一看就知道壞掉。
- 失敗品可以放上架，但客人會拒收、拿去丟；學生要自己撿去垃圾桶（紅箭頭會先指垃圾桶）。（2026-09-30 起改成各類貨架後：失敗品放進它那條線的貨架【推定：麵包線的失敗品放麵包架、三明治線的放三明治櫃、雞蛋線的放雞蛋架】，客人拿到一樣拒收、丟掉，再回來拿清單上的東西。）
- **撿起失敗品就問「怎麼會變成這樣？」**（2026-10-01：題目關掉後 5 秒內不再跳，排隊最多一題）（三選一，正解是順序錯的那個原因；三個選項一律兩行、每行 ≤5 字、同一字級，避免學生挑「字最多」的）。原因題庫見 `QuizData.ts` 的 `WHY`。

### §3-4 問 AI【規定】

- 做法同字母要塞的「緊急任務」：**問題、回答、小考全部預寫**（老師審過、本地直接回、不連 AI），學生要用**麥克風念出問題**才問得到；念不出來 2 次【假設】後出現「念不出來？直接問」。
- 流程：念出問題 → 語音辨識 → 念對（題目中文字對上五成【假設】）→ AI 想一下 → 回答一個字一個字打出來 → 打完才出三選一小考 → 答對下一題；答錯鎖 2 秒、重洗選項。
- **主題**（內容見 `AiMissions.ts`）：怎麼做麵包（開局，3 題）、怎麼做果醬（解鎖果醬區後，3 題）、**什麼是自動化**（W13 最後：小狐狸排好、商店升到 35 級後，2 題：怎樣讓店自己一直賺錢、順序排錯會怎樣；id 沿用 `order`）、怎麼做三明治（W14，解鎖三明治區後，3 題）、**小松鼠怎麼這麼慢**（W14，三位員工都自己上架到數量後，2 題：沒人幫牠、要自己做麵包煮果醬 → 找幫手、去工廠組搬運機器人；id `slow`，【草稿，待負責人審】；「為什麼」的「為」是破音字，改用「怎麼」）。
- （2026-10-01）放開麥克風按鈕後**馬上**變灰、圖示換成轉圈圈「等一下，正在聽…」，讓學生知道聲音送出去了。「念不出來？直接問」放在視窗最下面、純文字沒外框（給老師按）。
- （2026-09-30 新增，**已實作**，內容是【草稿，待負責人審】；在 AiMissions.ts 的 egg，實際是第五個主題——另一位開發者先加了「順序有多重要」）**第四個主題：怎麼養雞拿雞蛋**（解鎖雞舍後，3 題）。依 §0-2 每種新東西都先問 AI；題目、回答、小考**要負責人（老師）先審過**才放進遊戲。

### §3-10 紅色箭頭【規定】

- 紅色箭頭在下一步的目標上方跳動。**跟著任務表走**（負責人 2026-10-01：比較好控制小朋友的行為）。

## §7 畫面與技術【推定】

### §7-1 畫面
- **3D**（Unlit＋頂點色假光影＋GPU Instancing），場景沒有燈，明暗烘在頂點色。
- **low-poly 模型**（2026-09-30，as-built）：Blender 腳本產生（`hc-pilot/_source/blender/*.py`），顏色用 32×32 調色盤貼圖、明暗烘在頂點色，全部共用一個 Unlit 材質；模型沒載入時退回程式方塊。已換：小熊、小兔、小松鼠、5 種動物顧客、AI 機器人、麥子（每級 3 種樣式、隨機角度）、麥稈樁、田地、雜草。機台與家具、手上的物品還是程式方塊。
- **零件動畫**（as-built）：小熊（走路、揮鐮刀往前翻並水平掃 180 度、放東西伸手）、小兔與小松鼠（走路、在站點做事）；顧客、機器人不做。
- **自訂 shader**（as-built）：`plant-wind`（麥子與雜草風吹、小熊走過會撥開；田地土的貼圖＋法線）、`shop-floor`（上釉磁磚＋假反光）、`zone-glow`（站進框時框裡發光）、`slash`（揮砍刀光、打中的衝擊光圈）。打擊感另有麥粒碎屑、畫面震動、頓一下（只有畫面，不動數值）。
- 站名、放入／拿取、價錢等文字**畫在地板上**（不擋畫面，全部轉成正對鏡頭）；只有員工名牌與泡泡浮在頭上。
- **螢幕適配**：比 16:9 寬固定高度 720、比 16:9 窄固定寬度 1280，至少看得到 1280×720；視窗改大小時 HUD 跟著移到角落。

### §7-2 效能
- 內顯（Intel UHD）1920×1080 約 130～140 fps（2026-09-29，程式方塊版）。
- 2026-09-30 換模型、麥田、地板與特效後：獨顯（RTX 3070）開場約 365 fps、麥田邊約 335～480 fps；**內顯尚未實測**，要到教室電腦量過才能確認 ≥ 60 fps。
- ⚠ **瀏覽器要開硬體加速**：Chrome 關掉「使用圖形加速功能」時 WebGL 改用 CPU 模擬，只剩約 20 fps（2026-09-29 負責人電腦實測）。上課前要檢查教室電腦。

### §7-3 注音
- 遊戲自帶 **Bpmf GenSen Rounded 子集字型**（SIL OFL，約 190 KB），只收遊戲用到的字；負責人 2026-09-29 核准（正典 T-2）。
- 字型只有預設讀音：破音字靠改寫句子避開（§6）；輕聲（例：子）顯示本調，已接受。

### §7-4 大小
- 建置 gzip 後約 2.57 MB（2026-09-30；上限 5 MB）。已知浪費：多零件的 glb 在每個零件的網格檔都存一份整個檔案的資料，拆成一個零件一個檔案可以再省幾百 KB（待做）。
