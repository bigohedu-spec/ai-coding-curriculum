## 二十、課程 Web App 互動設計規範【所有年級適用】

> **生效範圍**：Lab Terminal 內的所有互動課程頁面（W1 起全面適用）。
> 本節是「十九節低年級原則」的延伸，補充 Web App 特有的互動設計規則。
> 技術實作細節（CSS、JS 程式碼）另見開發文件，本節只記錄**設計規則**。

---

### 鐵則 6：主觀選擇必須掛勾客觀驗證【不可違反】

#### 核心邏輯

「選一個你覺得最有用的」沒有正確答案 = 隨便選都過 = 沒有任何認知投入。
所有主觀選擇，**必須接著一個有客觀對錯的後續任務**，才算完成驗證。

#### 轉化方法

把「主觀判斷」接到一個「拖拉對應 / 配對 / 排序」的客觀任務上。

| ❌ 反模式 | ✅ 正確設計 |
|----------|-----------|
| 「點選最有用的一句建議」| AI 給 3 個建議，學生把每個建議拖到對應的設計槽（形狀/大小/特色），必須全部對才通過 |
| 「選一個你喜歡的方向」| 選完後必須填寫/組合一個與該方向一致的具體成果 |
| 「哪個比較好？」2 選 1 | 選完後必須從比較好的版本萃取出 3–4 個具體元素 |

#### 判斷標準

**「如果把選擇後的驗證步驟拿掉，學生隨便選也不會有任何後果嗎？」**
→ 是 = 缺少客觀驗證，必須補上。

### 鐵則 7：自由打字必須有完整輔助結構【不可違反】

#### 核心邏輯

讓學生對著空白輸入框打字 = 讓他們「通靈」——猜測你想要什麼答案。
沒有結構的自由打字必然產生兩個結果：打 `aaaaa` 通過，或完全不知道寫什麼。

#### 每個輸入欄位的必備五要素

| 要素 | 說明 | 範例 |
|------|------|------|
| **Hint Block** | 主題脈絡、為什麼要填、寫什麼方向 | 藍色提示框，說明本步驟的目的 |
| **結構模板** | 填空式框架，不能是純空白 | 「因為 ____，所以我選擇 ____」|
| **具體範例** | placeholder 直接給一個完整範例 | `例：圓柱形，高 10cm，有星星裝飾` |
| **實質內容驗證** | 關鍵字 / 元素類別檢查，**不只字數** | 必須包含「形狀」「大小」兩個類別的詞 |
| **具體錯誤訊息** | 指出缺少什麼，不只說「請填寫」| 「還沒提到：形狀、大小」|

#### 高年級自由打字專用：Step Flow 一頁一格

高年級（G3）的多步驟打字任務，必須採用 **Step Flow** 模式：
- 一次只顯示一個輸入格，完成當前步驟才前進
- 進度指示器明確顯示「第 X / N 步」
- 每步驗證通過才能繼續
- 最後一步驗證必須包含**前面步驟填入的值**（跨步一致性檢驗）

**禁止**：一頁多欄同時顯示、未驗證就允許跳過任一步驟。

### 雙難度設計矩陣【所有 Web App 課程強制適用】

| 環節類型 | 低年級 G1–G2 | 高年級 G3 |
|---------|--------------|-----------|
| 回顧上週 | 拖拉配對（圖示 × 名稱）| Step Flow 2 步自由打字 |
| 概念對比 | 元素萃取拖拉（從範例中拖出關鍵詞）| Step Flow 3 步打字（模糊/清楚/觀察）|
| 建構創作 | 下拉積木 + 即時 3D 預覽 | Step Flow 5 步打字 + 右側即時預覽 |
| 建議配對 | 拖拉對應（共用，難度相同）| 拖拉對應（共用）|
| 預演 Modal | 句子接龍（共用）| 句子接龍（共用）|
| 課堂總結 | 句子接龍（共用）| 句子接龍（共用）|
| 技能牆 | 浮動磚塊點擊飛入 | 表格 + 必填 checkbox |

**底層原則**：
- 低年級：點選、拖拉、圖示優先，文字量極少
- 高年級：Step Flow 自由打字 + 可見提示 + 跨步驟內容驗證
- **共用環節**（建議配對、預演、總結、技能牆）：所有學生過同樣的認知關卡，不因難度分流

### 標準課程骨架（7 個 Screen）【Web App 課程強制適用】

每堂課的互動流程固定為以下 7 個 screen，可依內容調整細節，但不可任意刪除：

```
0. start    — 難度選擇 + Hook（視覺承諾今天能做出 X）
1. recall   — 上週核心概念回顧（配對 / Step Flow）
2. taskA    — 概念建立（compare / extract / sort）
3. taskB    — 創作練習（build / construct）
4. summary  — 課堂總結（句子接龍，有教學意義反例）
5. wall     — 技能牆磚塊解鎖
6. done     — Deliver 頁（兌現 Hook 的承諾）
```

**固定附加**（不計入 7 個 screen）：
- 任務 A / B 完成後 → **Rehearsal Modal**（句子接龍，必答對才關閉）
- 每個 screen 進入時自動觸發對應的 `setup()` 函式

### Icon 視覺規範【Web App 全面適用】

#### 核心規則：**禁用 emoji，一律使用 AI 生成圖示**

| ❌ 禁止 | ✅ 正確作法 |
|--------|-----------|
| 任何 Unicode emoji（🎨 🔑 📦）| AI 生成的 PNG/SVG 圖示，存於 `assets/icons/` |
| 系統字型中的特殊符號 | 統一風格的向量圖示 |

**統一生成風格**（Gemini / 任何 text-to-image 工具）：
```
Style: BOLD modern flat-design vector icon, vibrant saturated colors
(purple #7C3AED, amber #F59E0B, teal #14B8A6, pink #EC4899),
thick black outlines 3-4px, sticker-like with subtle gradient shading,
playful child-friendly Duolingo-style mascot icon,
NO text NO letters NO words in image, centered single subject,
clean white background, square 1:1 ratio, simple distinct shapes, high contrast.
```

所有圖示使用同一套 prompt 後綴，確保風格一致。

### 防作弊驗證策略【Web App 全面適用】

#### 原則：內容驗證，不只字數

**禁止**：以字元數量作為唯一驗證條件（5 個字元就能用 `aaaaa` 通過）。

**必須採用的驗證層次**（依任務類型至少用其中一種）：

| 驗證方式 | 說明 | 適用情境 |
|---------|------|---------|
| 關鍵字檢查 | 正規表達式匹配特定詞彙或詞根 | 自由打字中必須提到的概念 |
| 多類別計數 | 必須同時包含 N 個不同類別的詞 | 「清楚版 Prompt 要含形狀/大小/特色」|
| 跨步一致性 | 最後一步的內容必須包含前面步驟填入的值 | Step Flow 的最終組合步驟 |
| 排列組合 | 拖拉/配對/排序的排列數 >> 30 秒能嘗試的次數 | 配對題：5 對 = 120 排列 |

#### 錯誤訊息規範

錯誤訊息必須具體，不能只說「請填寫」或「內容不足」：

| ❌ 無效訊息 | ✅ 有效訊息 |
|-----------|-----------|
| 「請填寫此欄位」| 「還沒提到：形狀、大小」|
| 「內容太短」| 「需要至少提到 3 個設計元素」|
| 「答案不對」| 「這個詞放錯槽了，試試看另一個」|

#### 防複製貼上

提示框（hint block）必須設定 `user-select: none`，不可被複製。
所有輸入框必須攔截 `paste` 和 `drop` 事件，觸發時顯示具體錯誤 toast。

#### 錯誤選項鎖定

任何選擇題，點錯後該選項必須永久鎖定（顯示刪除線 + 紅色 ✗ + `disabled`），
不可重複嘗試，讓錯誤有成本。

### Web App 課程開發自我審核清單

開發新一週課程時，逐項確認：

**內容設計**
- [ ] 7 個 screen 的標準骨架完整？
- [ ] 課堂核心訊息（key message）能一句話說清楚？
- [ ] 核心訊息在 App 中出現 **5 處以上**（Hook / 中間任務 / Rehearsal / Summary / Skill Wall / Done 徽章）？
- [ ] Hook 的視覺承諾與 Done 頁的 Deliver 相呼應？
- [ ] 所有主觀選擇都掛勾了客觀驗證步驟？
- [ ] 總結句子接龍的 4 個反例是有教學意義的錯誤（不是隨機干擾項）？

**互動防硬 A**
- [ ] 每個關卡用「30 秒亂點」測試，無法通過？
- [ ] N 選 1 都改成了拖拉 / 排序 / 句子接龍？
- [ ] 自由打字有完整的五要素（Hint / 模板 / 範例 / 內容驗證 / 具體錯誤訊息）？
- [ ] 高年級打字任務採用 Step Flow 一頁一格？
- [ ] 錯誤選項點擊後永久鎖定？

**視覺**
- [ ] 有無 emoji 殘留？→ 全部換成 AI 生圖
- [ ] 新圖示使用統一 prompt 風格生成？
- [ ] 3D 物件可視化在關鍵節點（Hook / 對比 / 建構 / Done）出現？

**防作弊**
- [ ] Hint 框設定 `user-select: none`？
- [ ] 輸入框攔截 paste / drop？
- [ ] 內容驗證為實質性（不只字數）？

### S3 GAMMA＋答題卡架構例外【S3 新版強制適用】

S3 的 `gamma-answer-worksheet` 不是本節 7-screen 單檔 HTML 課程。生成或修改 S3 答題版時，不套用固定 7-screen、Rehearsal Modal、技能牆或單檔 HTML 交付；改依下列共通正典：

- `wiki/programs/S3/課程規格/S3-答題版學習單新架構規格.md`
- `skills/s3-answer-sheet-course/SKILL.md`

S3 答題版固定維護「學生學習單＋課程規格內嵌 schema v3 JSON＋教案」三文件；左側 GAMMA 負責學生故事與題面，右側答題卡負責互動、檢核、保存與解鎖。若本節一般 Web App 規則與 S3 答題版總規格衝突，以 S3 總規格為準；共同原則（本地可重現判定、答案隔離、狀態保存、250 金幣、時長驗證）仍適用。
