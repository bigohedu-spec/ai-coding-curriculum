## 二十三、每週學習重點【所有學習單強制適用；2026-10-07 起】

> 背景（負責人 2026-10-07）：**課後複習改成依靠學習單**。後台「AI 出題」直接讀 GitHub `main` 分支的 `wiki/worksheets/**.md` 產生複習小考（gpt-clone `src/lib/homeworkAdmin.ts`），所以學習單一定要寫清楚**這一週學到什麼**，出題才不會偏題或考到別週。

### 強制規則

1. **每份學習單都要有 `## 本週學習重點` 這一節**，放在學習單**後段**（闖關／任務之後、老師筆記之前）。沒有這一節的學習單不算定稿。
2. **一份學習單只寫一週**：檔名 `[學期]-W[週次]-學習單.md`，學習重點只寫這一週。好幾週共用同一款遊戲（例如 P1U Arc 3 小熊麵包坊）也要**每週一份**，不能把六週寫在同一份裡（出題時分不出週次）。
3. **寫法**：
   - 3–5 條，每條**一句話**（小一、小二 ≤ 25 字；小三以上 ≤ 40 字），可以加注音。
   - 每條都是**學生這週親手做過、或問 AI 問過的事**，寫成「正確知識＋結果／原因」，讓複習題有明確的對錯。例：「麥子沒有磨成粉就拿去烤，會烤焦。」
   - 只寫**學習內容**（順序、概念、正確知識、怎麼除錯），不寫操作細節（按哪個鍵）和遊戲數值（價錢、等級）。
   - **不寫學生不該知道的機制**（例：動態金錢、時間到自動過關這類老師端設計）。
   - 跟遊戲／教材裡 AI 問答的**正確答案一致**；兩邊不一樣時以遊戲為準，並回頭修學習單。
4. **跟第十九節的關係**：第十九節禁止低年級學習單在任務前放概念說明。「本週學習重點」是**做完之後的回顧**（順序仍然是「玩 → 觀察 → 回顧」），所以：
   - 只能放在學習單後段，不能放在任務前面當預讀。
   - 不算進第十九節「純說明文字 ≤ 200 字」的上限。
   - 不寫原理長文：每條仍然只有一句。
5. 改了某一週的教學內容（教案、遊戲任務、AI 問答）→ 同一個 commit 一起改該週學習單的學習重點（Cascade）。

### 自我檢查

- [ ] 有 `## 本週學習重點`，3–5 條，每條一句
- [ ] 每條都能出成一題有明確答案的選擇題
- [ ] 只寫這一週，沒有混到別週
- [ ] 沒有操作細節、遊戲數值、老師端機制
- [ ] 跟 AI 問答的正確答案一致
