## 十二、作品導向設計規則（Project-Centric Design）【不可違反】

### 生效範圍

**S5 模組二（W7）起，所有 EX 任務強制適用。** S1–S5 模組一為技能習得階段，孤立練習可接受。S5 模組二 Copilot 正式入場後，規則生效，不得例外。

### 設計背景

有了 AI 輔助，學生在第一堂接觸 Copilot 的課就能產出一個可執行的遊戲。這代表課程的天花板已經大幅提高——如果我們還在設計「練習寫函式」這樣的孤立任務，就是在浪費 AI 帶來的槓桿效應。

**正確的設計邏輯是：**
> 所有中間過程（學函式、學參數、學 DOM 操作……）的本質，都是在為學生精修他們的個人專案。每個任務產出都應該是專案的一部分，而不是用完就丟的練習題。

### 作品導向三原則

**原則一：專案宣言優先**
每位學生在進入 S5 模組二時，必須先確立自己的「專案方向」（一句話說明要做什麼）。此後所有任務的「成功條件」都必須包含「這個功能已整合進你的專案」。

**原則二：每個任務 = 專案的一個功能**
任務設計不能是「寫一個函式，任意功能都行」，而是「為你的專案加入一個功能」。功能的選擇可以由學生決定，但必須與他們的專案有關。

**原則三：學期末必有可上線版本**
每個學期（S5 起）的里程碑任務，成功條件必須包含「專案可以被展示或部署」，而不只是「任務完成截圖」。

| 學期 | 作品狀態里程碑 |
|------|-------------|
| S5 | 有可執行的本地專案，核心功能運作 |
| S6 | 專案功能完整，代碼版本控制正常 |
| S7 | 專案已部署上線（GitHub Pages / Vercel / 等） |
| S8 | 專案已有真實用戶，嘗試變現或獲取回饋 |

### 任務設計驗證（S5 Module 2 起每次設計 EX 任務都要過這關）

**❌ 以下任何一項出現 → 任務設計需修改**

| 問題 | 說明 |
|------|------|
| 任務要求的產出與學生的個人專案無關 | 孤立練習，學完即丟，違反原則二 |
| 成功條件只有「截圖顯示程式碼」，沒有「整合進專案」 | 產出不累積，學生感受不到進步 |
| 任務功能由老師指定、全班一樣 | 應允許學生選擇與自己專案相關的功能方向 |
| 學期末里程碑沒有「可展示」的要求 | 違反原則三 |

**✅ 通過條件**

- 任務說明中有「為你的專案加入 _____ 功能」的框架
- 成功條件包含「在你的專案中可以看到這個功能運作」
- 學生可以自行決定功能的具體內容（老師設定框架，學生填入內容）
- 學期末里程碑的截圖包含整個專案的執行畫面
